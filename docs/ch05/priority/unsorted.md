# 정렬되지 않은 배열

[우선순위 큐 추상 자료형](adt.md)을 구현하는 가장 간단한 방법은 원소를 정렬되지 않은 배열에 담는 것이다. 넣기는 끝에 덧붙이기만 하면 되니 아주 쉽지만, 최솟값을 찾아 없애려면 배열 전체를 훑어야 한다. 이 절충 덕분에 넣기가 꺼내기보다 훨씬 많을 때 정렬되지 않은 배열 구현이 매력적이며, [정렬된 배열](sorted.md)이나 [힙](heap_preview.md) 같은 더 정교한 구현과 견줄 기준선이 되어 준다.

## 표현

이 우선순위 큐는 원소 $n$개를 **순서 제약 없이** 배열 $A[0 \ldots n-1]$에 담는다. 원소는 넣은 순서 그대로 놓인다.

## 연산

### 삽입

새 원소 $x$을 넣으려면 배열의 끝에 덧붙인다.

$$
T_{\text{insert}} = O(1)
$$

비교하거나 옮길 것이 없다. 동적 배열에서는 이따금 크기를 다시 잡느라 $O(n)$이 들지만 상각 비용은 $O(1)$로 유지된다.

### 최솟값 빼기

키가 가장 작은 원소를 빼서 돌려주려면 다음과 같이 한다.

1. 배열 전체를 훑어 최솟값의 인덱스 $j$을 찾는다.
2. $A[j]$을 마지막 원소 $A[n-1]$과 맞바꾼다.
3. 마지막 원소를 없앤다($n$을 1 줄인다).

훑는 데 $O(n)$이 든다.

$$
T_{\text{extract-min}} = O(n)
$$

마지막 원소와 맞바꾸면 옮길 필요가 없어 없애기 자체는 $O(1)$이 된다.

### 최솟값 찾기

꺼내지 않고 최솟값만 찾더라도 전체를 훑어야 한다.

$$
T_{\text{find-min}} = O(n)
$$

!!! tip "최솟값을 캐시하기"
    현재 최솟값을 가리키는 포인터를 캐시해 두는 최적화가 있다. 그러면 `find_min`이 $O(1)$이 되지만, `extract_min`은 없앤 뒤 새 최솟값을 찾으려고 여전히 훑어야 하고 `insert`은 새 원소를 캐시된 최솟값과 견주어야 한다. 최악의 경우 점근 복잡도는 나아지지 않는다.

## 복잡도 요약

| 연산 | 시간 |
|---|---|
| `insert(x)` | 상각 $O(1)$ |
| `extract_min()` | $O(n)$ |
| `find_min()` | $O(n)$ |
| `is_empty()` | $O(1)$ |

## 정렬된 배열과의 비교

정렬되지 않은 배열과 [정렬된 배열](sorted.md) 구현은 서로 보완적인 절충을 보인다.

| 연산 | 정렬되지 않음 | 정렬됨 (늘어나지 않는 차례) |
|---|---|---|
| `insert` | $O(1)$ | $O(n)$ |
| `extract_min` | $O(n)$ | $O(1)$ |
| `find_min` | $O(n)$ | $O(1)$ |

어느 쪽도 두 연산을 동시에 $O(\log n)$으로 하지는 못한다. 그러려면 [힙](heap_preview.md)이 필요하다.

## 정렬되지 않은 배열을 쓸 때

- **한꺼번에 넣고 모두 꺼낼 때**: 원소 $n$개를 $O(n)$에 넣은 뒤 정렬된 차례로 모두 꺼낸다. 전체 비용은 $O(n) + O(n) + O(n-1) + \cdots + O(1) = O(n^2)$이며 이는 선택 정렬과 같다.
- **데이터가 아주 적을 때**: $n$이 아주 작으면 정렬되지 않은 배열의 단순함이 힙의 상수 배 부담을 이길 수 있다.
- **넣기가 많은 작업**: 넣기와 꺼내기의 비가 크면 $O(1)$ 넣기 비용이 전체 성능을 좌우한다.

??? example "연산 따라가기"
    | 단계 | 연산 | 배열 | 반환값 |
    |------|-----------|-------|----------|
    | 1 | `insert(5)` | [5] | — |
    | 2 | `insert(3)` | [5, 3] | — |
    | 3 | `insert(8)` | [5, 3, 8] | — |
    | 4 | `insert(1)` | [5, 3, 8, 1] | — |
    | 5 | `find_min()` | [5, 3, 8, 1] | 1 |
    | 6 | `extract_min()` | [5, 3, 8] | 1 (1과 8을 맞바꾸고 마지막을 없앰) |
    | 7 | `extract_min()` | [5, 8] | 3 (3과 8을 맞바꾸고 마지막을 없앰) |

    6단계에서 최솟값(인덱스 3의 1)을 마지막 원소(8)와 맞바꾼 뒤 마지막 자리를 없앤다. 배열은 [5, 3, 8]이 된다. 순서가 바뀌었음에 유의하라. 배열이 정렬되어 있지 않으므로 당연한 일이다.

## 파이썬 구현

```python
"""넣기가 O(1)이고 최솟값 꺼내기가 O(n)인 정렬되지 않은 배열 우선순위 큐."""


# === 정렬되지 않은 배열 우선순위 큐 ===

class UnsortedArrayPQ:
    """A min-priority queue backed by an unsorted dynamic array.

    insert:      상각 O(1) (덧붙이기)
    extract_min: O(n) (선형 훑기)
    find_min:    O(n) (선형 훑기)
    """

    def __init__(self):
        self._data = []

    def __len__(self):
        return len(self._data)

    def is_empty(self):
        return len(self._data) == 0

    def insert(self, key):
        """상각 O(1) 시간에 키를 넣는다."""
        self._data.append(key)

    def find_min(self):
        """최소 키를 O(n) 시간에 돌려준다."""
        if self.is_empty():
            raise IndexError("find_min from empty priority queue")
        return min(self._data)

    def extract_min(self):
        """최소 키를 O(n) 시간에 빼서 돌려준다."""
        if self.is_empty():
            raise IndexError("extract_min from empty priority queue")
        min_idx = 0
        for i in range(1, len(self._data)):
            if self._data[i] < self._data[min_idx]:
                min_idx = i
        # 마지막 원소와 맞바꾼 뒤 빼기
        self._data[min_idx], self._data[-1] = self._data[-1], self._data[min_idx]
        return self._data.pop()


# === 시연 ===

if __name__ == "__main__":
    pq = UnsortedArrayPQ()
    for val in [5, 3, 8, 1, 9, 2]:
        pq.insert(val)
    print(f"Min: {pq.find_min()}")  # 1
    print(f"Extract: {pq.extract_min()}")  # 1
    print(f"Extract: {pq.extract_min()}")  # 2
    print(f"Remaining size: {len(pq)}")     # 4
```

## 연습문제

**연습문제 1.**
정렬되지 않은 배열의 추상 자료형이 지원하는 연산을 시간 복잡도와 함께 모두 열거하라. 어느 연산이 병목인가?

??? success "연습문제 1 풀이"
    추상 자료형은 구현과 무관하게 지원하는 연산을 정한다. 무엇이 병목인지는 쓰임새에 달렸다. 실시간 시스템에서는 최악의 복잡도가 중요하고, 일괄 처리에서는 상각 복잡도로 충분하다.

---

**연습문제 2.**
정렬되지 않은 배열을(를) 서로 다른 두 자료 구조로 구현하라. 각각의 절충을 비교하라.

??? success "연습문제 2 풀이"
    구현 1: 배열 기반 — 접근은 상수 시간이지만 크기를 다시 잡아야 할 수 있다. 구현 2: 연결 리스트 기반 — 삽입과 삭제는 상수 시간이지만 접근은 $O(n)$이다. 어느 쪽을 고를지는 응용에서 예상되는 연산의 구성에 달렸다.

---

**연습문제 3.**
정렬되지 않은 배열을(를) 쓰는 딥러닝 응용을 하나 설명하라(예: 그래프 신경망의 너비 우선 탐색, 기호 미분에서의 식 계산, 데이터 적재의 스케줄링).

??? success "연습문제 3 풀이"
    구체적인 응용은 그 추상 자료형의 순서 성질에 달렸다. 선입선출(큐)은 GNN의 너비 우선 그래프 순회에 쓰이고, 후입선출(스택)은 자동 미분 테이프 처리에 쓰이며, 우선순위 순서는 빔 탐색과 예정 표집에 쓰인다.

---

**연습문제 4.**
정렬되지 않은 배열을(를) 원형 배열로 구현하면 모든 연산이 상각 $O(1)$ 시간임을 증명하라.

??? success "연습문제 4 풀이"
    원형 배열은 머리와 꼬리 인덱스를 용량으로 나눈 나머지로 관리한다. 넣기와 빼기는 인덱스를 $O(1)$에 조정한다. 배열이 가득 차면 용량을 두 배로 늘리는 데 $O(n)$이 들지만, 이는 값싼 연산 $O(n)$번 뒤에 한 번 일어나므로 동적 배열과 같은 논법으로 상각 $O(1)$이 된다. $\square$
