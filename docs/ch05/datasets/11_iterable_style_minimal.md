# 반복자 방식 최소 예제

PyTorch는 두 가지 데이터셋 방식을 지원한다. `__getitem__`으로 임의 접근을 제공하는 맵 방식 데이터셋과, `__iter__`으로 데이터를 흘려보내는 반복자 방식 데이터셋이다. 반복자 방식은 스트리밍 데이터, 데이터베이스 질의, 메모리에 들어가지 않는 아주 큰 파일처럼 임의 인덱싱이 안 되는 데이터에 알맞다.

## 코드

```python
#!/usr/bin/env python3
# ========================================================
# 12_dataset_09_iterable_style_minimal.py
# ========================================================
"""
반복자 방식 데이터셋:
- __iter__으로 표본을 흘려보낸다. 설계상 임의 인덱싱이 없다.
- 길이를 모를 수 있다. __len__은 선택 사항이다.
- DataLoader는 IterableDataset에 표집기를 쓰지 않는다. 그저 반복자를 소비할 뿐이다.
- 섞기, 에포크 제어, 일꾼 분배가 필요하면 __iter__ 안에서 직접 구현한다.

다시 훑기:
- 교육용 예제에서는 __iter__ 안에서 씨앗을 다시 심어 매번 같은 열이
  나오게 하기도 한다.
- 실무에서는 에포크와 일꾼마다 씨앗을 달리한다 (torch.utils.data.get_worker_info 참고).

참고 — PyTorch의 두 가지 데이터셋 방식:
- 맵 방식 (torch.utils.data.Dataset): __len__과 __getitem__(i). Sampler(shuffle=True),
  random_split, Subset과 함께 쓸 수 있다.
- 반복자 방식 (torch.utils.data.IterableDataset): __iter__(흘려보내기).
  DataLoader가 표집하지 않으므로 섞기와 분배를 직접 처리한다.
"""


if __name__ == "__main__":
    pass
```

## 논의

맵 방식 데이터셋(`torch.utils.data.Dataset`)은 `__getitem__`으로 임의 인덱싱을 지원하며 섞기, 무작위 분할, 부분집합 선택을 위한 표집기와 매끄럽게 어울린다. 반복자 방식 데이터셋(`torch.utils.data.IterableDataset`)은 `__iter__`만 구현하면 되며 스트리밍 상황을 위해 설계되었다.

반복자 방식 데이터셋을 쓸 때에는 임의 접근이라는 개념이 없으므로 DataLoader가 표집기를 쓰지 않는다. 섞기가 필요하면 `__iter__` 안에서 직접 구현해야 한다. 마찬가지로 여러 일꾼으로 불러올 때에는 일꾼마다 데이터 흐름을 나누어 중복을 피해야 하며, 이는 `torch.utils.data.get_worker_info()`으로 맞출 수 있다.

실무에서는 대부분의 과제에 맵 방식 데이터셋을 선호한다. 표집기, 데이터 분할 도구, 분산 학습 같은 PyTorch 생태계와 더 잘 어울리기 때문이다. 반복자 방식은 데이터베이스 커서, 네트워크 스트림, 임의 접근을 하기에는 너무 큰 파일처럼 진짜로 흘러 들어오는 데이터원에만 쓴다.

## 연습문제

**연습문제 1.**
코드를 따라가며 쓰인 주요 자료 구조를 찾아라. 각각에 대해 자료형, (해당한다면) 모양, 파이프라인에서의 구실을 적어라.

??? success "연습문제 1 풀이"
    코드를 꼼꼼히 읽으며 변수 대입마다 살펴본다. 텐서는 `.shape`과 `.dtype`을 확인하고, 클래스는 `__init__`의 매개변수와 `forward`/`__call__`의 서명을 확인한다. 이름, 자료형, 모양, 구실을 열로 하는 표에 정리한다.

---


**연습문제 2.**
오류 처리와 입력 검증을 넣도록 코드를 고쳐라. 이 코드를 실전에 쓸 수 있게 하려면 어떤 검사를 더하겠는가?

??? success "연습문제 2 풀이"
    입력에 자료형 검사(`isinstance`), 모양 검증(`assert tensor.dim() == expected`), 값 범위 검사(예: 확률이 [0,1] 안인지)를 넣고, 입출력 연산은 try-except로 감싼다. 빈 배치나 NaN 같은 경계 상황에는 경고를 남긴다. 매개변수와 반환값의 자료형을 적은 독스트링을 붙인다.

**연습문제 3.**
직접 고른 새로운 쓰임새를 지원하도록 코드를 확장하라. 무엇을 왜 바꿀지 설명하라.

??? success "연습문제 3 풀이"
    알맞은 확장을 하나 고른다(예: 다른 데이터셋, 지표 추가, 새 모델 변형). 필요한 변경을 설명한다. 새 임포트, 클래스 정의 수정, 초매개변수 갱신, 새로운 시각화나 기록 등이다. 핵심 변경을 구현하고 간단한 시험으로 올바름을 확인한다.
