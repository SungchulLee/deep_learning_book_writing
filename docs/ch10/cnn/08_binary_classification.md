# 이진 분류

[MNIST 데이터셋](01_mnist_dataset.md)의 열 숫자를 두 개씩 짝지으면 45가지 이진 문제가 나온다. 이 쪽은 쌍마다 CNN을 따로 학습시켜 45개의 학습 곡선을 한자리에 모은다. 쌍을 갈라 놓으면 어느 숫자끼리 시각적으로 가까운지가 드러나리라는 것이 이 실험의 기대인데, 아래 출력 블록이 실제로 보여 주는 것은 그보다 한 걸음 앞선 사실이다. **45개 쌍이 모두 시험 정확도 99.41% 위에 있고 여덟 쌍은 100.00%이다.** 열 갈래를 한꺼번에 가르는 [3.4 MNIST 합성곱 신경망](../../ch03/mnist/04_cnn.md)이 99.21%를 내는 것과 견주면, 둘로 줄인 문제는 가장 어려운 쌍조차 그보다 덜 틀린다. 그러니 이 쪽에서 읽어 낼 것은 "어떤 쌍이 어려운가"가 아니라 "그 차이가 얼마나 작으며, 손실 곡선이 그 차이를 얼마나 알려 주는가"이다.

## 1. 코드

```python
"""
08_binary_classification.py
============================
MNIST 이진 분류 분석

난이도: 고급
예상 시간: 2~3시간

지은이: PyTorch CNN 실습
날짜: 2025년 11월
"""

import matplotlib.pyplot as plt
import torch
import torch.nn as nn
import torch.optim as optim
from torchvision import datasets, transforms
from torch.utils.data import TensorDataset, DataLoader

print("=" * 70)
print("Binary Classification Analysis on MNIST")
print("=" * 70)


# =============================================================================
# 1절: 이진 분류용 CNN
# =============================================================================

class BinaryCNN(nn.Module):
    """이진 분류를 위한 단순한 CNN.

    갈래가 둘뿐인데도 마지막 층의 출력 단위는 **둘**이다. 그래야 로짓을
    `nn.CrossEntropyLoss`에 그대로 넘길 수 있고, 이는 출력을 하나만 두고
    `nn.BCEWithLogitsLoss`를 쓰는 방식과 똑같은 손실을 준다(2.4절).

    무게 개수: conv1 160 + conv2 4,640 + fc1 100,416 + fc2 130 = 105,346.
    fc1 하나가 100,416으로 전체의 95.32%를 차지한다.
    """
    def __init__(self):
        super(BinaryCNN, self).__init__()
        self.conv1 = nn.Conv2d(1, 16, 3, padding=1)
        self.conv2 = nn.Conv2d(16, 32, 3, padding=1)
        self.pool = nn.MaxPool2d(2, 2)
        self.fc1 = nn.Linear(32 * 7 * 7, 64)
        self.fc2 = nn.Linear(64, 2)          # 갈래가 둘이므로 로짓도 둘

    def forward(self, x):
        # 28x28 -> conv -> 28x28 -> pool -> 14x14 -> conv -> 14x14 -> pool -> 7x7
        x = self.pool(torch.relu(self.conv1(x)))
        x = self.pool(torch.relu(self.conv2(x)))
        x = x.view(-1, 32 * 7 * 7)           # 32 x 7 x 7 = 1568
        x = torch.relu(self.fc1(x))
        x = self.fc2(x)
        # 로짓을 그대로 돌려준다. 시그모이드도 소프트맥스도 여기서 씌우지 않는다
        return x


# =============================================================================
# 2절: MNIST를 불러 숫자별로 나누기
# =============================================================================

transform = transforms.Compose([
    transforms.ToTensor(),
    transforms.Normalize((0.5,), (0.5,))
])

train_dataset = datasets.MNIST(root='./data', train=True, download=True, transform=transform)
# 배치 크기를 데이터셋 크기로 잡아 6만 장을 한 번에 메모리로 올린다
train_loader = DataLoader(train_dataset, batch_size=len(train_dataset))
all_images, all_labels = next(iter(train_loader))

# 숫자별로 데이터 정리.
# 부류별 장수는 고르지 않다 — 5,421장(숫자 5)에서 6,742장(숫자 1)까지 벌어진다.
# 그래서 쌍마다 학습 장수가 11,263장에서 13,007장 사이로 달라진다.
digit_images = {}
digit_labels = {}
for i in range(10):
    mask = all_labels == i
    digit_images[i] = all_images[mask]
    digit_labels[i] = all_labels[mask]


# =============================================================================
# 3절: 두 숫자로 학습시키기
# =============================================================================

def train_binary(model, images_0, labels_0, images_1, labels_1, epochs=10):
    """두 부류로 학습시키고 손실의 자취를 돌려준다.

    원래의 MNIST 이름표(`labels_0`, `labels_1`)는 **개수만** 쓰고 버린다.
    이진 문제의 이름표는 0과 1로 새로 붙이며, 앞에 온 쪽이 0이다.
    """
    images = torch.cat([images_0, images_1])
    labels = torch.cat([torch.zeros(len(labels_0), dtype=torch.long),
                        torch.ones(len(labels_1), dtype=torch.long)])
    dataset = TensorDataset(images, labels)
    loader = DataLoader(dataset, batch_size=64, shuffle=True)
    criterion = nn.CrossEntropyLoss()        # 로짓을 받는다. 소프트맥스는 이 안에서 걸린다
    optimizer = optim.Adam(model.parameters(), lr=0.001)

    loss_trace = []
    for epoch in range(epochs):
        total_loss = 0
        for batch_images, batch_labels in loader:
            optimizer.zero_grad()
            outputs = model(batch_images)
            loss = criterion(outputs, batch_labels)
            loss.backward()
            optimizer.step()
            total_loss += loss.item()
        loss_trace.append(total_loss / len(loader))
    return loss_trace


# =============================================================================
# 4절: 45개 쌍을 모두 돌리고 학습 곡선을 그리기
# =============================================================================

fig, axes = plt.subplots(10, 10, figsize=(15, 15))
final_loss = {}

for i in range(10):
    for j in range(10):
        if i >= j:
            axes[i, j].axis('off')
            continue

        # 쌍마다 씨앗을 되돌린다. 45개 모델이 모두 같은 초기 무게에서 떠나므로
        # 쌍 사이의 차이는 오직 데이터에서 온다. 쌍 하나만 따로 다시 돌려도
        # 같은 값이 나온다 — 처음에 한 번만 씨앗을 주면 어느 쌍의 값이든
        # 그 앞에 돈 쌍들의 난수에 딸리게 되어 따로 확인할 수 없다.
        torch.manual_seed(42)
        model = BinaryCNN()
        n_train = len(digit_images[i]) + len(digit_images[j])
        print(f"Training classifier: {i} vs {j}  (train {n_train}, batches {(n_train + 63) // 64})")
        loss_trace = train_binary(
            model, digit_images[i], digit_labels[i],
            digit_images[j], digit_labels[j], epochs=10
        )
        print("  loss " + " ".join(f"{v:.6f}" for v in loss_trace))
        final_loss[(i, j)] = loss_trace[-1]

        # 45개 쌍을 통틀어 손실이 0.000009에서 0.184까지, 곧 2만 배에 걸쳐 있다.
        # 선형 축에서는 모든 곡선이 바닥에 붙어 한 줄로 보이므로 로그 축을 쓴다.
        axes[i, j].plot(loss_trace, 'r-', linewidth=2)
        axes[i, j].set_yscale('log')
        axes[i, j].set_ylim([1e-6, 1])
        axes[i, j].set_title(f'{i} vs {j}', fontsize=8)
        axes[i, j].axis('off')
        # 아래쪽 삼각형은 바로 위와 같은 자취를 색만 바꾸어 되비친 것이다.
        # 따로 학습한 결과가 아니므로 45개 실험이 90칸에 그려진다.
        axes[j, i].plot(loss_trace, 'b-', linewidth=2)
        axes[j, i].set_yscale('log')
        axes[j, i].set_ylim([1e-6, 1])
        axes[j, i].set_title(f'{j} vs {i}', fontsize=8)
        axes[j, i].axis('off')

plt.suptitle('MNIST Binary Classification Learning Curves', fontsize=16)
plt.tight_layout()
plt.show()


# =============================================================================
# 5절: 마지막 손실로 45개 쌍 줄 세우기
# =============================================================================

print()
print("=" * 70)
print("Final-epoch loss, all 45 pairs (hardest first)")
print("=" * 70)
for (i, j), v in sorted(final_loss.items(), key=lambda kv: -kv[1]):
    print(f"  {i} vs {j}   {v:.6f}")


if __name__ == "__main__":
    pass
```

## 2. 논의

### 2.1 45개 쌍이 모두 쉽다

열 갈래 문제를 45개의 이진 부분 문제로 쪼개면 분류 지형의 짜임이 드러나리라 기대하게 된다. 그러나 먼저 눈에 들어와야 하는 것은 짜임이 아니라 **지형이 거의 평평하다**는 사실이다. 45개 쌍의 시험 정확도(연습문제 5에서 재는 값)는 가장 낮은 2 대 7의 99.4175%부터 여덟 쌍이 함께 서 있는 100.0000%까지, 폭이 0.5825%p에 지나지 않는다. 45개 문제의 시험 표본을 모두 합하면 90,000건 가운데 틀린 것이 154건, 0.171%이다.

이 값들이 어느 정도인지는 상수 예측기와 견주면 또렷하다. 두 부류의 장수가 가장 크게 벌어진 쌍은 1 대 5로, 시험 집합에서 1이 1,135장이고 5가 892장이다. 무엇을 보든 무조건 1이라고만 답하는 예측기의 정확도가 이미 55.99%이며, 이것이 이 쌍에서 넘어야 할 바닥이다. 실제로 잰 값은 99.9507%이므로 바닥보다 43.96%p 위에 있다. 나머지 44개 쌍의 바닥은 이보다 더 낮아, 시험 집합에서 모두 50.02%(3 대 9)와 54.23%(1 대 6) 사이에 있다.

그러므로 이 쪽의 학습 곡선에서 "어려운 쌍은 애를 먹는다"를 읽어 내려 해서는 안 된다. 애를 먹는 쌍은 하나도 없다. 읽어 낼 수 있는 것은 **거의 다 풀린 문제들 사이의 아주 작은 차이**이며, 아래 두 절이 그 차이의 크기와 믿을 만함을 다룬다.

### 2.2 어려운 쌍은 짐작과 반쯤만 맞는다

마지막 세대의 손실로 줄을 세우면 출력 블록의 끝에 있는 차례가 나온다. 가장 어려운 다섯은 **4 대 9**(0.008196), **3 대 5**(0.005721), **5 대 8**(0.004137), **8 대 9**(0.002990), **1 대 7**(0.002791)이고, 가장 쉬운 넷은 **6 대 7**(0.000009), **3 대 6**과 **0 대 7**(여섯째 자리까지 똑같이 0.000027), **0 대 4**(0.000031)이다. 양 끝의 비는 반올림하지 않은 값으로 901배여서, 45개 쌍이 모두 쉽다고 해도 그 안의 폭은 세 자릿수에 이른다.

윗자리 둘은 짐작대로다. 4와 9는 오른쪽 세로획이 같고 위가 닫혔느냐 열렸느냐만 다르며, 3과 5는 위의 가로획과 아래의 곡선을 나누어 가진다. 그런데 **1 대 7이 45개 가운데 다섯째로 어렵다**는 것은 짐작과 어긋난다. 획 하나와 획 둘이라 멀어 보이지만, 가로획 없이 쓴 1과 위 가로획이 짧은 7은 화소 수준에서 겹치는 부분이 크다. 더 뜻밖인 것은 **0 대 6**이 여섯째(0.002538)라는 점이다. 연습문제 5에서 세어 보면 이 쌍이 시험에서 틀린 열 건이 모두 6을 0으로 본 한쪽 방향이며, 고리를 크게 쓰고 위 꼬리를 짧게 흘린 6이 0과 갈리지 않는다.

거꾸로 가까워 보이는 쌍이 쉽게 갈리기도 한다. **3 대 8**은 첫 세대 손실이 0.124614로 45개 가운데 넷째로 높아 출발이 가장 힘든 축인데, 마지막에는 0.000490까지 내려가 어려운 차례로는 스무째다. 시험 정확도도 99.8992%(1,984건 가운데 2건 틀림)로 45개 가운데 위에서 스물한째, 곧 한가운데다. 첫 세대만 보고 "3과 8은 비슷해서 어렵다"고 적으면 틀리게 된다.

### 2.3 손실 곡선은 난이도를 얼마나 알려 주는가

학습 손실이 난이도를 곧바로 드러낸다는 말은 얼마나 믿을 만한가. 마지막 세대의 학습 손실과 시험 오류율의 스피어만 순위 상관계수는 45개 쌍에서 **0.647**이다. 방향은 분명히 맞지만 둘을 같은 것으로 볼 수는 없다. 어긋나는 예가 곧바로 보인다. 5 대 8은 손실로는 셋째로 어려운데 시험 정확도 99.7320%는 아래에서 열두째에 그치고, 거꾸로 시험에서 가장 많이 틀린 2 대 7(99.4175%)은 손실로는 아홉째다. 첫 세대의 손실은 더 멀어서, 마지막 손실과의 순위 상관이 0.577, 시험 오류율과는 0.536이다.

곡선이 매끄럽지 않다는 것도 눈여겨볼 대목이다. 45개 자취 가운데 **29개**가 어느 한 번은 앞 세대보다 올라간다. 네 쌍(5 대 8, 5 대 6, 7 대 8, 0 대 1)은 마지막 세대가 아홉째 세대보다 높다. 학습률을 줄이는 일정이 없고 손실이 이미 $10^{-3}$ 언저리라 배치 하나가 만드는 흔들림이 세대 평균에 그대로 남기 때문이다. 그러므로 곡선 한 번의 끝값을 그대로 난이도로 읽으면 안 되고, 씨앗을 바꾸어 여러 번 재어 퍼짐과 함께 보아야 한다. 이 쪽은 씨앗 하나로만 재었으므로 위의 차례도 그만큼만 믿을 값이다.

쌍별 분해가 실제로 쓰이는 데는 이런 조심스러움이 필요하다. 열 갈래 모델이 4를 9로 잘못 볼 때 그것이 이진 분석에서 본 모호함과 같은 것인지 말하려면, 두 실험이 같은 순위를 내는지 먼저 확인해야 한다. 쌍별 분해는 SVM 같은 전통적인 분류기가 쓰는 일대일(one-vs-one) 전략과도 이어진다. 거기서는 다부류 문제를 $\binom{10}{2} = 45$개의 이진 결정으로 줄인 뒤 투표로 합치는데, 대가는 연습문제 3에서 센다.

### 2.4 갈래가 둘인데 출력 단위가 둘인 까닭

`BinaryCNN`의 마지막 층은 `nn.Linear(64, 2)`이다. 갈래가 둘뿐인데 로짓을 둘 두는 것이 낭비처럼 보이지만, 손실을 적어 보면 하나를 두는 방식과 정확히 같다. 로짓을 $z_0, z_1$이라 하고 참값을 $y \in \{0, 1\}$이라 하면 `nn.CrossEntropyLoss`가 재는 값은

$$L = -\log \frac{e^{z_y}}{e^{z_0} + e^{z_1}}$$

이다. 분자와 분모를 $e^{z_0}$으로 나누고 $z = z_1 - z_0$으로 두면 $y = 1$일 때 $-\log \sigma(z)$, $y = 0$일 때 $-\log(1 - \sigma(z))$가 되어, 출력이 하나인 모델에 `nn.BCEWithLogitsLoss`를 씌운 것과 같은 식이 된다. 즉 출력 단위 둘은 자유도 하나가 남는 표현이며, 두 로짓에 같은 수를 더해도 손실은 꿈쩍하지 않는다.

여기서 조심할 것은 `nn.BCEWithLogitsLoss`가 **로짓**을 받는다는 점이다. 시그모이드를 안에서 걸어 주므로 `forward`에서 다시 `torch.sigmoid`를 씌우면 시그모이드가 두 번 걸린다. 이것은 오류를 내지 않고 조용히 학습만 망가뜨리는 종류의 실수이며, 연습문제 4에서 그 결과를 수로 확인한다. 확률을 직접 넘기고 싶다면 `nn.BCELoss`를 써야 하고, [7.2 이진 분류](../../ch07/logistic_regression/binary_classification.md)가 바로 그 짝(`torch.sigmoid` + `nn.BCELoss`)으로 로지스틱 회귀를 세운다.

**연습문제 1.** <span class="diff easy" title="쉬움"></span>
출력 블록의 `Training classifier: 1 vs 5  (train 12163, ...)`에서 보듯 이 쌍의 학습 장수는 12,163장이고, 코드의 주석에 따르면 숫자 1이 6,742장, 숫자 5가 5,421장이다. 무엇을 보든 무조건 1이라고만 답하는 상수 예측기의 학습 집합 정확도를 구하라. 시험 집합에서는 1이 1,135장, 5가 892장이다. 이때의 값도 구하고, 연습문제 5가 재는 99.9507%와 견주어라.

</div>

??? success "연습문제 1 풀이"
    상수 예측기의 정확도는 그냥 다수 부류의 비율이다.

    학습 집합에서는

    $$\frac{6{,}742}{6{,}742 + 5{,}421} = \frac{6{,}742}{12{,}163} = 0.5543$$

    이므로 55.43%이고, 시험 집합에서는

    $$\frac{1{,}135}{1{,}135 + 892} = \frac{1{,}135}{2{,}027} = 0.5599$$

    이므로 55.99%이다. 잰 값 99.9507%는 이보다 43.96%p 높다.

    이 계산을 반드시 해 두어야 하는 까닭은, 부류가 치우친 이진 문제에서는 아무것도 배우지 않은 모델도 정확도가 꽤 높게 나오기 때문이다. 여기서는 바닥이 55.99%뿐이라 99.95%가 뜻 있는 값이지만, 다수 부류가 99%인 문제였다면 "정확도 99%"는 아무 일도 하지 않았다는 말과 구별되지 않는다.

    이 쪽의 45개 쌍은 모두 치우침이 작다. 학습 집합에서 가장 고른 쌍은 0 대 6으로 5,923 대 5,918, 곧 바닥이 50.02%이고 가장 치우친 1 대 5의 55.43%가 최대이다. 시험 집합에서도 3 대 9의 50.02%부터 1 대 5의 55.99%까지이며, 1 대 5 다음으로 치우친 1 대 6이 54.23%다. 그래서 45개 정확도를 바닥 보정 없이 그대로 견주어도 된다.

**연습문제 2.** <span class="diff med" title="중간"></span>
출력 블록 끝의 차례에서 가장 어려운 쌍 셋과 가장 쉬운 쌍 셋을 읽어라. 어려운 셋은 어떤 시각적 특징을 함께 지니는가? 그리고 3 대 8은 첫 세대 손실이 45개 가운데 넷째로 높은데도 어려운 차례로는 스무째다. 이 어긋남을 어떻게 설명하겠는가?

</div>

??? success "연습문제 2 풀이"
    **가장 어려운 셋**은 4 대 9(0.008196), 3 대 5(0.005721), 5 대 8(0.004137)이다.

    - 4와 9는 오른쪽 세로획이 같고, 위쪽 고리가 닫혔느냐(9) 열렸느냐(4)만 다르다. 손으로 쓴 4의 위를 조금만 붙여 쓰면 9가 된다.
    - 3과 5는 위의 가로 성분과 아래의 오른쪽 볼록 곡선을 함께 지닌다. 갈리는 곳은 왼쪽 위 한 군데뿐이다.
    - 5와 8은 아래 고리를 함께 지니고, 위가 닫혀 고리를 이루느냐(8) 아니냐(5)만 다르다.

    셋 모두 **한 군데의 국소적인 차이**로만 갈린다는 공통점이 있다. 모양 전체가 다른 쌍이 아니라, 대부분이 겹치고 한 곳만 어긋나는 쌍이 어렵다.

    **가장 쉬운 셋**은 6 대 7(0.000009), 3 대 6(0.000027), 0 대 7(0.000027)이다. 7은 닫힌 고리가 없고 6과 0과 3은 곡선이 주도한다. 굳이 국소적인 차이를 찾지 않아도 갈린다.

    **3 대 8의 어긋남**은 첫 세대 손실이 재는 것과 마지막 세대 손실이 재는 것이 다르기 때문이다. 첫 세대 손실 0.124614는 "무작위로 시작한 무게가 얼마나 빨리 쓸 만해지는가"에 가깝고, 3과 8은 화소 분포가 크게 겹쳐 처음 몇백 걸음 동안은 실제로 잘 갈리지 않는다. 그러나 두 부류를 나누는 특징(왼쪽 위와 왼쪽 아래가 닫혔는가)이 일단 잡히고 나면 남는 애매한 표본이 거의 없다. 4 대 9는 그 특징이 잡힌 뒤에도 애매한 표본이 남는다. 두 손실의 순위 상관이 0.577밖에 되지 않는 것이 이 차이를 수로 말해 준다.

**연습문제 3.** <span class="diff med" title="중간"></span>
모델 45개를 따로 학습시키는 대신 열 갈래 모델 하나로 쌍별 혼동을 볼 수도 있다. 두 방식의 장단점을 서술하되, 학습 비용과 저장하는 무게 개수를 **수로** 견주어라. `BinaryCNN`의 무게는 105,346개이고, 마지막 층만 `nn.Linear(64, 10)`으로 바꾼 열 갈래 모델의 무게는 105,866개이다.

</div>

??? success "연습문제 3 풀이"
    **학습 비용**은 정확히 9배 차이다. 숫자 하나는 45개 쌍 가운데 9개에 나타나므로, 한 세대에 흐르는 이미지는

    $$9 \times 60{,}000 = 540{,}000$$

    장이다. 열 갈래 모델 하나는 한 세대에 60,000장이므로 열 세대면 600,000장이고, 45개 이진 모델은 5,400,000장이다. "10~50배"처럼 어림할 것 없이 쌍의 짜임에서 곧바로 9가 나온다.

    **저장하는 무게**는 $45 \times 105{,}346 = 4{,}740{,}570$개 대 105,866개로 **44.78배**다. 추론에서도 일대일 투표를 하려면 45번 앞먹임을 돌려야 하므로 비슷한 배수만큼 든다.

    **모델 하나의 장점**: 학습이 한 번이면 끝나고, 공유된 표현이 비슷한 과제 사이에 지식을 옮겨 주며, 한 번의 앞먹임으로 $10 \times 10$ 혼동 행렬을 얻는다. 성분 $(i, j)$는 $i$번 부류의 표본 가운데 몇 개를 $j$번으로 예측했는지 센다. 실제로 배포하는 모습과도 이 쪽이 가깝다.

    **이진 모델 45개의 장점**: 모델마다 다른 부류의 간섭 없이 제 쌍에만 맞추어지고, 학습 곡선이 쌍마다의 어려움을 따로 보여 주며, 부류를 가로지르는 오류 전파에 흔들리지 않는다. 용량도 쌍마다 온전히 쓴다.

    다만 이 쪽이 보인 값을 보면 그 대가가 값진지는 따져 볼 일이다. 45개 이진 모델의 시험 오류가 90,000건 가운데 154건(0.171%)이고, 열 갈래 모델은 [3.4 MNIST 합성곱 신경망](../../ch03/mnist/04_cnn.md)에서 99.21%, 곧 0.79%를 낸다. 두 값을 소수점까지 맞댈 수는 없다. 푸는 문제가 다르고(둘 가르기 대 열 가르기), 그 쪽 신경망은 매개변수가 421,642개로 `BinaryCNN`의 네 배이며, 학습 설정도 같지 않기 때문이다. 자릿수를 보는 값으로만 읽어야 한다.

**연습문제 4.** <span class="diff hard" title="어려움"></span>
출력 단위를 하나로 줄이고 `nn.BCEWithLogitsLoss`를 쓰도록 `BinaryCNN`을 고쳤는데, `forward`의 끝에 `torch.sigmoid`를 지우지 않고 남겨 두었다고 하자. (가) 손실이 실제로 쓰는 확률은 어떤 범위에 갇히는가? (나) 3 대 5 쌍에서 손실이 내려갈 수 있는 바닥을 구하고 본문의 값과 견주어라. (다) 학습을 마친 뒤 예측을 뽑는 두 가지 길 — 모델 출력을 바로 0.5로 자르기, 그리고 관례대로 시그모이드를 한 번 더 씌운 뒤 자르기 — 이 각각 어떻게 되는가?

</div>

??? success "연습문제 4 풀이"
    `nn.BCEWithLogitsLoss(o, y)`는 `o`를 **로짓으로 보고** 안에서 시그모이드를 건다. `forward`가 이미 $p = \sigma(z)$를 돌려주므로, 손실이 확률로 쓰는 값은 $\sigma(p) = \sigma(\sigma(z))$이다.

    **(가) 갇히는 범위.** $\sigma(z) \in (0, 1)$이므로 바깥 시그모이드에 들어가는 값이 0과 1 사이에 갇힌다. 따라서

    $$\sigma(\sigma(z)) \in \bigl(\sigma(0),\ \sigma(1)\bigr) = (0.5,\ 0.7311)$$

    이다. 로짓 $z$를 아무리 크게 또는 작게 만들어도 손실이 보는 확률은 이 좁은 띠를 벗어나지 못한다. 0.5 아래로 내려가는 일이 없으므로, 손실의 눈으로 보면 이 모델에는 "0번 갈래다"라고 말할 방법이 아예 없다.

    **(나) 손실의 바닥.** $y = 1$인 표본의 최선은 $-\log 0.7311 = 0.3133$이고, $y = 0$인 표본의 최선은 $-\log(1 - 0.5) = 0.6931$이다(닿지는 못하고 다가갈 뿐이다). 3 대 5 쌍은 3이 6,131장, 5가 5,421장이라 1번 갈래(숫자 5)의 비율이 0.46927이므로 바닥은

    $$0.46927 \times 0.3133 + 0.53073 \times 0.6931 = 0.5149$$

    이다. 실제로 이렇게 고친 모델을 3 대 5로 돌리면 첫 세대 손실이 0.576426, 둘째 세대가 0.522610으로 곧장 이 바닥에 들러붙는다. 본문의 3 대 5는 마지막 세대에 0.005721까지 내려갔으므로, 둘째 세대 값만 놓고 보아도 **91배 높은 자리**에서 멈추는 셈이다.

    **(다) 두 가지 예측 길.** 어느 쪽을 골라도 망가지지만 망가지는 모습이 다르다.

    - **모델 출력 $p = \sigma(z)$를 그대로 0.5로 자르는 길.** 이쪽은 뜻밖에도 그럭저럭 맞힌다. 기울기가 $p$를 참값 쪽으로 밀기는 하므로 표본의 순서가 살아 있기 때문이다. 위 실험에서 학습 집합 정확도가 첫 세대 85.92%, 둘째 세대 98.56%였다. "되기는 되는데 이상하게 안 좋다"로만 보이는 것이 바로 이 길이며, 그래서 실수가 오래 살아남는다.
    - **`torch.sigmoid(model(x))`로 확률을 뽑는 길.** `nn.BCEWithLogitsLoss`를 썼으니 평가할 때 시그모이드를 씌우는 것이 관례이고, 그렇게 하면 (가)에서 본 대로 값이 언제나 0.5보다 크다. 따라서 **모든 입력이 1번 갈래로 예측되어** 정확도가 1번 갈래의 비율인 46.93%에 고정된다. 모델이 무엇을 배웠든 상관이 없다.

    기울기 쪽에서 보아도 같은 말이 나온다. $\partial L / \partial p = \sigma(p) - y$인데 이 값은 $y = 1$일 때 $(-0.5,\ -0.2689)$, $y = 0$일 때 $(0.5,\ 0.7311)$에 갇힌다. 맞힌 표본에서도 기울기가 0으로 잦아들지 않고 계속 같은 방향으로 미는 것이다. 그래서 $p$가 0이나 1로 쏠리고, 그 자리에서는 $\sigma'(z) \approx 0$이라 학습이 멎는다.

    무서운 것은 이 실수가 조용하다는 점이다. 예외도 경고도 나지 않고 손실은 실제로 내려간다. 규칙은 짧다 — **`nn.BCEWithLogitsLoss`에는 로짓을, `nn.BCELoss`에는 확률을** 넘긴다. [7.2 이진 분류](../../ch07/logistic_regression/binary_classification.md)가 뒤쪽 짝(`torch.sigmoid` + `nn.BCELoss`)을 쓴다.

**연습문제 5.** <span class="diff hard" title="어려움"></span>
45개 이진 분류기마다 시험 정확도를 재고, 성분 $(i, j)$가 숫자 $i$와 $j$를 가르는 시험 정확도인 $10 \times 10$ 열지도를 그려라. 대각선을 0으로 두면 왜 안 되는지 밝히고, 나온 무늬를 2.2절의 손실 차례와 견주어라.

</div>

??? success "연습문제 5 풀이"
    본문의 코드를 돌린 뒤 이어서 실행한다. 씨앗을 본문과 같이 42로 되돌리므로 여기서 학습하는 45개 모델은 본문이 학습한 것과 같다.

    ```python
    import numpy as np

    # 대각선은 0이 아니라 NaN이어야 한다 — 아래에서 그 까닭을 밝힌다
    accuracy_matrix = np.full((10, 10), np.nan)

    test_dataset = datasets.MNIST(root='./data', train=False, transform=transform)
    test_loader = DataLoader(test_dataset, batch_size=len(test_dataset))
    test_images, test_labels = next(iter(test_loader))

    for i in range(10):
        for j in range(i + 1, 10):
            torch.manual_seed(42)              # 본문의 4절과 같은 씨앗
            model = BinaryCNN()
            train_binary(model, digit_images[i], digit_labels[i],
                         digit_images[j], digit_labels[j], epochs=10)

            # 시험 집합에서 평가. j가 1, i가 0 — train_binary가 붙인 차례와 같다
            mask = (test_labels == i) | (test_labels == j)
            test_data = test_images[mask]
            test_labs = (test_labels[mask] == j).long()
            model.eval()
            with torch.no_grad():
                outputs = model(test_data)
                _, preds = torch.max(outputs, 1)
                acc = (preds == test_labs).float().mean().item() * 100
            accuracy_matrix[i, j] = acc
            accuracy_matrix[j, i] = acc

    plt.imshow(accuracy_matrix, cmap='viridis')
    plt.colorbar(label='test accuracy (%)')
    plt.xticks(range(10))
    plt.yticks(range(10))
    plt.title('Pairwise binary test accuracy')
    plt.show()
    ```

    **대각선을 0으로 두면 안 되는 까닭.** `np.zeros`로 만들면 대각선 열 칸이 0.0으로 남는다. 나머지 90칸을 채우는 45개 값은 99.4175와 100.0000 사이의 0.58%p 띠 안에 있으므로, 색 눈금이 0부터 100까지 늘어나면 띠 전체가 한 색으로 뭉개진다. 열지도에서 보려던 차이가 바로 그 0.58%p인데 그것이 사라진다. `np.nan`으로 두면 `imshow`가 그 칸을 비워 두고 눈금은 남은 값에만 맞춰진다.

    **나온 값.** 낮은 쪽부터 2 대 7 99.4175%(2,060건 가운데 12건 틀림), 3 대 9 99.4552%(11/2,019), 3 대 5 99.4742%(10/1,902), 0 대 6 99.4840%(10/1,938), 7 대 9 99.5582%(9/2,037)이고, 4 대 5, 4 대 7, 4 대 8, 1 대 3, 1 대 4, 2 대 5, 3 대 6, 0 대 4의 여덟 쌍이 100.0000%이다. 45개 평균은 99.8280%이다.

    **오류의 방향.** `preds`와 `test_labs`를 두 방향으로 따로 세면(`((test_labs == 0) & (preds == 1)).sum()`과 그 반대) 더 볼 것이 나온다. 위의 다섯 쌍 가운데 네 쌍에서 오류가 한쪽으로 쏠린다.

    | 쌍 | 오류 | 방향 |
    |---|---|---|
    | 2 대 7 | 12 | 2 → 7이 6, 7 → 2가 6 |
    | 3 대 9 | 11 | 9 → 3이 10, 3 → 9가 1 |
    | 3 대 5 | 10 | 5 → 3이 9, 3 → 5가 1 |
    | 0 대 6 | 10 | 6 → 0이 10, 0 → 6이 0 |
    | 7 대 9 | 9 | 9 → 7이 7, 7 → 9가 2 |

    고르게 갈라지는 것은 2 대 7뿐이고, 0 대 6은 열 건이 모두 한 방향이다. 45개 쌍을 모두 합하면 참값이 9인 표본에서 28건, 6에서 25건, 2에서 24건이 틀리고 1에서는 3건뿐이다. 곧 이 실험에서 읽어 낼 것은 "어느 두 숫자가 서로 헷갈린다"보다 "어느 숫자가 남에게 잘못 읽힌다"에 가깝다.

    **손실 차례와의 어긋남.** 두 차례는 방향은 같지만 겹치지 않는다(순위 상관 0.647). 손실로 첫째인 4 대 9는 정확도로는 여섯째로 낮을 뿐이고, 정확도로 가장 낮은 2 대 7은 손실로는 아홉째다. 손실로 셋째인 5 대 8은 정확도 99.7320%로 아래에서 열두째에 그친다. 학습 손실은 학습 집합에서 남은 애매함을 재고 정확도는 시험 집합에서 넘은 문턱을 재므로, 둘이 정확히 같은 줄을 세울 이유가 없다.

    한편 흔히 짐작하는 3 대 8은 여기서 99.8992%(2/1,984)로 45개 가운데 위에서 스물한째, 곧 한가운데다. "3과 8은 비슷하니 어렵다"는 짐작은 이 실험에서 지지되지 않는다. 다만 이 모든 차례는 씨앗 하나로 잰 값이므로, 주장으로 삼으려면 씨앗을 바꾸어 여러 번 재고 퍼짐과 함께 적어야 한다.

## 정리하며

**다룬 것** — 이진 분류

열 갈래 문제를 45개의 이진 부분 문제로 쪼개면 세 가지가 드러난다. 첫째, 이진 MNIST는 고르게 쉽다. 45개 쌍이 모두 시험 정확도 99.41% 위에 있고 여덟 쌍은 100.00%이며, 90,000건 가운데 틀린 것이 154건(0.171%)이다. 둘째, 그래도 차례는 있다. 마지막 손실은 4 대 9의 0.008196에서 6 대 7의 0.000009까지 901배(반올림하지 않은 값)에 걸쳐 있고, 4 대 9와 3 대 5가 어렵다는 짐작은 맞지만 1 대 7이 다섯째, 0 대 6이 여섯째라는 것은 짐작으로는 나오지 않는다. 셋째, 학습 손실과 시험 오류의 순위 상관은 0.647로, 곡선 하나에서 난이도를 읽어 내는 일에는 조심이 필요하다.

그리고 갈래가 둘이어도 출력 단위는 둘로 두어 `nn.CrossEntropyLoss`에 넘기는 편이 안전하다. 출력을 하나로 줄이는 길도 수학적으로 같지만, `nn.BCEWithLogitsLoss`에 확률을 넘기는 실수가 조용히 숨어들 자리가 생긴다.

핵심 클래스는 `BinaryCNN`이며 앞의 연습문제 5개로 직접 확인할 수 있다.
