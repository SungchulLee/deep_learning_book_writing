# CIFAR-10 심화

CNN_CIFAR10은 컨볼루션 레이어 네 개와 완전 연결 레이어 두 개로 CIFAR-10을 분류한다. 총 2168362개의 파라메터를 사용하며, 기록된 시드 1 실행의 테스트 정확도는 54.82%이다. 이 페이지는 구조와 학습 기록을 분석하고 모델 크기·학습 일정·평가 조건을 구분해 해석한다.

## 1. 코드

```python
"""
07_cifar10_advanced.py
======================
성능이 더 좋은 CIFAR-10용 심화 CNN

난이도: 어려움
예상 시간: 2시간

지은이: PyTorch CNN 실습
날짜: 2025년 11월
"""

import torch.nn as nn
import torch.optim as optim
import cnn_utils as utils

cfg = utils.parse_args()
utils.set_seed(seed=cfg.seed)     # 기본값 1 — 아래 출력은 이 씨앗 하나의 것이다

CIFAR10_CLASSES = ('plane', 'car', 'bird', 'cat', 'deer',
                   'dog', 'frog', 'horse', 'ship', 'truck')

# 데이터 적재
# 학습 50,000장, 시험 10,000장, 부류마다 5,000장과 1,000장이다.
# batch_size=64 라 학습 배치는 782개(781 × 64 + 16 = 50,000)이고,
# log_interval=10 이라 세대마다 batch_idx 0, 10, …, 780 의 79줄이 찍힌다.
# 마지막 배치(781번)는 16장뿐이고 10의 배수가 아니라 찍히지 않는다 —
# 그래서 세대마다 마지막 줄이 50000 이 아니라 49920 에서 끝난다.
train_kwargs = {'batch_size': cfg.batch_size, 'shuffle': True}
test_kwargs = {'batch_size': cfg.test_batch_size, 'shuffle': False}
trainloader, testloader = utils.load_data(train_kwargs, test_kwargs, cifar10=True)

# 모델 준비
# CNN_CIFAR10 은 컨볼루션 넷(32, 32, 64, 64) 뒤에 완전 연결 레이어 둘(512, 10)을 둔다.
# conv1 896 + conv2 9,248 + conv3 18,496 + conv4 36,928
#   + fc1 2,097,664 + fc2 5,130 = 2,168,362 이고,
# 이 가운데 fc1 하나가 96.74%를 차지한다 (2.2절).
model = utils.CNN_CIFAR10().to(cfg.device)
total_params = sum(p.numel() for p in model.parameters())
print(f"Total parameters: {total_params:,}")

loss_ftn = nn.CrossEntropyLoss()
optimizer = optim.SGD(model.parameters(), lr=cfg.lr, momentum=cfg.momentum)
# StepLR(step_size=1, gamma=0.7) 은 세대마다 러닝레이트에 0.7을 곱한다.
# 14세대째 러닝레이트는 0.01 × 0.7^13 = 9.689e-05 로 첫 세대의 1/103 이다.
# 이 일정이 뒤쪽 세대를 사실상 멈춰 세운다 (2.3절).
scheduler = optim.lr_scheduler.StepLR(optimizer, step_size=1, gamma=cfg.gamma)

# 학습 전
# 시험 배치의 앞 열 장을 2 × 5 격자로 그린다. 아직 학습하지 않은 웨이트라
# 예측은 무작위에 가깝다. plt.show() 로 창에만 가므로 아래 출력 블록에는
# 아무 자국도 남지 않는다.
utils.show_batch_or_ten_images_with_label_and_predict(
    testloader, model, cfg.device, classes=CIFAR10_CLASSES, n=10, cifar10=True
)

# 학습
utils.train(
    model, trainloader, loss_ftn, optimizer, scheduler,
    cfg.device, cfg.epochs, cfg.log_interval, cfg.dry_run
)

# 학습 후
# 학습이 끝난 웨이트로 같은 열 장을 다시 그린다. 앞뒤 두 그림을 견주면
# 무엇이 달라졌는지 눈으로 볼 수 있다. 이것도 출력에는 남지 않는다.
utils.show_batch_or_ten_images_with_label_and_predict(
    testloader, model, cfg.device, classes=CIFAR10_CLASSES, n=10, cifar10=True
)
# compute_accuracy 는 'Test Accuracy: 5482/10000 (54.82%)' 를 스스로 찍고
# 값도 돌려준다. 그래서 아래 print 와 합쳐 Test Accuracy 줄이 두 번 나온다.
test_accuracy = utils.compute_accuracy(model, testloader, cfg.device)

if cfg.save_model:
    utils.save_model(model, cfg.path)

print(f"Test Accuracy: {test_accuracy:.2f}%")


if __name__ == "__main__":
    pass
```

## 2. 논의

### 2.1 무엇이 깊어졌는가

심화 구조는 풀링 연산마다 그 앞에 컨볼루션 레이어를 두 개씩 두어 컨볼루션 백본의 깊이를 두 배로 만든다. 첫 블록은 `Conv2d(3, 32, 3, padding=1)` 다음에 `Conv2d(32, 32, 3, padding=1)` 을 둔다. 첫 레이어가 채널 3개를 32개로 올리고, 둘째 레이어는 그 32개 채널 위에서 한 번 더 걸러 내는 것이지 3채널 입력을 두 번 받는 것이 아니다. 둘째 블록도 같은 방식으로 `Conv2d(32, 64, 3, padding=1)` 과 `Conv2d(64, 64, 3, padding=1)` 을 잇는다.

네 레이어 모두 `padding=1` 이라 컨볼루션은 공간 크기를 건드리지 않는다. 크기를 줄이는 것은 블록 끝의 `MaxPool2d(2, 2)` 뿐이어서 $32 \times 32 \to 16 \times 16 \to 8 \times 8$ 로 두 번 줄고, 펼친 벡터는 $64 \times 8 \times 8 = 4096$ 차원이 된다. 이 4096이 곧 `fc1` 의 입력 차원이다.

스트라이드 1·팽창률 1인 3×3 컨볼루션 두 개의 이론적 리셉티브 필드는 5×5이다. 네 컨볼루션과 두 풀링을 지나면 마지막 피처 한 위치의 범위는 16×16이다. 이 국소 범위와 여러 위치를 결합하는 완전 연결 분류기의 참조 범위는 다르다.

필터 수도 함께 늘었다. [기본 모델](06_cifar10_basic.md)의 `SimpleCNN` 이 6개/16개였다면 여기서는 32개/32개/64개/64개이고, 완전 연결 레이어의 뉴런은 120개에서 512개가 되었다.

### 2.2 파라메터는 어디에 있는가

출력의 첫 줄은 `Total parameters: 2,168,362` 이다. 레이어별로 나누어 보면 이 수가 어디에서 왔는지 바로 보인다.

| 레이어 | 웨이트 | 바이어스 | 합 |
|---|---|---|---|
| conv1 | $32 \times 3 \times 3 \times 3 = 864$ | 32 | 896 |
| conv2 | $32 \times 32 \times 3 \times 3 = 9{,}216$ | 32 | 9,248 |
| conv3 | $64 \times 32 \times 3 \times 3 = 18{,}432$ | 64 | 18,496 |
| conv4 | $64 \times 64 \times 3 \times 3 = 36{,}864$ | 64 | 36,928 |
| fc1 | $512 \times 4096 = 2{,}097{,}152$ | 512 | 2,097,664 |
| fc2 | $10 \times 512 = 5{,}120$ | 10 | 5,130 |
| **합계** | | | **2,168,362** |

컨볼루션 웨이트와 바이어스는 모두 65568개로 전체의 약 3.02%, fc1은 2097664개로 약 96.74%이다. 메모리에서 파라메터 저장이 어디에 집중되는지 보여 주지만, 계산 비용이나 과적합의 원인이 같은 비율로 분포한다는 뜻은 아니다. 드롭아웃 확률의 적절성도 이 비율만으로 정할 수 없다.

### 2.3 학습은 어디서 멈추는가

에포크마다 찍힌 요약 줄 열넷만 모으면 학습이 어떻게 진행되었는지가 드러난다.

| 에포크 | 평균 로스 | 학습 정확도 | 앞 에포크 대비 |
|---|---|---|---|
| 1 | 2.1525 | 20.22% | — |
| 2 | 1.7721 | 36.20% | +15.98%p |
| 3 | 1.5800 | 42.64% | +6.44%p |
| 4 | 1.4875 | 46.11% | +3.47%p |
| 5 | 1.4361 | 47.99% | +1.88%p |
| 6 | 1.4026 | 49.36% | +1.37%p |
| 7 | 1.3820 | 50.19% | +0.83%p |
| 8 | 1.3681 | 50.84% | +0.65%p |
| 9 | 1.3520 | 51.31% | +0.47%p |
| 10 | 1.3478 | 51.21% | −0.10%p |
| 11 | 1.3417 | 51.75% | +0.54%p |
| 12 | 1.3349 | 52.03% | +0.28%p |
| 13 | 1.3348 | 51.99% | −0.04%p |
| 14 | 1.3331 | 51.99% | 0.00%p |

1에포크에서 2에포크로 +15.98%p 뛴 뒤 증가폭이 줄곧 작아져, 9에포크부터 14에포크까지는 51.21%와 52.03% 사이 0.82%p 띠 안에 머문다. 10에포크와 13에포크는 바로 앞 에포크보다 오히려 낮고 14에포크는 13에포크와 같다.

에포크 말마다 StepLR을 호출하므로 k번째 에포크 러닝레이트는 0.01×0.7^(k−1)이다. 9번째는 약 0.0005765, 14번째는 약 0.00009689로 감소한다. 작은 러닝레이트는 갱신을 작게 할 수 있지만 정확도 정체의 원인을 일정 하나로 확정할 수는 없다. 러닝레이트의 합도 그래디언트·모멘텀을 반영한 실제 이동 거리와 같지 않다.

낮은 학습 정확도는 추가 최적화나 표현 변경을 검토할 이유지만 파라메터 수만으로 충분한 용량이 있다고 증명할 수는 없다. 전처리·로스·러닝레이트와 기간, 드롭아웃·초기화 등을 함께 점검한다. 현재 출력만으로 수렴을 확인하거나 배제할 수도 없다.

학습 중 정확도 51.99%와 학습 후 테스트 정확도 54.82%는 드롭아웃 모드와 웨이트 집계 시점이 다르다. 학습 기록은 에포크에 걸쳐 변하는 웨이트의 예측을 합치고, 테스트는 평가 모드에서 마지막 상태를 사용한다. 같은 평가 모드의 학습셋 결과를 추가로 확인해야 하며, 학습 정확도가 더 낮다는 사실만으로 과적합이 없거나 과소적합이라고 판정하지 않는다.

### 2.4 "심화"가 "기본"보다 나은가

심화라는 이름은 기본 예제보다 컨볼루션 레이어와 채널·완전 연결 레이어를 확장했다는 뜻이다. 어떤 학습 조건에서도 더 높은 정확도를 보장한다는 뜻은 아니다.

[기본 예제](06_cifar10_basic.md)의 기록된 기본 설정은 10.70%, 모멘텀 추가는 41.07%, BatchNorm까지 추가하면 57.17%이다. 이 수치는 각 설정의 관찰이며, 기본 실행의 부진이 모멘텀 부재만으로 발생했다는 보편적인 원인 설명은 아니다.

그러니 이 예제의 54.82%가 맞서야 할 상대는 세 가지다. 모두 기본 쪽이 잰 값이다.

| 무엇 | 파라메터 | 정확도 |
|---|---|---|
| 기본, 있는 그대로 | 62,006 | 10.70% |
| 기본 + `momentum=0.9` 한 단어 | 62,006 | 41.07% |
| 기본 + 배치 정규화 + 모멘텀 | 62,050 | **57.17%** |
| **이 예제** | **2,168,362** | **54.82%** |

기본+BatchNorm+모멘텀 실행의 57.17%는 심화 예제의 54.82%보다 높고 파라메터는 더 적다. 이 관찰은 모델 크기 증가만으로 성능 향상을 보장하지 않는다는 점을 보여 준다. 두 기법의 효과가 레이어나 파라메터 증가의 효과보다 항상 크다는 의미는 아니다.

러닝레이트와 일정·기간·정규화 등이 달라 깊이 증가만의 효과를 분리할 수 없다. 같은 분할과 명시한 조율·계산 예산으로 비교하고 반복 실행의 차이를 보고해야 한다. 마지막 학습 정확도가 낮다는 이유로 기록된 테스트 성능을 구조가 아닌 일정만의 결과라고 분류하지 않는다.

MNIST·Fashion-MNIST·CIFAR-10의 결과도 입력과 클래스 의미뿐 아니라 구조·드롭아웃·옵티마이저 등이 다르다. 정확도 순서를 데이터셋 난이도만의 효과로 설명하지 않는다. 관련 입력 구조와 전처리는 [CIFAR-10 데이터셋](03_cifar10_dataset.md)에서 확인한다.

다음 단계에서는 러닝레이트·기간의 탐색, 데이터 증강, 정규화와 잔차 구조 등을 후보로 비교할 수 있다. 특정 정확도에 이르기 위해 모든 기법이 필수이거나 반드시 그 수준에 도달한다는 보장은 없다. 검증셋에서 설정을 선택하고 마지막 테스트는 선택 이후에 수행한다.

**연습문제 1.** <span class="diff easy" title="쉬움"></span>
출력의 첫 줄은 `Total parameters: 2,168,362` 이다. `CNN_CIFAR10` 의 레이어 여섯 개(conv1~conv4, fc1, fc2)마다 웨이트와 바이어스를 따로 세어 합이 정말 2,168,362가 되는지 확인하라. 그리고 컨볼루션 네 레이어를 다 합친 몫과 `fc1` 한 레이어의 몫을 백분율로 비교하여라.

</div>

??? success "연습문제 1 풀이"
    컨볼루션의 웨이트는 (출력 채널) × (입력 채널) × (커널 높이) × (커널 너비)이고 바이어스는 출력 채널마다 하나다. 완전 연결 레이어의 웨이트는 (출력 차원) × (입력 차원)이고 바이어스는 출력 차원마다 하나다. `fc1` 의 입력 4096은 `padding=1` 컨볼루션이 크기를 지키고 풀링이 두 번 절반으로 줄인 결과인 $64 \times 8 \times 8$ 이다.

    | 레이어 | 웨이트 | 바이어스 | 합 |
    |---|---|---|---|
    | conv1 | $32 \times 3 \times 3 \times 3 = 864$ | 32 | 896 |
    | conv2 | $32 \times 32 \times 3 \times 3 = 9{,}216$ | 32 | 9,248 |
    | conv3 | $64 \times 32 \times 3 \times 3 = 18{,}432$ | 64 | 18,496 |
    | conv4 | $64 \times 64 \times 3 \times 3 = 36{,}864$ | 64 | 36,928 |
    | fc1 | $512 \times 4096 = 2{,}097{,}152$ | 512 | 2,097,664 |
    | fc2 | $10 \times 512 = 5{,}120$ | 10 | 5,130 |

    합은 $896 + 9{,}248 + 18{,}496 + 36{,}928 + 2{,}097{,}664 + 5{,}130 = 2{,}168{,}362$ 로 출력과 맞는다.

    컨볼루션 네 레이어는 $896 + 9{,}248 + 18{,}496 + 36{,}928 = 65{,}568$ 개, 곧 전체의 3.02%다. `fc1` 하나는 2,097,664개로 96.74%다. 깊이를 말하는 이름과 달리 이 모델의 무게는 거의 전부 완전 연결 레이어 하나에 있다. 컨볼루션 레이어를 하나 더 쌓는 것보다 풀링을 한 번 더 넣어 펼치는 차원을 $8 \times 8$ 에서 $4 \times 4$ 로 줄이는 쪽이 파라메터를 훨씬 많이 덜어 낸다는 뜻이기도 하다.

    from torchvision import transforms

        transforms.RandomCrop(32, padding=4),

    증강이 학습 문제를 어렵게 하거나 추가 학습을 요구할 수 있지만, 학습 정확도가 테스트 정확도를 넘어야만 사용할 수 있는 방법은 아니다. 검증셋에서 증강 유무와 적절한 학습 일정을 비교하고 개선·퇴보와 비용을 함께 평가한다. 고정된 정확도 증가분을 예상하지 않는다.

## 정리하며

CNN_CIFAR10은 마지막 8×8×64 피처를 4096차원으로 펼치며 총 2168362개의 파라메터 대부분이 fc1에 있다. 기록된 54.82%는 이 학습 설정의 결과이다. 정확도 정체와 train/test 차이로 원인을 단정하지 말고, 구조·일정·드롭아웃·증강을 검증 데이터와 통제된 비교로 평가한다.
