# CIFAR-10 심화

이 실습은 CIFAR-10 분류를 위해 합성곱 층 네 개와 더 많은 필터, 더 넓은 완전 연결층을 갖춘 깊은 CNN(`cnn_utils.py`의 `CNN_CIFAR10`, [cnn_utils](cnn_utils.md))을 구현한다. 매개변수는 2,168,362개로 [CIFAR-10 기본](06_cifar10_basic.md)의 `SimpleCNN`(62,006개)보다 34.97배 많다. 그런데 14세대를 학습시킨 아래 실행이 낸 시험 정확도는 **54.82%**이다. 같은 `cnn_utils` 틀로 [Fashion-MNIST](05_fashion_mnist_classifier.md)에서 얻은 85.84%, [MNIST](../../ch03/mnist/04_cnn.md)에서 얻은 99.21%와 견주면 한참 아래이고, 기본 쪽이 적어 놓은 60~70%보다도 낮다. 그러니 이 쪽이 실제로 보여 주는 것은 "깊고 넓게 만들면 정확도가 곧바로 오른다"가 아니다. 용량을 35배로 늘려도 학습 절차가 그 용량을 쓰게 해 주지 않으면 소용이 없다는 것 — 2절에서 그 절차가 어디서 멈추는지를 출력 블록의 수로 짚는다.

## 1. 코드

```python
"""
07_cifar10_advanced.py
======================
성능이 더 좋은 CIFAR-10용 심화 CNN

난이도: 어려움
예상 시간: 2시간

지은이: PyTorch CNN 실습
날짜: 2025년 11월
"""

import torch.nn as nn
import torch.optim as optim
import cnn_utils as utils

cfg = utils.parse_args()
utils.set_seed(seed=cfg.seed)     # 기본값 1 — 아래 출력은 이 씨앗 하나의 것이다

CIFAR10_CLASSES = ('plane', 'car', 'bird', 'cat', 'deer',
                   'dog', 'frog', 'horse', 'ship', 'truck')

# 데이터 적재
# 학습 50,000장, 시험 10,000장, 부류마다 5,000장과 1,000장이다.
# batch_size=64 라 학습 배치는 782개(781 × 64 + 16 = 50,000)이고,
# log_interval=10 이라 세대마다 batch_idx 0, 10, …, 780 의 79줄이 찍힌다.
# 마지막 배치(781번)는 16장뿐이고 10의 배수가 아니라 찍히지 않는다 —
# 그래서 세대마다 마지막 줄이 50000 이 아니라 49920 에서 끝난다.
train_kwargs = {'batch_size': cfg.batch_size, 'shuffle': True}
test_kwargs = {'batch_size': cfg.test_batch_size, 'shuffle': False}
trainloader, testloader = utils.load_data(train_kwargs, test_kwargs, cifar10=True)

# 모델 준비
# CNN_CIFAR10 은 합성곱 넷(32, 32, 64, 64) 뒤에 완전 연결층 둘(512, 10)을 둔다.
# conv1 896 + conv2 9,248 + conv3 18,496 + conv4 36,928
#   + fc1 2,097,664 + fc2 5,130 = 2,168,362 이고,
# 이 가운데 fc1 하나가 96.74%를 차지한다 (2.2절).
model = utils.CNN_CIFAR10().to(cfg.device)
total_params = sum(p.numel() for p in model.parameters())
print(f"Total parameters: {total_params:,}")

loss_ftn = nn.CrossEntropyLoss()
optimizer = optim.SGD(model.parameters(), lr=cfg.lr, momentum=cfg.momentum)
# StepLR(step_size=1, gamma=0.7) 은 세대마다 학습률에 0.7을 곱한다.
# 14세대째 학습률은 0.01 × 0.7^13 = 9.689e-05 로 첫 세대의 1/103 이다.
# 이 일정이 뒤쪽 세대를 사실상 멈춰 세운다 (2.3절).
scheduler = optim.lr_scheduler.StepLR(optimizer, step_size=1, gamma=cfg.gamma)

# 학습 전
# 시험 배치의 앞 열 장을 2 × 5 격자로 그린다. 아직 학습하지 않은 가중치라
# 예측은 무작위에 가깝다. plt.show() 로 창에만 가므로 아래 출력 블록에는
# 아무 자국도 남지 않는다.
utils.show_batch_or_ten_images_with_label_and_predict(
    testloader, model, cfg.device, classes=CIFAR10_CLASSES, n=10, cifar10=True
)

# 학습
utils.train(
    model, trainloader, loss_ftn, optimizer, scheduler,
    cfg.device, cfg.epochs, cfg.log_interval, cfg.dry_run
)

# 학습 후
# 학습이 끝난 가중치로 같은 열 장을 다시 그린다. 앞뒤 두 그림을 견주면
# 무엇이 달라졌는지 눈으로 볼 수 있다. 이것도 출력에는 남지 않는다.
utils.show_batch_or_ten_images_with_label_and_predict(
    testloader, model, cfg.device, classes=CIFAR10_CLASSES, n=10, cifar10=True
)
# compute_accuracy 는 'Test Accuracy: 5482/10000 (54.82%)' 를 스스로 찍고
# 값도 돌려준다. 그래서 아래 print 와 합쳐 Test Accuracy 줄이 두 번 나온다.
test_accuracy = utils.compute_accuracy(model, testloader, cfg.device)

if cfg.save_model:
    utils.save_model(model, cfg.path)

print(f"Test Accuracy: {test_accuracy:.2f}%")


if __name__ == "__main__":
    pass
```

## 2. 논의

### 2.1 무엇이 깊어졌는가

심화 구조는 풀링 연산마다 그 앞에 합성곱 층을 두 개씩 두어 합성곱 뼈대의 깊이를 두 배로 만든다. 첫 블록은 `Conv2d(3, 32, 3, padding=1)` 다음에 `Conv2d(32, 32, 3, padding=1)` 을 둔다. 첫 층이 채널 3개를 32개로 올리고, 둘째 층은 그 32개 채널 위에서 한 번 더 걸러 내는 것이지 3채널 입력을 두 번 받는 것이 아니다. 둘째 블록도 같은 방식으로 `Conv2d(32, 64, 3, padding=1)` 과 `Conv2d(64, 64, 3, padding=1)` 을 잇는다.

네 층 모두 `padding=1` 이라 합성곱은 공간 크기를 건드리지 않는다. 크기를 줄이는 것은 블록 끝의 `MaxPool2d(2, 2)` 뿐이어서 $32 \times 32 \to 16 \times 16 \to 8 \times 8$ 로 두 번 줄고, 펼친 벡터는 $64 \times 8 \times 8 = 4096$ 차원이 된다. 이 4096이 곧 `fc1` 의 입력 차원이다.

"합성곱 둘 뒤 풀링"이 무엇을 벌어 주는지는 수용 영역으로 셀 수 있다. $3 \times 3$ 합성곱 하나의 수용 영역은 $3 \times 3$ 이지만 두 개를 이으면 $5 \times 5$ 로 넓어진다. 네 합성곱과 두 풀링을 모두 지나고 나면 마지막 $8 \times 8$ 특징 맵의 화소 하나가 원본에서 $16 \times 16$ 을 본다. $32 \times 32$ 그림의 넓이로 4분의 1이다.

필터 수도 함께 늘었다. [기본 모델](06_cifar10_basic.md)의 `SimpleCNN` 이 6개/16개였다면 여기서는 32개/32개/64개/64개이고, 완전 연결층의 뉴런은 120개에서 512개가 되었다.

### 2.2 매개변수는 어디에 있는가

출력의 첫 줄은 `Total parameters: 2,168,362` 이다. 층별로 나누어 보면 이 수가 어디에서 왔는지 바로 보인다.

| 층 | 가중치 | 편향 | 합 |
|---|---|---|---|
| conv1 | $32 \times 3 \times 3 \times 3 = 864$ | 32 | 896 |
| conv2 | $32 \times 32 \times 3 \times 3 = 9{,}216$ | 32 | 9,248 |
| conv3 | $64 \times 32 \times 3 \times 3 = 18{,}432$ | 64 | 18,496 |
| conv4 | $64 \times 64 \times 3 \times 3 = 36{,}864$ | 64 | 36,928 |
| fc1 | $512 \times 4096 = 2{,}097{,}152$ | 512 | 2,097,664 |
| fc2 | $10 \times 512 = 5{,}120$ | 10 | 5,130 |
| **합계** | | | **2,168,362** |

합성곱 네 층을 다 합쳐도 65,568개로 전체의 3.02%이고, `fc1` 하나가 2,097,664개로 96.74%를 차지한다. "합성곱 층을 넷 쓰는 깊은 신경망"이라고 부르지만 무게는 합성곱이 아니라 펼치기 바로 다음의 완전 연결층 하나에 쏠려 있다. 드롭아웃 비율을 합성곱 뒤에서는 0.25로, 완전 연결층 뒤에서는 0.5로 둔 것도 이 쏠림과 맞아떨어진다.

### 2.3 학습은 어디서 멈추는가

세대마다 찍힌 요약 줄 열넷만 모으면 학습이 어떻게 진행되었는지가 드러난다.

| 세대 | 평균 손실 | 학습 정확도 | 앞 세대 대비 |
|---|---|---|---|
| 1 | 2.1525 | 20.22% | — |
| 2 | 1.7721 | 36.20% | +15.98%p |
| 3 | 1.5800 | 42.64% | +6.44%p |
| 4 | 1.4875 | 46.11% | +3.47%p |
| 5 | 1.4361 | 47.99% | +1.88%p |
| 6 | 1.4026 | 49.36% | +1.37%p |
| 7 | 1.3820 | 50.19% | +0.83%p |
| 8 | 1.3681 | 50.84% | +0.65%p |
| 9 | 1.3520 | 51.31% | +0.47%p |
| 10 | 1.3478 | 51.21% | −0.10%p |
| 11 | 1.3417 | 51.75% | +0.54%p |
| 12 | 1.3349 | 52.03% | +0.28%p |
| 13 | 1.3348 | 51.99% | −0.04%p |
| 14 | 1.3331 | 51.99% | 0.00%p |

1세대에서 2세대로 +15.98%p 뛴 뒤 증가폭이 줄곧 작아져, 9세대부터 14세대까지는 51.21%와 52.03% 사이 0.82%p 띠 안에 머문다. 10세대와 13세대는 바로 앞 세대보다 오히려 낮고 14세대는 13세대와 같다.

이 평평함을 "모델이 수렴했다"로 읽으면 안 된다. 평평해진 것은 걸음 폭이다. `StepLR(step_size=1, gamma=0.7)` 이 세대마다 학습률에 0.7을 곱하므로 $k$세대의 학습률은 $0.01 \times 0.7^{k-1}$ 이고, 정확도가 평평해지기 시작하는 9세대에서 이미 $0.01 \times 0.7^8 = 5.765 \times 10^{-4}$ 로 첫 세대의 17.3분의 1이며, 14세대에서는 $0.01 \times 0.7^{13} = 9.689 \times 10^{-5}$ 로 103.2분의 1이다. 마지막 다섯 세대의 학습률을 모두 더해도 0.00112라서 첫 세대 하나(0.01)의 9분의 1 남짓이고, 열네 세대를 다 더한 0.0331은 학습률을 0.01로 고정했을 때의 $14 \times 0.01 = 0.14$ 에 견주어 24%에 지나지 않는다.

학습 정확도가 52%인 모델은 용량이 모자라서 멈춘 것이 아니다. 매개변수 216만 개짜리 신경망이 시험 자료도 아닌 **학습 자료**를 절반밖에 못 맞히고 있다면 그것은 과소적합이고, 모자란 것은 용량이 아니라 걸음이다.

시험 정확도 54.82%가 마지막 학습 정확도 51.99%보다 2.83%p **높은** 것도 같은 이야기를 한다. 두 가지가 겹친 결과다. 하나, 드롭아웃이 세 군데(`dropout1` 두 번, `dropout2` 한 번) 학습 중에는 살아 있고 `model.eval()` 아래에서는 꺼진다. 둘, `utils.train` 의 학습 정확도는 세대 전체에 걸쳐 `correct` 를 누적한 값이라 세대 앞쪽의 나쁜 가중치가 함께 들어간다. 과적합이 없을 때 학습 정확도가 시험 정확도보다 낮게 나오는 것은 이상한 일이 아니다.

### 2.4 "심화"가 "기본"보다 나은가

이 쪽의 이름은 심화이고 앞에 [CIFAR-10 기본](06_cifar10_basic.md)이 있으니, 뒤의 것이 앞의 것을 이긴다는 이야기를 기대하게 된다. 그런데 이 쪽이 실제로 실은 수는 54.82%이고, 기본 쪽이 적어 놓은 60~70%보다 낮다.

그렇다고 "기본이 더 낫다"로 뒤집을 수도 없다. 두 수는 애초에 맞대 놓을 물건이 아니기 때문이다.

- 기본 쪽에는 출력 블록이 없다. 그 60~70%는 재어서 실은 값이 아니라 적어 놓은 값이다.
- 학습 절차가 다르다. 기본은 관성 없는 SGD에 학습률 0.001로 5세대를 돌리고, 이 쪽은 관성 0.5인 SGD에 학습률 0.01과 StepLR로 14세대를 돌린다.
- 무엇보다 한 번 돌린 것은 잰 것이 아니다. 씨앗을 바꾸어 여러 번 돌리고 퍼짐을 함께 실어야 하며, 퍼짐보다 작은 차이는 차이가 아니다. 이 쪽에도 기본 쪽에도 그런 퍼짐이 없다.

그러니 이 쪽이 말할 수 있는 것은 하나뿐이다. **이 설정으로 씨앗 1을 한 번 돌리면 54.82%가 나온다.** 깊이와 너비를 늘린 것이 이득이었는지는 이 쪽의 증거로 답할 수 없고, 2.3이 보인 대로 학습률 일정부터 고치지 않으면 답할 수도 없다. 35배 큰 모델이 학습 자료를 52%밖에 맞히지 못한 상태에서 잰 값은 구조에 대한 값이 아니라 일정에 대한 값이다.

데이터셋을 가로질러 보면 수가 말하는 것이 훨씬 또렷하다. 같은 `cnn_utils` 틀에서 [MNIST](../../ch03/mnist/04_cnn.md)는 99.21%, [Fashion-MNIST](05_fashion_mnist_classifier.md)는 85.84%, CIFAR-10은 54.82%다. 앞의 둘은 합성곱 두 층짜리 `CNN` 이고 마지막은 합성곱 네 층짜리 `CNN_CIFAR10` 이니, 더 깊은 구조를 쓰고도 가장 낮다. 이 차례를 만든 것은 구조가 아니라 데이터셋이며, [CIFAR-10 데이터셋](03_cifar10_dataset.md)이 같은 사다리를 같은 수로 적어 두었다.

어느 쪽이든 최상급($>95\%$)까지는 아직 멀다. 그 수준에 이르려면 잔차 연결, 데이터 증강, 층마다의 배치 정규화, 그리고 무엇보다 마지막 세대까지 학습이 이어지는 학습률 일정이 필요하다. 이 간격이 ResNet 같은 요즘 구조를 공부할 까닭이 된다.

**연습문제 1.** <span class="diff easy" title="쉬움"></span>
출력의 첫 줄은 `Total parameters: 2,168,362` 이다. `CNN_CIFAR10` 의 층 여섯 개(conv1~conv4, fc1, fc2)마다 가중치와 편향을 따로 세어 합이 정말 2,168,362가 되는지 확인하라. 그리고 합성곱 네 층을 다 합친 몫과 `fc1` 한 층의 몫을 백분율로 견주어라.

</div>

??? success "연습문제 1 풀이"
    합성곱의 가중치는 (출력 채널) × (입력 채널) × (핵 높이) × (핵 너비)이고 편향은 출력 채널마다 하나다. 완전 연결층의 가중치는 (출력 차원) × (입력 차원)이고 편향은 출력 차원마다 하나다. `fc1` 의 입력 4096은 `padding=1` 합성곱이 크기를 지키고 풀링이 두 번 절반으로 줄인 결과인 $64 \times 8 \times 8$ 이다.

    | 층 | 가중치 | 편향 | 합 |
    |---|---|---|---|
    | conv1 | $32 \times 3 \times 3 \times 3 = 864$ | 32 | 896 |
    | conv2 | $32 \times 32 \times 3 \times 3 = 9{,}216$ | 32 | 9,248 |
    | conv3 | $64 \times 32 \times 3 \times 3 = 18{,}432$ | 64 | 18,496 |
    | conv4 | $64 \times 64 \times 3 \times 3 = 36{,}864$ | 64 | 36,928 |
    | fc1 | $512 \times 4096 = 2{,}097{,}152$ | 512 | 2,097,664 |
    | fc2 | $10 \times 512 = 5{,}120$ | 10 | 5,130 |

    합은 $896 + 9{,}248 + 18{,}496 + 36{,}928 + 2{,}097{,}664 + 5{,}130 = 2{,}168{,}362$ 로 출력과 맞는다.

    합성곱 네 층은 $896 + 9{,}248 + 18{,}496 + 36{,}928 = 65{,}568$ 개, 곧 전체의 3.02%다. `fc1` 하나는 2,097,664개로 96.74%다. 깊이를 말하는 이름과 달리 이 모델의 무게는 거의 전부 완전 연결층 하나에 있다. 합성곱 층을 하나 더 쌓는 것보다 풀링을 한 번 더 넣어 펼치는 차원을 $8 \times 8$ 에서 $4 \times 4$ 로 줄이는 쪽이 매개변수를 훨씬 많이 덜어 낸다는 뜻이기도 하다.

**연습문제 2.** <span class="diff med" title="중간"></span>
[CIFAR-10 기본](06_cifar10_basic.md)의 `SimpleCNN` 과 이 쪽의 `CNN_CIFAR10` 의 매개변수 수를 견주어 비를 구하라. 그런 다음, 이 쪽이 실은 54.82%와 기본 쪽이 적어 놓은 60~70%를 근거로 "매개변수를 35배로 늘린 것이 이득이었는가"에 답할 수 있는지 판단하라. 답할 수 없다면 무엇을 더 돌려야 답할 수 있는지 적어라.

</div>

??? success "연습문제 2 풀이"
    `SimpleCNN` 의 매개변수는 conv1 $3 \times 6 \times 5 \times 5 + 6 = 456$, conv2 $6 \times 16 \times 5 \times 5 + 16 = 2{,}416$, fc1 $400 \times 120 + 120 = 48{,}120$, fc2 $120 \times 84 + 84 = 10{,}164$, fc3 $84 \times 10 + 10 = 850$ 을 더해 62,006개다. `CNN_CIFAR10` 은 2,168,362개이므로 비는 $2{,}168{,}362 / 62{,}006 = 34.97$ 배다.

    답할 수 없다. 까닭이 셋이다.

    1. **기본 쪽의 60~70%는 잰 값이 아니다.** 그 쪽에는 출력 블록이 아예 없다. 재지 않은 수와 잰 수를 빼는 것은 뺄셈이 아니다.
    2. **학습 절차가 다르다.** 기본은 관성 없는 SGD에 학습률 0.001로 5세대, 이 쪽은 관성 0.5인 SGD에 학습률 0.01과 `StepLR(gamma=0.7)` 로 14세대다. 두 수의 차이 가운데 어디까지가 구조 탓이고 어디까지가 절차 탓인지 갈라낼 방법이 없다.
    3. **한 번 돌린 것은 잰 것이 아니다.** 씨앗 하나짜리 값 둘을 빼서 나온 차이는 씨앗을 바꾸었을 때의 퍼짐보다 작을 수 있고, 그러면 그것은 차이가 아니다.

    답할 수 있게 하려면 이렇게 해야 한다. 먼저 두 모델을 **같은 절차**에 얹는다(같은 최적화기, 같은 학습률, 같은 일정, 같은 세대 수). 그리고 씨앗을 바꾸어 모델마다 여러 번(다섯 번쯤) 돌려 평균과 퍼짐을 함께 적는다. 평균 차이가 퍼짐보다 클 때에만 이득이라고 말한다. 그에 앞서 2.3이 보인 학습률 문제부터 고쳐야 한다. 학습 정확도가 52%에 멈춘 상태로 잰 값은 `CNN_CIFAR10` 이 낼 수 있는 값이 아니라 이 일정이 허락한 값이기 때문이다.

**연습문제 3.** <span class="diff med" title="중간"></span>
심화 모델은 (합성곱 블록 뒤에) 0.25, (완전 연결층 뒤에) 0.5의 드롭아웃 비율을 쓴다. 깊이에 따라 다른 비율을 쓰는 까닭과 둘 다 0.5로 두면 어떻게 될지 설명하라. 2.2의 매개변수 표를 근거로 삼아라.

</div>

??? success "연습문제 3 풀이"
    합성곱 층은 공간 위치에 걸쳐 매개변수를 나누어 쓰므로 활성값의 25%만 떨어뜨려도 공간 구조를 크게 망가뜨리지 않으면서 충분한 규제가 된다. 완전 연결층은 사정이 다르다. 2.2의 표대로 `fc1` 한 층이 2,097,664개, 곧 모델 전체의 96.74%를 쥐고 있고 위치를 나누어 쓰지도 않는다. 과적합이 일어난다면 거의 전부 여기서 일어나므로 0.5라는 높은 비율이 알맞다. 규제를 매개변수가 몰린 곳에 몰아 준 셈이다.

    둘 다 0.5로 두면 합성곱 층이 학습 중에 공간 정보를 너무 많이 잃는다. 특징 맵이 지나치게 성겨져 뒤따르는 층이 일관된 무늬를 잡기 어려워진다. 그러면 수렴이 느려지고 마지막 정확도도 떨어질 가능성이 크다. 다만 이 쪽의 실행은 이미 과소적합 쪽에 있다는 점을 잊지 말아야 한다(학습 정확도 51.99% < 시험 정확도 54.82%). 과소적합인 모델에 규제를 더 얹는 것은 방향이 반대다. 여기서 드롭아웃을 더 세게 하는 대신 오히려 약하게 하는 실험이 더 말이 된다 — 그리고 그 실험 역시 씨앗 여럿과 퍼짐 없이는 결론을 낼 수 없다.

**연습문제 4.** <span class="diff hard" title="어려움"></span>
`StepLR(optimizer, step_size=1, gamma=0.7)` 이 이 쪽의 결과에 어떤 몫을 했는지 따져라. (가) $k$세대의 학습률을 식으로 쓰고 1, 9, 14세대의 값을 구하라. (나) 2.3의 표에서 학습 정확도가 평평해지는 세대를 짚고, 그 세대의 학습률이 첫 세대의 몇 분의 일인지 구하라. (다) 이 평평함이 "수렴"이 아니라는 근거를 표의 값 하나로 대라. (라) `gamma` 를 고쳐 다시 돌린다면 무엇을 보고 나아졌다고 판단할지 적어라.

</div>

??? success "연습문제 4 풀이"
    **(가)** `scheduler.step()` 이 세대 끝마다 한 번 불리므로 $k$세대가 쓰는 학습률은

    $$\eta_k = 0.01 \times 0.7^{k-1}$$

    이다. $\eta_1 = 0.01$, $\eta_9 = 0.01 \times 0.7^8 = 5.765 \times 10^{-4}$, $\eta_{14} = 0.01 \times 0.7^{13} = 9.689 \times 10^{-5}$.

    **(나)** 9세대부터 학습 정확도가 51.21%와 52.03% 사이 0.82%p 띠에 갇힌다. 그 9세대의 학습률은 이미 첫 세대의 $1 / 0.7^8 = 17.35$ 분의 일이고, 14세대에서는 $1 / 0.7^{13} = 103.2$ 분의 일이다. 마지막 다섯 세대(10~14)의 학습률을 모두 더해도 0.00112로 첫 세대 하나의 9분의 1 남짓이라, 다섯 세대를 더 돌렸어도 걸음의 총량은 첫 세대 한 번에도 못 미친다.

    **(다)** 14세대의 학습 정확도가 51.99%라는 값 하나로 충분하다. 매개변수 216만 개짜리 모델이 시험 자료도 아닌 **학습 자료**를 절반밖에 못 맞히고 있다. 2.3이 말한 대로 이 수는 드롭아웃이 켜진 채 세대 전체에 걸쳐 누적된 값이라 조금 낮게 나오기는 하지만, 그 보정으로 메울 수 있는 크기가 아니다. 시험 정확도(54.82%)가 오히려 2.83%p 높아 과적합의 낌새가 전혀 없다는 것까지 겹치면, 멈춘 까닭은 모델이 다 배워서가 아니라 걸음이 사라져서다.

    **(라)** 판단 기준을 먼저 정해 두어야 한다.

    - 마지막 세대의 학습 정확도가 여전히 오르고 있는가. 오르고 있다면 일정이 학습을 가로막지 않는다는 뜻이다.
    - 학습 정확도가 시험 정확도를 **넘어서는가**. 넘어서야 비로소 규제와 증강을 이야기할 자리가 생긴다.
    - 시험 정확도가 올랐는가 — 단, 씨앗을 바꾼 여러 실행의 평균과 퍼짐으로 적어야 한다. 퍼짐보다 작은 차이는 차이가 아니다.

    고칠 방법은 여럿이다. `gamma=0.9` 로 두면 14세대 학습률이 $0.01 \times 0.9^{13} = 2.542 \times 10^{-3}$ 으로 첫 세대의 3.93분의 일에 머문다. `step_size` 를 5로 늘려 다섯 세대마다 한 번만 줄일 수도 있고, `CosineAnnealingLR(optimizer, T_max=cfg.epochs)` 처럼 마지막 세대에 맞추어 천천히 내리는 일정을 쓸 수도 있다. 어느 쪽이든 고른 뒤에는 한 번이 아니라 여러 번 돌려야 한다.

**연습문제 5.** <span class="diff hard" title="어려움"></span>
CIFAR-10 학습 변환에 데이터 증강(무작위 좌우 뒤집기와 `padding=4` 인 무작위 잘라내기)을 더하라. 좌우 뒤집기가 CIFAR-10의 모든 부류에 안전한 까닭을 [CIFAR-10 데이터셋](03_cifar10_dataset.md)의 측정으로 뒷받침하고, 이 쪽의 설정에 증강만 얹었을 때 정확도가 오르리라고 기대할 근거가 있는지 판단하라.

</div>

??? success "연습문제 5 풀이"
    ```python
    from torchvision import transforms

    train_transform = transforms.Compose([
        transforms.RandomCrop(32, padding=4),
        transforms.RandomHorizontalFlip(),
        transforms.ToTensor(),
        transforms.Normalize((0.5, 0.5, 0.5), (0.5, 0.5, 0.5))
    ])
    ```

    좌우 뒤집기가 안전하다는 것은 말로 할 것이 아니라 재는 것이다. [CIFAR-10 데이터셋](03_cifar10_dataset.md)의 연습문제 4가 학습 이미지 5만 장에서 이미지와 그 좌우 반전 사이의 평균 절대 차이를 부류마다 재었다. 열 부류가 0.1191(airplane)에서 0.1898(truck) 사이에 촘촘히 모여 가장 큰 값이 가장 작은 값의 1.59배에 지나지 않는다. 튀는 부류가 없다는 뜻이고, 자동차와 트럭과 말이 사진마다 아무 쪽이나 보고 있어 뒤집은 이미지도 이미 데이터셋 안에 있는 종류이기 때문이다. 같은 재기를 Fashion-MNIST에서 하면 앵클부츠 0.3269 대 티셔츠 0.0707로 4.6배까지 벌어지는데, 그 데이터셋의 신발이 모두 같은 쪽을 보고 찍혔기 때문이다. 그래서 이 증강은 CIFAR-10에서는 안전하고 Fashion-MNIST에서는 조심해야 한다. `"b"` 를 뒤집으면 `"d"` 가 되는 문자 인식과 대조하면 원리가 분명해진다.

    증강이 무엇을 하는지도 분명하다. 덧댄 뒤 무작위로 잘라 내면 물체가 화면 안에서 옮겨져 평행 이동 불변성을 흉내 내고, 좌우 뒤집기는 실질적인 학습 집합을 두 배로 만든다. 둘 다 모델이 화소의 정확한 자리와 방향을 외우지 못하게 하는 장치, 곧 규제다.

    그런데 이 쪽의 설정에 증강만 얹으면 정확도가 오르리라는 기대에는 근거가 없다. 규제는 과적합을 고치는 약인데 2.3에서 본 대로 이 실행은 과적합이 아니라 과소적합 상태다(학습 정확도 51.99% < 시험 정확도 54.82%). 증강은 학습 문제를 오히려 어렵게 만들어 보통 더 많은 세대를 요구하는데, 이 쪽은 이미 14세대째 학습률이 첫 세대의 1/103이라 더 배울 걸음이 남아 있지 않다. 순서를 지키려면 학습률 일정을 먼저 고치고(연습문제 4), 학습 정확도가 시험 정확도를 넘어서는 것을 확인한 다음에 증강을 얹어야 한다. 그리고 얼마나 올랐는지는 씨앗을 바꾼 여러 실행의 평균과 퍼짐으로만 적어야 한다. 흔히 3~5%p라는 수가 인용되지만 그것은 남의 설정에서 나온 수이지 이 쪽에서 잰 수가 아니다.

## 정리하며

**다룬 것** — CIFAR-10 심화

- **구조**: `Conv2d(3, 32)` → `Conv2d(32, 32)` → 풀링 → `Conv2d(32, 64)` → `Conv2d(64, 64)` → 풀링. `padding=1` 이라 크기를 줄이는 것은 풀링뿐이고 $32 \to 16 \to 8$, 펼치면 $64 \times 8 \times 8 = 4096$ 차원이다. 마지막 특징 맵의 화소 하나는 원본에서 $16 \times 16$ 을 본다.
- **매개변수 2,168,362개의 쏠림**: 합성곱 네 층을 다 합쳐 65,568개(3.02%), `fc1` 하나가 2,097,664개(96.74%). 깊이를 내세운 이름과 달리 무게는 완전 연결층에 있다.
- **멈춘 곳**: 학습 정확도가 9세대부터 0.82%p 띠 안에 갇히는데, 이는 수렴이 아니라 `StepLR(gamma=0.7)` 이 14세대 학습률을 첫 세대의 1/103로 줄여 놓은 결과다. 학습 정확도 51.99%가 시험 정확도 54.82%보다 낮다는 것이 아직 과소적합이라는 증거다.
- **실은 수**: 씨앗 1로 한 번 돌려 54.82%. 앞 쪽의 60~70%와 맞대 놓을 수 있는 값이 아니며, 퍼짐 없이는 어떤 이득도 주장할 수 없다. 데이터셋을 가로지른 99.21% → 85.84% → 54.82% 의 사다리는 구조가 아니라 데이터셋이 만든 것이다.
