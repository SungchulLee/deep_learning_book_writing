# 오토인코더의 주다양체

1차원 병목을 가진 비선형 오토인코더는 자료를 꿰는 굽은 주다양체를 배워, 주성분 분석의 선형 주축을 비선형 짜임까지 잡도록 넓힌다. 이 보기는 2차원 S자 곡선 자료 묶음에 작은 오토인코더를 익혀, 디코더가 최소 제곱 뜻에서 자료에 가장 잘 맞는 매끄러운 1차원 곡선, 곧 첫 주성분의 비선형 짝을 그려 내는 것을 보인다.

## 1. 코드

```python
"""오토인코더의 주다양체."""
import numpy as np
import matplotlib.pyplot as plt
import torch
import torch.nn as nn
import torch.optim as optim

def make_s_curve(n=400, noise=0.07, seed=0):
    rng = np.random.default_rng(seed)
    t = rng.uniform(-2.5, 2.5, size=n)
    x = t
    y = np.sin(1.5 * t)
    X = np.stack([x, y], axis=1)
    X += rng.normal(scale=noise, size=X.shape)
    return X.astype(np.float32)

X = make_s_curve(n=600, noise=0.06, seed=42)
X_mean, X_std = X.mean(axis=0, keepdims=True), X.std(axis=0, keepdims=True)
Xn = (X - X_mean) / X_std
Xt = torch.from_numpy(Xn)

class AE(nn.Module):
    def __init__(self):
        super().__init__()
        self.encoder = nn.Sequential(
            nn.Linear(2, 32), nn.Tanh(),
            nn.Linear(32, 16), nn.Tanh(),
            nn.Linear(16, 1),
        )
        self.decoder = nn.Sequential(
            nn.Linear(1, 16), nn.Tanh(),
            nn.Linear(16, 32), nn.Tanh(),
            nn.Linear(32, 2),
        )

    def forward(self, x):
        z = self.encoder(x)
        return self.decoder(z), z

ae = AE()
opt = optim.Adam(ae.parameters(), lr=5e-3)
loss_fn = nn.MSELoss()

for ep in range(1, 60001):
    perm = torch.randperm(len(Xt))
    for i in range(0, len(Xt), 128):
        xb = Xt[perm[i:i+128]]
        xhat, _ = ae(xb)
        loss = loss_fn(xhat, xb)
        opt.zero_grad()
        loss.backward()
        opt.step()

if __name__ == "__main__":
    pass
```

## 2. 논의

주성분 분석이 자료에 선을 맞출 때는 직교 쏘기 어긋남을 가장 작게 하는 선형 아래 공간을 찾는다. 1차원 병목과 비선형 활성화(쌍곡탄젠트)을 가진 오토인코더는 이를 넓혀 굽은 1차원 다양체를 찾는다. 디코더를 숨은 값의 범위에 걸쳐 훑으면 자료 구름을 꿰는 매끄러운 2차원 곡선이 그려지는데 이것이 "주다양체" 또는 "주곡선"이다.

(정류 선형 대신) 쌍곡탄젠트 활성화를 고른 것은 일부러이다. 쌍곡탄젠트는 매끄럽고 미분할 수 있는 내놓기를 내어 꺾임 없는 이어진 곡선을 만든다. 정류 선형은 조각마다 선형인 다양체를 만드는데 그것도 옳지만 매끄러운 곡선을 어림하려면 숨은 단위가 더 필요할 수 있다. 그물의 깊이(인코더와 디코더에 각각 세 층)가 S자 곡선의 굽음을 나타낼 담이를 넉넉히 준다.

익히기는 들임 점과 병목을 지나 다시 세운 것 사이 평균 제곱 어긋남 손실을 쓴다. 이는 자료 점마다 배운 다양체까지의 제곱 거리를 가장 작게 하는 것과 같다. 담이와 익히기가 넉넉하면 오토인코더는 자료가 가장 빽빽한 자리를 지나는 다양체로 모이며, 이는 주성분 분석의 주축이 자료 구름의 가운데를 지나는 것과 비슷하다.

**연습문제 5.** <span class="diff hard" title="어려움"></span>
활성화 함수를 모두 없애고 출력의 시그모이드까지 떼어 **정말로 선형인** 오토인코더를 만들어라. 이것은 주성분 분석과 같아지는가? 다시 세우기 오차와 아래 공간을 각각 재어라.

</div>

??? success "연습문제 5 풀이"
    이론이 먼저 답을 말해 준다. 선형 오토인코더의 복원은
    $\hat{x} = W_2 W_1 x + b$이고 $W_2 W_1$의 계수가 병목 $k$ 이하이므로, 이는
    **계수가 $k$ 이하인 아핀 사상** 가운데 하나다. 에카르트-영 정리에 따라 그런
    사상 가운데 제곱 오차를 가장 작게 하는 것이 주성분 분석이다. 따라서

    $$\text{선형 오토인코더의 오차} \;\ge\; \text{주성분 분석의 오차}$$

    이고 등호는 같은 아래 공간을 찾았을 때 성립한다. **선형 오토인코더는 주성분
    분석을 이길 수 없다.**

    병목 8에서 익히며 재어 보면 이론대로다.

    | 에포크 | 10 | 25 | 50 | 100 | 150 | 200 |
    |---|---|---|---|---|---|---|
    | 주성분 분석과의 오차 차이 | +0.000704 | +0.000151 | +0.000156 | +0.000043 | +0.000027 | **+0.000010** |
    | 복원 아래 공간의 평균 주각 | 14.51° | 11.57° | 10.31° | 1.96° | 0.70° | **0.67°** |

    차이가 **언제나 양수**이며 0으로 다가갈 뿐 음수가 되지 않는다. 주각도 0°로
    수렴한다. 곧 선형 오토인코더는 경사 하강법으로 주성분 분석의 아래 공간을
    **찾아간다.**

    !!! note "같은 아래 공간이지 같은 축이 아니다"
        복원 공간은 같아지지만 인코더의 가중치가 주성분과 같아지지는 않는다. 재어 보면
        $W_1 W_1^{\top}$의 비대각 성분이 대각의 10%쯤으로 **직교가 아니고**, 분산이 큰
        차례로 정렬되지도 않는다.

        까닭은 간단하다. 임의의 가역 행렬 $M$에 대해 $W_1 \to M W_1$,
        $W_2 \to W_2 M^{-1}$로 바꾸어도 곱 $W_2 W_1$이 그대로다. 손실이 곱만 보므로
        그 안에서 어떻게 나누든 상관하지 않는다.

        그러므로 **주성분 분석이 주는 것**(정렬된 직교 축, 축마다의 분산)을 오토인코더는
        주지 않는다. 얻는 것은 아래 공간뿐이다. 주성분 분석을 해석에 쓰는 까닭이 여기 있다.

**연습문제 6.** <span class="diff med" title="중간"></span>
병목에 비선형 활성화를 넣고 빼면서 같은 자료로 익혀 보라. 활성화의 종류가 얼마나 중요한가?

</div>

??? success "연습문제 6 풀이"
    병목 16, 15 에포크로 재면 이렇다.

    | 활성화 | 없음(선형+시그모이드) | ReLU | tanh | 시그모이드 |
    |---|---|---|---|---|
    | 시험 MSE | 0.02057 | **0.00926** | 0.00959 | 0.02055 |

    두 가지가 눈에 띈다.

    **있고 없고가 크다.** ReLU를 넣으면 오차가 절반 이하로 떨어진다. 3.3절에서 본
    것과 같은 이야기이며, 여기서도 비선형성이 없으면 선형 사영 수준에 머문다.

    **그런데 시그모이드는 도움이 되지 않는다.** 0.02055로 사실상 활성화가 없는 것과
    같다. 은닉층 두 개를 지나며 시그모이드가 값을 $(0,1)$로 눌러 버려 기울기가 잘
    흐르지 않기 때문이다. ReLU와 tanh는 비슷하다.

    곧 "비선형이면 아무거나 된다"가 아니다. **기울기가 흐르는 비선형**이어야 한다.

**연습문제 7.** <span class="diff easy" title="쉬움"></span>
주성분 분석은 닫힌 꼴로 한 번에 풀리는데 오토인코더는 경사 하강법으로 여러 에포크를 돌려야 한다. 그런데도 오토인코더를 쓰는 까닭은 무엇인가?

</div>

??? success "연습문제 7 풀이"
    주성분 분석은 공분산 행렬의 고유벡터를 구하면 끝이다. 답이 하나로 정해지고,
    다시 돌려도 같은 값이 나오며, 축마다의 분산까지 덤으로 준다.

    그럼에도 오토인코더를 쓰는 까닭이 셋이다.

    **첫째, 굽은 구조를 담는다.** 연습문제 4의 표에서 병목 16일 때 오차가 66% 낮았다.
    자료가 굽은 다양체 위에 놓여 있으면 선형 아래 공간으로는 따라갈 수 없다.

    **둘째, 자료가 커도 된다.** 주성분 분석은 $784 \times 784$ 공분산 행렬을
    다루지만, 화소가 수십만 개인 그림이라면 그 행렬만 수백 기가바이트다. 자기
    인코더는 배치 단위로 익히므로 자료 전체를 메모리에 올릴 필요가 없다.

    **셋째, 인코더를 그대로 쓸 수 있다.** 익히고 나면 새 자료를 한 번의 순전파로
    코드로 바꿀 수 있다. 주성분 분석도 사영이면 되지만, 오토인코더는 이 인코더를
    다른 일의 앞단으로 가져다 쓸 수 있다.

    거꾸로 **주성분 분석이 나은 자리**도 분명하다. 자료가 적거나, 답이 하나로 정해져야
    하거나, 축의 뜻을 읽어야 하거나, 빨리 답만 보면 될 때다.

**연습문제 8.** <span class="diff med" title="중간"></span>
이 쪽의 S자 곡선 실험에서 병목을 1로 둔 오토인코더가 찾은 것을 **주곡선**(principal curve)이라 한다. 주성분 분석의 주축과 주곡선의 관계를 한 문장으로 적고, 두 가지가 일치하는 경우를 말하라.

</div>

??? success "연습문제 8 풀이"
    주축은 자료에 가장 잘 맞는 **직선**이고 주곡선은 가장 잘 맞는 **곡선**이다. 둘 다
    "자료에서 자기 자신까지의 제곱 거리를 가장 작게 하는 1차원 대상"을 찾는다는
    점에서 같은 물음이며, 답을 찾는 모둠이 직선이냐 곡선이냐만 다르다.

    일치하는 경우는 **자료가 정말로 직선 둘레에 퍼져 있을 때**다. 그때는 가장 잘 맞는
    곡선이 곧 직선이므로 주곡선이 주축으로 되돌아온다. 연습문제 5에서 활성화를 없애면
    주성분 분석으로 돌아가는 것이 이 사실의 다른 얼굴이다.

    S자 곡선에서는 일치하지 않는다. 자료가 굽어 있으므로 직선으로는 아무리 잘 맞추어도
    곡선만 못하다.

**연습문제 9.** <span class="diff hard" title="어려움"></span>
다시 세우기 오차를 줄이는 것과 좋은 나타냄을 배우는 것은 같은 일인가? 병목을 784로 두면 어떻게 되는지 생각해 보라.

</div>

??? success "연습문제 9 풀이"
    같은 일이 아니며, 병목을 입력과 같은 784로 두면 그것이 극명해진다.

    그때 오토인코더는 **항등 함수**를 배우면 그만이다. 인코더와 디코더를 모두 항등
    행렬로 두면 다시 세우기 오차가 정확히 0이 된다. 오차로는 더할 나위 없지만
    배운 것은 아무것도 없다. 코드가 입력과 똑같으므로 눌러 담지도, 요약하지도 않았다.

    그러므로 **병목이야말로 이 방법의 전부**다. 오차를 줄이라는 목표는 그 자체로는
    아무 쓸모가 없고, "이만큼 좁은 통로로 밀어 넣고도"라는 제약이 붙어야 뜻이 생긴다.
    인코더는 통로를 지나기 위해 무엇이 중요한지 고를 수밖에 없으며, 그 고름이 곧
    나타냄이다.

    같은 이치가 다른 제약에도 적용된다. 병목을 넓게 두는 대신 다른 벌점을 주어도 된다.

    - **성김**: 코드의 대부분을 0으로 만들게 한다
    - **잡음**: 더럽힌 입력에서 깨끗한 것을 되세우게 한다(연습문제는 [잡음 없애는
      오토인코더](03_ae_denoising.md)에)
    - **오그림**: 입력이 흔들려도 코드가 덜 흔들리게 한다([오그리는 자기
      인코더](../variants/contractive.md))

    이들을 묶어 **정칙화된 오토인코더**라 하며, 공통점은 하나다. 다시 세우기만으로는
    좋은 나타냄이 나오지 않으므로 **무엇을 버릴지 강제한다.**

    그리고 이 장의 마지막 쪽이 보이듯, 다시 세우기를 아무리 잘해도
    [뽑을 수 있게 되지는 않는다](../limits/latent_sampling.md). 오차는 나타냄의
    품질을 재는 자가 아니다.

**연습문제 10.** <span class="diff easy" title="쉬움"></span>
주성분 분석은 자료의 평균을 빼고 시작한다. 오토인코더에는 그런 단계가 없는데 어떻게 같은 일을 하는가?

</div>

??? success "연습문제 10 풀이"
    치우침(bias)이 그 일을 한다.

    주성분 분석은 $\hat{x} = \bar{x} + P P^{\top}(x - \bar{x})$로 평균을 명시적으로
    빼고 더한다. 오토인코더의 층은 $Wx + b$이므로, 디코더의 마지막 치우침 $b$가
    평균 노릇을 할 수 있다. 실제로 익히고 나면 그 치우침이 자료 평균 근처에 자리
    잡는다.

    곧 오토인코더는 평균을 **빼도록 시키지 않고 배우게 둔다.** 이것이 오토인코더의
    성격을 잘 보여 준다. 주성분 분석이 손으로 정해 주던 것들(중심 옮기기, 직교성,
    분산 순서)을 오토인코더는 아무것도 정해 주지 않고 손실이 알아서 고르게 한다.
    그래서 더 유연하고, 그만큼 해석이 어렵다.
