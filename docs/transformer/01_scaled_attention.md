# 8.1 어텐션 식을 연다 — 왜 루트 d로 나누는가

<div class="leadbox" markdown>

**들어가는 이야기** — 한 줄짜리 까닭을 재어 본다

논문이 쓰는 어텐션 식에는 나눗셈이 하나 들어 있다.

$$
\mathrm{Attention}(Q, K, V) \;=\; \mathrm{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d_k}}\right) V
$$

왜 $\sqrt{d_k}$로 나누는가. 글쓴이들은 한 줄로 적어 두었다 — **수가 커지면 내적이 크게 자라, 소프트맥스를 기울기가 아주 작은 자리로 밀어 넣는다.**

짐작하지 말고 재자. 질의와 키를 아무렇게나 뽑아 놓고 $d_k$만 8에서 512까지 키워 본다.

| $d_k$ | 점수의 퍼짐 | 소프트맥스 최댓값 | 남은 기울기 |
|---|---|---|---|
| 8 | 2.86 | 0.426 | 0.718 |
| 512 | **23.11** | **0.906** | **0.127** |

**64배 키웠더니 퍼짐이 8배가 되었다.** $\sqrt{64} = 8$이다. 그만큼 소프트맥스가 한 칸으로 쏠려(0.426 → 0.906) 기울기가 **5분의 1 아래**로 줄었다. 배우라고 만든 장치가 배울 수 없는 자리로 가 버린 것이다.

나누면 어떻게 되는가. **$d_k$가 8이든 512든 퍼짐이 1.0 언저리로 똑같아진다.** 나눗셈 하나가 깊이와 무관하게 같은 형태를 지키게 한다.

이 쪽은 그 한 줄을 재고, 내친김에 **멀티헤드 어텐션** — 머리를 여럿 두고 따로
보게 하는 것 — 도 손으로 짜 본다. 거기서 뜻밖의 것이 하나 나온다 — 머리를 몇 개로 나누든 **파라메터가 하나도 늘지 않는다.**

</div>

## 0. Q, K, V — 머리글자가 곧 설명이다

식을 열기 전에 셋이 무엇인지 못 박아 두자. 머리글자가 그대로 뜻이다.

| | 영어 | 그 단어가 | 묻는 것 |
|---|---|---|---|
| $K$ | **K**ey — key features it **has** | **가진** 특징 | 나는 **무엇으로 불리는가** |
| $Q$ | **Q**uery — questions it **raises** | **던지는** 물음 | 나는 **무엇을 찾는가** |
| $V$ | **V**alue — values it **tosses when asked** | 걸렸을 때 **건네는** 값 | 나는 **무엇을 주는가** |

**단어 하나가 셋을 다 가진다.** 묻는 쪽과 답하는 쪽이 따로 있는 것이 아니라, 모든
자리가 동시에 묻고 동시에 답한다.

선반에 책 두 권이 꽂혀 있다고 해 보자.

| | 해리포터 | 스타워즈 |
|---|---|---|
| $K$ 이름표 | `마법 · 기숙학교 · 영국` | `우주 · 전투 · 로봇` |
| $V$ 내용 | 「친구들과 어른이 되어 가는 이야기」 | 「아버지와 아들의 이야기」 |
| $Q$ 물음 | 「마법 학교의 규칙이 궁금해」 | 「전쟁에서 가족은 어떻게 되나」 |

해리포터의 $Q$를 선반의 모든 $K$와 맞춰 본다. 제 이름표와는 잘 맞고(마법 ↔ 마법)
스타워즈 이름표와는 잘 안 맞는다(마법 ↔ 우주). 그 둘을 0.9와 0.1로 바꾼 뒤,
**건네받는 것은 $V$뿐**이다.

$$
\mathrm{Attention}(Q, K, V) \;=\;
\underbrace{\mathrm{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d_k}}\right)}_{\text{얼마나 볼지}}
\;\underbrace{V}_{\text{무엇을 건넬지}}
$$

$Q$와 $K$는 **가중치만** 정하고 식에서 빠진다. 실제로 섞여 나가는 것은 $V$다.

!!! note "$K$와 $V$가 왜 따로 있는가"
    스타워즈의 이름표는 `우주·전투·로봇`인데 내용은 「아버지와 아들」이다.
    **검색되는 말과 건네는 것이 다르다.**

    - 「우주 이야기 없나?」 → 이름표에 걸린다 → **「아버지와 아들」**을 받는다
    - 「가족 갈등이 궁금해」 → 이름표에 안 걸린다 → 내용에 있어도 **못 받는다**

    둘을 하나로 묶으면 **「무엇에 관련 있다고 내걸까」와 「무엇을 줄까」를 따로
    정할 수가 없다.** 그래서 둘이 아니라 셋이다.

**셋은 단어마다 만드는 행렬이 아니다.** 이름표를 뽑는 규칙 $W_K$, 내용을 뽑는
규칙 $W_V$, 물음을 뽑는 규칙 $W_Q$는 **모든 자리가 함께 쓰고**, 단어 하나는
거기서 **벡터 셋**을 얻는다. 아래 코드의 `in_proj_weight`가 $(3D, D)$인 것이
그것이다 — 사영 셋을 한 행렬에 쌓아 둔 것이다.

---

[7장](../imdb/index.md)은 `nn.MultiheadAttention`을 그대로 가져다 썼다. 잘 돌아갔고, 그래서 안을 열어 볼 일이 없었다. 이 쪽이 연다. 여는 방법은 하나다 — **식을 손으로 다시 짜서 같은 값이 나오는지 보는 것.**

## 1. 코드

```python
"""8.1 블랙박스를 연다 — 왜 루트 d_k 로 나누는가, 멀티헤드는 무엇인가.

7장은 nn.MultiheadAttention 을 그대로 가져다 썼다. 그 안에서 무슨 일이
일어나는지는 열어 보지 않았다. 이 쪽이 연다.

「Attention Is All You Need」가 적은 식은 이렇다.

    Attention(Q, K, V) = softmax(Q K^T / sqrt(d_k)) V

논문은 나누는 까닭을 한 줄로 적는다 — d_k 가 커지면 내적이 크게 자라
소프트맥스를 기울기가 아주 작은 자리로 밀어 넣는다. 짐작하지 말고 재자.

실행: 이 쪽의 코드를 파일로 갈무리해 돌린다. 학습이 없어 몇 초면 끝난다.
"""
import torch
import torch.nn as nn
import torch.nn.functional as F

SEED = 42
torch.manual_seed(SEED)


# === 1. 나누지 않으면 무슨 일이 일어나는가 ==================================
def probe(d_k, n=64, scale=True):
    """질의·키를 N(0,1)에서 뽑아 점수의 퍼짐과 소프트맥스의 쏠림을 잰다."""
    g = torch.Generator().manual_seed(SEED)
    q = torch.randn(n, d_k, generator=g)
    k = torch.randn(n, d_k, generator=g)
    s = q @ k.T
    if scale:
        s = s / (d_k ** 0.5)
    p = s.softmax(dim=-1)
    # 소프트맥스의 쏠림 — 최댓값과 엔트로피(고를 때가 log n)
    ent = -(p * p.clamp_min(1e-12).log()).sum(-1).mean() / torch.tensor(float(n)).log()
    # 그래디언트가 얼마나 남는가 — 소프트맥스 야코비안의 크기 대용
    gnorm = (p * (1 - p)).sum(-1).mean()
    return float(s.std()), float(p.max(-1).values.mean()), float(ent), float(gnorm)


# === 2. 멀티헤드를 손으로 짠다 ==============================================
def multihead_by_hand(x, mha):
    """nn.MultiheadAttention 이 하는 일을 식 그대로 다시 적는다.

    머리 h 개는 d_model 을 h 조각으로 나누어 「따로」 어텐션한 뒤 다시 잇는다.
    파라메터는 nn.MultiheadAttention 의 것을 그대로 빌려 와 값이 같은지 본다.
    """
    B, L, D = x.shape
    h = mha.num_heads
    dk = D // h
    # in_proj_weight 는 (3D, D) 로 Q·K·V 세 사영을 쌓아 둔 것이다
    W = mha.in_proj_weight
    b = mha.in_proj_bias
    q = x @ W[:D].T + b[:D]
    k = x @ W[D:2 * D].T + b[D:2 * D]
    v = x @ W[2 * D:].T + b[2 * D:]
    # (B, L, D) -> (B, h, L, dk) : 머리마다 따로 본다
    sp = lambda t: t.view(B, L, h, dk).transpose(1, 2)
    q, k, v = sp(q), sp(k), sp(v)
    att = (q @ k.transpose(-2, -1) / dk ** 0.5).softmax(-1)
    out = (att @ v).transpose(1, 2).reshape(B, L, D)
    return mha.out_proj(out), att.mean(1)


if __name__ == "__main__":
    print("  === 1. sqrt(d_k) 로 나누지 않으면 ===")
    print(f"  {'d_k':>5}{'점수 std':>10}{'소프트맥스 최댓값':>14}{'엔트로피':>10}{'남은 기울기':>11}")
    for scale in (False, True):
        print(f"  -- {'나눈다' if scale else '안 나눈다'}")
        for d_k in (8, 32, 128, 512):
            s, mx, ent, gn = probe(d_k, scale=scale)
            print(f"  {d_k:5d}{s:10.2f}{mx:14.3f}{ent:10.3f}{gn:11.4f}")

    print("\n  === 2. 멀티헤드를 손으로 짜면 같은 값이 나오는가 ===")
    torch.manual_seed(SEED)
    B, L, D, H = 2, 7, 64, 8
    x = torch.randn(B, L, D)
    mha = nn.MultiheadAttention(D, H, batch_first=True)
    mha.eval()
    with torch.no_grad():
        ref, ref_w = mha(x, x, x, need_weights=True, average_attn_weights=True)
        mine, mine_w = multihead_by_hand(x, mha)
    print(f"  머리 {H}개, d_model {D} 이므로 머리마다 d_k = {D // H}")
    print(f"  출력 최대 차이   {float((ref - mine).abs().max()):.2e}")
    print(f"  어텐션 무게 차이 {float((ref_w - mine_w).abs().max()):.2e}")

    print("\n  === 3. 머리를 나누면 파라메터가 느는가 ===")
    for h in (1, 2, 4, 8, 16):
        m = nn.MultiheadAttention(D, h, batch_first=True)
        print(f"  머리 {h:2d}개  d_k = {D // h:2d}  파라메터 "
              f"{sum(p.numel() for p in m.parameters()):,}")

    # === 4. 같은 단어가 둘레에 따라 다른 벡터가 되는가 =====================
    # 6 장이 일곱 군데에서 「8 장이 이것을 고친다」고 적어 두었다. 그 말이
    # 무엇을 뜻하는지 여기서 수로 본다. 같은 star 를 둘레만 바꾸어 두 번
    # 넣는다 - 연예인 쪽과 하늘 쪽이다.
    print("\n  === 4. 같은 단어, 다른 둘레 ===")
    vocab = ["star", "movie", "actor", "sky", "night", "bright", "the", "was"]
    torch.manual_seed(SEED)
    E = torch.randn(len(vocab), D)             # 단어 임베딩 표 (학습 전)
    ix = {w: i for i, w in enumerate(vocab)}
    SENT_A = ["star", "movie", "actor", "the", "was", "the"]
    SENT_B = ["star", "sky", "night", "bright", "the", "was"]
    xa = E[[ix[w] for w in SENT_A]].unsqueeze(0)
    xb = E[[ix[w] for w in SENT_B]].unsqueeze(0)
    cos = lambda u, v: float(F.cosine_similarity(u.flatten(), v.flatten(), 0))

    print(f"  A: {' '.join(SENT_A)}")
    print(f"  B: {' '.join(SENT_B)}")
    print(f"  어텐션 앞 star(A)-star(B) 코사인  {cos(xa[0, 0], xb[0, 0]):.6f}"
          f"   <- 같은 표에서 꺼낸 같은 줄")
    with torch.no_grad():
        oa, wa = multihead_by_hand(xa, mha)
        ob, wb = multihead_by_hand(xb, mha)
    print(f"  어텐션 뒤 star(A)-star(B) 코사인  {cos(oa[0, 0], ob[0, 0]):.6f}"
          f"   <- 둘레가 섞여 들어갔다")
    print(f"  star 가 제 자신에게 준 무게   A {float(wa[0, 0, 0]):.3f}  "
          f"B {float(wb[0, 0, 0]):.3f}")
    print(f"  곧 벡터의 {1 - float(wa[0, 0, 0]):.0%} 가량이 둘레에서 온다")
```

## 2. 나누지 않으면 소프트맥스가 굳는다

| $d_k$ | 점수 std | 소프트맥스 최댓값 | 엔트로피 | 남은 기울기 |
|---|---|---|---|---|
| 8 | 2.86 | 0.426 | 0.489 | 0.7176 |
| 32 | 5.63 | 0.684 | 0.229 | 0.4331 |
| 128 | 11.67 | 0.902 | 0.068 | 0.1455 |
| 512 | **23.11** | **0.906** | **0.051** | **0.1269** |

**퍼짐이 $\sqrt{d_k}$를 따라간다.** $d_k$를 8에서 512로 64배 키웠더니 점수의 표준편차가 2.86에서 23.11로 **8.08배**가 되었다. $\sqrt{64} = 8$이니 식 그대로다.

까닭은 간단하다. $q$와 $k$의 각 성분이 평균 0, 분산 1이고 서로 독립이면, 내적 $q \cdot k = \sum_{i=1}^{d_k} q_i k_i$는 **분산이 $d_k$**다. 표준편차는 $\sqrt{d_k}$가 된다. 그래서 $\sqrt{d_k}$로 나누면 다시 1이 된다.

**그 퍼짐이 소프트맥스를 굳힌다.** 엔트로피가 0.489에서 0.051로 떨어진다 — 고르게 퍼지면 1, 한 칸에 몰리면 0인 자다. $d_k = 512$에서는 **64개 칸 가운데 사실상 하나만 본다.**

마지막 칸이 논문이 말한 바로 그것이다. 「남은 기울기」는 소프트맥스가 제 입력에 대해 얼마나 반응하는지를 $\sum_j p_j(1 - p_j)$로 잰 것인데, 0.7176에서 **0.1269**로 떨어진다. $p$가 0이나 1에 붙으면 $p(1-p)$가 0에 가까워지기 때문이다. **기울기가 거의 흐르지 않는다.**

### 나누면 $d_k$가 사라진다

| $d_k$ | 점수 std | 소프트맥스 최댓값 | 엔트로피 | 남은 기울기 |
|---|---|---|---|---|
| 8 | 1.01 | 0.103 | 0.889 | 0.9618 |
| 32 | 1.00 | 0.102 | 0.888 | 0.9620 |
| 128 | 1.03 | 0.120 | 0.877 | 0.9577 |
| 512 | 1.02 | 0.114 | 0.881 | 0.9595 |

**네 줄이 사실상 같다.** 이것이 그 나눗셈이 하는 일이다 — $d_k$를 바꾸어도 어텐션이 **같은 온도에서 시작하게** 만든다. 모델을 키울 때 따로 손볼 것이 없어진다.

「온도」라는 말을 쓴 것이 비유가 아니다. 소프트맥스에 넣기 전에 수를 나누는 이 연산을 **temperature**라 하고, [8.3절](03_sampling.md)이 글을 뽑을 때 같은 손잡이를 돌린다. 거기서는 $\sqrt{d_k}$ 대신 $T$라 적고 **골라서** 쓴다.

!!! warning "이 실험이 말해 주지 않는 것"
    여기서는 질의와 키를 $N(0, 1)$에서 **아무렇게나** 뽑았다. 학습된 모델에서는 그 둘이 독립이 아니고 분산도 1이 아니다. 그러니 위의 수는 **「왜 그렇게 설계했는가」를 보이는 것**이지, 학습 중에 실제로 그 값이 나온다는 뜻이 아니다.

    또 「남은 기울기」는 소프트맥스 한 단계만 본 대용값이다. 깊은 모델에서 실제로 기울기가 얼마나 흐르는지는 잔차 연결과 레이어 정규화까지 함께 보아야 한다.

## 3. 머리를 나누어도 파라메터가 늘지 않는다

머리가 여럿이라는 말은 **$d_{\text{model}}$을 $h$조각으로 쪼개 따로 어텐션한 뒤 다시 잇는다**는 뜻이다. 코드의 `multihead_by_hand`가 그 식을 그대로 적은 것이고, 파라메터는 `nn.MultiheadAttention`에서 빌려 왔다.

```
출력 최대 차이   1.19e-07
어텐션 무게 차이 2.98e-08
```

**같은 값이다.** $10^{-7}$ 수준의 차이는 부동소수점 반올림이다. 곧 `nn.MultiheadAttention` 안에는 특별한 것이 없고, 위 코드 열 줄이 그 전부다.

그리고 셋째 출력이 뜻밖이다.

| 머리 수 $h$ | 머리마다 $d_k$ | 파라메터 |
|---|---|---|
| 1 | 64 | 16,640 |
| 2 | 32 | 16,640 |
| 4 | 16 | 16,640 |
| 8 | 8 | 16,640 |
| 16 | 4 | 16,640 |

**하나도 늘지 않는다.** 머리를 열여섯으로 쪼개도 파라메터가 그대로다. 쪼개는 것이 **웨이트를 더 두는 일이 아니라 같은 웨이트를 다르게 묶어 읽는 일**이기 때문이다. $Q$·$K$·$V$ 사영은 $d_{\text{model}} \times d_{\text{model}}$ 한 장이고, 머리는 그 결과를 $h$조각으로 잘라 볼 뿐이다.

그래서 머리를 늘리는 데 드는 값은 파라메터가 아니라 **머리마다의 $d_k$가 작아지는 것**이다. 위 표에서 $h = 16$이면 $d_k = 4$인데, 네 개짜리 벡터로 닮음을 재는 것은 거칠다. 논문이 $d_{\text{model}} = 512$에 $h = 8$을 골라 $d_k = 64$를 지킨 것이 그 맞바꿈이다.

## 4. 6장이 넘긴 것을 여기서 받는다

[6장](../embeddings/index.md)은 세 가지 길로 단어 벡터를 만들어 놓고 셋이 **같은 자리에서** 막힌다고 적었다 — **단어 하나에 벡터가 하나**라 `bank`가 강둑인지 은행인지 가리지 못한다. 그리고 「8장이 그것을 고친다. 거기서는 단어의 벡터가 **그 문장 안에서** 만들어진다」고 넘겼다.

그 말이 무엇을 뜻하는지 출력 4부가 수로 보인다. 같은 `star`를 둘레만 바꾸어 두 번 넣었다.

```
A: star movie actor the was the        (연예인 쪽)
B: star sky   night bright the was     (하늘 쪽)
```

| | `star(A)`와 `star(B)`의 코사인 |
|---|---|
| 어텐션 **앞** | **1.000000** |
| 어텐션 **뒤** | **0.703399** |

**앞은 정확히 1이다.** 단어 임베딩 표에서 같은 줄을 꺼냈으니 그럴 수밖에 없다. 6장이 만든 것이 바로 그 표이고, 그 표만으로는 두 `star`를 구별할 길이 **원리적으로** 없다.

**뒤는 0.7034다.** 무엇이 끼어들었는가. 어텐션이 `star` 자리에 내놓는 것은 제 벡터가 아니라 **문장 안 모든 단어의 값을 무게 주어 섞은 것**이기 때문이다. 그 무게를 찍어 보면

| | `star`가 제 자신에게 준 무게 |
|---|---|
| A | 0.167 |
| B | 0.177 |

**여덟 자리 가운데 제 몫이 6분의 1뿐이다.** 나머지 **83%**가 둘레에서 온다. 둘레가 다르면 섞이는 것이 다르고, 그래서 같은 단어가 다른 벡터가 된다. **고르거나 운이 좋아서가 아니라 식이 그렇게 생겼다.**

!!! warning "이것은 「된다」이지 「잘 된다」가 아니다"
    위의 두 수는 **학습하기 전** 웨이트에서 나왔다. 그러니 보인 것은 **구조가 문맥 의존을 보장한다**는 것까지이고, 그 차이가 **쓸모 있는** 차이인지는 다른 물음이다.

    쓸모는 학습이 정하고, 그 답은 7장에 이미 있다. [7.5절](../imdb/05_attention.md)에서 어텐션은 86.11%로 LSTM의 81.51%를 크게 이겼고 스프레드도 0.33 대 4.74였다. 다만 그 쪽은 **단어 벡터를 그냥 평균 낸 87.03%를 넘지는 못했다.** 문맥을 보는 것이 공짜로 이기지는 않는다.

    그리고 6장의 `bank`를 이 쪽이 실제로 갈랐다고 말할 수도 없다. 그것을 보이려면 두 뜻이 다 들어 있는 말뭉치에서 학습해 **뜻별로 갈라지는지**를 재야 하는데, 이 쪽은 그 실험을 하지 않았다.

---

## 5. 7장으로 돌아가 보면

[7.6절](../imdb/06_transformer.md)이 쓴 설정은 $d_{\text{model}} = 64$에 머리 4개였다. 그러니 머리마다 $d_k = 16$이고, 점수는 $\sqrt{16} = 4$로 나뉘고 있었다. 우리가 적지 않았을 뿐 `nn.MultiheadAttention`이 안에서 하고 있던 일이다.

이 쪽이 더한 것은 성능이 아니라 **그 안이 보이게 된 것**이다. 다음 쪽부터는 이 블록을 가지고 **글을 지어내는** 쪽으로 간다. 거기서 하나가 더 필요해진다 — 지어낼 때는 **아직 쓰지 않은 단어를 미리 보면 안 되기** 때문이다.

## 연습문제

<div class="drillbox" markdown>

**연습문제 1.** <span class="diff easy" title="쉬움"></span> 성분이 평균 0, 분산 1이고 서로 독립일 때 내적 $q \cdot k$의 분산이 $d_k$임을 보이라.

</div>

??? success "풀이"

    $q \cdot k = \sum_{i=1}^{d_k} q_i k_i$이고 항들이 서로 독립이므로 분산이 더해진다.

    항 하나의 분산은 $\operatorname{Var}(q_i k_i) = \mathbb{E}[q_i^2 k_i^2] - (\mathbb{E}[q_i k_i])^2$다. $q_i$와 $k_i$가 독립이고 평균이 0이므로 $\mathbb{E}[q_i k_i] = 0$이고, $\mathbb{E}[q_i^2 k_i^2] = \mathbb{E}[q_i^2]\,\mathbb{E}[k_i^2] = 1 \cdot 1 = 1$이다.

    따라서 항마다 분산이 1이고, $d_k$개를 더하면 $d_k$다. 표준편차는 $\sqrt{d_k}$이므로 그것으로 나누면 1로 돌아온다. 출력의 「점수 std」 줄이 2.86·5.63·11.67·23.11로 $\sqrt{8}=2.83$, $\sqrt{32}=5.66$, $\sqrt{128}=11.31$, $\sqrt{512}=22.63$에 가까운 것이 이 셈이다.

<div class="drillbox" markdown>

**연습문제 2.** <span class="diff med" title="중간"></span> 3절은 머리를 늘려도 파라메터가 늘지 않음을 보였다. 그렇다면 **셈의 양**은 어떤가. 머리 수 $h$를 바꿀 때 어텐션 한 번에 드는 곱셈 횟수가 어떻게 달라지는지 따지라.

</div>

??? success "풀이"

    길이 $n$, $d_{\text{model}} = d$라 하자. 점수 행렬은 머리마다 $n \times n$이고 각 칸이 $d_k = d/h$번의 곱셈이므로, 머리 하나에 $n^2 d / h$다. 머리가 $h$개이니 합하면 $n^2 d$로 **$h$가 사라진다.**

    무게를 값에 곱하는 쪽도 같다. 머리마다 $n^2 d_v = n^2 d / h$이고 $h$개를 합하면 $n^2 d$다. 사영 세 장과 출력 사영도 $h$와 무관하다.

    곧 **파라메터도 셈도 머리 수에 거의 영향받지 않는다.** 달라지는 것은 그 셈을 **어떻게 나누어 보느냐**뿐이다. 머리를 늘리면 서로 다른 관계를 동시에 볼 수 있지만, 머리마다 쓰는 벡터가 짧아져 하나하나는 거칠어진다.

<div class="drillbox" markdown>

**연습문제 3.** <span class="diff hard" title="어려움"></span> 2절의 실험은 질의와 키를 $N(0, 1)$에서 뽑았다. **학습된 모델**에서 실제로 점수의 퍼짐이 얼마인지 재는 실험을 설계하라. 무엇을 자로 쓰고, $\sqrt{d_k}$ 나눗셈을 **뺐을 때** 무엇이 달라지는지 어떻게 확인하겠는가.

</div>

??? success "풀이"

    [7.6절](../imdb/06_transformer.md)의 모델을 두 벌 학습한다. 하나는 그대로, 하나는 어텐션에서 $\sqrt{d_k}$ 나눗셈을 뺀 것이다(`nn.MultiheadAttention` 대신 이 쪽의 `multihead_by_hand`를 쓰되 `/ dk ** 0.5`를 지운다). **바꾸는 것은 그 하나뿐이어야 한다.**

    잴 것은 셋이다. **(가)** 학습이 끝난 뒤 시험 묶음을 흘려 보내며 소프트맥스 **이전** 점수의 표준편차와 소프트맥스 **이후** 엔트로피를 쌓는다. **(나)** 학습 곡선 — 나눗셈을 뺀 쪽이 늦게 출발하거나 아예 못 내려가는지. **(다)** 최종 정확도.

    주의할 것이 하나 있다. [7장이 되풀이해 말하듯](../imdb/04_lstm.md) **시드 하나로는 판정할 수 없다.** 특히 학습이 불안정해지는 쪽을 보려는 것이므로 시드 다섯 벌을 돌려 **스프레드까지** 보아야 한다. 평균만 보면 「조금 나쁘다」로 보일 것이 실은 「가끔 아예 안 된다」일 수 있다.

    $d_{\text{model}} = 64$, 머리 4개라 $d_k = 16$이고 $\sqrt{16} = 4$다. 2절의 표로 보면 $d_k = 16$은 8과 32 사이라 쏠림이 아주 심한 자리는 아니다. **그래서 차이가 안 나올 수도 있다** — 그러면 그것이 답이고, 나눗셈이 중요해지는 것은 $d_k$가 더 클 때라는 뜻이 된다.
