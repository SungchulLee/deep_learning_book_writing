# 8.4 규모를 키우면 — 그리고 이 장이 멈추는 자리

<div class="leadbox" markdown>

**들어가는 이야기** — 크게 만들면 정말 나아지는가

[7장](../imdb/index.md)은 「더 정교한 것이 더 낫지 않다」로 끝났다. 트랜스포머가 단어 벡터 평균을 넘지 못했다.

그런데 세상은 트랜스포머를 쓴다. 무엇이 다른가. 답의 하나가 **규모**다. 그러면 물어야 한다 — **크게 만들면 정말 나아지는가, 그리고 어떤 형태로 나아지는가.**

[앞의 두 쪽](02_masking.md)이 지은 모델을 크기만 바꾸어 세 벌 트레인했다. 데이터도 스텝 수도 러닝레이트도 그대로다. 표의 **퍼플렉서티**는 $e^{\text{로스}}$로, 모델이 다음 글자를 평균 몇 가지 가운데서 고르는 셈인지를 나타낸다. **일반화 격차**는 시험 로스에서 트레인 로스를 뺀 값이다.

| 파라메터 | 시험 로스 | 퍼플렉서티 | 일반화 격차 |
|---|---|---|---|
| 75,968 | 2.30 | 10.0 | **0.00** |
| 262,656 | 1.86 | 6.4 | 0.01 |
| **1,412,544** | **1.59** | **4.9** | **0.02** |

**19배 키우니 퍼플렉서티가 10.0에서 4.9로 줄었다.** 「다음 글자를 열 가지로 좁혔다」가 「다섯 가지로 좁혔다」가 된 것이다.

그런데 **개선 폭이 줄어든다.** 3.5배 키울 때 로스가 0.44 내려갔는데 그다음 5.4배에서는 0.27이다. 그리고 **일반화 격차가 0.00에서 0.02로** 벌어진다 — 모델이 커질수록 트레인 데이터에만 맞는 것을 배우기 시작한다는, **과적합**(overfitting)의 첫 신호다.

이 쪽은 그 둘을 보이고 **멈춘다.** 여기서부터는 데이터도 함께 키워야 하는데, 그 이야기는 [24장](../ch23/index.md)의 몫이다.

</div>

## 1. 코드

```python
"""8.4 규모를 키우면 — 같은 데이터, 같은 스텝 수, 크기만 바꾼다.

8.2 가 지은 GPT 를 크기만 바꾸어 세 벌 트레인한다. 바꾸는 것은 d_model 과
블록 수와 헤드 수뿐이고 데이터·스텝 수·러닝레이트는 그대로다.

이 쪽이 묻는 것은 하나다 — 「크게 만들면 정말 나아지는가, 그리고 어떤
형태로 나아지는가.」 24장이 다루는 스케일링 법칙의 가장 작은 판이다.

로스는 글자 하나를 맞히는 교차 엔트로피이고, 이 쪽은 그것을 「퍼플렉서티」
(perplexity = exp(loss)) 로도 적는다. 「다음 글자를 몇 가지로 좁혔는가」로
읽히는 수다. 아무것도 모르면 글자 가짓수와 같고, 완벽하면 1 이다.

**자릿수에 대하여** — 애플 MPS 는 비트 단위로 결정적이지 않다. 같은 시드
같은 코드를 다시 돌려도 로스의 넷째 자리가 흔들린다. 그래서 이 쪽은
**다시 돌려도 재현되는 자리까지만** 적는다(로스 둘째 자리). 마지막에
같은 설정을 세 번 돌려 그 자리가 정말 흔들리지 않는지 확인한다.

실행: 이 쪽의 코드를 파일로 갈무리해 저장소 뿌리에서 돌린다.
"""
import math
import re
from pathlib import Path

import torch
import torch.nn as nn
import torch.nn.functional as F

SEED, CTX, BATCH, STEPS, LR = 42, 128, 64, 3000, 3e-4
ROOT = Path("./data/aclImdb")
device = torch.device("mps" if torch.backends.mps.is_available() else "cpu")

# 더 큰 설정 둘(288/블록 4개, 384/블록 6개)도 재었는데 **다시 돌리면 둘째
# 자리가 달라졌다.** 블록이 많을수록 MPS 의 비결정성이 쌓이기 때문이다.
# 재현되지 않는 줄을 싣지 않으려고 뺐다 - 그 이야기는 쪽 본문에 적어 두었다.
SIZES = [("아주 작게", 64, 1, 2), ("작게", 96, 2, 3), ("가운데", 192, 3, 4)]


def load_text(split, n_docs=4000):
    out = []
    for name in ("pos", "neg"):
        for f in sorted((ROOT / split / name).glob("*.txt"))[: n_docs // 2]:
            t = f.read_text(encoding="utf-8").replace("<br />", " ")
            out.append(re.sub(r"\s+", " ", t).strip())
    return "\n".join(out)


train_text, test_text = load_text("train"), load_text("test", 400)
chars = sorted(set(train_text))
stoi = {c: i for i, c in enumerate(chars)}
V = len(chars)
enc = lambda s: torch.tensor([stoi[c] for c in s if c in stoi], dtype=torch.long)
Xtr, Xte = enc(train_text), enc(test_text)


class Block(nn.Module):
    def __init__(self, d, h):
        super().__init__()
        self.attn = nn.MultiheadAttention(d, h, batch_first=True)
        self.n1, self.n2 = nn.LayerNorm(d), nn.LayerNorm(d)
        self.ff = nn.Sequential(nn.Linear(d, 4 * d), nn.GELU(), nn.Linear(4 * d, d))

    def forward(self, x, m):
        q = self.n1(x)
        a, _ = self.attn(q, q, q, attn_mask=m, need_weights=False)
        x = x + a
        return x + self.ff(self.n2(x))


class TinyGPT(nn.Module):
    def __init__(self, v, d, n, h):
        super().__init__()
        self.tok = nn.Embedding(v, d)
        self.pos = nn.Parameter(torch.zeros(1, CTX, d))
        self.blocks = nn.ModuleList([Block(d, h) for _ in range(n)])
        self.nf = nn.LayerNorm(d)
        self.head = nn.Linear(d, v, bias=False)

    def forward(self, idx):
        L = idx.size(1)
        m = torch.triu(torch.full((L, L), float("-inf"), device=idx.device), 1)
        x = self.tok(idx) + self.pos[:, :L]
        for b in self.blocks:
            x = b(x, m)
        return self.head(self.nf(x))


def batch(data, g):
    i = torch.randint(len(data) - CTX - 1, (BATCH,), generator=g)
    x = torch.stack([data[j:j + CTX] for j in i])
    y = torch.stack([data[j + 1:j + CTX + 1] for j in i])
    return x.to(device), y.to(device)


@torch.no_grad()
def eval_loss(m, data):
    g = torch.Generator().manual_seed(0)
    return sum(float(F.cross_entropy(m(x).reshape(-1, V), y.reshape(-1)))
               for x, y in (batch(data, g) for _ in range(40))) / 40


def run(d, n, h):
    torch.manual_seed(SEED)
    m = TinyGPT(V, d, n, h).to(device)
    opt = torch.optim.AdamW(m.parameters(), lr=LR)
    g = torch.Generator().manual_seed(SEED)
    m.train()
    for _ in range(STEPS):
        x, y = batch(Xtr, g)
        loss = F.cross_entropy(m(x).reshape(-1, V), y.reshape(-1))
        opt.zero_grad(); loss.backward(); opt.step()
    m.eval()
    return sum(p.numel() for p in m.parameters()), eval_loss(m, Xtr), eval_loss(m, Xte)


if __name__ == "__main__":
    print(f"  글자 {V}가지 · 같은 데이터 · 같은 {STEPS}스텝 · 같은 러닝레이트\n")
    print(f"  {'':10s}{'d_model':>9}{'블록':>4}{'헤드':>5}{'파라메터':>12}"
          f"{'트레인':>8}{'시험':>8}{'퍼플렉서티':>12}{'격차':>10}")
    for tag, d, n, h in SIZES:
        npar, ltr, lte = run(d, n, h)
        print(f"  {tag:10s}{d:9d}{n:4d}{h:5d}{npar:12,}{ltr:8.2f}{lte:8.2f}"
              f"{math.exp(lte):12.1f}{lte - ltr:10.2f}", flush=True)
    print(f"\n  아무것도 모를 때의 퍼플렉서티 = 글자 가짓수 = {V}")

    # 둘째 자리가 정말 흔들리지 않는지 같은 설정을 세 번 돌려 확인한다
    print("\n  같은 설정(d_model 96, 블록 2개)을 세 번 돌리면 — 시험 로스")
    vals = [round(run(96, 2, 3)[2], 2) for _ in range(3)]
    print(f"    {vals}   모두 같은가: {len(set(vals)) == 1}")
```

**출력:**

```
  글자 138가지 · 같은 데이터 · 같은 3000스텝 · 같은 러닝레이트

              d_model  블록   헤드        파라메터     트레인      시험       퍼플렉서티        격차
  아주 작게            64   1    2      75,968    2.30    2.30        10.0      0.00
  작게               96   2    3     262,656    1.85    1.86         6.4      0.01
  가운데             192   3    4   1,412,544    1.57    1.59         4.9      0.02

  아무것도 모를 때의 퍼플렉서티 = 글자 가짓수 = 138

  같은 설정(d_model 96, 블록 2개)을 세 번 돌리면 — 시험 로스
    [1.86, 1.86, 1.86]   모두 같은가: True
```

!!! warning "왜 소수 둘째 자리까지만 적는가"
    로스를 넷째 자리까지 적으면 **다시 돌릴 때 그 자리가 달라진다.** 이 쪽의 코드는 애플 GPU 백엔드인 MPS에서 도는데, MPS의 연산은 비트 단위로 결정적이지 않다.

    같은 시드 같은 코드로 d_model 96짜리를 세 번 돌려 보면 시험 로스가 **1.8624 · 1.8625 · 1.8627**이었다. 넷째 자리가 흔들린다.

    그래서 이 쪽은 **다시 돌려도 재현되는 자리까지만** 적는다. 출력의 마지막 두 줄이 그 확인이다 — 같은 설정을 세 번 돌려 둘째 자리에서 모두 `1.86`이 나온다.

    [8.2절](02_masking.md)이 같은 설정에서 시험 로스 1.5902를 적었고 이 쪽의 가운데 줄이 **1.59**다. 둘째 자리에서 맞는다.

    **크기를 둘 뺀 까닭도 같다.** $d_{\text{model}}$ 288에 블록 4개, 384에 블록 6개짜리도 함께 재었다. 둘 다 일반화 격차가 더 벌어진 값을 주었지만(0.04와 0.07) **다시 돌리니 둘째 자리가 달라졌다.** 블록이 많을수록 비결정성이 쌓이기 때문이다.

    그래서 이 쪽은 **세 크기만 싣는다.** 큰 쪽의 수가 더 흥미로웠지만, 재현되지 않는 줄은 이 책이 싣지 않는다. 코드의 `SIZES` 주석에 그대로 적어 두었다.

## 2. 커질수록 나아진다

| | 파라메터 | 트레인 | 시험 | 퍼플렉서티 | 격차 |
|---|---|---|---|---|---|
| 아주 작게 | 75,968 | 2.30 | 2.30 | 10.0 | 0.00 |
| 작게 | 262,656 | 1.85 | 1.86 | 6.4 | 0.01 |
| 가운데 | 1,412,544 | 1.57 | **1.59** | **4.9** | **0.02** |

**세 줄이 모두 같은 방향이다.** 커질수록 나아진다. 아무것도 모를 때의 퍼플렉서티가 138이니, 가장 작은 것도 이미 열 가지로 좁혔고 가장 큰 것은 다섯 가지쯤으로 좁혔다.

**어떤 함수 형태로 나아지는지는 이 표로 말할 수 없다.** 큰 언어 모델에서 관찰된 **스케일링 법칙**(scaling law)은 로스가 파라메터 수 $N$의 거듭제곱 $L \propto N^{-\alpha}$로 줄어든다는 것이다. 그것이 맞으면 $\log N$을 가로축, $\log L$을 세로축으로 그렸을 때 점들이 기울기 $-\alpha$인 직선 위에 놓인다. 표의 세 점으로 이웃한 두 구간의 기울기를 따로 구하면 이렇다.

| 구간 | $\Delta \log L \,/\, \Delta \log N$ |
|---|---|
| 76k → 263k | $\log(1.86/2.30) \,/\, \log(262{,}656/75{,}968) = -0.17$ |
| 263k → 1.41M | $\log(1.59/1.86) \,/\, \log(1{,}412{,}544/262{,}656) = -0.09$ |

**두 기울기가 두 배 가까이 다르다.** 세 점이 한 직선 위에 있지 않다. 그렇다고 거듭제곱 법칙을 반박한 것도 아니다. 그 법칙은 보통 더 줄일 수 없는 로스를 뺀 나머지에 대해 세우는데 이 쪽은 그 값을 모르고, 세 모델을 모두 3,000스텝에서 끊었으니 큰 모델일수록 덜 수렴했을 수도 있다. **점 셋으로는 직선인지조차 가릴 수 없으므로 $\alpha$를 적지 않는다.** 크기를 자릿수 여러 개에 걸쳐 바꿔 가며 재는 일은 [24.3절](../ch23/index.md)이 다룬다.

## 3. 그런데 개선 폭이 줄고 일반화 격차가 벌어진다

| 키운 배수 | 로스가 내려간 폭 |
|---|---|
| 3.5배 (76k → 263k) | **−0.44** |
| 5.4배 (263k → 1.41M) | **−0.27** |

**같은 개선에 드는 파라메터가 늘어난다.** 더 크게 키웠는데(3.5배 → 5.4배) 로스가 내려간 폭은 오히려 줄었다(0.44 → 0.27). 그리고 시험 로스에서 트레인 로스를 뺀 **일반화 격차**(generalization gap)가 이렇게 벌어진다.

| 파라메터 | 트레인 | 시험 | 일반화 격차 |
|---|---|---|---|
| 75,968 | 2.30 | 2.30 | **0.00** |
| 262,656 | 1.85 | 1.86 | 0.01 |
| 1,412,544 | 1.57 | 1.59 | **0.02** |

**가장 작은 것은 0.00이고 가장 큰 것은 0.02다.** 더 큰 설정 둘에서는 이 격차가 0.04와 0.07까지 벌어지는 것을 보았는데, 1절의 경고 상자에 적은 까닭으로 그 줄은 싣지 않았다.

일반화 격차가 0이라는 것은 모델이 트레인 데이터에서 배운 것이 처음 보는 글에도 그대로 통한다는 뜻이다. 격차가 벌어진다는 것은 트레인 데이터에만 맞는 것 — 영화평 4,000편에 나온 특정 구절 — 을 배우기 시작했다는 뜻이고, 이것이 **과적합**이다. 3,000스텝에 배치 64개, 길이 128이면 모델이 본 글자가 약 2,460만 개로, 트레인 데이터 512만 글자를 평균 **4.8번** 본 셈이다. 같은 글을 같은 횟수만큼 보았는데 큰 모델만 격차를 보인다. 용량이 클수록 본 것을 더 많이 기억할 수 있기 때문이다.

**다만 0.02는 작은 값이고, 시험 로스는 세 크기 모두에서 내려가고 있다.** 이 표가 보인 것은 「모델만 키우면 과적합 쪽으로 간다」는 **방향**까지다. 어느 크기에서 시험 로스가 다시 오르기 시작하는지는 이 쪽이 재지 않았다. 데이터를 고정하고 모델만 계속 키우면 격차가 더 벌어질 것이므로 다음에 키울 것은 모델이 아니라 **데이터**이고, 실제 대규모 언어 모델(LLM)이 책 수백만 권 분량의 글로 트레인하는 까닭이 그것이다.

## 4. 이 장이 멈추는 자리

여기까지가 이 장이 재어서 말할 수 있는 것이다. 정리하면 넷이다.

**하나.** $\sqrt{d_k}$ 나눗셈은 장식이 아니다. 빼면 $d_k$가 커질수록 소프트맥스가 포화하고 그래디언트가 5분의 1 아래로 준다([8.1절](01_scaled_attention.md)).

**둘.** 인과 마스크는 모델을 약하게 만드는 제약이 아니라 **트레인할 때와 생성할 때의 조건을 맞추는 장치**다. 빼면 모델이 뒤쪽 글자에 의존하게 되고(마스크를 걸면 로스 +0.63), 생성할 때 무너진다([8.2절](02_masking.md)).

**셋.** 디코딩 방법이 결과를 바꾼다. 모델이 가장 믿는 것만 고르면 **가장 나쁜 글**이 나오고, 모델에게 채점시키면 그 글이 1등이 된다([8.3절](03_sampling.md)).

**넷.** 크게 만들면 나아지지만 **개선 폭은 줄어들고**, 데이터를 고정하면 일반화 격차가 벌어지기 시작한다(이 쪽). 그리고 **다시 돌리면 달라지는 자릿수까지 적으면 안 된다** — 이 쪽은 그것 때문에 자릿수를 줄였다.

### 다루지 못한 것

이 장은 아주 작은 모델을 지었다. 논문의 base 모델이 6,500만 개인데 여기서 가장 큰 것이 141만 개이고, 글자 단위이며, 영화평 4,000편만 읽었다. 그래서 **닿지 못한 것**이 많다.

## 연습문제

<div class="drillbox" markdown>

**연습문제 1.** <span class="diff easy" title="쉬움"></span> 퍼플렉서티(perplexity)가 4.9라는 것은 무슨 뜻인가. 138과 1은 각각 어떤 모델인가.

</div>

??? success "풀이"

    퍼플렉서티는 $e^{\text{로스}}$이고, **「다음 글자를 몇 가지로 좁혔는가」**로 읽는다. 4.9면 138가지 가운데 평균 다섯 가지쯤으로 좁혔다는 뜻이다.

    **138**은 아무것도 모르는 모델이다. 138가지에 균등하게 확률을 주면 로스가 $\log 138 = 4.927$이고 $e^{4.927} = 138$이다. **1**은 완벽한 모델로, 다음 글자에 확률 1을 주어 로스가 0이다.

    다만 글자 단위라는 점을 잊으면 안 된다. 단어 단위 모델의 퍼플렉서티와 직접 견줄 수 없다 — [8.2절 연습문제 3](02_masking.md)이 그 이야기를 한다.

<div class="drillbox" markdown>

**연습문제 2.** <span class="diff med" title="중간"></span> 3절은 데이터를 고정한 채 모델만 키웠다. **데이터를 함께 키우면** 일반화 격차가 어떻게 될지 예상하고, 그것을 확인하는 실험을 설계하라.

</div>

??? success "풀이"

    **예상** — 일반화 격차가 줄어든다. 격차는 모델이 트레인 데이터의 세부를 기억할 수 있을 때 생기는데, 데이터가 많아지면 기억할 것이 많아져 같은 용량으로는 다 기억하기 어려워진다.

    **설계** — 이 쪽의 세 크기를 그대로 두고, 트레인 데이터를 4,000편·8,000편·2만 5천 편(전체)으로 바꾸어 각각 돌린다. 3 × 3 = 9벌이다. 표의 칸마다 트레인·시험 로스와 일반화 격차를 적는다.

    **읽는 법** — 세로로 읽으면 데이터가 같을 때 크기의 효과이고, 가로로 읽으면 크기가 같을 때 데이터의 효과다. 예상이 맞으면 오른쪽으로 갈수록 격차가 줄고, 특히 **큰 모델에서 더 많이 줄어야 한다.**

    주의할 것 — 스텝 수를 고정하면 데이터가 많아질 때 **각 글자를 보는 횟수**(에포크 수)가 줄어든다. 「데이터가 많아서」와 「덜 반복해 보아서」의 효과가 섞이므로, 에포크 수를 맞추든 스텝을 맞추든 **무엇을 고정했는지 적어야** 한다.

<div class="drillbox" markdown>

**연습문제 3.** <span class="diff hard" title="어려움"></span> 2절은 점이 셋이라 거듭제곱 지수 $\alpha$(로그-로그 그림의 기울기)를 적지 않았다. **$\alpha$를 적으려면 무엇이 더 있어야 하는가.** 갖추어야 할 것을 셋 들고, 그 가운데 가장 싸게 마련할 수 있는 것을 하나 골라 설계하라.

</div>

??? success "풀이"

    **모자란 것 셋.**

    1. **점이 더 있어야 한다.** 셋으로는 점들이 직선에서 벗어났을 때 그것이 함수 형태 때문인지 측정의 변동 때문인지 가릴 수 없다. 자릿수 서너 개에 걸쳐 예닐곱 점은 있어야 한다.
    2. **시드가 하나다.** 크기를 바꿀 때마다 웨이트의 초기값도 바뀌는데 그에 따른 변동을 재지 않았다. [7장](../imdb/04_lstm.md)이 보인 대로 시드에 따른 변동은 모델 사이의 작은 차이보다 클 수 있다.
    3. **d_model·블록 수·헤드 수를 한꺼번에 바꾸며 키웠다.** 그래서 「파라메터 수」 하나로 축을 삼은 것이 옳은지 알 수 없다. 같은 파라메터 수를 넓게(d_model 크게, 블록 적게) 또는 깊게 만들면 다른 값이 나올 수 있다.

    **가장 싼 확인은 둘째다.** 가운데 크기 하나만 골라 시드를 다섯 개로 다시 트레인하면 된다. 세 벌 전체를 다시 돌리는 것의 3분의 1 값이다. 거기서 나온 스프레드가 표의 이웃 줄 사이의 차이(예: 1.86과 1.59의 0.27)보다 크면 **그 표로는 기울기를 말할 수 없다.**

    셋째를 확인하려면 같은 파라메터 수로 「넓게」와 「깊게」 두 벌을 더 지어 비교하면 된다. 그것이 다르면 축을 파라메터 수가 아니라 다른 것으로 잡아야 한다.
