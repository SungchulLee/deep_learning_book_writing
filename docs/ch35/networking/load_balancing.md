# 짐 고르기

한 서비스개가 감당할 수 있는 것보다 많은 요청이 얼개에 들어오면 **짐 고르개**가 들어오는 오감을 여러 뒤편 서비스개에 나눈다. 나름을 가장 크게 하고, 답하는 때를 가장 짧게 하며, 어느 서비스개에도 짐이 넘치지 않게 하는 것이 뜻이다. 짐 고르기 알고리즘은 돌아가며 주기 같은 단순한 붙박이 방침에서 그때그때 서비스개의 몸 상태를 보고 맞추어 가는 꾀까지 갖가지다.

---

## 1. 문제 세우기

담는 크기가 $c_1, c_2, \ldots, c_n$인 서비스개 $n$개와 짐이 $w_1, w_2, \ldots$인 요청 줄기가 주어졌을 때, 요청마다 서비스개를 매겨 **가장 큰 짐**(마침 때)을 가장 작게 하라.

$$
\min \max_{j=1}^{n} \sum_{i \in S_j} w_i
$$

여기서 $S_j$은 서비스개 $j$에 매긴 요청의 모임이다. 이는 여러 다룸꾼 차례 잡기 문제와 같고 두루 보아 NP 어려움이므로, 참으로 쓰는 짐 고르개는 어림 방침을 쓴다.

---

## 2. 붙박이 알고리즘

### 돌아가며 주기

요청을 고리 차례로 서비스개에 매긴다. 요청 $i$은 서비스개 $(i \bmod n)$으로 간다.

- **때 복잡도**: 요청마다 $O(1)$.
- **나은 점**: 단순하고 지닐 상태가 없다.
- **나쁜 점**: 서비스개의 짐과 요청의 무게를 살피지 않으므로, 일감이 고르지 않으면 짐이 기운다.

### 짐 실은 돌아가며 주기

담는 크기에 비례해 서비스개에 짐 $c_1, \ldots, c_n$을 매긴다. 서비스개 $j$은 돌이마다 요청 $c_j$개를 받는다.

$$
\text{서비스개 } j \text{로 가는 오감의 몫} = \frac{c_j}{\sum_{k=1}^{n} c_k}
$$

### 해시 바탕

요청 열쇠(보기로 손님 IP, 자리 번호)를 해시해 서비스개를 고른다.

$$
\text{서비스개}(r) = h(r) \bmod n
$$

이렇게 하면 같은 손님이 늘 같은 서비스개에 닿지만(자리 붙임), 서비스개를 붙이거나 떼면 거의 모든 열쇠가 다시 매겨진다.

!!! tip "한결같은 해시"
    한결같은 해시는 서비스개와 열쇠를 모두 크기 $2^{32}$인 고리에 앉힌다. 그래서 서비스개를 붙이거나 떼도 고르게 $O(K/n)$개의 열쇠만 다시 매겨진다($K$은 온 열쇠의 수). 흩은 캐시와 CDN 여럿의 밑바탕이다.

---

## 3. 움직이는 알고리즘

### 가장 적은 이음

새 요청마다 살아 있는 이음이 가장 적은 서비스개로 보낸다.

$$
\text{서비스개}^* = \arg\min_{j=1}^{n} \text{살아 있는 이음}_j
$$

요청마다 걸리는 때가 들쭉날쭉해도 맞추어 가므로 HTTP 짐 고르개에서 널리 쓴다.

### 짐 실은 가장 적은 이음

담는 크기 짐과 이음 세개를 함께 쓴다.

$$
\text{서비스개}^* = \arg\min_{j=1}^{n} \frac{\text{살아 있는 이음}_j}{c_j}
$$

담는 크기 짐이 큰 서비스개는 "짐이 찼다"고 여겨지기까지 더 많은 이음을 받아 낸다.

### 가장 빠른 답

요즘 고르게 답하는 때가 가장 짧은 서비스개로 보내어 쓰는 이의 겪음을 곧바로 다듬는다. 서비스개마다의 늦음을 좇는 지켜보기 얼개가 있어야 한다.

---

## 4. 둘 가운데 고르기의 힘

아무렇게나 하는 짐 고르기에서 이름난 열매가 있다. 요청마다 아무 서비스개 하나에 매기는 대신 **서비스개 둘을 아무렇게나 골라** 짐이 덜한 쪽으로 보내는 것이다.

서비스개 $n$개에 요청 $m = n$개면(서비스개마다 고르게 하나씩), 아주 아무렇게나 매길 때 가장 큰 짐은 다음과 같다.

$$
\Theta\!\left(\frac{\log n}{\log \log n}\right)
$$

둘 가운데 고르는 꾀를 쓰면 가장 큰 짐이 곱절꼴로 떨어져 다음이 된다.

$$
\frac{\log \log n}{\log 2} + O(1)
$$

속뜻은 이렇다. 아주 아무렇게나 매기면 운 나쁘게 겹친 것이 가장 짐이 무거운 서비스개에 쌓인다. 둘 가운데 고르면 알고리즘이 짐이 더 무거운 쪽을 피하므로 쌓임이 자라지 않는다. 이 곱절꼴 나아짐에 드는 값은 요청마다 한 번 더 더듬는 것뿐이라 셈에 들 것이 없다.

---

## 5. 몸 살피기

짐 고르개는 성치 않은 서비스개를 가려내 빼야 한다.

- **살아 있는 살핌**: 이따금 더듬는 요청을 보낸다(HTTP GET, TCP SYN).
- **가만한 살핌**: 참 오감의 답 부호와 늦음을 지켜본다.
- **끊는 개**: 잇달아 $k$번 어긋나면 서비스개를 빼고, 나으면 도로 넣는다.

## 6. 짜보기

```python
"""
짐 고르기 -- 돌아가며 주기, 가장 적은 이음, 둘 가운데 고르기.

여러 짐 고르기 꾀를 흉내내고 서비스개마다 쌓인 짐의 퍼짐을
견준다.
"""

import random

# === 돌아가며 주기 ==========================================================

class RoundRobinBalancer:
    """서비스개를 차례대로 돈다."""

    def __init__(self, n_servers: int):
        self.n_servers = n_servers
        self.counter = 0

    def select(self) -> int:
        """다음 서비스개 번호를 내놓는다."""
        server = self.counter % self.n_servers
        self.counter += 1
        return server

# === 가장 적은 이음 =========================================================

class LeastConnectionsBalancer:
    """살아 있는 이음이 가장 적은 서비스개로 보낸다."""

    def __init__(self, n_servers: int):
        self.n_servers = n_servers
        self.active = [0] * n_servers

    def select(self) -> int:
        """살아 있는 이음이 가장 적은 서비스개를 내놓는다."""
        server = min(range(self.n_servers), key=lambda j: self.active[j])
        self.active[server] += 1
        return server

    def release(self, server: int) -> None:
        """이음 하나가 끝났다고 적는다."""
        self.active[server] -= 1

# === 둘 가운데 고르기 =======================================================

class TwoChoiceBalancer:
    """서비스개 둘을 아무렇게나 골라 짐이 덜한 쪽으로 보낸다."""

    def __init__(self, n_servers: int):
        self.n_servers = n_servers
        self.load = [0] * n_servers

    def select(self) -> int:
        """아무렇게나 고른 서비스개 둘 가운데 짐이 덜한 쪽을 내놓는다."""
        a, b = random.sample(range(self.n_servers), 2)
        server = a if self.load[a] <= self.load[b] else b
        self.load[server] += 1
        return server

# === 흉내내기 ===============================================================

def simulate(balancer, n_requests: int, n_servers: int) -> list[int]:
    """흉내내기를 돌리고 서비스개마다의 요청 수를 내놓는다."""
    counts = [0] * n_servers
    for _ in range(n_requests):
        server = balancer.select()
        counts[server] += 1
    return counts

# === 메인 ===================================================================

if __name__ == "__main__":
    random.seed(42)
    n_servers = 10
    n_requests = 10000

    for name, balancer in [
        ("돌아가며 주기", RoundRobinBalancer(n_servers)),
        ("가장 적은 이음", LeastConnectionsBalancer(n_servers)),
        ("둘 가운데 고르기", TwoChoiceBalancer(n_servers)),
    ]:
        counts = simulate(balancer, n_requests, n_servers)
        max_load = max(counts)
        min_load = min(counts)
        print(f"{name:20s}  가장 큼={max_load}  가장 작음={min_load}  "
              f"기움={max_load - min_load}")
```

## 연습문제

**연습문제 1.**
돌아가며 주기, 가장 적은 이음, 한결같은 해시 짐 고르기 꾀를 견주어라. 저마다 어떤 일감 결에 알맞은가?

??? success "연습문제 1 풀이"
    **돌아가며 주기**: 요청을 고리처럼 돌려 서비스개에 나눈다. 단순하고 상태가 없으며 $O(1)$이다. 요청마다 다루는 때가 한결같고 서비스개가 다 같을 때 가장 낫다. 요청마다 값이 크게 다르면 무너진다(어떤 서비스개는 비싼 요청을 받는데 노는 서비스개는 기다린다). **가장 적은 이음**: 살아 있는 이음이 가장 적은 서비스개로 보낸다. 요청 값이 들쭉날쭉해도 맞추어 간다. 요청 길이가 들쭉날쭉한 뒤섞인 일감(보기로 데이터베이스 물음 대 붙박이 두루마리 내주기)에 가장 낫다. 이음 세개를 좇아야 한다(가장 작은 것이 위로 오는 더미를 쓰면 $O(1)$). **한결같은 해시**: 요청 열쇠를 해시해 고리의 자리로 옮기고 가장 가까운 서비스개로 보낸다. 자리 붙임을 주고(같은 이가 늘 같은 서비스개에 닿는다) 서비스개가 드나들 때 흔들림이 가장 적다. 캐시와 상태를 지니는 서비스에 가장 낫다. $\square$

**연습문제 2.**
서비스개마다 헛 마디 $k$개를 두는 한결같은 해시가 서비스개 $n$개 사이에서 짐 기움 인자 $O(\log n / k)$을 이룬다는 것을 밝혀라.

??? success "연습문제 2 풀이"
    서비스개마다 헛 마디가 $k$개면 해시 고리에 모두 $kn$개의 마디가 있다. 서비스개마다 고리에서 차지하는 몫은 $kn$개 가운데 $k$개의 활 남짓이다. 공을 그릇에 던지는 셈(요청마다 아무 자리에나 해시되는 "공")으로 보면 서비스개마다 바라는 짐은 온 짐의 $1/n$이다. 체르노프 울타리로 보면 가장 큰 짐은 큰 참일 값으로 온 짐의 많아야 $(1 + \sqrt{c \ln(n)/k}) / n$이고 $c$은 어떤 붙박이 수다. 기움 비(가장 큰 짐 / 고른 짐)는 $1 + O(\sqrt{\ln n / k})$이다. $k = O(\log n)$이면 기움 인자가 붙박이가 된다. 서비스개마다 헛 마디를 $k = 100$~$200$개 두고 서비스개가 $n = 100$개면 가장 큰 짐이 고른 값의 $\sim$10\% 안에 든다. $\square$

**연습문제 3.**
짐 고르개가 서비스개 10개로 오감을 보낸다. 그 가운데 하나가 나머지보다 두 곱절 빠르다. 짐 실은 돌아가며 주기를 어떻게 맞추어야 하며 그 열매로 짐이 어떻게 퍼지는가?

??? success "연습문제 3 풀이"
    빠른 서비스개에 짐 2을, 여느 서비스개 9개에 저마다 짐 1을 매긴다. 온 짐은 $2 + 9 \times 1 = 11$이다. 빠른 서비스개가 오감의 $2/11 \approx 18.2\%$을, 여느 서비스개가 저마다 $1/11 \approx 9.1\%$을 받는다. 짐 실은 돌아가며 주기에서 요청 11개짜리 돌이 하나는 빠른 서비스개에 2개를, 나머지에 저마다 1개를 보낸다. 요청마다 다루는 때가 한결같으면 빠른 서비스개가 여느 서비스개가 1개를 마치는 때에 2개를 마치므로 모든 서비스개가 함께 끝난다. 빠른 서비스개가 같은 때에 두 곱절의 요청을 다루면, 짐을 싣지 않은 돌아가며 주기(빠른 서비스개를 덜 쓰는)에 견주어 나름이 $1/11 \approx 9\%$ 는다. $\square$

**연습문제 4.**
"둘 가운데 고르기의 힘" 짐 고르기 꾀를 밝히고, 아무렇게나 매기는 것에 견주어 왜 가장 큰 짐을 크게 줄이는지 밝혀라.

??? success "연습문제 4 풀이"
    요청마다 아무 서비스개 하나로 해시하는 대신 서비스개 둘을 고루 아무렇게나 뽑아 짐이 덜한 쪽으로 보낸다. 살핌(Azar 외, 1999)에 따르면 서비스개 $n$개에 요청 $n$개일 때 아무렇게나 매기면 가장 큰 짐이 $\Theta(\log n / \log \log n)$이다. 둘 가운데 고르면 가장 큰 짐이 $\Theta(\log \log n)$으로 떨어지니 곱절꼴로 나아진 것이다. 속뜻은 둘째 고를 거리가 짐이 넘친 서비스개에서 빠져나갈 길을 준다는 데 있다. 요청마다 여전히 아무렇게나 하더라도 짐이 더 무거운 쪽을 피할 수 있으므로 짐이 쌓이지 않는다. 1에서 2로 늘릴 때 얻는 것이 가장 크고, 더 늘려도(3, 4, ...) 붙박이 곱만큼만 나아진다. 지닐 상태가 아주 적고(지금 짐 세개만 있으면 된다) 거의 가장 좋은 고름을 이루므로 널리 쓴다. $\square$

**연습문제 5.**
어느 금융 거래소가 서비스개 50개로 초마다 주문 1000만 건을 다룬다. 같은 종목의 주문이 차례대로 다뤄지도록(주문 장부가 어긋나지 않도록) 하는 짐 고르기 얼개를 꾸며라.

??? success "연습문제 5 풀이"
    **열쇠 바탕 보내기**(나누기)를 쓴다. 종목 이름표를 해시해 서비스개를 고른다. 종목 $I$의 주문은 모두 서비스개 $h(I) \bmod 50$으로 간다. 이러면 종목마다 차례대로 다뤄지면서(주문이 서비스개 하나에 그물 차례대로 온다) 서로 다른 종목은 여러 서비스개에 흩어진다. 걸림돌은 이렇다. (1) 사람이 몰리는 종목(보기로 AAPL, SPY)은 짐을 서비스개 하나에 몰아넣는다. 뜨거운 종목을 서비스개 안에서 여러 "나눔"으로 쪼개 안쪽 줄을 두어 눅인다. (2) 서비스개가 무너질 때는 한결같은 해시를 써서 무너진 서비스개의 종목만 이웃에 다시 흩어지게 한다. (3) 짐이 기울면 서비스개마다의 나름을 지켜보고 종목-서비스개 짝지음을 그때그때 다시 고르며, 찬 종목을 뜨거운 서비스개에서 찬 서비스개로 옮긴다. 종목마다의 차례가 옳음의 요건인 거래소 짝짓기 엔진(보기로 LMAX, 나스닥)에서 여느 얼개다. $\square$
