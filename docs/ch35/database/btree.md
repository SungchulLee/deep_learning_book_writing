# B 나무 색인

데이터베이스 시스템은 으뜸 기억에 담기지 않을 만큼 많은 자료를 갈무리하므로, 물음마다 끝내 원반에서 쪽을 읽어야 한다. 원반에 아무렇게나 한 번 닿는 데 CPU 걸음이 수백만 번 드니 들고남 횟수가 판치는 비용이다. B 나무는 **넓고 얕은 나무**를 써서 이 비용을 가장 작게 한다. 마디마다 원반 쪽 하나를 꽉 채워 나무 높이를, 따라서 찾기마다의 들고남 횟수를 아주 작게 지킨다. 이것이 B 나무가 40년 넘게 관계형 데이터베이스의 기본 색인 얼개인 까닭이다.

## 들고남 모형

바깥 기억(들고남) 모형에서 자료는 크기 $B$인 쪽 단위로 원반과 기억 사이를 오간다. 알고리즘의 비용은 CPU 연산이 아니라 쪽 옮김 횟수로 잰다.

차수(가장 작은 갈래 수)가 $t$인 B 나무에서 속마디마다 열쇠를 $t - 1$개에서 $2t - 1$개까지 갈무리하고 자식을 $t$개에서 $2t$개까지 지닌다. 열쇠가 $n$개면 나무 높이가 다음을 채운다.

$$
h \leq \log_t \frac{n + 1}{2}
$$

흔한 데이터베이스 쪽은 4~16 KB이고 열쇠와 손가락질이 저마다 20바이트쯤 쓰므로 $t$이 수백이 될 수 있다. $t = 500$이고 $n = 10^9$이면 높이가 많아야 $\log_{500}(5 \times 10^8) \approx 3.2$이므로, 아무 열쇠나 원반 읽기 네 번 안에 찾는다.

## B 나무 마디의 얼개

마디마다 다음을 담는다.

- 매긴 차례의 열쇠 $k$개: $\text{열쇠}_1 < \text{열쇠}_2 < \cdots < \text{열쇠}_k$
- 자식 손가락질 $k + 1$개: 자식 $i$은 $\text{열쇠}_i$과 $\text{열쇠}_{i+1}$ 사이의 열쇠를 지닌 밑나무로 이어진다
- 이 마디가 잎인지 알리는 깃발

온 잎이 같은 깊이에 놓여 한결같은 됨됨이가 보장된다.

## 연산과 들고남 복잡도

| 연산 | 들고남 | CPU 때 |
|-----------|------|----------|
| 찾기 | $O(\log_t n)$ | $O(\log n)$ |
| 넣기 | $O(\log_t n)$ | $O(t \log_t n)$ |
| 지우기 | $O(\log_t n)$ | $O(t \log_t n)$ |
| 범위 물음(열매 $k$개) | $O(\log_t n + k/B)$ | $O(\log n + k)$ |

종요로운 눈길은 열 억 줄짜리 표에서 $\log_t n$이 흔히 3~4라는 것이다. 이진 나무의 $\log_2 n \approx 30$과 견주어 보라.

## 찾기

뿌리에서 시작해 열쇠 $k$을 찾으려면:

1. 지금 마디 안에서 $k$을 그 마디의 열쇠 가운데 두 갈래로 찾는다.
2. 찾으면 그에 딸린 값을 돌려준다.
3. 찾지 못하면 $k$을 사이에 끼고 있는 두 열쇠 사이의 자식 손가락질을 따라간다.
4. 잎에 이를 때까지 되풀이한다.

걸음마다 마디 하나(원반 쪽 하나)를 읽으므로 온 들고남 비용이 나무 높이와 같다.

## 앞질러 쪼개며 넣기

B 나무는 넣는 동안 되짚어 가지 않도록 **앞질러 쪼개기**를 쓴다.

1. 뿌리에서 알맞은 잎 쪽으로 걸어간다.
2. 길에서 **꽉 찬 마디**($2t - 1$개 열쇠)를 만나면 그 안으로 내려가기 앞서 곧바로 쪼갠다.
3. (이제 꽉 차지 않은) 잎에 열쇠를 넣는다.

꽉 찬 마디를 쪼개면 저마다 $t - 1$개 열쇠를 지닌 마디 둘이 나오고 가운뎃값 열쇠가 어버이로 올라간다. 어버이가 꽉 차지 않음이 보장되어 있으므로(필요하면 앞서 쪼갰다) 올려 보내기가 늘 이루어진다.

이 위에서 아래로 가는 길은 많아야 $O(\log_t n)$번 쪼개며 아래로 한 번만 지나간다.

## 데이터베이스의 B+ 나무

거의 모든 데이터베이스 시스템은 **B+ 나무**라는 갈래를 쓴다.

- 온 자료 기록(또는 그 손가락질)이 **잎 마디**에만 놓인다.
- 속마디는 열쇠와 자식 손가락질만 갈무리해 갈래 수를 가장 크게 한다.
- 잎 마디가 **두 겹 이음 목록**으로 이어져 잇단 훑기와 범위 물음이 값싸다.

잎이 이어져 있으므로 `SELECT * FROM t WHERE x BETWEEN 100 AND 200` 같은 범위 물음은 시작점을 찾는 데 $O(\log_t n)$번 들고나고, 그다음에는 잎 사슬을 죽 훑는다. 열매를 얻는 데 아무 닿기가 하나도 없다.

## 적기 부풀림

!!! warning "고치는 비용"
    B 나무를 고칠 때마다 한 바이트만 바뀌어도 온 쪽 하나를 원반에 적는다. 작은 고침이 많은 일감에서 이 **적기 부풀림**은 대수롭다. 4 KB 쪽에 100바이트 기록을 담는 B 나무의 적기 부풀림 인자는 대략 40배다. 이것이 적기가 많은 일감에서 LSM 나무 바탕 곳간 엔진을 쓰는 까닭 가운데 하나다.

## 한꺼번에 쓰기

참 데이터베이스의 B 나무는 **빗장 게걸음**(빗장 잇기라고도 한다)으로 한꺼번에 닿기를 받쳐 준다.

1. 뿌리에 빗장을 얻는다.
2. 자식에 빗장을 얻는다.
3. 자식이 "안전"하면(넣기에서는 꽉 차지 않음, 지우기에서는 가장 적은 열쇠보다 많음) 어버이의 빗장을 놓는다.
4. 잎까지 되풀이한다.

이 규약은 한꺼번에 쥐는 빗장을 많아야 $O(\log_t n)$개로 지켜 온 세상 잠금을 비껴간다.

## 구현

```python
"""
B 나무 -- 찾기와 넣기를 기억 안에서 흉내 내기.

여러 갈래로 나뉘는 찾기와 앞질러 마디를 쪼개며 넣기라는 B 나무의
한가운데 연산을 보인다.
"""

# === B 나무 마디 ==============================================================

class BTreeNode:
    """가장 작은 차수가 t인 B 나무의 마디."""

    def __init__(self, t: int, leaf: bool = True):
        self.t = t
        self.leaf = leaf
        self.keys: list[int] = []
        self.children: list["BTreeNode"] = []


# === 찾기 =====================================================================

def btree_search(node: BTreeNode, key: int) -> bool:
    """B 나무에서 열쇠를 찾는다."""
    i = 0
    while i < len(node.keys) and key > node.keys[i]:
        i += 1
    if i < len(node.keys) and key == node.keys[i]:
        return True
    if node.leaf:
        return False
    return btree_search(node.children[i], key)


# === 자식 쪼개기 ==============================================================

def split_child(parent: BTreeNode, idx: int) -> None:
    """번호 idx의 꽉 찬 자식 마디를 쪼갠다."""
    t = parent.t
    full_child = parent.children[idx]
    new_node = BTreeNode(t, leaf=full_child.leaf)

    # 열쇠의 윗절반을 새 마디로 옮긴다
    new_node.keys = full_child.keys[t:]
    median = full_child.keys[t - 1]
    full_child.keys = full_child.keys[:t - 1]

    if not full_child.leaf:
        new_node.children = full_child.children[t:]
        full_child.children = full_child.children[:t]

    parent.children.insert(idx + 1, new_node)
    parent.keys.insert(idx, median)


# === 넣기 =====================================================================

def btree_insert(root: BTreeNode, key: int) -> BTreeNode:
    """앞질러 쪼개기로 열쇠를 넣는다."""
    t = root.t
    if len(root.keys) == 2 * t - 1:
        new_root = BTreeNode(t, leaf=False)
        new_root.children.append(root)
        split_child(new_root, 0)
        root = new_root

    node = root
    while not node.leaf:
        i = len(node.keys) - 1
        while i >= 0 and key < node.keys[i]:
            i -= 1
        i += 1
        if len(node.children[i].keys) == 2 * t - 1:
            split_child(node, i)
            if key > node.keys[i]:
                i += 1
        node = node.children[i]

    # 꽉 차지 않은 잎에 넣는다
    node.keys.append(key)
    node.keys.sort()
    return root


# === 메인 =====================================================================

if __name__ == "__main__":
    t = 2  # 가장 작은 차수(2-3-4 나무)
    root = BTreeNode(t)

    keys = [10, 20, 5, 6, 12, 30, 7, 17]
    for k in keys:
        root = btree_insert(root, k)
        print(f"Inserted {k:2d} -> root keys: {root.keys}")

    # 찾기 시험
    for k in [6, 15, 30]:
        found = btree_search(root, k)
        print(f"Search {k:2d}: {'found' if found else 'not found'}")
```

**출력:**
```
Inserted 10 -> root keys: [10]
Inserted 20 -> root keys: [10, 20]
Inserted  5 -> root keys: [5, 10, 20]
Inserted  6 -> root keys: [10]
Inserted 12 -> root keys: [10]
Inserted 30 -> root keys: [10]
Inserted  7 -> root keys: [10]
Inserted 17 -> root keys: [10]
Search  6: found
Search 15: not found
Search 30: found
```

## 연습문제

**연습문제 1.**
차수 $m = 200$인 B 나무가 기록 $10^8$개를 색인한다. 나무의 가장 큰 높이와 찾기마다의 가장 많은 원반 들고남 횟수를 셈하여라.

??? success "연습문제 1 풀이"
    차수 $m$인 B 나무는 마디마다 자식을 많아야 $m$개 지닌다. 속마디의 가장 적은 채움은 자식 $\lceil m/2 \rceil = 100$개다. 높이 $h$에서 열쇠의 최댓값은 $m^h - 1$이고 최솟값은 $2 \lceil m/2 \rceil^{h-1} - 1$이다. 열쇠가 $10^8$개면 $200^h \ge 10^8$에서 $h \ge \log_{200}(10^8) = 8 / \log_{10}(200) \approx 8 / 2.3 \approx 3.5$이므로 $h = 4$이다. 찾기는 많아야 마디 4개(뿌리에서 잎까지)를 지나므로 원반 들고남이 많아야 4번이다. (흔한 관행대로) 뿌리를 기억에 갈무리하면 3번으로 준다. 견주어 보면 이진 나무는 $\log_2(10^8) \approx 27$번 들고나야 한다. $\square$

**연습문제 2.**
B 나무와 B+ 나무의 다름을 풀어라. 거의 모든 데이터베이스 시스템이 B+ 나무를 쓰는 까닭은 무엇인가?

??? success "연습문제 2 풀이"
    **B 나무**에서는 마디마다 열쇠와 자료 손가락질(또는 값)을 함께 갈무리한다. **B+ 나무**에서는 잎 마디만 자료를 갈무리하고 속마디는 열쇠와 자식 손가락질만 지닌다. B+ 나무의 이로움은 둘이다. (1) 속마디가 (자료 손가락질이 없어) 더 작으므로 마디마다 열쇠가 더 들어가고, 갈래 수가 늘어 나무 높이가 준다. 4 KB 쪽이면 B+ 나무 속마디에 열쇠 500개가 들어갈 수 있고 B 나무에는 200개다. (2) 잎 마디가 두 겹 이음 목록으로 이어져 범위 훑기가 값싸다. 시작 열쇠를 찾은 뒤 속마디를 다시 들르지 않고 잎 손가락질을 죽 따라간다. B 나무는 속마디가 걸리는 가운데 먼저 훑기를 해야 한다. 범위 물음과 잇단 훑기가 흔하므로(보기로 `WHERE price BETWEEN 10 AND 50`) 거의 모든 데이터베이스가 B+ 나무를 쓴다. $\square$

**연습문제 3.**
마디가 넘칠 때의 B 나무 넣기 알고리즘을 밝혀라. 마디 쪼개기의 나눠 갚는 비용은 얼마인가?

??? success "연습문제 3 풀이"
    ($m - 1$개 열쇠를 담은) 꽉 찬 마디에 열쇠를 넣을 때: (1) 그 열쇠를 잠깐 마디에 넣는다(이제 $m$개). (2) 가운뎃값 열쇠에서 마디를 둘로 쪼갠다. 왼쪽 마디가 앞의 $\lfloor(m-1)/2\rfloor$개, 오른쪽이 뒤의 $\lfloor(m-1)/2\rfloor$개를 받고 가운뎃값 열쇠가 어버이로 올라간다. (3) 어버이가 넘치면 되돌아 들어가며 쪼갠다. 가장 나쁠 때 쪼개기가 뿌리까지 번져 나무 높이가 1 는다. 나눠 갚는 비용: 쪼갤 때마다 새 마디 하나와 어버이의 새 열쇠 하나가 생긴다. 쪼개기는 마디가 꽉 찼을 때에만 생기고, 꽉 찬 마디는 지난번 쪼개기(또는 만들어진 때) 뒤로 $\lceil m/2 \rceil$번 넣어져 찬 것이므로, 넣기마다 나눠 갚는 쪼개기 횟수가 $O(1/m)$이다. 넣기마다 나눠 갚는 원반 들고남 비용은 찾기에 $O(\log_m n)$, 쪼개기에 나눠 갚아 $O(1)$이다. $\square$

**연습문제 4.**
어떤 데이터베이스 표에 줄이 $10^7$개 있고 8바이트 열쇠를 지닌 칸에 B+ 나무 색인이 있다. 원반 쪽마다 8 KB이다. 잎 쪽 개수, 속쪽 개수, 나무 높이를 어림하여라.

??? success "연습문제 4 풀이"
    잎 쪽마다 열쇠-손가락질 짝을 갈무리한다. 8바이트 열쇠와 8바이트 손가락질이면 항목마다 16바이트다. 잎 쪽 용량: $8192 / 16 = 512$개. 잎 쪽 개수: $\lceil 10^7 / 512 \rceil = 19{,}532$개. 속마디는 열쇠와 자식 손가락질을 갈무리한다. 8바이트 열쇠와 8바이트 손가락질이면 속 항목마다 (대략) 16바이트이므로 속마디마다 자식이 약 512개다. 1켜(잎 위): $\lceil 19{,}532 / 512 \rceil = 39$개. 2켜: $\lceil 39 / 512 \rceil = 1$개(뿌리). 높이: 3(뿌리 + 속 1켜 + 잎). 온 속쪽: $39 + 1 = 40$개. 이는 기억에 넉넉히 들어간다(40쪽 × 8 KB = 320 KB). 속마디가 갈무리되어 있으므로 낱점 물음마다 원반 들고남이 1번이다. $\square$

**연습문제 5.**
적기가 90%이고 읽기가 10%인 일감에서 B 나무 색인과 LSM 나무를 견주어라. 어느 얼개가 나으며 그 까닭은 무엇인가?

??? success "연습문제 5 풀이"
    **B 나무 적기**: 넣거나 고칠 때마다 겨눈 잎 쪽을 읽고 고쳐 되적어야 하므로 적기마다 아무 들고남이 적어도 2번(읽기 + 적기)이다. 적기 부풀림은 어중간하다(적기마다 쪽 하나를 건드린다). **LSM 나무 적기**: 넣기가 기억 안 버퍼(memtable)로 간다. 꽉 차면 그 버퍼를 새 매긴 파일(SSTable)로 죽 이어 흘려보낸다. 잇단 적기는 굳은 원반에서든 SSD에서든 아무 적기보다 10~100배 빠르다. (뭉치기가 자료를 여러 번 되적으므로) 적기 부풀림은 더 크지만 들고남마다 잇달아 있다. 적기가 90%이면 잇단 들고남의 처리량이 아무 들고남보다 훨씬 높으므로 LSM 나무가 판친다. 적기가 많은 LSM 엔진(보기로 RocksDB)은 같은 기계에서 초당 10만 번 넘게 적을 수 있고 B 나무는 약 1만 번이다. 10%인 읽기는 값을 치른다. LSM 읽기는 여러 켜를 살펴야 할 수 있고(읽기 부풀림) B 나무 읽기는 늘 들고남 한 번이다. 이 일감에서는 적기의 이로움이 읽기의 벌보다 크다. $\square$
