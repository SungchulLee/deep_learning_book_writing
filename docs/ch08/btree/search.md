# B-트리의 찾기

[B-트리](definition.md)의 찾기는 이진 탐색 트리의 찾기를 여러 갈래로 넓힌 것이다. 노드마다 알고리즘이 열쇠를 $2t - 1$개까지 살펴 어느 자식 부분 트리로 내려갈지 가리며, 열쇠를 찾거나 맞는 것 없이 잎에 닿을 때까지 이를 되풀이한다. 최소 차수가 $t$인 B-트리의 높이가 $O(\log_t n)$이므로 찾기마다 많아야 노드 $O(\log_t n)$개를 건드리고, 디스크 기반 시스템에서는 그것이 곧 디스크 읽기 $O(\log_t n)$번이 된다.

---

## 1. 알고리즘

B-트리 노드 $x$과 찾기 열쇠 $k$이 주어졌을 때 다음과 같이 한다.

1. **노드 안에서 차례로 훑기:** $k \le x.key_i$인 가장 작은 색인 $i$을 찾는다.
2. $k = x.key_i$이면 열쇠를 찾았으므로 $(x, i)$을 돌려준다.
3. $x$이 잎이면 그 열쇠가 트리에 없으므로 `nil`을 돌려준다.
4. 그렇지 않으면 자식 $x.c_i$($x.key_{i-1}$과 $x.key_i$ 사이의 열쇠를 담은 부분 트리)으로 **재귀한다**.

노드마다의 찾기는 차례로 훑는 대신 **이진 탐색**을 쓸 수도 있어 노드당 일이 $O(t)$에서 $O(\log t)$으로 줄어든다.

---

## 2. 의사코드

```
B-TREE-SEARCH(x, k):
    i = 1
    while i <= x.n and k > x.key[i]:
        i = i + 1
    if i <= x.n and k == x.key[i]:
        return (x, i)                 # 자리 i에서 열쇠를 찾았다
    elif x.leaf:
        return nil                     # 열쇠가 트리에 없다
    else:
        DISK-READ(x.c[i])
        return B-TREE-SEARCH(x.c[i], k)
```

`DISK-READ` 호출은 자식 노드가 디스크에 있어 살펴보기 전에 메모리로 올려야 한다는 사실을 나타낸다.

??? example "t = 3인 B-트리에서 열쇠 14 찾기"
    ```
              [  8, 17  ]
             /     |      \
       [2,4,6]  [10,13,15]  [20,25]
    ```

    | 단계 | 노드 | 살펴본 열쇠 | 하는 일 |
    |------|------|---------------|--------|
    | 1 | 뿌리 | 8, 17 | $14 > 8$이고 $14 < 17$ → 가운데 자식으로 내려간다 |
    | 2 | [10,13,15] | 10, 13, 15 | $14 > 13$이고 $14 < 15$ → 내려가야 하지만 이것이 잎이다 |
    | 3 | — | — | 열쇠 14를 못 찾음 → `nil`을 돌려준다 |

---

## 3. 노드 안에서의 이진 탐색

$t$이 크면(디스크 기반 시스템에서는 수백에서 수천이다) 노드마다 열쇠 $O(t)$개를 차례로 훑는 것은 아깝다. 노드 안에서 이진 탐색을 하면 노드당 비교 횟수가 줄어든다.

$$
\text{Per-node cost: } O(\log(2t - 1)) = O(\log t)
$$

전체 찾기 시간은 다음과 같이 된다.

$$
O(\log_t n) \cdot O(\log t) = O(\log n)
$$

이는 전체 열쇠 비교 횟수가 균형 잡힌 이진 탐색 트리와 같음을 보여 준다. 그런데 **디스크 접근** 횟수는 $O(\log_t n)$으로 훨씬 적다.

---

## 4. 복잡도

| 지표 | 비용 |
|--------|------|
| 디스크 접근 | $O(\log_t n)$ |
| 열쇠 비교 (차례로 훑기) | $O(t \log_t n)$ |
| 열쇠 비교 (이진 탐색) | $O(\log n)$ |

!!! note "디스크 접근이 좌우한다"
    실제로 디스크 접근의 비용은 열쇠 비교의 CPU 비용을 압도한다. $t = 1000$이고 $n = 10^9$인 B-트리에서 찾기에는 디스크 읽기가 많아야 3번 든다. 노드 안의 $O(\log t)$ 이진 탐색은 전부 메모리에서 일어나며 밀리초 규모의 디스크 지연에 견주면 무시할 만하다.

---

## 5. 찾기와 순회

B-트리의 찾기는 뿌리에서 잎까지의 경로 하나를 따라가며 노드 $O(\log_t n)$개를 들른다. **범위 질의**나 **전체 순회**는 중위 걸음으로 노드 $O(n/t)$개를 모두 들른다. 정렬된 데이터의 범위 질의에는 [B+ 트리](b_plus.md)가 더 효율적인데, 잎 층의 연결 리스트가 내부 노드를 되짚지 않고 차례로 훑게 해 주기 때문이다.

## 연습문제

**연습문제 1.**
B-트리의 찾기의 균형 불변식을 밝히고 그것이 높이 $O(\log n)$을 보장함을 증명하라.

??? success "연습문제 1 풀이"
    각 구조의 불변식(균형 인수, 색의 성질, 차수 제약)이 경로 길이의 치우침을 묶는다. 높이의 한계는 그 불변식에서 따라 나온다. 트리의 층마다 (불변식이 정하는) 최소한의 노드가 있어야 하므로 전체 노드 수 $n$이 높이에 따라 지수적으로 늘고, 따라서 $h = O(\log n)$이다.

---

**연습문제 2.**
구조를 다시 짜야 하는(회전, 색 바꾸기, 쪼개기·합치기) 트리에서 B-트리의 찾기를 따라가라. 앞뒤의 상태를 보여라.

??? success "연습문제 2 풀이"
    이 쪽에서 설명한 재구성 상황을 일으키는 트리를 하나 만들어라. 어긋난 곳을 보이고, 어느 경우에 해당하는지 가리고, 고친 뒤, 불변식이 되살아났는지 확인하라.

---

**연습문제 3.**
B-트리의 찾기이(가) 구조를 다시 짜는 연산을 많아야 $O(\log n)$번 필요로 함을 증명하라.

??? success "연습문제 3 풀이"
    구조를 다시 짤 때마다 어긋난 곳이 뿌리에 한 층 가까워지거나 해소된다. 트리의 층이 $O(\log n)$개이므로 재구성은 많아야 $O(\log n)$번 필요하다. 레드-블랙 삽입 같은 연산에서는 회전 2번과 색 바꾸기 $O(\log n)$번이면 충분하다. $\square$

---

**연습문제 4.**
최악의 높이, 연산마다의 회전 횟수, 구현의 까다로움 면에서 B-트리의 찾기를 다른 균형 트리 구조와 견주어라.

??? success "연습문제 4 풀이"
    AVL은 높이가 $1.44\log n$ 이하이고 삭제마다 회전이 $O(\log n)$번까지 든다. 레드-블랙은 높이가 $2\log n$ 이하이고 연산마다 회전이 많아야 3번이다. B-트리는 높이가 $O(\log_B n)$이며 디스크 입출력에 맞추어져 있다. 스플레이 트리는 분할 상환으로 $O(\log n)$이지만 최악은 $O(n)$이다.
