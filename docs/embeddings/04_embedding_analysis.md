## 2. 논의

분석에는 단어와 행 인덱스의 대응, 학습된 임베딩 행렬, 비교할 단어 목록이 필요하다. 코사인 유사도는 방향을 비교하므로 벡터의 노름과는 다른 정보를 준다. 영벡터와 어휘 밖 단어의 처리 규칙을 정하고, 최근접 이웃 검색에서는 자기 자신을 후보에서 제외한다.

유추는 $v_b-v_a+v_c$와 가까운 단어를 찾는 방식으로 구성할 수 있다. 이는 모든 관계를 보존하는 대수 법칙이 아니며, 관계 종류와 평가 집합에 따라 성공률이 달라진다. 예시 몇 개를 골라 보여 주는 것과 전체 평가 성능을 구분한다.

임베딩 자체의 유사도·유추 평가는 과제 모델의 성능과 별개다. 실제 분류나 검색에서 쓸 표현이라면 해당 검증 과제에서도 평가한다. 학습 말뭉치의 바이어스와 빈도 차이, 다의어를 단일 벡터로 표현하는 한계도 함께 살펴야 한다.

**연습문제 4.** <span class="diff hard" title="어려움"></span>
아래의 테스트 코드 조각을 검토하라. 정의되지 않은 클래스와 잘못된 이름, 입력 모양 가정을 찾아 이 페이지의 실제 함수에 맞는 점검 항목을 제안하라.

</div>

??? success "풀이"
    아래 조각은 실제 실행 가능한 테스트가 아니다. 함수 이름과 모델 이름부터 이 예제에 맞게 작성해야 한다.
    ```python
    def test_embedding analysis():
        model = Embedding Analysis(...)
        # 보통의 입력
        assert model(normal_input).shape == expected_shape
        # 원소가 하나인 배치
        assert model(single_input).shape == (1, ...)
        # 큰 값 (넘침을 확인한다)
        out = model(torch.ones(...) * 1000)
        assert torch.isfinite(out).all()
        # 경사의 흐름
        out = model(normal_input)
        out.sum().backward()
        for p in model.parameters():
            assert p.grad is not None
    ```
    이 페이지는 완성된 사용자 정의 모델 클래스를 제공하지 않는다. 실제 함수의 입력·출력 모양, 허용 자료형, 유한한 값과 경사의 유무를 기준으로 검사한다. 빈 입력을 처리하는 방식은 연산마다 다르며, 무조건 정상적인 로스나 경사가 나와야 한다고 가정하지 않는다.

## 정리하며
