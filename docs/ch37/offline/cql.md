# 33.5.2 보수적 Q 학습(CQL)

---

## 1. 핵심 아이디어

**CQL**(Kumar et al., 2020)은 참 Q 값의 하한이 되는 *보수적인* Q 함수를 배워 오프라인 강화학습의 외삽 오차를 다룬다. 핵심 통찰은 분포 밖 액션을 막는 대신 모든 액션의 Q 값에 벌을 주고 데이터셋에 있는 액션의 Q 값에는 상을 주는 것이다.

---

## 2. 목표

CQL은 일반 벨먼 로스에 정칙화 항을 더한다:

$$\mathcal{L}_{\text{CQL}}(\theta) = \alpha \left(\mathbb{E}_{s \sim \mathcal{D}} \left[\log \sum_a \exp(Q_\theta(s, a))\right] - \mathbb{E}_{(s,a) \sim \mathcal{D}}[Q_\theta(s, a)]\right) + \frac{1}{2}\mathbb{E}_\mathcal{D}\left[(Q_\theta(s, a) - \hat{\mathcal{B}}^\pi Q_{\theta^-}(s, a))^2\right]$$

정칙화 항에는 항이 둘 있다:

1. **끌어내리기**: $\log \sum_a \exp(Q(s, a))$ — 모든 액션에 대한 소프트 최댓값(log-sum-exp)이라, Q 값을 모두 끌어내리되 큰 Q 값일수록 세게 끌어내린다
2. **밀어 올리기**: $-\mathbb{E}_{a \sim \mathcal{D}}[Q(s, a)]$ — 데이터셋에 있는 액션의 Q 값을 올린다

결과로 분포 안 액션의 Q 값은 대체로 맞고 분포 밖 액션의 Q 값은 보수적이 된다(비관적).

---

## 3. 변형

### CQL(H) — 엔트로피 정칙화
(위처럼) 로그-합-지수를 끌어내리기 항으로 쓴다. 로그-합-지수는 액션 분포 $\mu$ 에 대한 $\mathbb{E}_{a\sim\mu}[Q(s,a)] + \mathcal{H}(\mu)$ 의 최댓값과 같으므로, 끌어내리는 분포를 엔트로피 정칙화로 고른 것에 해당한다. 그 최대를 이루는 $\mu$ 는 $\exp Q(s, \cdot)$ 에 비례하는 소프트맥스 분포라, Q 값이 큰 액션일수록 더 세게 끌어내린다.

### CQL(ρ) — 폴리시 기반
엔트로피 대신 사전 분포 $\rho$ 와의 KL 발산으로 정칙화하면 끌어내리는 쪽의 분포가 $\rho$ 를 따른다. 간단히 적으면 다음과 같다:

$$\mathbb{E}_{a \sim \rho(a|s)}[Q(s, a)] - \mathbb{E}_{a \sim \hat{\pi}_\beta(a|s)}[Q(s, a)]$$

여기서 $\rho$ 는 직전 단계의 폴리시처럼 정해 둔 분포이고, $\hat{\pi}_\beta$ 는 데이터셋을 모은 행동 폴리시다.

---

## 4. 이론적 보장

CQL은 참 Q 함수의 하한을 준다:

$$Q^{\text{CQL}}(s, a) \leq Q^{\pi}(s, a) \quad \text{for all } (s, a)$$

이 점별 하한은 끌어내리기 항만 쓰고 $\alpha$ 가 충분히 클 때 높은 확률로 성립한다. 위의 목표처럼 밀어 올리기 항을 함께 쓰면 점별 하한은 더 이상 보장되지 않고, 대신 폴리시 아래의 기댓값, 곧 가치의 하한 $\mathbb{E}_{a\sim\pi}[Q^{\text{CQL}}(s, a)] \le V^\pi(s)$ 이 보장된다. 어느 쪽이든 이로써 $Q^{\text{CQL}}$ 에서 얻은 폴리시의 성능을 과대평가하지 않게 된다.

---

## 5. 이산 액션의 구현

이산 액션 공간에서 CQL은 간단하다:

```python
# 눌러 내리기: 모든 액션에 대한 log-sum-exp
logsumexp = torch.logsumexp(q_all_actions, dim=1).mean()

# 밀어 올리기: 자료 뭉치 액션의 Q 값
dataset_q = q_all_actions.gather(1, actions.unsqueeze(1)).squeeze(1).mean()

# CQL 다듬개
cql_loss = alpha * (logsumexp - dataset_q)

# 전체 로스 = CQL 다듬개 + 보통 벨먼 로스
total_loss = cql_loss + bellman_loss
```

---

## 6. 하이퍼파라미터

| 파라미터 | 흔한 값 | 메모 |
|-----------|---------|-------|
| $\alpha$ | 1.0~5.0 | 보수성 벌점의 웨이트. 클수록 더 보수적이다 |
| $\alpha$(자동 튜닝) | 라그랑주 | 타깃 Q 값 간격을 맞추도록 튜닝한다 |
| 러닝레이트 | $3 \times 10^{-4}$ | 오프라인 강화학습의 일반 값 |

---

## 7. 적응형 α(라그랑주)

CQL은 라그랑주 정식화로 $\alpha$ 를 자동으로 튜닝할 수 있다:

$$\alpha^* = \arg\min_{\alpha \geq 0} \alpha \cdot (\text{CQL regularizer} - \tau)$$

여기서 $\tau$ 는 정칙화 항이 넘지 않기를 바라는 문턱값이다. 실제로는 Q 에 대해서는 최소화하고 $\alpha \ge 0$ 에 대해서는 **최대화**하는 min–max 문제로 푼다. 정칙화 항이 $\tau$ 보다 크면 $\alpha$ 가 커져 보수성을 강화하고, $\tau$ 보다 작으면 $\alpha$ 가 0 쪽으로 줄어 지나치게 보수적이 되는 것을 막는다.

---

## 8. 금융 응용

CQL은 다음 까닭으로 금융 거래에 잘 맞는다:

- 지난 거래 데이터가 "오프라인 데이터셋"이다
- 보수적인 Q 값이 데이터가 뒷받침하지 않는 극단적 포지션을 잡지 못하게 막는다
- 하한 보장이 위험을 고려한 결정을 준다
- $\alpha$ 를 튜닝해 보수성의 정도(위험 감수 성향)를 조절할 수 있다

## 연습문제

<div class="drillbox" markdown>

**연습문제 1.** <span class="diff med" title="중간"></span>
액션이 둘인 상태 $s$ 에서 $Q(s, a_1) = q_1$, $Q(s, a_2) = q_2$ 이고 데이터셋에는 $(s, a_1)$ 만 있다고 하자. 「5. 이산 액션의 구현」의 `cql_loss`(배치 하나, $\alpha = 1$)를 $q_1, q_2$ 로 적고, 그 값이 늘 0 이상임을 보여라. $q_1$ 과 $q_2$ 에 대한 그래디언트를 구해, 경사 하강법 한 스텝이 두 Q 값을 각각 어느 쪽으로 움직이는지 설명하라.

</div>

??? success "풀이"
    `cql_loss` $= \log(e^{q_1} + e^{q_2}) - q_1 = \log(1 + e^{q_2 - q_1})$ 이고, 로그 안이 1 보다 크므로 늘 양수다. $q_2 \ll q_1$ 이면 0 에 가까워진다. 소프트맥스 확률 $p_i = e^{q_i}/(e^{q_1} + e^{q_2})$ 로 쓰면 $\partial/\partial q_1 = p_1 - 1 = -p_2$, $\partial/\partial q_2 = p_2$ 이다. 경사 하강법은 그래디언트 반대로 가므로 $q_1$ 은 $p_2$ 에 비례해 **올라가고**, 데이터에 없는 $q_2$ 는 $p_2$ 에 비례해 **내려간다**. $q_2$ 가 클수록($p_2$ 가 클수록) 두 힘이 모두 세진다. 곧 CQL 은 데이터 밖 행동의 Q 값이 데이터 안 행동보다 클 때 가장 강하게 작동하고, 이미 충분히 작으면 거의 손대지 않는다. 벨먼 로스는 데이터에 있는 $q_1$ 만 맞추므로, 이 정칙화가 없으면 $q_2$ 는 아무것도 붙들어 주지 않는 값으로 남는다. $\square$

<div class="drillbox" markdown>

**연습문제 2.** <span class="diff hard" title="어려움"></span>
「오프라인 강화학습의 기초」 쪽의 `train_offline_dqn` 에 「5. 이산 액션의 구현」의 CQL 항을 더하라. 그 쪽의 `collect_dataset` 으로 만든 expert 데이터셋과 random 데이터셋에서 $\alpha \in \{0, 1, 5\}$ 를 시드 여러 개로 트레인하고, 평가 리턴과 「데이터에 있는 행동의 Q − 데이터에 없는 행동의 Q」 평균을 보고하라. 오프라인 학습이므로 「둘레를 푸는 데 걸린 에피소드 수」는 뜻이 없다는 점에 주의한다.

</div>

??? success "풀이"
    `train_offline_dqn` 안에서 `q_net(s)` 의 전체 출력 `q_all` 을 받아 `alpha * (torch.logsumexp(q_all, 1).mean() - q.mean())` 을 벨먼 로스에 더하면 된다. $\alpha = 0$ 은 제약 없는 오프라인 DQN 그대로다. 오프라인 학습은 둘레와 주고받지 않으므로 트레인 곡선의 가로축은 에피소드가 아니라 **업데이트 스텝**이고, 일정 간격마다 그리디 폴리시를 둘레에서 평가해 세로축을 얻는다(실제 오프라인 설정이라면 이 평가조차 할 수 없다는 점을 적어 둔다). 보고할 것은 두 가지다. (가) 평가 리턴의 시드 평균과 표준편차, (나) Q 값 간격. $\alpha$ 가 커지면 간격이 양수 쪽으로 벌어져야 하고, 그것이 「데이터에 없는 행동을 믿지 않는다」는 뜻이다. expert 데이터처럼 덮음이 좁은 데이터에서 $\alpha > 0$ 의 이득이 크게 나타날 것으로 예상하지만, $\alpha$ 가 너무 크면 데이터의 행동을 그대로 따라 하는 행동 복제에 가까워져 random 데이터에서는 오히려 나빠질 수 있다. 시드 사이 흩어짐보다 작은 차이는 우열로 읽지 말고, 수치는 직접 잰 값을 적는다. $\square$

**연습문제 3.** <span class="diff med" title="중간"></span>
기본 오프라인 DQN 에 견주어 CQL 이 더하는 계산·메모리 오버헤드를 이산 액션과 연속 액션에서 각각 분석하라. 포지션을 몇 단계로 나눈 금융 거래 응용에서는 어느 쪽에 해당하는가?

</div>

??? success "풀이"
    이산 액션에서는 벨먼 로스를 계산하려고 이미 `q_net(s)` 로 모든 액션의 Q 값을 구해 두었으므로, CQL 항은 그 출력에 `logsumexp` 와 `gather` 를 한 번씩 더할 뿐이다. 샘플마다 $O(|\mathcal{A}|)$ 의 연산이고 추가 순전파도, 새 파라메터도 없다. 연속 액션에서는 $\log\sum_a \exp Q$ 를 적분으로 바꿔야 하므로, 균등 분포와 현재 폴리시에서 액션을 $N$ 개(흔히 10 개 안팎)씩 뽑아 중요도 가중치로 어림한다. 그만큼 Q 네트워크를 상태마다 $2N$ 번 더 평가해야 해서 업데이트 비용이 몇 배로 는다. $\alpha$ 를 자동으로 튜닝하면 라그랑주 승수 하나가 더 붙는다. 포지션을 「매수·보유·매도」나 몇 단계 크기로 나눈 거래 문제는 이산 액션이라 오버헤드가 거의 없으므로, 데이터 밖 포지션을 막는 이득을 사실상 공짜로 얻는다. $\square$

**연습문제 4.** <span class="diff med" title="중간"></span>
리워드 신호가 성기고(거래를 마칠 때만 실현되고) 지연되는 금융 거래 응용에 이 방법을 어떻게 맞출지 논하라.

</div>

??? success "풀이"
    성긴 리워드는 신용 할당을 어렵게 한다. 에이전트는 여러 스텝 전의 액션을 마지막에 생긴 이익이나 손실에 연결해야 한다. 해결책: (1) 최적 폴리시를 보존하면서 더 촘촘한 피드백을 주는 중간 신호(미실현 손익, 위험 지표)로 리워드 셰이핑, (2) 성긴 리워드를 더 효율적으로 뒤로 전파하는 멀티스텝 리턴, (3) 지난 경험에 실제로 이룬 결과로 새 레이블을 붙이는 사후 경험 리플레이(hindsight experience replay). CQL 자체는 신용 할당을 돕지 않으므로 (2)의 멀티스텝 타깃을 벨먼 로스 쪽에 그대로 붙여 쓸 수 있다. CQL 이 맡는 몫은 다른 데 있다. 리워드가 성기면 대부분의 전이에서 타깃이 부트스트랩 값뿐이라, 데이터 밖 행동의 Q 값이 낙관적으로 외삽되면 그것이 막을 것 없이 번진다. CQL 은 그런 Q 값을 끌어내려 지난 거래 기록에 없던 극단적 포지션을 고르지 않게 한다. $\square$
