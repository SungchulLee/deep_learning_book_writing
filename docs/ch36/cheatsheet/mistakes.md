# 흔한 잘못

솜씨 좋은 짓는 이도 때에 쫓기며 알고리즘을 짤 때는 늘 같은 잘못을 저지른다.
이 쪽은 가장 잦은 잘못을 모으고, 왜 생기는지 밝히고, 손에 잡히는 고침을 준다.
겨루기나 면담에 앞서 이 결을 훑어보면 벌레잡는 때가 크게 줄어든다.

## 하나 어긋나는 잘못

하나 어긋나는 잘못은 다른 어떤 벌레보다 많은 틀린 답을 낳는다. 끝을 넣을지 뺄지,
0부터 셀지 1부터 셀지 헷갈려서 생긴다.

| 잘못 | 틀림 | 옳음 | 까닭 |
|---|---|---|---|
| 돌기 끝(0부터 셀 때) | `for i in range(1, n)` | `for i in range(n)` | 번호 0을 놓친다 |
| 돌기 끝(끝을 넣을 때) | `for i in range(l, r)` | `for i in range(l, r + 1)` | 마지막 원소를 놓친다 |
| 이진 찾기의 mid | `mid = (lo + hi) / 2` | `mid = lo + (hi - lo) // 2` | 넘침도 막는다 |
| 부분 글자열 길이 | `s[i:j]`의 길이가 `j - i + 1` | 길이는 `j - i` | 파이썬 저미기는 끝을 뺀다 |
| 배열 자리 잡기 | `int arr[n]` | `int arr[n + 1]` | 갈피 다지기는 번호 $n$이 필요할 때가 많다 |

!!! warning "이진 찾기의 끝없는 돌기"
    가장 왼쪽이나 오른쪽 원소를 찾을 때 `lo < hi`인지 `lo <= hi`인지,
    `mid = lo + (hi - lo) // 2`인지 `mid = lo + (hi - lo + 1) // 2`인지를
    올바로 짝지어야 한다. 어긋나면 크기 2인 배열에서 끝없이 돈다.

## 옹근수 넘침

너비가 붙박인 옹근수를 쓰는 말(C, C++, 자바)은 가운데 셈이 그 갈래의 너비를
넘으면 소리 없이 넘친다.

| 연산 | 무릅씀 | 안전한 갈음 |
|---|---|---|
| $a, b \le 10^9$일 때 $a + b$ | 32비트 넘침 | `long long`(64비트)을 쓴다 |
| $a, b \le 10^9$일 때 $a \times b$ | 64비트도 넘칠 수 있다 | `__int128`이나 나머지 셈을 쓴다 |
| $n \ge 21$일 때 $n!$ | 64비트를 넘는다 | 나머지 계승을 쓴다 |
| 원소 $n$개의 합 | $n \times \max > 2^{63}$이면 넘친다 | 64비트로 쌓는다 |

파이썬은 옹근수가 얼마든지 커질 수 있어 넘침 걱정이 없다. 다만 빠듯한 돌기에서
파이썬의 큰 옹근수를 쓰면 너비 붙박이 셈보다 느리다.

## 밑자리를 잊음

되돌이와 갈피 다지기 풀이에는 또렷한 밑자리가 있어야 한다. 잊으면 되돌이가 끝나지
않거나 답이 틀린다.

| 알고리즘 | 흔히 잊는 밑자리 | 나오는 탈 |
|---|---|---|
| 이진 찾기 | 빈 너비($lo > hi$) | 끝없는 돌기나 자리 어긋남 |
| 깊이/너비 먼저 훑기 | 들렀는지 살피기 | 맴돌이 있는 그래프에서 끝없이 돈다 |
| 갈피 다지기(갈무리) | $dp[0]$이나 $dp[1]$ 첫자리 잡기 | 틀린 값이 퍼진다 |
| 나무 되돌이 | 널 마디 살피기 | 널 손가락질 어긋남 |
| 나누어 다스리기 | 원소 하나인 작은 문제 | 쌓개 넘침 |

!!! tip "지키는 밑자리"
    어떤 되돌이 함수에서든 밑자리를 늘 먼저 다루라. 다른 이치에 앞서 널, 빔,
    크기 1인 들임을 살펴라.

## 복잡도를 잘못 따짐

복잡도를 잘못 보면 풀이가 때를 넘기거나, 더 나쁘게는 작은 시험은 지나가고 큰
시험에서 무너진다.

| 잘못 | 그렇게 여김 | 참 |
|---|---|---|
| `break`이 있는 겹친 돌기 | $O(n)$ | 가장 나쁠 때 여전히 $O(n^2)$ |
| 돌기 안의 해시 짝지음 닿기 | $O(n)$ | 해시가 부딪히면 $O(n^2)$ |
| 돌기 안의 줄 세우기 | $O(n \log n)$ | 돌기가 $n$번 돌면 $O(n^2 \log n)$ |
| 돌기 안의 글자열 이어 붙이기 | $O(n)$ | 베끼느라 $O(n^2)$(말에 따라) |
| 파이썬의 `set.add()` | 고르게 나눈 $O(1)$ | 연산마다 가장 나쁠 때 $O(n)$ |

## 그래프 알고리즘의 잘못

| 잘못 | 나타남 | 고침 |
|---|---|---|
| 들렀다고 표시하기를 잊음 | 끝없는 돌기 | 줄에 넣기 앞이나 그때 표시한다 |
| 너비 먼저에서 첫 거리를 잘못 잡음 | 가장 짧은 길이 하나 어긋남 | 보낸 곳 거리를 1이 아니라 0으로 잡는다 |
| 음수 짐에 데이크스트라를 씀 | 가장 짧은 길이 틀림 | 대신 벨먼-포드를 쓴다 |
| 훑는 동안 이웃 목록을 고침 | 변을 건너뛰거나 되풀이함 | 베낀 것을 훑는다 |
| 방향 있음과 없음을 헷갈림 | 변을 빠뜨리거나 두 번 셈 | 방향 없으면 양쪽으로 변을 넣는다 |

## 갈피 다지기의 잘못

| 잘못 | 나타남 | 고침 |
|---|---|---|
| 되돌이 방향이 틀림 | 아직 셈하지 않은 상태에 닿음 | 작은 문제의 갈래 차례를 살핀다 |
| 상태에 축이 빠짐 | 어떤 들임에서 답이 틀림 | 상태가 작은 문제를 홀로 가려내는지 살핀다 |
| 갈피 다지기 표를 0으로 첫자리 잡음 | 값이 가장 작은 문제에서 틀림 | 가장 작게 하는 문제에는 $\infty$을 쓴다 |
| 빈 부분 열을 다루지 않음 | 하나 어긋남 | 크기 0의 허수아비 가로줄/세로줄을 넣는다 |
| 풀이를 되세우기를 잊음 | 값은 알리되 참 답을 못 알림 | 갈피 다지기 값과 함께 어버이 손가락질을 좇는다 |

## 줄 세우기와 견주기의 잘못

| 잘못 | 나타남 | 고침 |
|---|---|---|
| 한결같지 않은 줄 세우기가 차례를 바꿈 | 같은 값에서 내놓기가 틀림 | 한결같은 줄 세우기를 쓰거나 같은 값의 차례를 또렷이 정한다 |
| 손수 만든 견줌개가 옮겨지지 않음 | 알 수 없는 결이나 무너짐 | $a < b$이고 $b < c$이면 $a < c$이게 한다 |
| 열쇠를 잘못 잡아 줄 세움 | 복잡도는 맞고 답이 틀림 | 줄 세우는 열쇠를 다시 살핀다 |
| 줄 세우기가 $O(n \log n)$임을 잊음 | 빠듯한 돌기에서 때를 넘김 | 한 번 줄 세우고 여러 번 묻는다 |

## 말마다의 함정

| 말 | 함정 | 고침 |
|---|---|---|
| 파이썬 | 되돌이 한도(맡긴 값 1000) | `sys.setrecursionlimit(N)` |
| 파이썬 | `input()`으로 들고나기가 느림 | `sys.stdin.readline()`을 쓴다 |
| C++ | 첫자리를 안 잡은 변수 | 늘 첫자리를 잡는다, 특히 배열 |
| C++ | `endl`이 버퍼를 흘려보냄 | 빠르려면 `"\n"`을 쓴다 |
| 자바 | `==`이 값이 아니라 자리를 견줌 | 글자열과 물체에는 `.equals()`을 쓴다 |
| 자바 | 저절로 상자에 담는 짐 | `ArrayList<Integer>`이 아니라 밑 갈래 배열을 쓴다 |

!!! warning "파이썬의 되돌이 한도"
    파이썬의 맡긴 되돌이 한도 1000은 웬만한 알고리즘 문제에 모자란다.
    `sys.setrecursionlimit(10**6)`으로 또렷이 올리되, 쌓개 크기 한도 때문에
    깊은 되돌이가 여전히 자리 어긋남을 낼 수 있음을 알아 두라.

## 익힘 문제

**익힘 1.**
가장 큰 부분 배열 합을 찾는 다음 코드의 벌레를 짚어라. `max_sum = 0; for i in range(n): curr += a[i]; max_sum = max(max_sum, curr); if curr < 0: curr = 0`. 언제 무너지는가?

??? success "익힘 1 풀이"
    벌레는 `max_sum = 0`으로 첫자리를 잡은 데 있다. 원소가 모두 음수면(보기로 `[-3, -2, -1]`) 가장 큰 부분 배열 합은 $-1$인데 코드는 0을 내놓는다(부분 배열을 하나도 고르지 않는다). 고침: `max_sum = a[0]`과 `curr = a[0]`으로 첫자리를 잡고 번호 1부터 돈다. 아니면 `max_sum = float('-inf')`으로 잡는다. 이는 카데인 알고리즘 짜보기에서 가장 흔한 잘못으로, 문제가 적어도 원소 하나를 고르라고 하는데도 답이 음수가 아니라고 여긴 것이다. $\square$

---

**익힘 2.**
어떤 풀이가 이진 찾기에서 `int mid = (lo + hi) / 2`을 쓴다. 넘침 벌레를 밝히고 옳은 식을 주어라.

??? success "익힘 2 풀이"
    `lo`과 `hi`이 모두 큰 양수 옹근수면(보기로 $2^{31} - 1$ 언저리) 합 `lo + hi`이 32비트 옹근수 너비를 넘어 음수가 된다. 뒤이은 나눗셈이 음수 `mid`을 주어 배열 밖에 닿는다. 옳은 식: `int mid = lo + (hi - lo) / 2`. 같은 값을 셈하면서도 가운데 셈이 `hi`을 넘지 않는다. 파이썬은 옹근수가 얼마든지 커질 수 있어 넘치지 않지만, 옮겨 쓰기 좋게 이 고침을 쓰는 것이 좋은 버릇이다. $\square$

---

**익힘 3.**
어떤 그래프 알고리즘이 `for each component: visited = [False]*n; dfs(...)`처럼 돌기 안에서 들렀는지 담는 배열의 첫자리를 잡는다. 왜 $O(n + m)$이 아니라 $O(n^2)$이 되는지 밝혀라.

??? success "익힘 3 풀이"
    돌기 안에서 `visited = [False]*n`을 다시 잡으면 조각마다 $O(n)$이 든다. 조각이 $k$개면 온 첫자리 잡기 값이 $O(kn)$이다. $k = n$이면(마디마다 제 조각일 때, 보기로 변이 없는 그래프) $O(n^2)$이다. 고침: 돌기에 앞서 `visited`의 첫자리를 한 번만 잡는다. 온 조각에 걸친 깊이 먼저 훑기가 이미 마디마다 한 번씩 들르므로 온 깊이 먼저 훑기 때는 $O(n + m)$이다. 들른 마디에는 다시 들르지 않으므로 다시 첫자리를 잡을 까닭이 없다. 이 잘못은 한 곳에서 뻗는 깊이 먼저 코드를 여러 곳에서 뻗는 훑기로 고칠 때 흔하다. $\square$

---

**익힘 4.**
떠 있는 소수점을 `if a == b`으로 견주는 것이 왜 미덥지 않은지 밝혀라. 너그러움 값을 매개변수로 받는 든든한 견줌 방법을 주어라.

??? success "익힘 4 풀이"
    떠 있는 소수점 셈은 반올림 어긋남을 들인다. 보기로 IEEE 754에서 `0.1 + 0.2`은 `0.3`이 아니라 `0.30000000000000004`이 된다. 수학으로 같은 두 값이 떠 있는 소수점 나타냄에서 다를 수 있으므로 곧바로 같은지 견주면 무너진다. 든든한 견줌: 절댓값 너그러움이면 `abs(a - b) < eps`, 견준 너그러움이면 `abs(a - b) < eps * max(abs(a), abs(b))`. `eps`은 문제에 맞추어 고른다. 꼴 문제에는 `eps = 1e-9`이 흔하다. 금융 셈에는 이 문제를 아예 피하도록 붙박인 소수점 셈(전 단위를 옹근수로)을 쓰라. 0과 견줄 때는 절댓값 너그러움만 쓴다(견준 너그러움은 0으로 나눈다). $\square$

---

**익힘 5.**
어떤 되돌이 함수에 빈 들임에 대한 밑자리가 없다. 무너지는 결을 밝히고 지키는 밑자리가 왜 꼭 있어야 하는지 밝혀라.

??? success "익힘 5 풀이"
    빈 들임(보기로 `n = 0`, 빈 배열, 널 마디)에 대한 밑자리가 없으면 되돌이 함수는 (1) 밖의 번호에 닿아(보기로 빈 배열에 `arr[0]`) 돌 때 어긋나거나, (2) (들임이 빌 때 되돌이 부름이 문제 크기를 줄이지 못하면) 끝없이 되돌이해 쌓개가 넘친다. 보기: `i >= len(arr)`을 살피지 않는 `def sum(arr, i): return arr[i] + sum(arr, i+1)`. 고침: 첫머리에 `if i >= len(arr): return 0`을 더한다. 지키는 밑자리가 꼭 있어야 하는 까닭은 (1) 참 들임에 가장자리 자리가 든다(빈 모둠, 원소 하나), (2) 되돌이로 쪼개면 빈 작은 문제가 자주 나온다(보기로 이진 찾기 나무의 빈 왼 밑나무), (3) 겨루기 심판과 면담하는 이가 일부러 가장자리 자리를 시험하기 때문이다. $\square$
