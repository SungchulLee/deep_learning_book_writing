# 맵리듀스

기계 한 대로 테라바이트급 자료를 다루기는 될 일이 아니다. 맵리듀스는
일을 **맵**과 **리듀스**라는 단순한 함수 둘로 적어 수천 대의 기계에
셈을 흩는 짜기 모형이다. 틀이 나란히 하기, 고장 견디기, 자료 흩기를
저절로
해 준다.

---

## 1. 짜기 모형

맵리듀스 셈은 들임 열쇠-값 짝의 모임을 쓰는 이가 뜻매김한 두 함수로
내놓기 열쇠-값 짝의 모임으로 바꾼다.

### 맵

$$
\text{Map}: (k_1, v_1) \to \text{list}(k_2, v_2)
$$

맵 함수는 들임 짝마다 따로 다루어 중간 열쇠-값 짝을 0개 넘게
내놓는다.

### 리듀스

$$
\text{Reduce}: (k_2, \text{list}(v_2)) \to \text{list}(v_3)
$$

리듀스 함수는 주어진 열쇠에 딸린 모든 중간 값을 받아 (보통 더 작은)
내놓기 값의 모임으로 합친다.

맵과 리듀스 사이에서 **섞기** 마당이 중간 짝을 열쇠로 묶어 알맞은
리듀서에 나누어 준다.

---

## 2. 돌림 흐름

1. **가르기.** 들임을 조각 $M$개로 갈라 저마다 매퍼에
   맡긴다.
2. **맵.** 매퍼마다 제 조각에 맵 함수를 써서 그 자리 원반에 적는 중간
   짝을 낸다.
3. **섞기/줄 세우기.** 틀이 중간 짝을 열쇠로 가르고(보통 $R$이 리듀서 수일 때
   $\text{hash}(k_2) \bmod R$으로) 줄
   세운다.
4. **리듀스.** 리듀서마다 제 몫의 열쇠마다 모든 값에 리듀스 함수를
   쓴다.
5. **내놓기.** 리듀서 결과를 나눠진 파일 시스템에 적는다.

!!! note "고장 견딤"
    매퍼나 리듀서가 고장 나면 틀이 다른 기계에서 그 일을 다시 돌린다.
    맵 내놓기는 그 자리 원반에 담기므로 고장 난 일만 다시 돌리면 된다.
    맵과 리듀스가 모두 **정해져 있고** **곁 효과가 없기** 때문에
    이것이 가능하다.

## 3. 고전 보기: 낱말 세기

```python
"""
맵리듀스 낱말 세기(기계 한 대로 흉내 낸 판).

낱말 잦음을 세는 맵 함수와 리듀스 함수를 보여 준다.
"""

from collections import defaultdict

# === 맵 함수 ===
def map_fn(doc_id: str, text: str) -> list[tuple[str, int]]:
    """글의 낱말마다 (낱말, 1)을 내놓는다."""
    pairs = []
    for word in text.lower().split():
        pairs.append((word, 1))
    return pairs

# === 리듀스 함수 ===
def reduce_fn(word: str, counts: list[int]) -> int:
    """주어진 낱말의 셈을 모두 더한다."""
    return sum(counts)

# === 맵리듀스 흉내내기 ===
def mapreduce(documents: dict[str, str]) -> dict[str, int]:
    """맵리듀스 낱말 세기를 흉내 낸다."""
    # 맵 마당
    intermediate: defaultdict[str, list[int]] = defaultdict(list)
    for doc_id, text in documents.items():
        for word, count in map_fn(doc_id, text):
            intermediate[word].append(count)

    # 리듀스 마당
    result = {}
    for word, counts in sorted(intermediate.items()):
        result[word] = reduce_fn(word, counts)
    return result

# === 보기 ===
if __name__ == "__main__":
    docs = {
        "doc1": "the cat sat on the mat",
        "doc2": "the dog sat on the log",
        "doc3": "the cat and the dog",
    }
    counts = mapreduce(docs)
    for word, count in sorted(counts.items(), key=lambda x: -x[1])[:5]:
        print(f"  {word}: {count}")
```

**출력:**

```
  the: 6
  cat: 2
  dog: 2
  on: 2
  sat: 2
```

## 4. 복잡도 모형

맵리듀스 복잡도 모형의 핵심 잣대는 다음과 같다:

| 잣대 | 밝힘 |
|---|---|
| **바퀴** | 맵리듀스 바퀴 수(차례대로 하는 걸음) |
| **주고받기** | 섞기 동안 보낸 온 자료 |
| **맵 일** | 모든 매퍼를 통틀어 온 셈 |
| **리듀스 일** | 모든 리듀서를 통틀어 온 셈 |

많은 문제를 맵리듀스 $O(1)$바퀴로 풀 수 있지만(보기로 낱말 세기, 뒤집은 색인)
그래프 문제는 흔히 $O(\log n)$바퀴 넘게
든다.

## 5. 맵리듀스 알고리즘

### 줄 세우기

- 맵: $k$이 줄 세우기 열쇠일 때 $(k, v)$을 내놓는다.
- 섞기 마당이 저절로 열쇠로 줄 세운다.
- 리듀스: 항등 함수.

온 주고받기: $N$이 들임 크기일 때 $O(N)$.

### 행렬 곱하기

$A$이 $m \times p$이고 $B$이 $p \times n$일 때 $C = AB$을 셈하려면:

- 맵: $A_{ij}$마다 모든 $k$에 대해 $((i, k), A_{ij})$을 내놓고,
  $B_{jk}$마다 모든 $i$에 대해 $((i, k), B_{jk})$을 내놓는다.
- 리듀스: 열쇠 $(i, k)$에 대해 $C_{ik} = \sum_j A_{ij} B_{jk}$을 셈한다.

한 바퀴, 주고받기 $O(mpn)$.

## 6. 한계와 넓힘

- **되풀이 알고리즘.** 그래프 알고리즘(PageRank, 이어진 조각)은 맵리듀스
  바퀴를 여러 번 돌아야 하고 바퀴마다 섞기 덧짐이
  든다.
- **뒤처지는 것.** 느린 매퍼 하나가 온 셈을 늦춘다. 미리 헤아려 돌리기(같은 일을
  겹쳐 돌리기)가 이를 누그러뜨린다.
- **맵리듀스 너머.** Spark(질긴 나눠진 자료 뭉치), Dryad(방향 있고 돌이 없는 그래프 돌림),
  Pregel(꼭짓점 중심 그래프 다루기) 같은 시스템이 이 한계를
  다룬다.

!!! tip "합치개"
    **합치개**는 섞기 전에 매퍼마다 그 자리에서 하는 리듀스다.
    합처럼 결합과 교환이 되는 연산에서는 이것이 그물 오감을
    크게 줄인다.

## 연습문제

**연습문제 1.**
맵리듀스 짜기 모형을 보기와 함께 밝혀라.

??? success "연습문제 1 풀이"
    맵리듀스는 자료를 두 마당으로 다룬다. 맵: 들임 기록마다 함수를 써서 (열쇠, 값) 짝을 낸다. 섞기: 모든 값을 열쇠로 묶는다. 리듀스: 열쇠와 그 값 목록마다 함수를 써서 마지막 내놓기를 낸다. 보기(낱말 세기): 맵이 글의 낱말마다 (낱말, 1)을 내놓는다. 섞기가 낱말로 묶는다. 리듀스가 낱말마다 셈을 더한다. 틀이 흩기, 고장 견디기, 일정 잡기를 맡는다. 자료 가까움: 맵 일은 자료를 담은 마디에서 돈다.

---

**연습문제 2.**
바퀴, 주고받기, 셈으로 맵리듀스의 복잡도를 살펴라.

??? success "연습문제 2 풀이"
    맵리듀스 일감 하나는 1바퀴다(맵 + 섞기 + 리듀스). 주고받기(섞기): $O(\sum |\text{맵 내놓기}|)$바이트. 셈: 맵은 민망할 만큼 나란하다(들임 $n$개와 매퍼 $p$개에서 셈틀마다 $O(n/p)$). 리듀스는 열쇠 분포에 매인다. 어떤 문제는 여러 바퀴가 든다. 줄 세우기는 1바퀴(온 일 $O(n \log n)$), PageRank은 되풀이 $k$번에 $k$바퀴, 이음은 1~2바퀴다. 섞기 마당이 그물 들고남 때문에 대개 병목이다.

---

**연습문제 3.**
맵리듀스와 Apache Spark을 견주어라. Spark의 이점은 무엇인가?

??? success "연습문제 3 풀이"
    Spark의 핵심 이점은 질긴 나눠진 자료 뭉치를 쓴 기억 속 셈이다. 맵리듀스는 일감마다 중간 결과를 원반에 적지만 Spark은 기억에 둔다. 되풀이 알고리즘(기계 배움 익히기, PageRank)에서 원반 들고남을 거듭하지 않아 10~100배 빨라진다. Spark은 느긋한 따지기(돌리기 전에 바꿈의 방향 있고 돌이 없는 그래프를 짓는다), 더 많은 연산자(거르기, 잇기, 묶기, 줄이기), 주고받는 묻기도 받쳐 준다. 맵리듀스의 이점은 더 단순한 고장 견딤 모형과 되풀이 없는 일감에서 기억을 덜 쓴다는 것이다.

---

**연습문제 4.**
맵리듀스 틀은 나눠 하는 깊은 배움의 자료 앞손질에 어떻게 쓰이는가?

??? success "연습문제 4 풀이"
    큰 규모 익히기의 자료 앞손질은 맵리듀스 무늬를 쓴다. (1) 맵: 날 자료(그림, 글)를 뜯어 바꿈(크기 바꾸기, 토막 내기)을 쓰고 (조각 번호, 손질한 기록)을 내놓는다. (2) 섞기: 기록을 조각별로 묶는다. (3) 리듀스: 조각마다 TFRecord/Parquet 파일로 적는다. 이로써 고르고 잘 섞인 익히기 자료가 생긴다. 다른 쓰임새: 자료 뭉치 통계 셈하기(고르게 맞추기용 평균/흩어짐), 낱말 짓기(낱말 세기), 겹침 없애기(표본마다 흩어 흩기값으로 묶고 무리마다 하나만 남김), 특징 뽑아내기(표본마다 미리 익힌 모델을 돌림).
