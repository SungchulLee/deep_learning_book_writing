# 들고남 다듬기

겨루기 짜기에서 때 초과와 통과를 가르는 것이 알고리즘이 아니라 들고남 방법일 때가 있다. C++과 파이썬의 여느 들고남 절차에는 맞추기와 꼴 갖추기 덧짐이 있어 들임 값이 $10^5$~$10^6$개인 문제에서는 때 밑천의 상당 부분을 잡아먹을 수 있다. 이 마디는 가장 영향이 큰 들고남 다듬기와 언제 쓸지를 다룬다.

## 들고남 성능이 중요한 까닭

정수 $10^6$개를 읽는다고 하자. 파이썬의 기본 `input()`과 `int()`으로는 1~2초쯤 걸려 셈을 시작하기도 전에 2초 한도를 넘길 수 있다. `sys.stdin`으로 한꺼번에 읽으면 같은 일이 0.1~0.2초에 끝난다.

C++에서 맞추기를 켠 `cin >> x`은 C의 `stdio`와 흐름을 맞추느라 `scanf("%d", &x)`보다 5~10배 느리다.

## C++의 들고남 다듬기

### 흐름 맞추기 끄기

기본으로 C++은 서로 섞어 쓸 수 있도록 `cin`/`cout`을 `scanf`/`printf`와 맞춘다. 이 맞추기를 끄면 크게 빨라진다.

```cpp
ios_base::sync_with_stdio(false);
cin.tie(nullptr);
```

이 두 줄 뒤에는 `cin`과 `cout`이 `scanf`, `printf`만큼 빠르다. 다만 맞추기를 끈 뒤에는 한 프로그램에서 C 방식(`scanf`/`printf`)과 C++ 방식(`cin`/`cout`)의 들고남을 섞어 쓰면 안 된다.

### endl 대신 '\n' 쓰기

`endl`은 줄마다 내놓기 버퍼를 비우는데 이는 비싸다. 대신 `'\n'`을 쓴다.

```cpp
// Slow: flushes buffer each time
cout << x << endl;

// Fast: no flush
cout << x << '\n';
```

### printf으로 한꺼번에 내놓기

큰 내놓기의 꼴을 갖출 때는 맞추기를 꺼도 `printf`이 `cout`보다 빠를 수 있다. C++ 흐름의 꼴 갖추기 덧짐을 피하기 때문이다.

## 파이썬의 들고남 다듬기

### 빠른 들임을 위한 sys.stdin

한꺼번에 읽으려면 `input()`을 `sys.stdin`으로 바꾼다.

```python
"""
파이썬에서 빠른 들고남 재주를 보인다.

큰 들임을 읽을 때 보통 input()과 sys.stdin을 견준다.
"""

import sys

# ===================================================================
# 빠른 들임 방법
# ===================================================================

def read_fast():
    """들임을 한 번에 다 읽고 토막으로 가른다."""
    data = sys.stdin.buffer.read().split()
    n = int(data[0])
    arr = [int(data[i + 1]) for i in range(n)]
    return n, arr

# ===================================================================
# 다른 길: sys.stdin으로 줄마다 읽기
# ===================================================================

def read_lines():
    """sys.stdin으로 들임을 줄마다 읽는다."""
    input_fn = sys.stdin.readline
    n = int(input_fn())
    arr = list(map(int, input_fn().split()))
    return n, arr

# ===================================================================
# 빠른 내놓기
# ===================================================================

def write_fast(arr):
    """빠르기를 위해 sys.stdout.write로 내놓는다."""
    sys.stdout.write(' '.join(map(str, arr)) + '\n')

# ===================================================================
# 메인
# ===================================================================

if __name__ == "__main__":
    # 줄마다 읽기를 쓰는 보기
    input_fn = sys.stdin.readline
    n = int(input_fn())
    arr = list(map(int, input_fn().split()))
    arr.sort()
    sys.stdout.write(' '.join(map(str, arr)) + '\n')
```

### 파이썬 들고남의 핵심 재주

| 재주 | 빨라짐 | 언제 쓸까 |
|---|---|---|
| `input()` 대신 `sys.stdin.readline()` | 2~3배 | 늘 |
| `sys.stdin.buffer.read()`으로 한꺼번에 읽기 | 5~10배 | 들임이 크고 꼴이 단순할 때 |
| `print()` 대신 `sys.stdout.write()` | 2배 | 내놓기가 클 때 |
| `' '.join(map(str, arr))` | 되돌이보다 3~5배 | 배열을 찍을 때 |

### 문자열을 거듭 이어 붙이지 않기

되돌이에서 문자열에 덧붙여 내놓기를 만들면 그때마다 새 문자열 대상이 생겨 온 비용이 $O(n^2)$이 된다. 대신 내놓기 조각을 목록에 모아 한 번에 잇는다.

```python
# 느림: O(n^2) 문자열 이어 붙이기
result = ""
for x in arr:
    result += str(x) + "\n"
print(result)

# 빠름: O(n) 잇기
print('\n'.join(map(str, arr)))
```

## 들고남 빠르기 견주기

여느 채점기에서 정수 $10^6$개를 읽는 대략의 때:

| 방법 | 말 | 때 |
|---|---|---|
| `cin >> x`(맞추기 켬) | C++ | 1.5초쯤 |
| `cin >> x`(맞추기 끔) | C++ | 0.2초쯤 |
| `scanf("%d", &x)` | C++ | 0.2초쯤 |
| 되돌이의 `input()` | 파이썬 3 | 2.0초쯤 |
| 되돌이의 `sys.stdin.readline()` | 파이썬 3 | 0.7초쯤 |
| `sys.stdin.buffer.read()`으로 한꺼번에 | 파이썬 3 | 0.15초쯤 |

## 들고남 다듬기가 필요 없을 때

모든 문제에 빠른 들고남이 필요하지는 않다. 들임 크기가 작고($n \le 10^4$) 알고리즘이 병목이면 여느 들고남으로 넉넉하다. 다음과 같은 문제에 들고남 다듬기의 힘을 쏟는다:

- $n \ge 10^5$이고 알고리즘이 $O(n)$이나 $O(n \log n)$이다.
- 시험 사례가 여러 개여서 들고남 양이 늘어난다.
- 때 한도가 빡빡하다(1초).

## 연습문제

**연습문제 1.**
정수 $10^6$개를 읽어 합을 찍는 문제가 있다. 느린 파이썬 풀이와 빠른 풀이를 모두 적고 여느 온라인 채점기에서 걸리는 때 차이를 어림하여라.

??? success "연습문제 1 풀이"
    되돌이에서 `input()`을 쓰는 느린 판:
    ```python
    n = int(input())
    s = 0
    for _ in range(n):
        s += int(input())
    print(s)
    ```
    `sys.stdin`을 쓰는 빠른 판:
    ```python
    import sys
    input = sys.stdin.readline
    data = sys.stdin.read().split()
    n = int(data[0])
    s = sum(int(data[i+1]) for i in range(n))
    print(s)
    ```
    느린 판은 파이썬 함수 부름 덧짐과 함께 `input()`과 `int()`을 $n$번 불러 $n = 10^6$에서 1.5~2초쯤 걸린다. 빠른 판은 시스템 부름 한 번으로 자료를 다 읽고 C에서 쪼개어 0.2~0.3초쯤 걸린다. 5~8배 빠르다. $\square$

**연습문제 2.**
`ios_base::sync_with_stdio(false)`이 C++ 들고남을 왜 빠르게 하는지, 어떤 매임을 두는지 밝혀라. 그 매임을 어기면 어떻게 되는가?

??? success "연습문제 2 풀이"
    기본으로 C++은 `cin`/`cout`과 `scanf`/`printf`을 마음대로 섞어 쓸 수 있도록 `iostream` 버퍼를 C의 `stdio` 버퍼와 맞춘다. 이 맞추기는 들고남마다 두 버퍼 체계 사이에 자물쇠와 비우기를 요구해 덧짐이 크다. `sync_with_stdio(false)`으로 끄면 C++ 흐름이 제 버퍼를 따로 써서 훨씬 빨라진다. 매임은 한 프로그램에서 C 방식(`scanf`, `printf`, `getchar`)과 C++ 방식(`cin`, `cout`)을 섞어 쓰면 안 된다는 것이다. 어기면 두 버퍼 체계가 따로 돌아 내놓기가 뒤섞이거나 들임을 엉뚱한 흐름이 먹어 자료가 엉키거나 빠진다. $\square$

**연습문제 3.**
좋아하는 말에서 들임 방법 넷의 처리량(초당 정수 개수)을 재는 잣대 시험을 설계하여라. 날 들고남 빠르기 말고 겨루기 성적에 영향을 주는 요인을 다루어라.

??? success "연습문제 3 풀이"
    아무 정수 $10^6$개의 파일을 만든다. 방법마다 걸리는 때를 잰다. (1) 말의 기본 줄 단위 들임, (2) 한꺼번에 읽고 쪼개기, (3) 기억에 옮긴 파일, (4) 바이트를 곧바로 읽는 스스로 만든 정수 뜯개. 파이썬에서 흔한 처리량은 대략 `input()` 되돌이가 초당 $5 \times 10^5$, `sys.stdin.read().split()`이 초당 $3 \times 10^6$, `mmap`이 초당 $4 \times 10^6$이다. 날 빠르기 말고도 내놓기 버퍼(되돌이에서 찍기와 이어 붙여 한 번에 찍기), 소수 뜯기 덧짐, 파이썬에서 문자열과 정수를 오가는 덧짐이 성적에 영향을 준다. $\square$

**연습문제 4.**
정수 하나씩 담긴 줄 $10^6$개를 내놓는 문제가 있다. 되돌이에서 찍기와 내놓기를 모아 한 번에 찍기의 성능을 견주어라. 파이썬 코드를 둘 다 보여라.

??? success "연습문제 4 풀이"
    되돌이 방식(느림):
    ```python
    for x in results:
        print(x)
    ```
    한꺼번에 방식(빠름):
    ```python
    import sys
    sys.stdout.write('\n'.join(map(str, results)) + '\n')
    ```
    되돌이 방식은 `print()`을 $10^6$번 부른다. 부를 때마다 꼴 갖추기, 버퍼에 적기, 어쩌면 비우기가 든다. 한꺼번에 방식은 정수를 모두 문자열로 바꾸고 `'\n'.join()` 한 번으로 이은 뒤 시스템 부름 한 번으로 적는다. 보통 3~5배 빠르다. 중간 방식으로 `print('\n'.join(map(str, results)))`을 쓰면 거의 그만큼 빠르다. $\square$

**연습 5.**
묻기가 $2 \times 10^5$개이고 저마다 소수 9자리 실수를 찍는 문제가 있다. C++에서 `printf("%.9f\n", x)`과 (맞추기를 끈) `cout << fixed << setprecision(9) << x << '\n'`의 성능을 견주어라. 어느 쪽이 왜 더 빠른가?

??? success "연습 5의 풀이"
    맞추기를 끄면 꼴 갖춘 실수 내놓기에서 보통 `printf`이 `cout`보다 10~30% 빠르다. `printf`은 `%f` 지정자에 맞춰 다듬은 C 꼴 갖추기 절차를 곧바로 쓰지만 `cout`은 `fixed`와 `setprecision` 조작자를 흐름의 로케일 단면으로 다루어야 해서 내놓기마다 덧짐이 붙기 때문이다. 내놓기가 $2 \times 10^5$개면 차이가 작지만(수십 밀리초) 한도가 빡빡하고 내놓기가 많아지면 커진다. 실제 절충은 실수에는 `printf`, 정수에는 `cout`을 쓰는 것인데 `sync_with_stdio(true)`을 지킬 때만(또는 `printf`만 쓸 때만) 그렇다. $\square$
