# 묶음 처리

많은 겨루기 짜기 문제는 답을 내기 전에 물음을 모두 먼저 준다. **묶음 처리**는 이를 살려 물음을 다시 줄 세우거나 묶어 다루어 물음마다 따로 답하는 것보다 나은 때 복잡도를 이룬다. 복잡한 즉시 처리 자료 얼개를 지니는 대신 묶음 처리 재주는 물음을 슬기롭게 줄 세우고 좋은 차례로 다룬 뒤 본디 물음 차례로 답을 내놓는다.

## 언제 묶음 처리를 쓰는가

묶음 처리는 다음일 때 쓴다:

- 물음을 모두 미리 안다(앞선 답에 기대는 물음이 없다).
- 물음을 다른 차례로 다루면 겹치는 셈이 줄어든다.
- 물음 사이에 고침이 섞이지 않거나 고침을 묶어서 다룰 수 있다.

핵심 맞바꿈: 묶음 처리 알고리즘은 물음에 그때그때 답할 수 없지만 흔히 훨씬 나은 점근 복잡도나 더 간단한 짜기를 이룬다.

## 모 알고리즘

모 알고리즘은 물음을 조심스레 고른 차례로 다루어 고정된 배열의 범위 물음 $[l, r]$에 $O((n + q) \sqrt{n})$ 때에 답한다.

### 생각

흐르는 답을 지닌 "지금 창" $[l_{\text{cur}}, r_{\text{cur}}]$을 지닌다. 새 물음 $[l, r]$에 답하려면 원소를 하나씩 넣거나 빼서 창을 늘리거나 줄인다. 전체 움직임 값은 물음 차례에 달렸다.

### 물음 차례 정하기

1. 번호를 크기 $\sqrt{n}$인 덩이 $\sqrt{n}$개로 나눈다.
2. 물음을 첫째 열쇠 = $l$의 덩이 번호, 둘째 열쇠 = $r$(짝수와 홀수 덩이에서 방향을 갈마듦)로 줄 세운다.

이는 다음을 보장한다:

- 한 덩이 안에서 $r$은 모두 많아야 $O(n)$만큼 움직인다.
- 덩이 사이에서 $l$은 물음마다 많아야 $O(\sqrt{n})$만큼 움직인다.
- 전체 움직임: $O((n + q)\sqrt{n})$.

### 복잡도

$$
T(n, q) = O\!\left((n + q)\sqrt{n}\right)
$$

```python
"""
오프라인 구간 물음을 위한 모 알고리즘.

물음을 다시 줄 세워 전체 가리개 움직임을 가장 작게 하며 고정된 배열의
범위 물음을 다뤄 O((n+q)*sqrt(n))을 이룬다.
"""

import math

# ===================================================================
# 모 알고리즘
# ===================================================================

def mos_algorithm(arr, queries):
    """모 알고리즘으로 구간 합 물음에 답한다.

    인수:
        arr: 들임 정수 배열
        queries: (왼쪽, 오른쪽) 짝의 목록(0부터 세며 양 끝을 넣는다)

    반환값:
        본디 물음 차례의 답 목록
    """
    n = len(arr)
    block_size = max(1, int(math.sqrt(n)))

    # 본디 번호를 붙이고 모의 차례로 줄 세움
    indexed_queries = [(l, r, i) for i, (l, r) in enumerate(queries)]
    indexed_queries.sort(key=lambda q: (q[0] // block_size,
                                        q[1] if (q[0] // block_size) % 2 == 0
                                        else -q[1]))

    answers = [0] * len(queries)
    cur_l, cur_r = 0, -1
    cur_sum = 0

    for l, r, idx in indexed_queries:
        # 창을 늘리거나 줄임
        while cur_r < r:
            cur_r += 1
            cur_sum += arr[cur_r]
        while cur_l > l:
            cur_l -= 1
            cur_sum += arr[cur_l]
        while cur_r > r:
            cur_sum -= arr[cur_r]
            cur_r -= 1
        while cur_l < l:
            cur_sum -= arr[cur_l]
            cur_l += 1

        answers[idx] = cur_sum

    return answers

# ===================================================================
# 메인
# ===================================================================

if __name__ == "__main__":
    arr = [1, 3, 5, 2, 7, 6, 3, 8, 4, 2]
    queries = [(0, 3), (1, 5), (4, 8), (0, 9), (2, 6)]

    answers = mos_algorithm(arr, queries)

    print("Array:", arr)
    print("\nRange sum queries:")
    for (l, r), ans in zip(queries, answers):
        expected = sum(arr[l:r+1])
        print(f"  sum[{l}..{r}] = {ans}  (check: {expected})")
```

**출력:**
```
Array: [1, 3, 5, 2, 7, 6, 3, 8, 4, 2]

Range sum queries:
  sum[0..3] = 11  (check: 11)
  sum[1..5] = 23  (check: 23)
  sum[4..8] = 28  (check: 28)
  sum[0..9] = 41  (check: 41)
  sum[2..6] = 23  (check: 23)
```

## 묶음 처리 LCA(타잔 알고리즘)

LCA 물음을 모두 미리 알 때 타잔의 묶음 처리 알고리즘은 합치기-찾기를 써서 깊이 먼저 훑기 한 번에 물음 $q$개에 모두 답한다.

### 알고리즘

1. 뿌리에서 깊이 먼저 훑기를 한다.
2. 마디 $u$가 끝나면(아이를 모두 다루면) $u$를 그 어버이와 합친다.
3. $u$에 딸린 물음 $(u, v)$마다 $v$를 이미 들렀다면 $\text{LCA}(u, v) = \text{find}(v)$이다.

### 복잡도

$$
T(n, q) = O\!\left((n + q) \cdot \alpha(n)\right)
$$

여기서 $\alpha$는 역 애커만 함수다. 이는 거의 선형이다.

## 다른 묶음 처리 재주

| 재주 | 생각 | 복잡도 |
|---|---|---|
| 모 알고리즘 | 범위 물음을 덩이로 다시 줄 세움 | $O((n+q)\sqrt{n})$ |
| 타잔의 묶음 처리 LCA | LCA 물음에 깊이 먼저 훑기와 합치기-찾기 | $O((n+q)\alpha(n))$ |
| CDQ 나눠 다스리기 | 물음을 때로 갈라 되돌이로 풂 | 문제에 따라 다름 |
| 묶음에서 즉시로(거슬러) | 고침을 거꾸로 다룸 | 문제에 따라 다름 |

## 언제 묶음 처리를 쓰지 않는가

묶음 처리는 다음일 때 쓸 수 없다:

- 물음이 하나씩 와서 바로 답해야 한다.
- 물음의 값이 앞선 답에 기댄다(맞춰 가는 물음).
- 문제가 실시간 응답 보장을 요구한다.

이런 때는 즉시 처리 자료 얼개(토막 나무, 균형 두 갈래 찾기 나무 등)가 필요하다.

## 연습문제

**연습문제 1.**
원소 $n = 9$개의 배열과 물음 4개 $[1,3], [2,5], [0,8], [4,6]$이 주어진다. 덩이 크기 $B = 3$일 때 모 알고리즘이 이 물음을 다루는 차례를 보여라. 전체 가리개 움직임을 셈하여라.

??? success "연습문제 1 풀이"
    덩이 크기 $B = 3$이다. $\lfloor l / B \rfloor$로 물음마다 덩이를 매긴다. $[1,3] \to$ 덩이 0, $[2,5] \to$ 덩이 0, $[0,8] \to$ 덩이 0, $[4,6] \to$ 덩이 1. 덩이 0 안에서 $r$로 줄 세우면 $[1,3], [2,5], [0,8]$이다. 덩이 1에는 물음이 하나 $[4,6]$이다. 다루는 차례: $[1,3], [2,5], [0,8], [4,6]$. 가리개 움직임: $[1,3]$에서 시작($l$을 0에서 1로: 1, $r$을 0에서 3으로: 3). $[2,5]$로: $l$이 $1 \to 2$: 1, $r$이 $3 \to 5$: 2. $[0,8]$로: $l$이 $2 \to 0$: 2, $r$이 $5 \to 8$: 3. $[4,6]$로: $l$이 $0 \to 4$: 4, $r$이 $8 \to 6$: 2. 모두: $1 + 3 + 1 + 2 + 2 + 3 + 4 + 2 = 18$번 움직인다. $\square$

**연습문제 2.**
덩이 크기 $B = \lceil \sqrt{n} \rceil$인 모 알고리즘이 크기 $n$인 배열의 물음 $q$개에 대해 전체 가리개 움직임 $O((n + q) \sqrt{n})$을 이룸을 증명하여라.

??? success "연습문제 2 풀이"
    $l$ 축을 크기 $B = \lceil \sqrt{n} \rceil$인 덩이로 나누면 덩이가 $O(\sqrt{n})$개다. 덩이 안에서 물음은 $r$로 줄 세워진다. (1) **오른쪽 가리개**: 덩이 안에서 $r$은 한 방향으로 움직이므로 덩이마다 많아야 자리 $n$개를 지난다. 덩이가 $O(\sqrt{n})$개이므로 오른쪽 가리개의 전체 움직임은 $O(n \sqrt{n})$이다. (2) **왼쪽 가리개**: 덩이 안의 물음은 모두 $l$이 크기 $B$인 같은 덩이에 있으므로 잇닿은 물음의 $l$ 차이는 많아야 $2B$다. 물음마다 왼쪽 가리개는 $O(B) = O(\sqrt{n})$만큼 움직인다. 물음 $q$개에 걸쳐 왼쪽 가리개의 전체 움직임은 $O(q \sqrt{n})$이다. (3) $r$의 **덩이 넘기**: 새 덩이로 옮길 때 $r$은 많아야 $n$만큼 뛰지만 넘기가 $O(\sqrt{n})$번뿐이라 모두 $O(n\sqrt{n})$이다. 합치면 $O(n\sqrt{n} + q\sqrt{n}) = O((n + q)\sqrt{n})$이다. $\square$

**연습문제 3.**
원소 $n$개와 물음 $q$개가 주어지는 문제인데 물음마다 범위 $[l, r]$의 서로 다른 원소 수를 묻는다. 모 알고리즘으로 묶음 처리 풀이를 설계하고 언제 이것이 지속 토막 나무 길보다 나은지 살펴라.

??? success "연습문제 3 풀이"
    잦기 배열 `cnt[]`와 셈틀 `distinct`를 지닌다. 원소 $a[i]$를 넣을 때 `cnt[a[i]]`를 올리고 그 값이 1이 되면 `distinct`를 올린다. 뺄 때는 `cnt[a[i]]`를 내리고 0이 되면 `distinct`를 내린다. 모의 차례로 물음을 다루며 물음마다 `distinct`를 내놓는다. 때: $O((n + q)\sqrt{n})$. 지속 토막 나무는 이를 즉시 처리로 $O((n + q) \log n)$에 풀어 점근으로 더 낫다. 그러나 실제로 모 알고리즘이 이기는 때가 있다. (1) $n$과 $q$가 어중간하고($\le 2 \times 10^5$) 지속 토막 나무의 상수 인수(가리개 바탕 얼개와 캐시 어긋남)가 클 때, (2) 넣기와 빼기 셈이 간단하고(셈틀 고치기뿐) 상수가 작을 때, (3) 대회에서 짜기의 간단함이 뜻있을 때다. $n$이나 $q$가 $\sim 3 \times 10^5$을 넘으면 $\sqrt{n}$ 인수가 커져 모 알고리즘이 진다. $\square$

**연습문제 4.**
나무 위의 물음을 다루도록 모 알고리즘을 늘리는 길을 밝혀라(나무 위의 모 알고리즘). 어떤 미리 다듬기가 필요하고 그 결과 복잡도는 얼마인가?

??? success "연습문제 4 풀이"
    마디를 두 번(들어갈 때와 나올 때) 적는 오일러 돌기로 나무를 편다. 이는 길이 $2n$의 배열을 낸다. 마디 $v$의 밑나무 물음에는 범위 $[\text{tin}(v), \text{tout}(v)]$을 바로 쓴다. $u$에서 $v$까지의 길 물음은($\text{tin}(u) < \text{tin}(v)$이라 하자) $u$가 $v$의 조상이면 범위 $[\text{tin}(u), \text{tin}(v)]$을 쓰고, 아니면 범위 $[\text{tout}(u), \text{tin}(v)]$을 쓰되 LCA를 따로 넣는다. 오일러 돌기 배열에서 마디가 나타날 때마다 그 이바지를 뒤집는다. 범위에 짝수 번 나타난 마디는 아무 이바지도 하지 않는다(서로 지워진다). 이 범위에 길이 $2n$인 배열 위의 모 알고리즘을 쓴다. 미리 다듬기: 오일러 돌기에 $O(n)$, LCA에 $O(n \log n)$. 복잡도: 배열 판과 같은 $O((n + q)\sqrt{n})$이지만 배열 길이가 두 배다. $\square$

**연습 5.**
DSU를 쓰는 타잔의 묶음 처리 LCA 알고리즘을 밝혀라. 때 복잡도는 얼마이고 왜 즉시 처리로 쓸 수 없는가?

??? success "연습 5의 풀이"
    타잔의 알고리즘은 깊이 먼저 훑기 한 번 동안 LCA 물음을 다룬다. 마디 $u$마다 아이를 모두 다룬 뒤 (1) $v$를 이미 들른 물음 $(u, v)$마다 답은 DSU의 $\text{find}(v)$이며 이것이 LCA다. (2) $u$를 그 어버이와 합친다. 길 옥죄기와 등수 합치기를 하는 DSU는 셈마다 고르게 나눈 $O(\alpha(n))$이다. 모든 때: $O((n + q) \cdot \alpha(n))$이며 사실상 $O(n + q)$이다. 깊이 먼저 훑기를 시작하기 전에 물음을 모두 알아야 하므로 즉시 처리로는 쓸 수 없다. 알고리즘은 마디 $u$가 훑기 중에 들러질 때만 $u$가 든 물음을 다룬다. $u$의 밑나무를 다 다룬 뒤에 오는 물음 $(u, v)$은 그 틈을 놓친다. 즉시 처리 LCA에는 두 갈래 들어 올리기나 오일러 돌기와 성긴 표가 필요하며, 이는 미리 다듬은 뒤 아무 차례의 물음도 받친다. $\square$
