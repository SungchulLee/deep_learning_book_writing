# 빠른 찾기

빠른 찾기는 합치기-찾기 추상 자료형의 가장 단순한 구현이다. 합치기가 느려지는 대신 소속을 묻는 일을 빠르게 하는 데 무게를 둔다. 핵심 생각은 모음의 대표를 납작한 배열에 곧바로 담는 것이다. 그래서 FIND은 배열을 한 번 들여다보는 $O(1)$이지만 UNION은 한 모음에 딸린 모든 자리를 고쳐야 해서 합칠 때마다 $O(n)$이 든다. 이 주고받음 때문에 빠른 찾기는 합치기-찾기를 이해하는 좋은 출발점이지만 들임이 크면 쓸 수 없다.

## 자료 구조

크기 $n$인 배열 `id[]`을 지니며, `id[x]`은 $x$을 담은 모음의 대표(또는 "조각 번호")를 담는다.

**불변식**: 두 원소 $x$과 $y$이 같은 모음에 있을 때 그리고 오직 그때만 `id[x] == id[y]`이다.

**첫값 잡기**: 모든 $x$에 대해 `id[x] = x`이며, 이는 원소마다 저마다의 대표라는 뜻이다.

## 연산

### FIND(x)

그저 `id[x]`을 돌려준다. 대표를 곧바로 담고 있으므로 $O(1)$ 시간이 든다.

### UNION(x, y)

$x$과 $y$을 담은 모음을 합치려면:

1. `id_x = id[x]`, `id_y = id[y]`이라 하자.
2. `id_x == id_y`이면 두 원소가 이미 같은 모음에 있으므로 끝이다.
3. 그렇지 않으면 배열 전체를 훑어 `id_y`과 같은 자리를 모두 `id_x`으로 바꾼다.

이 훑기는 모음의 크기와 상관없이 $O(n)$ 시간이 든다.

## 구현

```python
"""
합치기-찾기의 빠른 찾기 구현.

id[x]이 대표를 곧바로 담는 납작한 배열을 쓰므로
FIND은 O(1)이지만 UNION은 O(n)이다.
"""


# === 빠른 찾기 ===

class QuickFind:
    """find이 O(1)이고 union이 O(n)인 합치기-찾기."""

    def __init__(self, n: int):
        """홑원소 모음 {0}, {1}, ..., {n-1} 만들기."""
        self.id = list(range(n))
        self.count = n  # 서로 다른 모음의 개수

    def find(self, x: int) -> int:
        """x이 든 모음의 대표를 O(1)에 돌려준다."""
        return self.id[x]

    def union(self, a: int, b: int) -> bool:
        """a과 b을 담은 모음 합치기.

        배열 전체를 훑어 모든 자리를 고치므로 O(n) 시간이 든다.
        a과 b이 서로 다른 모음에 있었으면 True를 돌려준다.
        """
        id_a = self.id[a]
        id_b = self.id[b]
        if id_a == id_b:
            return False
        # id_b인 자리를 모두 id_a으로 바꾸기
        for i in range(len(self.id)):
            if self.id[i] == id_b:
                self.id[i] = id_a
        self.count -= 1
        return True

    def connected(self, a: int, b: int) -> bool:
        """a과 b이 같은 모음에 있는지 O(1)에 살핀다."""
        return self.id[a] == self.id[b]


# === 시연 ===

if __name__ == "__main__":
    qf = QuickFind(6)
    print(f"Initial id array: {qf.id}")

    qf.union(0, 1)
    print(f"After union(0,1): {qf.id}")

    qf.union(2, 3)
    print(f"After union(2,3): {qf.id}")

    qf.union(0, 3)
    print(f"After union(0,3): {qf.id}")

    print(f"connected(0,3): {qf.connected(0, 3)}")
    print(f"connected(0,4): {qf.connected(0, 4)}")
    print(f"Components: {qf.count}")
```

**출력:**
```
Initial id array: [0, 1, 2, 3, 4, 5]
After union(0,1): [0, 0, 2, 3, 4, 5]
After union(2,3): [0, 0, 2, 2, 4, 5]
After union(0,3): [0, 0, 0, 0, 4, 5]
connected(0,3): True
connected(0,4): False
Components: 3
```

## 돌아가는 자취

원소 6개로 시작하면 배열이 다음처럼 바뀐다:

| 연산 | id[0] | id[1] | id[2] | id[3] | id[4] | id[5] | 조각 수 |
|-----------|-------|-------|-------|-------|-------|-------|------------|
| 첫값 | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
| union(0,1) | 0 | 0 | 2 | 3 | 4 | 5 | 5 |
| union(2,3) | 0 | 0 | 2 | 2 | 4 | 5 | 4 |
| union(0,3) | 0 | 0 | 0 | 0 | 4 | 5 | 3 |

`union(0,3)`이 돌아갈 때 `id_a = id[0] = 0`이고 `id_b = id[3] = 2`이다. 알고리즘은 배열 전체를 훑어 모든 `2`을 `0`으로 바꾸며, 이는 자리 2과 자리 3에 영향을 준다.

## 복잡도 분석

| 연산 | 시간 | 설명 |
|-----------|------|-------------|
| MAKE-SET | $O(1)$ | 배열 자리 하나에 첫값 잡기 |
| FIND | $O(1)$ | 배열을 한 번 들여다봄 |
| UNION | $O(n)$ | 배열 전체 훑기 |

(원소 $n$개를 모두 한 모음으로 합치는) UNION 연산 $n - 1$번의 늘어놓음에서 전체 값은 다음과 같다

$$
\sum_{i=1}^{n-1} O(n) = O(n^2)
$$

이 이차 값 때문에 빠른 찾기는 들임이 크면 맞지 않다. 꼭짓점 $V$개, 변 $E$개인 그래프에서 크러스컬 알고리즘은 빠른 찾기를 쓰면 $O(E \cdot V)$이 드는데, 이는 최적화한 합치기-찾기로 이루는 $O(E \log E)$보다 훨씬 나쁘다.

## 한계

- **UNION이 너무 비싸다**: 연산마다 드는 $O(n)$이 웬만한 합치기 늘어놓음에서 판친다.
- **조금씩 나아지지 않는다**: (빠른 합치기 같은) 숲에 바탕을 둔 방식과 달리 연산을 되풀이해도 짜임이 나아지지 않는다.
- **규모를 못 키운다**: 합치기 $n$번에 $O(n^2)$이 들어 꼭짓점이 몇천 개를 넘는 그래프에는 쓸 수 없다.

빠른 합치기는 나무(숲) 짜임을 써서 이 한계를 다룬다. 이는 최악의 경우 FIND을 느리게 만드는 대신 UNION의 값을 줄일 수 있다.

## 연습문제

**연습문제 1.**
합치기-찾기의 빠른 찾기 방식을 설명하여라. 어떤 배열을 지니는가?

??? success "연습문제 1 풀이"
    빠른 찾기는 배열 `id[0..n-1]`을 지니며 `id[i]`은 원소 $i$의 조각 번호를 담는다. 두 원소가 같은 `id` 값을 가질 때 그리고 오직 그때만 같은 조각에 있다. **Find**: `id[x]`을 $O(1)$에 돌려준다. **Union(x, y)**: `id[x]`인 자리를 모두 `id[y]`으로(또는 그 반대로) $O(n)$에 바꾼다. $\square$

---

**연습문제 2.**
빠른 찾기에서 Union 연산 $n - 1$번 뒤에 Find 연산 $n$번을 할 때의 최악 시간을 살펴라.

??? success "연습문제 2 풀이"
    Union마다 배열 전체를 훑으므로 $O(n)$이다. Union $n - 1$번이면 모두 $O(n^2)$이다. Find마다 $O(1)$이므로 Find $n$번은 $O(n)$이다. 다 합치면 $O(n^2)$이다. Union의 이 이차 값 때문에 $n$이 크면 빠른 찾기를 쓸 수 없다. Find이 판치고 Union이 드물 때만 맞다. $\square$

---

**연습문제 3.**
Union이 느린데도 빠른 찾기를 왜 "빠르다"고 부르는가?

??? success "연습문제 3 풀이"
    그 이름은 Find 연산이 있을 수 있는 가장 빠른 $O(1)$임을 가리킨다. 그 대신 Union이 비싸다($O(n)$). 조각 번호를 곧바로 지니려면 합쳐진 조각의 모든 원소를 고쳐야 하기 때문이다. 빠른 찾기의 "빠름"은 "묻기가 빠름"이지 "전체가 빠름"이 아니다. 다른 길인 빠른 합치기는 Find이 느려지는 대신 Union을 빠르게 한다. $\square$

---

**연습문제 4.**
Union의 평균 값을 줄이도록 빠른 찾기를 고칠 방법을 내놓아라. 힌트: 조각의 크기를 좇아라.

??? success "연습문제 4 풀이"
    **무게 붙인 빠른 찾기**를 쓴다. 곧 조각마다 크기를 좇는다. Union할 때 늘 더 작은 조각의 번호를 더 큰 조각에 맞춰 바꾼다. 원소마다 번호가 많아야 $\log n$번 바뀐다(바뀔 때마다 그 원소를 담은 조각의 크기가 적어도 곱절이 된다). 모든 Union의 전체 값은 $O(n^2)$이 아니라 $O(n \log n)$이다. Find은 그대로 $O(1)$이다. 이러면 상수 시간 Find을 지키면서 Union마다 고르게 친 $O(\log n)$을 얻는다. $\square$
