# Open IE: 개방형 정보 추출

Open IE는 미리 정한 관계 유형에만 출력을 제한하지 않고 텍스트의 관계 표현과 인자를 추출한다. 흔히 (주어, 관계, 목적어) 삼중항으로 표현하지만 부정·조건·인용·시간 같은 한정 정보도 보존해야 한다. ‘열린’이라는 말은 원문에 없는 사실을 자유롭게 추측한다는 뜻이 아니다.

## 1. 관계 표현과 스키마

예를 들어 ‘민수는 서울에서 태어났고 부산에서 일했다’에서 (민수, 태어난 곳, 서울), (민수, 일한 곳, 부산)을 얻을 수 있다. 이는 개념 설명을 위한 예시이며 실제 추출기를 실행한 결과는 아니다. 스키마 기반 시스템이라면 같은 정보를 born-in·works-in 같은 정해진 관계 ID로 변환할 수 있다.

Open IE도 학습 자료와 모델·출력 형식의 제약을 가진다. 모든 관계를 빠짐없이 추출하거나 문장에 암시된 사실을 완전하게 추론하지는 않는다. 관계 표현이 달라도 의미가 같을 수 있어 검색·지식 그래프 통합에는 추가 정규화가 필요하다.

## 2. 대표 접근

[ReVerb](https://aclanthology.org/D11-1142/)는 관계 구문의 형태와 어휘적 제약으로 부적절한 추출을 줄인다. [OLLIE](https://aclanthology.org/D12-1048/)는 의존 구문 기반 패턴을 학습하며 동사 이외의 관계 표현과 발언 주체·조건 등의 문맥을 다룬다. [Stanford Open IE](https://aclanthology.org/P15-1034/)는 절 분해와 자연 논리 기반 축약을 활용한다. 이 접근들이 모든 문장을 독립적인 참인 삼중항으로 로스 없이 분해하는 것은 아니다.

뉴럴 모델은 토큰 레이블링이나 시퀀스 생성으로 인자와 관계를 출력할 수 있다. 학습 방식이 규칙·지도 학습·약한 감독 중 무엇인지는 Open IE라는 출력 설정만으로 결정되지 않는다.

## 3. 생성 프롬프트 예시

```python
# 열린 앎 뽑기에 지어내는 모델 쓰기
prompt = (
    "Extract all (subject, relation, object) triples from:\n"
    "Apple acquired Beats for \$3B in 2014.\n"
    "Triples:"
)
# 나올 내놓음:
# (Apple, acquired, Beats)
# (Apple, acquired Beats for, \$3B)
# (acquisition, occurred in, 2014)
```

위 코드는 prompt 문자열만 정의한다. 모델·토크나이저·추론 호출·결과 파싱이 없으며 주석의 삼중항은 실제 모델 출력이 아니다. 금액·날짜를 별도 삼중항으로 만들 때는 그것이 어떤 인수 사건에 연결되는지 보존해야 한다. 문자열에 나타나는 이스케이프 표기도 최종 모델 입력과 구분해서 확인한다.

생성한 관계가 원문의 구간에서 근거를 가지는지, 주어·목적어를 뒤집지 않았는지, 금액과 시간의 사건 연결이 맞는지 검토해야 한다. 출력 형식이 올바른 것과 내용이 원문으로 뒷받침되는 것은 별개다.

## 4. 스키마 기반 추출과 비교

| 구분 | 스키마 기반 추출 | Open IE |
|------|-------------------|---------|
| 관계 표현 | 정의한 유형·슬롯 | 원문의 표현 등 열린 관계 |
| 통합 | 같은 유형의 레코드로 모으기 쉬움 | 유사 표현의 정규화 필요 |
| 누락 위험 | 스키마 밖 정보 | 추출 규칙·모델이 다루지 못한 표현 |
| 평가 | 정의된 구간·관계의 매칭 | 표현 변형·함의와 중복 처리까지 필요 |

대상이 다른 평가에서 정밀도·재현율을 단순 비교하지 않는다. Open IE가 항상 재현율이 높거나 스키마 기반 모델이 항상 정밀도가 높은 것은 아니다. 시스템의 적용 범위와 같은 평가 조건에서 실제로 확인한다.

## 5. 문맥 보존과 활용

‘회사는 B사를 인수하지 않았다’, ‘인수하면’, ‘분석가는 인수할 것이라고 말했다’에서 인수 삼중항만 남기면 부정·조건·예측 주체를 잃는다. 원문의 출처·구간·시간과 한정 조건을 함께 저장해야 한다. 긴 관계 표현·명사화·대명사·중복 및 중첩 관계도 주요 오류 원인이다.

뉴스·보고서에서 새로운 공급 관계나 사업 관련 표현을 탐색하는 데 사용할 수 있다. 다만 원문에 없는 관계를 발견한 사실처럼 기록하거나 단순 추출을 인과·투자 판단의 증거로 확대해서는 안 된다. 최종 그래프 통합 전에 개체 식별·관계 정규화·사건 상태와 근거를 검토한다.

## 연습문제

**연습문제 1.** <span class="diff med" title="중간"></span>
Open IE가 ‘스키마가 없다’는 말의 범위와 실제로 남는 제약을 설명하라.

</div>

??? success "연습문제 1 풀이"

    관계 유형을 고정된 목록에만 제한하지 않는다는 뜻이다. 모델·학습 자료·인자 형식·문맥 표현은 여전히 제약을 가진다. 규칙 기반만 가능한 것도 아니고 모든 관계를 완전하게 추출하는 것도 아니다. 스키마 기반 추출과의 차이를 감독 방식이나 보편적인 정확도 순위로 바꾸지 않는다.



---

<div class="drillbox" markdown>

**연습문제 2.** <span class="diff med" title="중간"></span>
‘분석가는 A사가 B사를 인수할 수 있다고 말했다’에서 단순 삼중항만 저장할 때 잃는 정보를 설명하라.

</div>

??? success "연습문제 2 풀이"

    (A사, 인수하다, B사)만 저장하면 분석가에게 귀속된 가능성 발언을 실제 발생한 인수로 오해할 수 있다. 발언 주체·가능성·시점과 원문 근거를 함께 저장해야 한다. 발언 사실과 발언 내용의 사실성은 다르다.



---

<div class="drillbox" markdown>

**연습문제 3.** <span class="diff med" title="중간"></span>
관계 표현이 다른 삼중항을 지식 그래프에 통합할 때 필요한 검토를 설명하라.

</div>

??? success "연습문제 3 풀이"

    같은 개체인지 식별하고 관계의 방향·의미·시간·부정·사건 상태를 맞춰 정규화한다. ‘인수 계획’과 ‘인수 완료’처럼 비슷한 표현도 다른 상태일 수 있다. 문자열 유사성만으로 합치지 않고 원문 근거·출처를 보존한다.



---

<div class="drillbox" markdown>

**연습문제 4.** <span class="diff easy" title="쉬움"></span>
이 페이지의 코드가 실제 추출을 수행하는지와 생성형 Open IE를 평가할 기준을 설명하라.

</div>

??? success "연습문제 4 풀이"

    코드는 프롬프트 문자열만 정의하며 주석 예시는 측정 출력이 아니다. 실제 시스템에는 모델 호출·파싱·오류 처리가 필요하다. 평가는 형식 준수 외에 원문 근거·인자와 관계 방향·한정 문맥·중복·누락을 포함하고, 의미가 같은 표현을 어떻게 매칭하는지 명시해야 한다.



## 정리하며

Open IE는 열린 관계 표현을 추출하지만 원문 근거와 한정 문맥을 보존해야 한다. 스키마·감독 방식·성능을 구분하고, 프롬프트 예시와 실제 모델 추론·평가를 혼동하지 않는다.
