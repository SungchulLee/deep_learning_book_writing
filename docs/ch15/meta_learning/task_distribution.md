# 메타 학습을 위한 과제 분포 설계

메타 학습은 여러 과제를 통해 새로운 과제에 적응하는 방식을 배운다. 따라서 과제를 어떻게 추출하고 서포트와 쿼리를 어떻게 분리하는지가 학습 목표와 평가 결과를 결정한다. 과제 수를 늘리는 것뿐 아니라 실제 적용 환경을 대표하는지, 평가 정보가 학습에 유입되지 않는지를 살펴야 한다.

## 1. 핵심 개념

- **과제**: 예측 목표와 로스, 서포트·쿼리 데이터로 정의하는 학습 단위
- **과제 분포**: 어떤 과제를 어떤 확률로 추출할지 정하는 규칙
- **과제 다양성**: 클래스·도메인·잡음·표본 수 등의 변화
- **메타 일반화**: 학습에 쓰지 않은 과제에서의 적응 성능
- **커리큘럼**: 학습 진행에 따라 과제 추출 확률이나 난이도를 바꾸는 설계

## 2. 메타 학습에서 과제의 정의

### 과제 명세

과제는 다음으로 이루어진다.

$$\mathcal{T} = \{\mathcal{D}_{\text{train}}, \mathcal{D}_{\text{test}}, \ell(\cdot)\}$$

여기서 각 기호는 다음과 같다.

- $\mathcal{D}_{\text{train}} = \{(\mathbf{x}_i, y_i)\}_{i=1}^k$은 서포트 집합이다
- $\mathcal{D}_{\text{test}} = \{(\mathbf{x}_j, y_j)\}_{j=1}^q$은 쿼리 집합이다
- $\ell(\cdot)$은 과제마다의 로스 함수이다

### 과제 유사도

과제의 차이를 비음수 값으로 정의한 뒤 다음처럼 유사도로 바꿀 수 있다.

$$\text{Sim}(\mathcal{T}_i, \mathcal{T}_j) = \frac{1}{1 + \text{거리}(\mathcal{T}_i, \mathcal{T}_j)}$$

이 식은 비음수 차이를 유사도 점수로 바꾸는 한 가지 선택이다. KL 발산은 비대칭이며 무한대가 될 수 있어 일반적인 거리와 다르다. 성능 상관이나 피처 공간 차이를 사용하려면 측정 방법과 스케일을 먼저 정한다.

- 분포 발산: $\text{KL}(P_i \| P_j)$
- 과제 성능의 상관
- 피처 공간의 겹침

## 3. 과제 분포의 성격

### 다양성의 축

질 좋은 과제 분포는 여러 축을 따라 달라진다.

| 축 | 변화시키는 조건 | 예시 |
|---|---|---|
| 입력 분포 | 도메인·피처 | 촬영 환경이나 시장 시기 |
| 표본 수 | 적응 데이터의 양 | 1샷과 5샷 |
| 예측 목표 | 출력과 로스 | 분류와 회귀 |
| 잡음 | 관측·라벨 오차 | 센서 잡음이나 라벨 오류 |
| 시간 구조 | 의존성과 변화 | 정상 시계열과 분포 변화 |

### 복잡도와 난이도의 균형

!!! tip "난이도와 적용 환경"
    너무 쉬운 과제만 반복하면 필요한 적응 능력을 배우지 못할 수 있고, 어려운 과제만 쓰면 학습이 불안정할 수 있다. 난이도 혼합과 커리큘럼의 효과는 독립적인 검증 과제로 비교한다. 서로 다른 출력 구조를 섞으려면 모델과 로스도 이를 지원해야 한다.

## 4. 금융 과제 분포 설계

### 자산 기준 나누기

서로 다른 증권과 상품 종류에서 과제를 만든다.

**금융 과제 보기**:

- **서포트 집합**: 1~3월에 관측이 완료된 입력과 정답
- **쿼리 집합**: 4월의 예측 입력과 정답
- **로스**: 서포트로 적응한 모델의 4월 예측 오차

메타 학습 과제의 쿼리 정답은 외부 학습에 사용한다. 최종 테스트 과제의 쿼리 정답은 모델 선택이나 적응에 사용하지 않고 평가에만 쓴다.

```
Tasks = {
  Task 1: Predict AAPL returns using Jan-Mar AAPL data
  Task 2: Predict MSFT returns using Jan-Mar MSFT data
  Task 3: Predict BTC returns using Jan-Mar BTC data
  ...
  Task N: Predict sector index using historical data
}
```

서로 다른 자산을 과제로 삼아 공통 초기화나 적응 규칙을 학습할 수 있다. 자산별 과제라도 같은 날짜의 공통 정보로 연결될 수 있으므로 시간 분할도 함께 적용한다.

### 시간 기준 분할

서로 다른 기간에서 과제를 만든다.

**국면 기준 과제**:

- 상승장 기간
- 하락장 기간
- 횡보장 기간
- 국면 전환 기간
- 변동성이 큰 기간
- 변동성이 작은 기간

국면별 과제를 만들 때는 그 시점에 국면을 판별할 수 있었는지 확인한다. 미래 수익률로 붙인 국면 라벨을 예측 입력으로 사용하면 정보 누수가 된다.

### 시장 상황 기준 나누기

시장의 성격으로 과제를 묶는다.

| 시장 상황 | 관측할 수 있는 특성 |
|---|---|
| 높은·낮은 유동성 | 스프레드·거래량·체결 가능성 |
| 높은·낮은 변동성 | 수익률 변동의 크기 |
| 추세·평균 회귀 | 선택한 기간과 지표에서 측정한 액션 |

낮은 변동성이 반드시 높은 예측 가능성을 뜻하지는 않는다. 과제 구분 기준과 측정 기간을 먼저 정한다.

## 5. 과제 분포 짜기

### 샘플링 전략

**균등 샘플링**: 과제 종류마다 같은 확률(가장 단순하다)

**가중 샘플링**: 중요하거나 어려운 과제 종류에 힘을 싣는다.

$$P(\mathcal{T}) \propto \text{중요도}(\mathcal{T})$$

**커리큘럼 샘플링**: 난이도를 차츰 올린다.

$$\mathcal T\sim p_t(\mathcal T)$$

p_t는 메타 학습 반복 t에 따라 달라지는 과제 분포다. 난이도를 어떻게 측정하고 확률을 어떻게 정규화하는지 구현에서 정한다. 특정 난이도 값을 분포 함수에 대입하는 것만으로 완전한 샘플링 규칙이 되지는 않는다.

### 서포트·쿼리 분할 전략

**퓨샷 구성 예시**: N개 클래스를 선택하고 클래스마다 서포트 K개와 쿼리 Q개를 겹치지 않게 추출한다. 5샷·쿼리 15개는 한 가지 설정이며 모든 평가의 표준은 아니다.

K와 Q, N은 데이터 가용성과 적용 목표에 따라 정한다. 고정 N-way 분류 헤드에서는 학습 중 N을 임의로 바꾸기 어렵다. 서로 다른 구성의 성능은 같은 표에 섞지 말고 조건을 구분해 보고한다.


**시계열 구성**: 서포트는 쿼리보다 앞선 기간에 두고, 예측 기간과 정답 확정 시점을 반영해 간격을 둔다. 필요한 기간 길이는 데이터 빈도와 예측 목표에 따라 검증하며 모든 문제에 10~20일 같은 고정 길이를 권할 수는 없다.

## 6. 과제 분포의 함정 피하기

### 분포 어긋남 피하기

!!! warning "평가 분포의 차이"
    실제 적용 환경과 학습 과제의 분포가 다르면 적응 성능이 떨어질 수 있다. 같은 분포의 새 과제와 도메인·시간이 바뀐 과제를 구분하여 평가한다.

**해법**: 과제 분포가 현실의 시험 상황을 비추게 하라.

**시간 분할 예시**: 최종 테스트보다 앞선 구간에서 메타 학습과 검증을 끝낸다. 전처리 통계와 과제 선택 기준도 그 시점 이전 정보로 정한다. 단순히 연도를 나누는 것만으로 미래 정답이나 겹치는 윈도우의 누수가 모두 제거되는 것은 아니다.

### 과제 오염 다루기

서포트 집합과 쿼리 집합 사이로 정보가 새지 않게 막는다.

$$\mathcal{D}_{\text{train}} \cap \mathcal{D}_{\text{test}} = \emptyset$$

표본이 겹치지 않는 것은 기본 조건이다. 같은 개체의 중복 이미지, 미래 구간으로 계산한 정규화 통계, 시계열의 겹치는 정답 기간도 누수 경로가 될 수 있다. 메타 학습·검증·테스트 과제 사이의 분할도 별도로 관리한다.

### 목표에 맞는 과제 구성

어떤 과제 분포는 너무 쉬워서 배울 신호를 주지 못한다.

**이미지 예시**: 같은 클래스와 입력 분포를 반복 추출하면 새로운 클래스에 대한 적응을 충분히 학습하지 못할 수 있다. 회전이나 크기 변화를 추가하더라도 목표와 무관한 변형이면 도움이 되지 않는다. 목표 평가에 필요한 변화와 클래스 분할을 먼저 정한다.

**시계열 예시**: 여러 자산과 기간을 포함하되 무조건 다양하게 섞기보다 적용하려는 예측 목표와 시간 순서를 유지한다. 같은 국면의 과제도 실제 적용 분포를 대표한다면 학습에 의미가 있다.

## 7. 과제 분포의 질 재기

### 과제 다양성 지표

**쌍마다의 평균 거리**:

$$\bar{d} = \frac{1}{\binom{|T|}{2}} \sum_{i<j} d(\mathcal{T}_i, \mathcal{T}_j)$$

같은 거리 정의와 스케일에서 값이 클수록 과제 서술자가 더 벌어져 있다. 이것이 더 좋은 메타 학습 성능을 뜻하지는 않는다. 평균 쌍별 거리는 과제가 적어도 두 개 있어야 정의된다.

**스펙트럼 분석**: 과제 서술자에 주성분 분석을 하면 주요 변화 방향이 드러난다.

**분포 엔트로피**: 과제 분포가 얼마나 고른가?

$$H = -\sum_i P(\mathcal{T}_i) \log P(\mathcal{T}_i)$$

### 메타 일반화 평가

**동일 분포 일반화**: 학습과 같은 과제 생성 규칙에서 새 과제를 추출하여 평가한다. 이는 오라클 성능이나 이론적 상한이 아니다.

**분포 이동 성능**: 다른 분포에서 온 과제로 시험한다(현실에 가까운 평가).

**학습 경향**: 메타 학습 로스와 독립적인 검증 과제의 적응 후 로스를 함께 기록한다. 학습 과제 성능만 좋아지는지 확인한다.

## 8. 한 스텝 나아간 과제 분포 설계

### 커리큘럼 학습

메타 학습 중에 난이도를 차츰 올린다.

```
Phase 1 (Iterations 1-1000): Easy tasks only
Phase 2 (Iterations 1001-3000): Mix easy and medium
Phase 3 (Iterations 3001-5000): All difficulty levels
Phase 4 (Iterations 5001+): Hard tasks emphasized
```

커리큘럼은 초기 학습을 도울 수 있지만 최종 성능이나 안정성이 항상 좋아지지는 않는다. 같은 학습 예산의 고정 샘플링과 비교한다.

### 적대적 과제 생성

메타 학습기를 몰아붙여 시험하는 어려운 과제를 알아서 만들어 낸다.

$$\mathcal{T}_{\text{adv}} = \arg\max_{\mathcal{T}} \text{오차}_{\text{meta-learner}}(\mathcal{T})$$

허용된 과제 범위 안에서 어려운 과제를 생성한다. 현실과 무관하거나 라벨이 잘못된 과제를 최대 오차만으로 선택하지 않도록 제약이 필요하다.

### 적응형 과제 가중

메타 학습기의 불확실성으로 과제에 무게를 준다.

$$w_i(t) = 1 - \text{자신감}(\mathcal{T}_i, \text{되풀이 } t \text{의 메타 학습기})$$

확률로 보정된 신뢰도가 0~1 범위라면 위 식을 비음수 웨이트로 사용할 수 있다. 샘플링 확률로 쓰려면 합이 1이 되도록 정규화하고, 모든 웨이트가 0일 때의 처리도 정한다. 낮은 신뢰도만으로 과제의 유용성을 판단할 수는 없다.

## 9. 금융 구현 보기

### 일별 예측의 과제 분포

```
Tasks = {
  Stock 1 - Bull Period: Support [2017-2018], Query [2019]
  Stock 1 - Bear Period: Support [2020], Query [2020-2021]
  Stock 2 - Bull Period: Support [2017-2018], Query [2019]
  ...
  Index - All Periods: Support [2015-2019], Query [2020-2021]
}
```

위 도식의 두 번째 과제는 서포트 2020년과 쿼리 2020~2021년이 겹친다. 실제 데이터에서는 기간과 정답 범위를 분리해야 한다. 또한 서로 다른 자산의 같은 기간을 학습과 최종 테스트로 나누면 공통 시장 정보가 공유될 수 있다.

### 여러 자산 포트폴리오의 과제 분포

```
Tasks = {
  Equities: Support [train data], Query [test data]
  Bonds: Support [train data], Query [test data]
  Commodities: Support [train data], Query [test data]
  FX: Support [train data], Query [test data]
}
```

자산 종류를 과제로 삼을 수 있지만 입력 차원과 예측 목표가 서로 호환되어야 한다. 위 목록 자체가 학습 알고리즘이나 일반화 검증을 제공하지는 않는다.

    표본 수준 일반화는 정해진 과제의 새 표본을 예측하는 능력이다. 과제 수준 일반화는 학습에 쓰지 않은 과제에서 주어진 서포트로 적응한 뒤 쿼리를 예측하는 능력이다. 새 과제가 반드시 새 클래스일 필요는 없으며 도메인이나 예측 함수가 달라질 수도 있다.

아래 과제 샘플러가 반환하는 값과 빠진 검증을 설명하라. Omniglot 전처리와 에피소드 라벨 매핑도 제공하는가?

??? success "연습문제 4 풀이"
    아래 조각은 표본 인덱스만 반환한다. torch와 random의 임포트, 클래스별 K+Q개 이상 표본 확인, 로컬 라벨 생성과 이미지 로딩은 별도로 필요하다. nonzero().squeeze()는 표본이 하나일 때 스칼라가 되므로 차원 처리도 주의한다. Omniglot의 회전 어그멘테이션과 클래스 분할은 이 코드에 포함되지 않는다.

    ```python
    class TaskSampler:
        def __init__(self, labels, n_way, k_shot, q_query):
            self.label_to_indices = {l: (labels==l).nonzero().squeeze() for l in labels.unique()}
            self.n_way, self.k_shot, self.q_query = n_way, k_shot, q_query
        def sample(self):
            classes = random.sample(list(self.label_to_indices.keys()), self.n_way)
            support, query = [], []
            for c in classes:
                idx = self.label_to_indices[c][torch.randperm(len(self.label_to_indices[c]))]
                support.append(idx[:self.k_shot])
                query.append(idx[self.k_shot:self.k_shot+self.q_query])
            return torch.cat(support), torch.cat(query)
    ```
