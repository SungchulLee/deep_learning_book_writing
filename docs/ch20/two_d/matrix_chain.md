# 행렬 사슬 곱하기

행렬 사슬 $A_1 A_2 \cdots A_n$을 곱하면 괄호를 어떻게 매기든 결과는 늘 같지만 스칼라 곱셈의 수는 크게 달라진다. 행렬 사슬 곱하기는 스칼라 곱셈의 총수를 가장 적게 하는 괄호 매김을 묻는다. 이 고전 동적 짜기 문제는 연산 자체가 아니라 연산의 차례가 셈 값을 정한다는 것을 보여 준다.

---

## 1. 문제 서술

행렬 $A_i$의 꼴이 $p_{i-1} \times p_i$인 행렬 사슬 $A_1, A_2, \ldots, A_n$이 주어질 때 스칼라 곱셈의 총수를 가장 적게 하는 괄호 매김을 찾아라.

$p \times q$ 행렬에 $q \times r$ 행렬을 곱하려면 스칼라 곱셈이 $p \cdot q \cdot r$번 든다. 같은 사슬이라도 괄호를 어떻게 매기느냐에 따라 값이 자릿수만큼 달라질 수 있다.

**보기.** 꼴이 $10 \times 30$, $30 \times 5$, $5 \times 60$인 행렬 셋에 대해:

- $(A_1 A_2) A_3$: $10 \cdot 30 \cdot 5 + 10 \cdot 5 \cdot 60 = 1500 + 3000 = 4500$
- $A_1 (A_2 A_3)$: $30 \cdot 5 \cdot 60 + 10 \cdot 30 \cdot 60 = 9000 + 18000 = 27000$

첫 괄호 매김이 6배 싸다.

---

## 2. 가장 좋은 밑짜임

$A_i A_{i+1} \cdots A_j$에 가장 좋게 괄호를 매기려면 어떤 자리 $k$에서 $(A_i \cdots A_k)(A_{k+1} \cdots A_j)$으로 가른다. 두 아래 사슬도 저마다 가장 좋게 괄호가 매겨져 있어야 한다. 그렇지 않다면 더 나은 괄호 매김으로 갈음해 전체 값을 줄일 수 있어 가장 좋음에 어긋난다.

---

## 3. 점화식

$m[i][j]$을 $A_i A_{i+1} \cdots A_j$을 셈하는 데 드는 가장 적은 스칼라 곱셈 수라 하자. 행렬 하나에는 곱셈이 필요 없다:

$$
m[i][i] = 0
$$

$i < j$이면 가르는 점 $k$을 모두 시험해 가장 작은 것을 취한다:

$$
m[i][j] = \min_{i \le k < j} \bigl\{ m[i][k] + m[k+1][j] + p_{i-1} \cdot p_k \cdot p_j \bigr\}
$$

항 $p_{i-1} \cdot p_k \cdot p_j$은 꼴이 $p_{i-1} \times p_k$과 $p_k \times p_j$인 두 결과 행렬을 곱하는 값이다.

---

## 4. 채우는 차례

$m[i][j]$의 되돌이 관계식은 사슬 길이가 더 짧은 아래 문제에 기댄다. 사슬 길이 $\ell = j - i + 1$이 늘어나는 차례로 표를 채운다:

- $\ell = 1$: 모든 $m[i][i] = 0$
- $\ell = 2$: $i$마다 $m[i][i+1]$
- $\ell = 3, 4, \ldots, n$: 점점 긴 사슬

---

## 5. 복잡도

| 갈래 | 값 |
|---|---|
| 시간 | $O(n^3)$ — 세 겹 되풀이 |
| 공간 | $O(n^2)$ — 표 $m$과 $s$에 |
| 아래 문제 | $\binom{n}{2} + n = O(n^2)$ |

---

## 6. 파이썬 구현

```python
"""
행렬 사슬 곱하기 — 동적 짜기.

스칼라 곱셈을 가장 적게 하는 괄호 매김을 아래에서 위로 가는 표 채우기와
풀이 다시 세우기로 찾는다.
"""

# === 아래에서 위로 가는 표 채우기 ===

def matrix_chain_order(dims: list[int]) -> tuple[int, list[list[int]]]:
    """행렬 사슬의 가장 적은 곱셈 수를 찾는다.

    인수:
        dims: 행렬 i의 크기가 dims[i-1] x dims[i]인 꼴의 목록.
              행렬 n개에 길이는 n+1이다.

    반환값:
        (가장 적은 값, 가르기 표)의 짝. 여기서 split_table[i][j]이
        가장 좋은 가르는 점 k을 준다.
    """
    n = len(dims) - 1  # 행렬 수
    m = [[0] * n for _ in range(n)]
    s = [[0] * n for _ in range(n)]

    # 사슬 길이가 늘어나는 차례로 채운다
    for chain_len in range(2, n + 1):
        for i in range(n - chain_len + 1):
            j = i + chain_len - 1
            m[i][j] = float("inf")
            for k in range(i, j):
                cost = m[i][k] + m[k + 1][j] + dims[i] * dims[k + 1] * dims[j + 1]
                if cost < m[i][j]:
                    m[i][j] = cost
                    s[i][j] = k

    return m[0][n - 1], s

# === 괄호 매김 다시 세우기 ===

def print_optimal_parens(s: list[list[int]], i: int, j: int) -> str:
    """가장 좋은 괄호 매김을 글줄로 다시 세운다."""
    if i == j:
        return f"A{i + 1}"
    k = s[i][j]
    left = print_optimal_parens(s, i, k)
    right = print_optimal_parens(s, k + 1, j)
    return f"({left} x {right})"

# === 메인 ===

if __name__ == "__main__":
    # 행렬: A1(10x30), A2(30x5), A3(5x60)
    dims = [10, 30, 5, 60]
    min_cost, split = matrix_chain_order(dims)
    n = len(dims) - 1
    parens = print_optimal_parens(split, 0, n - 1)

    print(f"Dimensions: {dims}")
    print(f"Minimum multiplications: {min_cost}")
    print(f"Optimal parenthesization: {parens}")

    # 더 큰 보기: A1(30x35), A2(35x15), A3(15x5), A4(5x10), A5(10x20), A6(20x25)
    dims2 = [30, 35, 15, 5, 10, 20, 25]
    min_cost2, split2 = matrix_chain_order(dims2)
    n2 = len(dims2) - 1
    parens2 = print_optimal_parens(split2, 0, n2 - 1)

    print(f"\nDimensions: {dims2}")
    print(f"Minimum multiplications: {min_cost2}")
    print(f"Optimal parenthesization: {parens2}")
    # 내임:
    # 꼴: [10, 30, 5, 60]
    # 가장 적은 곱셈 수: 4500
    # 가장 좋은 괄호 매김: ((A1 x A2) x A3)
    #
    # 꼴: [30, 35, 15, 5, 10, 20, 25]
    # 가장 적은 곱셈 수: 15125
    # 가장 좋은 괄호 매김: ((A1 x (A2 x A3)) x ((A4 x A5) x A6))
```

## 7. 풀이 예제

꼴이 $p = [30, 35, 15, 5, 10, 20, 25]$인(행렬 여섯 개) 경우 $m$ 표는 다음처럼 채워진다:

| $m[i][j]$ | $j=1$ | $j=2$ | $j=3$ | $j=4$ | $j=5$ | $j=6$ |
|---|---|---|---|---|---|---|
| $i=1$ | 0 | 15750 | 7875 | 9375 | 11875 | **15125** |
| $i=2$ | | 0 | 2625 | 4375 | 7125 | 10500 |
| $i=3$ | | | 0 | 750 | 2500 | 5375 |
| $i=4$ | | | | 0 | 1000 | 3500 |
| $i=5$ | | | | | 0 | 5000 |
| $i=6$ | | | | | | 0 |

가장 좋은 값은 $m[1][6] = 15125$이고 괄호 매김은 $((A_1(A_2 A_3))((A_4 A_5) A_6))$이다.

## 연습문제

**연습문제 1.**
행렬 사슬 곱하기의 상태, 옮아감, 바탕 경우를 가려내어라.

??? success "연습문제 1 풀이"
    **상태**는 아래 문제를 적는 데 필요한 앎을 담는다. **옮아감**(되돌이 관계식)은 어떤 상태의 가장 좋은 값을 더 작은 상태로 나타낸다. **바탕 경우**는 곧바로 풀 수 있는 가장 작은 아래 문제의 값을 준다. 이 셋이 함께 동적 짜기 풀이를 온전히 정한다. $\square$

---

**연습문제 2.**
행렬 사슬 곱하기의 위에서 아래로(적어 두기) 짜기와 아래에서 위로(표 채우기) 짜기를 견주어라. 어느 쪽이 나으며 왜 그런가?

??? success "연습문제 2 풀이"
    **위에서 아래로**: 곳간을 곁들인 되돌이. 정말 필요한 아래 문제만 셈한다(게으른 값매김). 되돌이 관계식에서 옮겨 적기 쉽다. 되돌이 깊이 문제가 생길 수 있다. **아래에서 위로**: 되풀이로 기댐 차례에 따라 표를 채운다. 필요 없는 것까지 모든 아래 문제를 셈한다. 되돌이 군더더기가 없다. 공간을 줄이기 쉽다. 이 문제에서는 아래 문제가 모두 필요하면 아래에서 위로가 흔히 낫고, 닿지 않는 아래 문제가 많으면 위에서 아래로가 낫다. $\square$

---

**연습문제 3.**
행렬 사슬 곱하기의 시간 복잡도와 공간 복잡도는 무엇인가? 공간을 더 줄일 수 있는가?

??? success "연습문제 3 풀이"
    시간 복잡도는 상태의 수에 상태마다의 옮아감 값을 곱한 것으로 정해진다. 공간은 담아 두는 상태의 수와 같다. 옮아감이 앞선 상태 가운데 한정된 몇 개에만 기대면(예컨대 2차원 표의 바로 앞 가로줄) 그 상태만 기억 공간에 두어 공간을 줄일 수 있으며, 흔히 $O(n^2)$에서 $O(n)$으로 줄어든다. $\square$

---

**연습문제 4.**
행렬 사슬 곱하기의 알고리즘을 네가 고른 작은 보기에 대해 좇아라. 동적 짜기 표의 값을 보여라.

??? success "연습문제 4 풀이"
    작은 들임(예컨대 $n = 5$이나 짧은 글줄/배열)을 골라라. 동적 짜기 표를 한 걸음씩 채우면서 각 칸이 앞서 셈한 칸에서 어떻게 나오는지 보여라. 마지막 답을 막무가내로 다 세어 본 것과 견주어 확인하라. 이렇게 좇아 보면 되돌이 관계식이 옳음을 확인하고 알고리즘에 대한 직관이 선다. $\square$
