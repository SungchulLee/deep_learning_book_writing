# 5걸음 셀프 어텐션 — 길이가 답이었다

[4걸음](04_lstm.md)은 물음을 남긴 채 끝났다. LSTM이 [3걸음](03_embedding.md)보다 5.52%포인트 낮았는데, 퍼짐이 4.75여서 그 값을 믿을 수 없었다. **구조 탓인지 예산 탓인지** 가릴 수 없었다.

이 절이 그것을 가른다. 차례를 보는 또 다른 구조를 같은 예산에 올려 재면, 내려감이 "차례를 보아서"인지 "LSTM이라서"인지 드러난다.

세 걸음이 **같은 박아 넣기를 지닌다.** 바뀌는 것은 그 위에 무엇을 얹느냐뿐이다.

| 걸음 | 박아 넣기 | 그 위에 얹은 것 | 합계 | 박아 넣기 몫 |
|---|---|---|---|---|
| [3 평균](03_embedding.md) | 1,280,000 | 평균 — 0 | 1,280,130 | 100% |
| [4 LSTM](04_lstm.md) | 1,280,000 | LSTM 33,280 | 1,313,410 | 97.5% |
| 5 어텐션 | 1,280,000 | 자리 + 어텐션 + 정규화 42,368 | 1,322,498 | 96.8% |

**세 모델 모두 매개변수의 97% 안팎이 박아 넣기다.** 차례를 다루는 장치는 어느 쪽도 3%를 넘지 않는다. 그러므로 이 장의 견줌은 크기를 붙들어 맨 채 구조만 바꾼 견줌이다.

---

## 1. 모든 낱말이 서로를 곧장 본다

LSTM은 왼쪽에서 오른쪽으로 한 칸씩 간다. 100칸 떨어진 낱말에 닿으려면 100번을 거쳐야 한다. **셀프 어텐션은 한 번에 닿는다.** 낱말마다 다른 모든 낱말을 보고, 얼마나 볼지를 무게로 정해 섞는다.

값이 둘 든다.

**하나, 어텐션 자체는 순서를 모른다.** 낱말들을 뒤섞어 넣어도 결과가 같다. 그래서 자리마다 다른 벡터를 더해 준다(`self.pos`). 이것을 빼면 3걸음의 평균과 다를 바가 없어진다.

**둘, 채움 칸을 보지 않게 막아야 한다.** `key_padding_mask`가 그 일을 한다. 막지 않으면 400칸 가운데 절반이 넘는 빈 칸이 무게를 나눠 갖는다.

마지막에 자리마다 나온 벡터를 **평균낸다.** 이 점을 기억해 두자. 이 절의 결과를 설명하는 것이 이 한 줄이다.

## 2. 코드

```python
"""5걸음: 셀프 어텐션. 모든 낱말이 서로를 곧장 본다.

4걸음 LSTM은 왼쪽에서 오른쪽으로 한 칸씩 갔다. 멀리 있는 낱말에
닿으려면 그만큼 거쳐야 한다. 어텐션은 낱말마다 다른 모든 낱말을
곧장 보고, 얼마나 볼지를 무게로 정해 섞는다.

매개변수가 3걸음과 거의 같다(1,322,498 대 1,280,130). 그러므로
차이가 나면 그것은 크기가 아니라 구조의 몫이다.
"""

import re, time
from collections import Counter
from pathlib import Path

import numpy as np
import torch
import torch.nn as nn
import torch.optim as optim
from torch.utils.data import DataLoader, TensorDataset

ROOT = Path("./data/aclImdb")
VOCAB_SIZE, MAX_LEN, EMB_DIM, HEADS = 20000, 400, 64, 4
EPOCHS, BATCH, LR, PAD = 5, 100, 1e-3, 0
torch.set_num_threads(1)          # 스레드 수가 바뀌면 더하는 차례가 바뀐다

TOKEN = re.compile(r"[a-z']+")


def tokenize(t):
    return TOKEN.findall(t.replace("<br />", " ").lower())


def load(split):
    docs, labels = [], []
    for label, name in ((1, "pos"), (0, "neg")):
        for f in sorted((ROOT / split / name).glob("*.txt")):
            docs.append(tokenize(f.read_text(encoding="utf-8")))
            labels.append(label)
    return docs, np.array(labels)


train_docs, train_y = load("train")
test_docs, test_y = load("test")
counts = Counter(w for d in train_docs for w in d)
vocab = ["<pad>"] + [w for w, _ in counts.most_common(VOCAB_SIZE - 1)]
index = {w: i for i, w in enumerate(vocab)}


def to_ids(docs):
    X = np.zeros((len(docs), MAX_LEN), dtype=np.int64)
    for r, d in enumerate(docs):
        ids = [index[w] for w in d if w in index][:MAX_LEN]
        X[r, :len(ids)] = ids
    return X


Xtr = torch.from_numpy(to_ids(train_docs)); ytr = torch.from_numpy(train_y).long()
Xte = torch.from_numpy(to_ids(test_docs));  yte = torch.from_numpy(test_y).long()
print(f"자료 학습 {len(train_docs):,}편  시험 {len(test_docs):,}편", flush=True)


# === 5걸음: 모든 낱말이 서로를 곧장 본다 ====================================
class AttentionClassifier(nn.Module):
    """어텐션 한 겹. 자리 박아 넣기가 있어야 순서를 안다."""

    def __init__(self):
        super().__init__()
        self.emb = nn.Embedding(VOCAB_SIZE, EMB_DIM, padding_idx=PAD)
        self.pos = nn.Parameter(torch.randn(1, MAX_LEN, EMB_DIM) * 0.02)
        self.attn = nn.MultiheadAttention(EMB_DIM, HEADS, batch_first=True)
        self.norm = nn.LayerNorm(EMB_DIM)
        self.fc = nn.Linear(EMB_DIM, 2)

    def forward(self, x):
        e = self.emb(x) + self.pos
        pad = (x == PAD)
        a, _ = self.attn(e, e, e, key_padding_mask=pad)   # 채움 칸은 보지 않는다
        h = self.norm(e + a)                              # 남은 이음
        m = (~pad).unsqueeze(-1).float()
        return self.fc((h * m).sum(1) / m.sum(1).clamp(min=1))   # 다시 평균이다


def run(seed):
    torch.manual_seed(seed)
    m = AttentionClassifier()
    opt = optim.Adam(m.parameters(), lr=LR)
    crit = nn.CrossEntropyLoss()
    g = torch.Generator().manual_seed(seed)
    ld = DataLoader(TensorDataset(Xtr, ytr), batch_size=BATCH, shuffle=True, generator=g)
    for _ in range(EPOCHS):
        m.train()
        for xb, yb in ld:
            opt.zero_grad(); crit(m(xb), yb).backward(); opt.step()
    m.eval()
    with torch.no_grad():
        pred = torch.cat([m(Xte[i:i + 500]).argmax(1) for i in range(0, len(Xte), 500)])
    return 100.0 * pred.eq(yte).float().mean().item(), sum(p.numel() for p in m.parameters())


accs = []
for seed in (0, 1, 2, 3, 4):
    t0 = time.time()
    acc, npar = run(seed)
    accs.append(acc)
    print(f"  씨앗 {seed}  {acc:.2f}%  ({time.time() - t0:.0f}s)", flush=True)

print(f"\n5걸음 셀프 어텐션  평균 {sum(accs) / len(accs):.2f}%  "
      f"퍼짐 {max(accs) - min(accs):.2f} ({min(accs):.2f}~{max(accs):.2f})  "
      f"매개변수 {npar:,}")
```

**출력:**

```
자료 학습 25,000편  시험 25,000편
  씨앗 0  86.19%
  씨앗 1  86.30%
  씨앗 2  85.97%
  씨앗 3  86.06%
  씨앗 4  86.03%

5걸음 셀프 어텐션  평균 86.11%  퍼짐 0.33 (85.97~86.30)  매개변수 1,322,498
```

## 3. LSTM을 크게 이기고 3걸음에 조금 못 미친다

| 걸음 | 정확도 | 퍼짐 | 남은 오차 | 앞 걸음 대비 | 매개변수 |
|---|---|---|---|---|---|
| [1 최근접 중심](01_counting.md) | 65.16% | — | 34.84%p | — | 40,000 |
| [2 선형 학습](02_linear.md) | 78.80% | 0.23 | 21.20%p | 39% | 40,002 |
| [3 박아 넣기 + 평균](03_embedding.md) | **87.03%** | 0.34 | **12.97%p** | 39% | 1,280,130 |
| [4 LSTM](04_lstm.md) | 81.51% | 4.75 | 18.49%p | −43% | 1,313,410 |
| 5 셀프 어텐션 | 86.11% | **0.33** | 13.89%p | 25% | 1,322,498 |

두 가지를 함께 읽어야 한다.

**어텐션은 LSTM을 확실히 이긴다.** 86.11% 대 81.51%, 4.60%포인트다. 두 범위가 85.97\~86.30과 78.76\~83.51로 2.46만큼 떨어져 있으므로 씨앗을 바꾸어 뒤집히지 않는다.

**그런데 3걸음을 넘지 못한다.** 86.11% 대 87.03%, 0.92%포인트 모자란다. 이쪽도 범위가 갈린다(85.97\~86.30 대 86.92\~87.26, 0.62만큼). **작지만 참인 차이다.**

곧 사다리의 꼭대기는 여전히 **차례를 통째로 버리는 3걸음**이다.

## 4. 퍼짐이 4걸음의 물음에 답한다

[4걸음](04_lstm.md)이 답하지 못하고 넘긴 물음은 이것이었다. 내려감이 구조 탓인가 예산 탓인가.

| 걸음 | 퍼짐 | 무엇을 뜻하는가 |
|---|---|---|
| 3 평균 | 0.34 | 자리를 잡았다 |
| 4 LSTM | **4.75** | 자리를 잡지 못했다 |
| 5 어텐션 | **0.33** | 자리를 잡았다 |

**어텐션의 퍼짐은 0.33이다.** 3걸음의 0.34, 2걸음의 0.23과 나란하다. 씨앗을 바꾸어도 같은 곳에 내려앉으니 이 모델은 5 에포크 안에 자리를 잡았다.

그러므로 어텐션의 86.11%에는 "예산이 모자랐다"는 변명이 붙지 않는다. **자리를 잡은 채로 3걸음에 못 미친 것이다.**

이것이 4걸음의 물음을 반쯤 가른다.

- **LSTM의 내려감은 예산 탓이 크다.** 같은 예산에서 다른 구조는 자리를 잡았으니, 5 에포크가 절대적으로 모자란 것이 아니다. 모자란 쪽은 LSTM이다.
- **그러나 차례를 보는 것이 이 일감에서 벌어 주는 몫은 0 이하다.** 자리를 잡은 어텐션조차 평균을 넘지 못했다.

## 5. 세 걸음이 한 가지로 설명된다

3걸음과 5걸음은 잘하고 4걸음만 못한다. 셋을 가르는 것이 무엇인가?

**낱말에서 출력까지의 거리다.**

| 걸음 | 낱말 하나에서 출력까지 | 퍼짐 | 정확도 |
|---|---|---|---|
| 3 평균 | **1** | 0.34 | **87.03%** |
| 4 LSTM | 최대 **400** | 4.75 | 81.51% |
| 5 어텐션 | **1** | 0.33 | 86.11% |

3걸음은 낱말 벡터를 그냥 평균내므로 모든 낱말이 출력까지 한 걸음이다. 5걸음은 **무게를 준 평균**이므로 역시 한 걸음이다. 4걸음만 다르다. 첫 낱말이 출력에 닿으려면 상태를 400번 거쳐야 한다.

기울기는 그 길을 거꾸로 흐른다. 길이 길면 약해지고, 약해지면 앞부분 낱말은 늦게 배운다. **퍼짐 4.75가 그 늦음의 모습이다.**

!!! note "어텐션은 평균의 한 갈래다"
    이 절의 코드 마지막 줄이 `(h * m).sum(1) / m.sum(1)`이다. 3걸음과 똑같은 평균이며, 다른 것은 평균내는 대상이 **낱말 벡터**가 아니라 **다른 낱말들을 보고 고쳐진 벡터**라는 점뿐이다.

    그래서 어텐션은 3걸음의 강점(짧은 길)을 지킨 채 차례를 더한다. 값이 3걸음 언저리에 머무는 것이 이치에 맞고, LSTM처럼 무너지지 않는 것도 이치에 맞는다.

    트랜스포머가 되돌이 그물을 밀어낸 까닭의 절반이 여기에 있다. 나머지 절반은 **한꺼번에 셈할 수 있다**는 것인데, 그 이야기는 [12.5절](../ch11/attention/self_attention.md)이 다룬다.

## 6. 이 장이 남기는 것

다섯 걸음을 걸었고 꼭대기는 3걸음이다.

**차례를 읽는 장치를 둘이나 붙였는데 둘 다 벌지 못했다.** 하나는 무너졌고(LSTM) 하나는 겨우 따라붙었다(어텐션).

3장과 4장에서는 이런 일이 없었다. 생각을 더할 때마다 값이 올랐다. 그래서 이 장의 결론은 그 두 장의 결론과 다르다.

> **어떤 생각이 값을 버는가는 일감에 딸려 있다.**

IMDB에서 좋게 보았는지 나쁘게 보았는지를 가르는 일은 **어떤 낱말이 나왔는가**로 거의 풀린다. `terrible`, `waste`, `perfect`가 있는지가 그 낱말들이 어떤 차례로 놓였는지보다 훨씬 많은 것을 말해 준다. 그러므로 차례를 읽는 장치는 벌 것이 별로 없는 곳에 힘을 쓴 셈이다.

!!! warning "이 결론을 넓히면 안 된다"
    "차례는 중요하지 않다"가 아니다. **IMDB 감성 분류에서, 5 에포크 예산으로, 한 겹짜리 구조에서** 그렇다는 것이다.

    셋 다 조건이다. 번역이나 물음 답하기였다면 낱말 주머니로는 시작도 못 한다. 어텐션을 여러 겹 쌓고 예산을 늘리면 3걸음을 넘어선다는 것도 알려져 있다. 이 장이 보인 것은 **그 넘어섬이 공짜가 아니라는 것**이다.

    [4장](../ch04/index.md)이 같은 주의를 그림에서 적었다. MNIST만 보면 합성곱이 1.50%포인트짜리 다듬기로 보이지만 CIFAR-10에서는 20.78%포인트를 번다. 자료가 바뀌면 순위가 바뀐다.

**연습문제 1.** <span class="diff easy" title="쉬움"></span>
`self.pos`를 빼면 이 모델은 무엇과 같아지는가? 정확도가 어떻게 될지 어림하라.

</div>

??? success "연습문제 1 풀이"
    **[3걸음](03_embedding.md)과 거의 같아진다.**

    자리 박아 넣기가 없으면 어텐션은 입력 낱말들을 뒤섞어도 같은 값을 낸다. 낱말 주머니를 받아 서로 섞은 뒤 평균내는 것이므로, 3걸음의 평균에 "낱말끼리 한 번 섞는 층"을 하나 얹은 꼴이다.

    그러므로 정확도는 **87% 언저리**로 오르거나 비슷할 것이라 어림할 수 있다. 본문의 86.11%보다 낮아지지는 않을 가능성이 높다. 차례 정보를 잃지만, 애초에 이 일감에서 차례가 벌어 주는 것이 0 이하였기 때문이다.

    이것을 재어 보는 것이 본문 주장을 시험하는 가장 곧은 길이다. **자리 박아 넣기를 뺐는데 값이 오른다면**, 차례를 읽는 장치가 이 일감에서 짐이었다는 뜻이 된다.

<div class="drillbox" markdown>

**연습문제 2.** <span class="diff normal" title="중간"></span>
본문은 LSTM의 퍼짐 4.75를 "출력까지의 길이가 길어서"로 설명했다. 이 설명이 맞다면, LSTM의 구조를 어떻게 고쳤을 때 퍼짐이 줄어야 하는가? 두 가지를 적어라.

</div>

??? success "연습문제 2 풀이"
    **하나, 모든 상태를 평균내어 쓴다.** 마지막 상태 하나만 쓰는 대신 400칸에서 나온 상태를 모두 평균내면, 낱말마다 출력까지 가는 짧은 길이 하나씩 생긴다. 어텐션이 지닌 성질을 LSTM에 옮기는 셈이다.

    **둘, 양방향으로 읽는다.** 왼쪽에서도 오른쪽에서도 읽으면 어떤 낱말이든 두 끝 가운데 가까운 쪽까지의 거리로 줄어든다. 최대 400이 최대 200이 된다.

    두 고침 모두 **길을 짧게 만드는 것**이고, 본문의 설명이 맞다면 둘 다 퍼짐을 줄여야 한다. 줄지 않는다면 길이가 원인이 아니라는 뜻이므로, 이 설명을 버려야 한다.

    반대로 길을 **더 길게** 만드는 고침(층을 더 쌓아 400칸을 두 번 거치게 하는 것)은 퍼짐을 키워야 한다. 예측이 양쪽으로 서는 설명이 좋은 설명이다.

**연습문제 3.** <span class="diff hard" title="어려움"></span>
이 장의 사다리에서 3걸음이 꼭대기였다. 그렇다면 "차례를 보는 장치는 쓸모없다"고 적어도 되는가? 적으면 안 된다면, 이 표로 적을 수 있는 가장 강한 문장은 무엇인가?

</div>

??? success "연습문제 3 풀이"
    **적으면 안 된다.** 이 표가 재지 않은 것이 셋이다.

    **하나, 다른 일감을 재지 않았다.** IMDB 감성 분류는 낱말 하나하나가 판정을 거의 결정한다. 번역에서는 "개가 사람을 물었다"와 "사람이 개를 물었다"가 다른 문장이므로 낱말 주머니로는 시작조차 못 한다.

    **둘, 다른 예산을 재지 않았다.** 5 에포크다. [4장](../ch04/index.md)이 세 번 보인 대로 예산을 바꾸면 부호가 뒤집힐 수 있고, LSTM은 퍼짐 4.75로 그 의심을 직접 드러냈다.

    **셋, 다른 크기를 재지 않았다.** 어텐션 한 겹이다. 여러 겹 쌓은 것은 재지 않았다.

    그러므로 적을 수 있는 가장 강한 문장은 조건을 모두 달고 있어야 한다.

    > IMDB 감성 분류에서, 5 에포크 예산으로, 한 겹짜리 구조로는, 차례를 읽는 장치가 낱말 벡터의 평균을 넘지 못한다.

    길고 재미없어 보이지만 **이것이 잰 것의 전부**다. 여기서 조건을 하나라도 떼면 재지 않은 것을 주장하게 된다.

    그리고 이 문장도 쓸모가 있다. 새 일감을 만났을 때 **가장 단순한 것을 먼저 재어 보라**는 뜻이기 때문이다. 이 장에서 그것은 40,002개짜리 선형 모델이 78.80%를 낸 자리였고, 백만 개가 넘는 모델 둘이 그 위에서 자리다툼을 했다.
