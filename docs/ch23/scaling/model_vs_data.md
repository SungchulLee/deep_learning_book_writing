# 모델 크기와 학습 데이터의 트레이드오프

같은 학습 계산량에서도 파라메터를 늘릴지 토큰을 더 학습할지 선택해야 한다. 학습 로스를 최소화하는 선택과 배포 후 전체 비용·지연·품질을 만족하는 선택은 다를 수 있다. 토큰/파라메터 비율은 구성의 요약이지 과적합·품질·최적성을 혼자 결정하는 지표가 아니다.

## 1. 학습량과 계산 최적성

[Chinchilla 연구](https://arxiv.org/abs/2203.15556)는 당시 큰 모델을 주어진 계산 예산에서 상대적으로 적은 토큰으로 학습하는 경향을 재검토했다. 700억 파라메터·1.4조 토큰의 D/N=20은 그 연구의 대표 구성이지 보편적인 경계값이 아니다.

D/N이 작다고 곧바로 과적합이라고 진단할 수 없다. 같은 계산의 더 작은 모델을 더 오래 학습한 쪽이 나을 수 있다는 계산 배분 문제와, 학습·검증 로스 차이로 확인하는 과적합은 다르다. 반대로 D/N이 크다는 ‘overtraining’ 표현도 반드시 학습이 망가졌다는 뜻은 아니다. 여기서는 학습 계산만의 최적점보다 더 많은 토큰을 쓴다는 상대적 의미로 구분한다.

10·20·50 같은 비율로 모든 모델을 세 구간으로 분류하거나 덜 학습된 구성을 절대 사용하지 말라고 단정하지 않는다. 목적·자료·모델·일정·자원에 맞춘 로스와 비용을 확인해야 한다.

## 2. 전체 비용과 추론 사용량

학습 비용에 요청당 추론 비용을 더한 단순 모형을 생각할 수 있다.

$$C_{\mathrm{total}}=C_{\mathrm{train}}(N,D)+K\,C_{\mathrm{infer}}(N,\ell_{\mathrm{in}},\ell_{\mathrm{out}},\text{실행 조건}).$$

K는 정한 운영 기간의 총 요청 수다. FLOPs·시간·금액 중 무엇을 비용 단위로 쓰는지 통일해야 한다. 추론은 파라미터 수뿐 아니라 입력·출력 길이, batch·cache·정밀도·통신과 하드웨어 이용률에도 달려 있다.

[추론을 고려한 스케일링 연구](https://arxiv.org/abs/2401.00448)는 이런 운영 비용이 학습 계산만의 최적 배분을 바꿀 수 있음을 다룬다. 사용량이 많으면 작고 충분히 학습한 모델이 유리할 수 있지만 요구 품질을 못 채우면 비용만으로 선택할 수 없다. 작은 모델이 항상 더 빠르거나 전체적으로 더 싸다는 법칙도 아니다.

## 3. 고유 데이터와 반복 토큰

학습에 사용한 총 토큰 수는 고유 토큰 수와 다르다. 같은 문서를 여러 번 읽으면 일부 학습 신호를 더 얻을 수 있지만 새 정보량이 같은 비율로 증가하지는 않는다. [데이터가 제한된 언어 모델 연구](https://arxiv.org/abs/2305.16264)는 반복과 자원 배분을 함께 분석했다.

반복의 이득·포화·악화는 원문 양·질·모델·러닝레이트 일정과 예산에 따라 달라진다. ‘웹 데이터는 4에포크부터 반드시 악화된다’는 보편적 규칙으로 읽지 않는다. 중복·노이즈·오염을 확인하고 여러 반복 횟수의 검증 로스·유형별 품질을 비교한다.

필터링이 자료를 줄이면서 분포를 바꿀 수 있으므로 고품질이라는 이름만으로 모든 과제에 더 좋다고 가정하지 않는다. 특히 특정 분야 자료만 반복하면 다른 언어·과제의 성능과 강건성도 함께 확인해야 한다.

## 4. 크기 선택 함수의 실제 범위

```python
def recommend_model_size(
    queries_per_day: int,
    latency_requirement_ms: float,
    accuracy_priority: str,
) -> dict:
    if accuracy_priority == "high" and latency_requirement_ms > 5000:
        return {"size": "70B+", "regime": "chinchilla-optimal",
                "note": "Use for deep analysis, report generation"}
    elif queries_per_day > 100_000 or latency_requirement_ms < 500:
        return {"size": "7-13B", "regime": "over-trained",
                "note": "Over-train on domain data; quantize for deployment"}
    else:
        return {"size": "13-34B", "regime": "slightly over-trained",
                "note": "Good balance for most finance workloads"}
```

recommend_model_size는 요청 수·지연 기준·문자열 우선순위로 고정 범주를 반환한다. 모델·하드웨어·입출력 길이의 실측이나 로스 적합이 없으며 임계값·크기 범위는 검증된 추천이 아니다. 첫 high 분기가 뒤의 요청량 조건보다 먼저 적용되므로 많은 요청이라도 70B+를 반환할 수 있다.

accuracy_priority의 유효 값·양의 요청 수·지연 등 입력 검사도 없다. 함수가 출력한 ‘chinchilla-optimal’이나 ‘over-trained’ 레이블만으로 실제 학습 이력과 최적성을 알 수 없다. 특정 분야의 모든 작업에 7~13B나 13~34B가 맞는다고 제시하지 않는다.

## 5. 실제 선택 절차

목표 과제의 품질·유보·오류 허용 범위와 지연·메모리·운영 기간의 사용량을 먼저 정한다. 여러 후보를 같은 자료·프롬프트·길이·정밀도와 실제 실행 환경에서 비교한다. 학습·추론 비용과 데이터 확보·검증·유지 비용을 함께 고려해 선택한다.

출시 논문에 공개되지 않은 특정 모델의 토큰 수를 추측해 D/N을 계산하지 않는다. 파라미터 수만으로 능력이나 데이터를 대체하는 정도도 결정할 수 없다. 외부 API·직접 운영·양자화·증류 등 선택은 같은 목표를 충족하는지 검증한 뒤 비교한다.

**연습문제 1.** <span class="diff med" title="중간"></span>
D/N이 작은 모델을 반드시 과적합이라고 할 수 없는 이유를 설명하라.

</div>

??? success "풀이"

    D/N은 총 학습 토큰과 파라미터 수의 비율이다. 과적합은 학습 대비 검증 일반화의 악화로 확인해야 하며 비율만으로 결정되지 않는다. 계산 최적점보다 토큰이 적다는 판단도 자료·스케줄·적합한 로스식의 조건에 따른다.

<div class="drillbox" markdown>

**연습문제 2.** <span class="diff med" title="중간"></span>
학습 최적과 운영 최적이 달라질 수 있는 상황을 설명하라.

</div>

??? success "풀이"

    많은 요청에서 작은 모델의 낮은 요청당 비용이 추가 학습 비용을 상쇄할 수 있다. 반대로 요청이 적거나 작은 모델이 품질을 못 채우면 다른 선택이 낫다. 운영 기간의 K, 같은 비용 단위와 입력·출력 길이·실행 조건을 맞춰 총비용을 비교해야 한다.



---

<div class="drillbox" markdown>

**연습문제 3.** <span class="diff med" title="중간"></span>

</div>

??? success "풀이"

    고정 if 분기에는 모델별 품질·실제 지연·하드웨어·길이·운영 비용 측정이 없다. 초기 우선순위 분기가 뒤 조건을 가릴 수도 있다. 대표 자료의 독립 품질 평가와 실제 환경의 지연·메모리·비용, 요구 조건을 충족한 후보 간 비교가 필요하다.



## 정리하며

모델과 데이터의 비율은 학습·일반화·운영 비용을 함께 검토하기 위한 한 정보다. 고정 구간·고정 크기 추천을 피하고 고유 데이터와 반복, 학습 최적과 전체 운영 최적을 구분한다.
