# 대화형 AI 도입 시나리오

이 절은 금융 고객 지원, 의료 행정 지원, 전자상거래 고객 지원에서 대화형 AI를 설계하는 세 가지 **가상 시나리오**를 살펴본다. 원문에는 기관명·평가 기간·측정 방법·출처가 없는 개선 수치가 제시되어 있어 검증된 실증 사례로 사용할 수 없다. 여기서는 구조와 평가 질문을 설명하는 예시로 범위를 명확히 한다.

## 1. 금융 고객 지원

은행의 상품 안내와 계좌 조회를 돕는 상황을 생각해 보자. 상품 문서는 검색 증강 생성(RAG)으로 찾고, 계좌 잔액처럼 사용자의 권한과 현재 상태에 따른 정보는 인증된 API에서 조회한다. 검색한 문서와 개인 계좌 데이터는 출처·접근 권한·갱신 시점이 다르므로 같은 지식 저장소처럼 처리하지 않는다.

```
User Query → Intent Classification → Knowledge Retrieval → LLM Generation → Compliance Filter → Response
```

위 흐름도는 의도 분류→정보 검색→답변 생성→검사→응답의 개념적 구조다. 검사 단계가 있다는 사실만으로 답변의 사실성이나 규정 적합성이 보장되는 것은 아니다. 계좌 조회와 이체 실행은 서로 다른 권한과 부작용을 가지므로 요청 해석, 인증, 대상·금액 확인, 실행 결과 기록을 구분해 설계한다.

평가에는 정확한 답변 비율, 해결률, 응답 지연의 분포, 사람 상담으로의 전환, 잘못된 계좌 정보 제공이나 의도하지 않은 처리 건수를 포함할 수 있다. 상담원 대비 몇 초 빨랐다는 평균만으로 고객 문제를 정확히 해결했다고 결론 내릴 수 없다. 비용도 모델 사용료뿐 아니라 통합·감사·오류 처리와 운영 인력을 포함해 비교한다.

## 2. 의료 행정 지원

진료 예약, 방문 전 서류 안내, 예약 알림처럼 행정 업무를 돕는 상황을 생각해 보자. 일정과 안내문은 승인된 업무 시스템과 문서에서 가져오고, 진료 판단이 필요한 질문은 별도의 전문 인력 대응으로 연결하도록 범위를 정할 수 있다.

행정 자동화와 증상에 대한 임상 판단은 평가 목적과 실패 비용이 다르다. 모델이 스스로 표현한 확신만으로 임상적 안전성을 판정할 수 없으며, 지식 그래프나 규칙 검사를 추가했다는 이유만으로 전문적인 판단 성능을 입증할 수도 없다. 이 가상 시나리오는 환자 진료 지침이나 특정 지역의 법규 준수 여부를 제시하는 사례가 아니다.

예약 완료율, 중복·오예약, 안내의 정확성, 알림 수신 동의, 사람에게 연결되는 시간 등을 정의해 평가할 수 있다. 예약 불참률의 변화를 보려면 비교 기간, 대상 환자와 진료 종류, 다른 운영 변화도 고려해야 한다. 전후 수치가 달라졌다는 사실만으로 AI 도입의 인과 효과라고 단정하지 않는다.

## 3. 전자상거래 고객 지원

주문 상태, 반품 조건과 배송 문의를 처리하는 상황에서는 의도 분류, 개체명 추출, API 연동을 결합할 수 있다. 주문 번호·상품명·날짜를 추출하고 사용자의 주문에 접근할 권한을 확인한 뒤, 실제 주문 상태와 폴리시 문서에 근거해 답변한다.

환불 가능 여부 안내와 환불 실행은 다르다. 상품 데이터의 가격·재고·배송 상태도 바뀌므로 모델이 기억한 정보와 현재 API 결과를 구분한다. 답변의 친절함뿐 아니라 정확한 해결, 불필요한 재문의, 잘못된 환불과 사용자 불만을 함께 측정한다.

추천이 고가 상품에 치우친다면 가격대·노출·재고·사용자 조건별로 조사해야 한다. 후기의 문체나 학습 데이터 때문이라고 추정할 수 있어도 원인 분석 없이 단정하지 않는다. 모델, 검색·추천 순위와 사업 규칙이 모두 바이어스에 영향을 줄 수 있다.

## 4. 공통 설계와 평가 질문

세 시나리오에서 반복되는 질문은 다음과 같다.

- 어떤 업무를 지원하며 어떤 조건에서 사람에게 연결하는가?
- 조회하는 정보의 출처·갱신 시점·사용자 권한을 어떻게 확인하는가?
- 외부 문서의 문장과 실행 권한을 어떻게 구분하는가?
- 해결률과 실패율의 분모, 측정 기간 및 비교 기준은 무엇인가?
- 재문의·정정·민원과 사람에게 이관된 건까지 평가에 포함하는가?

RAG와 API 연결은 근거를 제공하지만 오류를 제거하지는 않는다. 사람에게 연결할 때는 업무에 필요한 맥락을 전달하되 불필요한 개인정보 공유를 피하도록 설계한다. 모델의 확신, 키워드 탐지나 자동 필터 하나만을 완전한 판정기로 사용하지 않는다.

배포 뒤에는 요청 분포, 문서·폴리시, 모델 버전과 실패 사례를 추적한다. 변경 시 재평가하고 이전 버전으로 복구할 수 있어야 한다. 지속적인 모니터링이 필요하다는 사실이 매번 모델 재학습이 필요하다는 뜻은 아니다. 검색 데이터나 업무 규칙의 갱신만으로 해결할 문제와 모델 변경이 필요한 문제를 구분한다.

## 정리하며

대화형 AI 도입은 모델 선택뿐 아니라 정보 출처, 업무 권한, 사람에게 연결하는 흐름과 평가 설계를 포함한다. 가상 설계와 실증 성과를 구분하고 출처 없는 개선 수치를 실제 도입 효과로 보고하지 않는다.
