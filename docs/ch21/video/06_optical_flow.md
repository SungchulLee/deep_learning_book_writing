# 옵티컬 플로우의 의미와 추정 조건

옵티컬 플로우는 연속 프레임 사이에서 영상의 무늬가 이동한 것으로 추정되는 2차원 벡터장이다. 객체의 실제 3차원 속도와 같지 않으며 카메라 움직임·깊이·투영·조명·가림의 영향을 받는다. 이 페이지의 기존 코드는 메시지만 출력하고 flow 계산은 구현하지 않는다. 계산 예는 [Two-Stream 절](05_two_stream_network.md)의 Farnebäck 함수를 참고한다.

## 1. 기존 코드와 출력

```python
"""빛 흐름 셈하기"""
import torch

# ========================================================================
# 메인
# ========================================================================
print("Optical Flow Computation module")


if __name__ == "__main__":
    pass
```

**기존 출력:**

```
Optical Flow Computation module
```

메시지 출력은 알고리즘 실행·흐름 추정·정확도 평가의 증거가 아니다. 아래는 구현을 읽기 전에 이해할 개념이다.

## 2. 좌표와 밝기 불변 가정

첫 프레임의 위치 (x,y)가 다음 프레임의 (x+u,y+v)에 대응한다고 할 때 flow는 (u,v)다. 일반적인 영상 좌표에서 x는 오른쪽, y는 아래쪽으로 증가한다. 프레임 간격을 따로 나누지 않은 값은 보통 픽셀/프레임 쌍의 이동량이며 m/s 단위의 속도가 아니다. 다른 fps·stride에서 얻은 크기는 관측 시간 간격과 함께 비교한다.

밝기가 보존되고 변화가 작다고 근사하면 다음 제약을 얻는다.

$$I_xu+I_yv+I_t=0.$$

한 픽셀에서 미지수는 u,v 두 개인데 식은 하나이므로 이 식만으로 flow를 정할 수 없다. 직선 경계의 접선 방향 운동을 구분하기 어려운 aperture problem이나 무늬 없는 영역의 불확실성이 생긴다. 이웃 운동의 일관성·부드러움·피라미드·학습된 사전 등 추가 정보가 필요하다.

## 3. 희소·밀집 추정과 실패 사례

희소 추정은 선택한 특징점의 이동을, 밀집 추정은 넓은 픽셀 격자의 벡터를 구한다. 밀집 출력이라는 이유만으로 모든 픽셀에 신뢰할 수 있는 대응점이 있다는 뜻은 아니다. 가려지거나 새로 나타난 영역에는 실제 일대일 대응이 없을 수 있다.

[OpenCV 흐름 설명](https://docs.opencv.org/4.x/d4/dee/tutorial_optical_flow.html)의 Lucas–Kanade·Farnebäck 등은 입력 표현과 가정을 확인해 사용한다. 큰 이동·motion blur·반복 무늬·밝기 변화·가림은 추정 오차를 키울 수 있다. 정지 카메라를 가정하지 않으면 배경 flow도 나타나므로 벡터 크기만으로 움직이는 객체를 판정하지 않는다.

## 4. 네트워크 입력과 시각화

H×W×2의 flow를 채널 우선 2×H×W로 옮기고 연속 L개 쌍을 쌓으면 2L×H×W가 된다. 어떤 프레임 사이의 flow인지와 채널 순서를 고정해야 하며 L쌍에는 보통 L+1개의 원본 프레임이 필요하다. 실제 추정값의 범위·정규화와 학습 모델이 기대하는 분포도 맞춘다.

방향을 색상, 크기를 밝기로 표시할 수 있지만 그림별 min-max 정규화는 절대 크기를 감춘다. 좌우 반사·resize에는 벡터 부호와 각 축 크기의 변환이 필요하다. 시간 역방향 flow는 단순히 같은 좌표에서 순방향 벡터의 음수를 취한 것과 일반적으로 다르다.

## 5. 평가와 계산비용

정답 흐름이 있으면 유효 픽셀의 endpoint error 등으로 벡터 오차를 계산할 수 있다. 분류기가 flow를 입력으로 쓴다면 행동 인식 성능과 흐름 자체의 추정 오차는 별도 지표다. 그림이 그럴듯하거나 분류 정확도가 높다는 것만으로 flow 정확도가 검증되지는 않는다. 사전 계산하면 학습 중 비용을 옮길 수 있지만 저장 공간·원본과의 정렬·전체 시스템의 추론 비용은 남는다.

    def test_module 34():

        out = model(normal_input)

        for p in model.parameters():

## 정리하며

옵티컬 플로우는 프레임 쌍의 2차원 대응 이동이며 물리적 속도나 객체 운동과 동일하지 않다. 시간 간격·벡터 단위·추정 가정과 가림을 이해하고 네트워크 입력·시각화·평가에서 같은 정의를 유지한다. 기존 코드는 계산 구현이 아닌 시작용 파일이다.
