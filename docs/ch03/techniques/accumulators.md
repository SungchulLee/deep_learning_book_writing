# 누적자를 이용한 재귀

**누적자(accumulator)** 는 재귀 호출을 거치며 중간 결과를 나르는 추가 매개변수이다. (표준 재귀처럼) 기저 사례에서 되돌아오는 길에 답을 쌓아 올리는 대신, 누적자 기반 재귀는 *내려가는* 길에 답을 쌓는다. 그러면 재귀 호출이 마지막 연산이 되어 꼬리 재귀가 가능해진다.

---

## 1. 표준 방식과 누적자 방식

계승을 계산하는 경우를 생각해 보자. 표준 재귀는 재귀 호출이 반환된 *뒤에* 곱셈을 한다.

```python
def factorial(n):
    if n <= 1:
        return 1
    return n * factorial(n - 1)  # 곱셈이 반환을 기다린다
```

누적자를 쓰면 곱셈이 재귀 호출 *전에* 일어난다.

```python
"""계승으로 보여주는 누적자 기반 재귀."""

# === 누적자를 쓰는 계승 ===

def factorial_acc(n, acc=1):
    """중간 곱을 나르는 누적자로 n!을 계산한다."""
    if n <= 1:
        return acc
    return factorial_acc(n - 1, acc * n)  # 결과를 앞으로 나른다

# === 메인 ===

if __name__ == "__main__":
    for n in [0, 1, 5, 10]:
        print(f"{n}! = {factorial_acc(n)}")
```

**출력:**
```
0! = 1
1! = 1
5! = 120
10! = 3628800
```

---

## 2. 누적자의 동작 방식

표준 재귀에서는 호출 스택이 프레임을 풀어 가며 수행할 대기 연산(곱셈, 덧셈)을 담고 있다. 누적자를 쓰면 대기 연산이 없다. 현재 결과가 언제나 누적자 매개변수 안에 있다.

| 호출 | `n` | `acc` |
|---|---|---|
| `factorial_acc(5, 1)` | 5 | 1 |
| `factorial_acc(4, 5)` | 4 | 5 |
| `factorial_acc(3, 20)` | 3 | 20 |
| `factorial_acc(2, 60)` | 2 | 60 |
| `factorial_acc(1, 120)` | 1 | 120 → 반환 |

---

## 3. 이점

누적자 방식의 재귀는 **꼬리 재귀** 이다. 재귀 호출이 마지막 연산이고 대기 중인 계산이 없다. 꼬리 호출 최적화를 지원하는 언어는 현재 스택 프레임을 재사용하여 $O(n)$의 스택 사용을 $O(1)$로 바꿀 수 있다.

## 연습문제

**연습문제 1.**
누적자를 이용한 재귀에 대해 기저 사례와 재귀 사례를 찾아라. 모든 유효한 입력에 대해 재귀가 종료됨을 증명하라.

??? success "연습문제 1 풀이"
    기저 사례는 가장 작은 유효한 입력을 직접 처리한다. 재귀 사례는 호출마다 감소하는 잘 정의된 척도로 문제 크기를 줄인다. 이 척도가 (기저 사례의 문턱값으로) 아래로 유계이면서 엄격히 감소하므로 재귀는 반드시 유한한 단계 안에 종료된다.

---

**연습문제 2.**
누적자를 이용한 재귀의 시간 복잡도에 대한 점화식을 유도하고 풀어라.

??? success "연습문제 2 풀이"
    $T(n)$을 재귀 호출과 호출당 일의 함수로 표현한다. 이 점화식은 분기 계수, 부분문제 크기의 감소, 결합 비용을 담는다. 펼치기, 마스터 정리, 치환 중 하나로 풀어 닫힌 형태를 얻는다.

---

**연습문제 3.**
$n = 8$일 때 누적자를 이용한 재귀의 재귀 트리를 그려라. 각 층에서의 일과 전체 일을 계산하라.

??? success "연습문제 3 풀이"
    트리의 깊이는 입력이 기저 사례까지 얼마나 빨리 줄어드는지로 정해진다. 각 층에서 모든 노드의 일을 더한다. 모든 층에 걸친 총합이 실행 시간을 준다. $n = 8$이면 트리가 작아서 전부 열거할 수 있다.

---

**연습문제 4.**
재귀 구현을 반복 버전으로 변환하라. 공간 복잡도를 비교하라.

??? success "연습문제 4 풀이"
    호출 스택을 명시적 스택이나 반복 변수로 대체한다. 꼬리 재귀 형태는 while 반복문으로 곧바로 바뀐다. 꼬리가 아닌 형태는 호출 스택을 흉내 내기 위해 명시적 스택이 필요하다. 반복 버전은 보통 $O(\text{depth})$의 스택 공간을 아낀다.
