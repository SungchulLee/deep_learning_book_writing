# 선형 모델

---

## 1. 학습 목표

이 쪽을 마치면 다음을 할 수 있게 된다.

- $y = xA + b$가 MNIST에서 무엇을 뜻하는지 설명하기
- 찾아야 할 수가 7,850개인 까닭을 층별로 세어 보이기
- 이 모델이 [1단계 템플릿 학습](../mnist/01_template_learning.md)과 같은 얼개임을 밝히기
- 이미지를 펼치는 순간 무엇을 잃는지 말하기

---

## 2. 모델

28×28 이미지를 784차원 벡터로 펼치고, 아핀 변환으로 클래스마다 점수 하나씩을 만든다.

$$
y = xA + b, \qquad A \in \mathbb{R}^{784 \times 10}, \quad b \in \mathbb{R}^{10}
$$

여기서 $x$는 펼친 이미지, $y$는 길이 10의 벡터이고 $y_k$가 "이 이미지가 숫자 $k$일 듯한 정도"를 나타내는 점수다. 이 점수를 **로짓**(logit)이라 부른다.

찾아야 할 수를 세어 보자.

| | 개수 |
|---|---|
| 가중치 $A$ | $784 \times 10 = 7{,}840$ |
| 편향 $b$ | $10$ |
| 합 | **$7{,}850$** |

모델의 정의는 여기서 끝이다. 남은 것은 이 7,850개의 수를 정하는 일뿐이며, 그것이 이 절의 나머지 다섯 쪽이 하는 이야기다.

!!! note "행과 열의 관례"
    수식에서는 $y = xA + b$로 적어 $A$를 $(784, 10)$으로 두었지만, PyTorch의 `nn.Linear(784, 10)`은 가중치를 $(10, 784)$로 저장하고 $y = xA^{\top} + b$를 계산한다. 담긴 수는 같고 늘어놓은 방향만 다르다. 자세한 것은 [Linear 가중치 관례](../../ch06/tensor_attrs/05_linear_weight_convention.md)에 있다.

---

## 3. 1단계와 같은 얼개다

[1단계 템플릿 학습](../mnist/01_template_learning.md)에서 제곱 거리 규칙을 전개하면 다음을 얻었다.

$$
\arg\min_k \lVert x - \overline{x}_k \rVert^2
= \arg\max_k \left( x^{\top}\overline{x}_k - \tfrac{1}{2}\lVert \overline{x}_k \rVert^2 \right)
$$

오른쪽은 가중치가 $w_k = \overline{x}_k$이고 편향이 $b_k = -\tfrac{1}{2}\lVert \overline{x}_k \rVert^2$인 **선형 분류기**다. 곧 1단계는 이미 이 쪽의 모델이었고, 다만 7,850개의 수가 다음처럼 **못박혀** 있었다.

| | 1단계 템플릿 학습 | 2단계 선형 모델 |
|---|---|---|
| $A$의 각 열 | 클래스 평균 $\overline{x}_k$ | 학습한다 |
| $b$의 각 성분 | $-\tfrac{1}{2}\lVert \overline{x}_k \rVert^2$ | 학습한다 |
| 매개변수 수 | 7,850 | 7,850 |
| 시험 정확도 | 82.03% | 92.51% |

**매개변수의 수가 같다.** 모델을 키우지도, 층을 쌓지도 않았다. 같은 수를 데이터에 맞추어 움직인 것만으로 10%포인트를 넘게 얻는다. 이 절이 보이려는 것이 바로 그 몫이다.

---

## 4. 펼치는 순간 잃는 것

`x.view(-1, 784)`로 이미지를 펼치는 일은 값을 하나도 버리지 않는다. 784개 숫자가 그대로 784개로 남는다. 그런데 **어느 화소가 어느 화소 옆에 있었는지**는 사라진다.

이것이 말뿐인 손실이 아님을 보이는 방법이 있다. 모든 이미지의 화소를 **같은 순서로** 뒤섞어 보는 것이다. 사람 눈에는 알아볼 수 없는 잡음이 되지만, 이 모델의 정확도는 전혀 달라지지 않는다. 순열은 $A$의 행을 맞바꾸는 것과 같고, 학습은 맞바꾼 자리에서 같은 값을 찾아내면 되기 때문이다(연습문제 6).

곧 이 모델은 입력을 **순서 없는 784개 숫자 꾸러미**로 본다. 이웃 관계를 되찾는 일은 [3.4 합성곱 신경망](../mnist/04_cnn.md)의 몫이다.

---

## 5. 이 모델이 그릴 수 있는 경계

로짓이 $x$의 아핀 함수이므로, 클래스 $i$와 $j$를 가르는 자리는

$$
x^{\top}(a_i - a_j) + (b_i - b_j) = 0
$$

곧 **초평면**이다. 784차원 공간을 평평한 칼로 자르는 것이 이 모델이 할 수 있는 전부다.

그래서 이 모델의 한계도 미리 알 수 있다. 한 클래스가 서로 떨어진 두 덩이로 나타나야 하는 자료라면 담을 수 없다. MNIST에서 이것이 실제로 걸림돌이 되는지는 연습문제 11에서 재어 보고, 그 제약을 푸는 일은 [3.3 다층 퍼셉트론](../mnist/03_mlp.md)이 맡는다.

## 6. 세 주장을 수로 확인한다

앞의 다섯 절이 주장을 셋 했다. 매개변수가 7,850개라는 것, 1단계가 이미 이 모델이었다는 것, 화소를 뒤섞어도 달라지지 않는다는 것이다. 셋 다 돌려 보면 곧바로 보인다.

```python
"""선형 모델 절의 주장 셋을 수로 확인한다.

    주장 1  찾아야 할 수가 7,850개다
    주장 2  1단계 템플릿 학습은 **이미 이 쪽의 모델**이었다 (수가 못박혀 있었을 뿐)
    주장 3  화소를 뒤섞어도 정확도가 달라지지 않는다 (= 이웃 관계를 안 쓴다)
"""

import numpy as np
import torch
import torch.nn as nn
import torch.optim as optim
from torch.utils.data import DataLoader, TensorDataset
import torchvision
import torchvision.transforms as transforms

SEED, BATCH, LR, EPOCHS = 42, 128, 1e-3, 10
MEAN, STD = 0.1307, 0.3081

# 자료를 한 번만 읽어 텐서로 펼쳐 둔다 (ToTensor만 — 정규화는 뒤에서 따로 건다)
raw = transforms.ToTensor()
tr_ds = torchvision.datasets.MNIST("./data", train=True, download=True, transform=raw)
te_ds = torchvision.datasets.MNIST("./data", train=False, download=True, transform=raw)


def flatten(ds):
    X = torch.stack([x for x, _ in ds]).reshape(len(ds), -1)   # (n, 784)
    y = torch.tensor([y for _, y in ds])
    return X, y


Xtr, ytr = flatten(tr_ds)
Xte, yte = flatten(te_ds)
print(f"자료  학습 {tuple(Xtr.shape)}  시험 {tuple(Xte.shape)}\n")


# ==========================================================================
# 주장 1 — 매개변수는 7,850개
# ==========================================================================
print("=" * 64)
print("주장 1  찾아야 할 수는 7,850개")
print("=" * 64)

model = nn.Linear(784, 10)
n_w = model.weight.numel()
n_b = model.bias.numel()
print(f"  가중치 A : {model.weight.shape[1]} x {model.weight.shape[0]} = {n_w:,}")
print(f"  편향   b : {n_b:,}")
print(f"  합       : {n_w + n_b:,}")
print(f"  torch가 세어 준 값: {sum(p.numel() for p in model.parameters()):,}")


# ==========================================================================
# 주장 2 — 템플릿 학습은 이미 선형 모델이었다
# ==========================================================================
print("\n" + "=" * 64)
print("주장 2  템플릿 학습 = 가중치가 못박힌 선형 모델")
print("=" * 64)

# 클래스마다 평균 이미지를 만든다. 이것이 '템플릿'이다.
means = torch.stack([Xtr[ytr == k].mean(0) for k in range(10)])   # (10, 784)

# (가) 가장 가까운 템플릿을 고르는 규칙 — 1단계가 한 일
d = torch.cdist(Xte, means) ** 2            # (10000, 10) 제곱 거리
pred_nc = d.argmin(1)
acc_nc = 100.0 * (pred_nc == yte).float().mean().item()

# (나) 같은 것을 선형 모델로 적는다.
#     ||x - m_k||^2 을 펴면 ||x||^2 - 2 x·m_k + ||m_k||^2 이고,
#     ||x||^2 은 k에 따라 변하지 않으므로 argmin 에서 빼도 된다. 남는 것은
#         argmax_k ( x·m_k - 0.5||m_k||^2 )
#     곧 A의 열이 m_k, b가 -0.5||m_k||^2 인 선형 분류기다.
A = means.T                                  # (784, 10)
b = -0.5 * (means ** 2).sum(1)               # (10,)
pred_lin = (Xte @ A + b).argmax(1)
acc_lin = 100.0 * (pred_lin == yte).float().mean().item()

print(f"  (가) 가장 가까운 템플릿 고르기      : {acc_nc:.2f}%")
print(f"  (나) A=평균, b=-0.5||평균||^2 인 선형 : {acc_lin:.2f}%")
print(f"  두 방법의 예측이 몇 개나 다른가      : {int((pred_nc != pred_lin).sum())}개")
print("\n  하나도 다르지 않다. 두 식이 같은 것이기 때문이다.")

# 정규화를 걸어도 템플릿 학습의 값이 바뀌지 않는지 확인한다.
#   (x - MEAN)/STD 는 모든 화소에 똑같이 걸리는 아핀 변환이므로
#   거리를 1/STD^2 배로 줄일 뿐, 어느 것이 가장 가까운지는 바꾸지 않는다.
Xtr_n, Xte_n = (Xtr - MEAN) / STD, (Xte - MEAN) / STD
means_n = torch.stack([Xtr_n[ytr == k].mean(0) for k in range(10)])
acc_nc_n = 100.0 * ((torch.cdist(Xte_n, means_n) ** 2).argmin(1) == yte).float().mean().item()
print(f"  정규화를 걸고 다시 재면              : {acc_nc_n:.2f}%  (같아야 한다)")


# ==========================================================================
# 주장 2 (이어서) — 같은 7,850개를 '학습하면' 얼마나 오르는가
# ==========================================================================
def train_linear(X, y, Xt, yt, seed=SEED, epochs=EPOCHS):
    """같은 nn.Linear(784, 10)을 자료에 맞추어 움직인다."""
    torch.manual_seed(seed)
    m = nn.Linear(784, 10)
    opt = optim.Adam(m.parameters(), lr=LR)
    crit = nn.CrossEntropyLoss()
    g = torch.Generator().manual_seed(seed)
    ld = DataLoader(TensorDataset(X, y), batch_size=BATCH, shuffle=True, generator=g)
    for _ in range(epochs):
        m.train()
        for xb, yb in ld:
            opt.zero_grad(); crit(m(xb), yb).backward(); opt.step()
    m.eval()
    with torch.no_grad():
        return 100.0 * (m(Xt).argmax(1) == yt).float().mean().item()


acc_trained = train_linear(Xtr_n, ytr, Xte_n, yte)
print(f"\n  같은 7,850개를 **학습하면**          : {acc_trained:.2f}%")
print(f"  못박아 두었을 때와의 차이            : {acc_trained - acc_nc:+.2f}%포인트")
print("\n  매개변수의 수는 그대로다. 값을 자료에 맞추어 움직인 몫이다.")


# ==========================================================================
# 주장 3 — 화소를 뒤섞어도 정확도가 그대로다
# ==========================================================================
print("\n" + "=" * 64)
print("주장 3  화소를 뒤섞어도 달라지지 않는다")
print("=" * 64)

# 모든 이미지에 **같은** 순열을 건다. 사람 눈에는 잡음이 되지만
# 784개 숫자 꾸러미로서는 이름표만 바뀐 셈이다.
g = torch.Generator().manual_seed(0)
perm = torch.randperm(784, generator=g)
Xtr_p, Xte_p = Xtr_n[:, perm], Xte_n[:, perm]

acc_shuf = train_linear(Xtr_p, ytr, Xte_p, yte)
print(f"  뒤섞지 않은 자료 : {acc_trained:.2f}%")
print(f"  뒤섞은 자료      : {acc_shuf:.2f}%")
print(f"  차이             : {acc_shuf - acc_trained:+.2f}%포인트")
print("\n  순열은 A의 행을 맞바꾸는 것과 같고, 학습은 맞바꾼 자리에서")
print("  같은 값을 찾아내면 된다. 곧 이 모델은 입력을 **순서 없는**")
print("  784개 숫자 꾸러미로 본다. 이웃 관계는 쓰지 않는다.")
```

**출력:**

```
자료  학습 (60000, 784)  시험 (10000, 784)

================================================================
주장 1  찾아야 할 수는 7,850개
================================================================
  가중치 A : 784 x 10 = 7,840
  편향   b : 10
  합       : 7,850
  torch가 세어 준 값: 7,850

================================================================
주장 2  템플릿 학습 = 가중치가 못박힌 선형 모델
================================================================
  (가) 가장 가까운 템플릿 고르기      : 82.03%
  (나) A=평균, b=-0.5||평균||^2 인 선형 : 82.03%
  두 방법의 예측이 몇 개나 다른가      : 0개

  하나도 다르지 않다. 두 식이 같은 것이기 때문이다.
  정규화를 걸고 다시 재면              : 82.03%  (같아야 한다)

  같은 7,850개를 **학습하면**          : 92.42%
  못박아 두었을 때와의 차이            : +10.39%포인트

  매개변수의 수는 그대로다. 값을 자료에 맞추어 움직인 몫이다.

================================================================
주장 3  화소를 뒤섞어도 달라지지 않는다
================================================================
  뒤섞지 않은 자료 : 92.42%
  뒤섞은 자료      : 92.40%
  차이             : -0.02%포인트

  순열은 A의 행을 맞바꾸는 것과 같고, 학습은 맞바꾼 자리에서
  같은 값을 찾아내면 된다. 곧 이 모델은 입력을 **순서 없는**
  784개 숫자 꾸러미로 본다. 이웃 관계는 쓰지 않는다.
```

**주장 1**은 셈하면 끝이다. $784 \times 10 + 10 = 7{,}850$.

**주장 2가 이 절에서 가장 중요한 자리다.** 가장 가까운 템플릿을 고르는 규칙과, $A$ 의 열을 클래스 평균으로 $b$ 를 $-\tfrac{1}{2}\lVert \overline{x}_k \rVert^2$ 으로 못박은 선형 모델이 **예측을 하나도 다르게 하지 않는다.** 1만 장 가운데 0개다.

"비슷하다"가 아니라 "같다"인 까닭은 3절의 전개가 **항등식**이기 때문이다. $\lVert x \rVert^2$ 이 $k$ 에 따라 변하지 않아 $\arg\max$ 에서 빠지는 것, 그것이 전부다. 코드는 그 전개를 그대로 옮겨 적었을 뿐이다.

그리고 같은 7,850개를 **학습하면** 92.42%가 된다. 못박아 두었을 때보다 10.39%포인트 높다. 모델을 키우지도 층을 쌓지도 않았다.

!!! note "정규화를 걸어도 82.03%인 까닭"
    [1단계](../mnist/01_template_learning.md)는 `ToTensor`만 쓰고 이 절은 `Normalize`를 더 쓴다. 전처리가 다른데 82.03%와 92.51%를 나란히 놓아도 괜찮은가?

    괜찮다. 위 출력이 보이듯 정규화를 걸어도 템플릿 학습은 **82.03% 그대로**다. $(x-\mu)/\sigma$ 는 모든 화소에 똑같이 걸리는 아핀 변환이라 거리를 $1/\sigma^2$ 배로 줄일 뿐이고, **어느 것이 가장 가까운지**는 바꾸지 않는다. 그러므로 두 값을 견주는 데 문제가 없다.

**주장 3**은 92.42%와 92.40%다. 화소를 통째로 뒤섞었는데 0.02%포인트밖에 움직이지 않았다. 사람은 알아볼 수 없게 된 그림인데 모델은 아무렇지 않다. 곧 이 모델은 **이웃 관계를 처음부터 쓰지 않았다**(아래 **연습문제 6**이 그 까닭을 따진다).

!!! warning "학습한 값이 92.51%가 아니라 92.42%인 것"
    본문과 [6쪽 구현](06_implementation.md)은 92.51%를 싣는다. 여기서는 92.42%가 나왔다. 이 절 첫머리의 안내대로 초기 가중치와 섞는 차례에 따라 마지막 자리가 0.1\~0.4%포인트 흔들리며, 0.09%포인트는 그 안이다.

    한 표 안의 값끼리는 같은 조건에서 잰 것이므로 견주는 데 문제가 없다. **82.03과 92.42의 차이**를 읽으면 되고, 92.51이라는 특정한 값을 붙들 것은 아니다.

    ```python
        print(f"{name:16s} {tuple(p.shape)}  {p.numel():>6,}")
    print(sum(p.numel() for p in model.parameters()))     # 7850
    ```

    | | 꼴 | 개수 |
    |---|---|---|
    | 가중치 | $(10, 784)$ | $7{,}840$ |
    | 편향 | $(10,)$ | $10$ |
    | 합 | | **$7{,}850$** |

    그러니 두 걸음의 차이를 "모델을 키웠다"로 설명할 수 없다. 82.03%와 92.51%를

**연습문제 10.** <span class="diff hard" title="어려움"></span>
이 모델이 클래스 $i$와 $j$를 가르는 경계가 **초평면**임을 보여라. 1단계의 경계와 견주면 무엇이 같고 무엇이 다른가?

</div>

??? success "연습문제 10 풀이"
    클래스 $i$를 고르는 자리는 $y_i > y_j$가 모든 $j \ne i$에 대해 성립하는 곳이다.
    두 클래스만 볼 때 경계는 $y_i = y_j$이므로, $a_i$를 $A$의 $i$번째 행이라 하면

    $$x^{\top} a_i + b_i = x^{\top} a_j + b_j$$

    곧

    $$x^{\top} (a_i - a_j) + (b_i - b_j) = 0$$

    이다. 이는 법선 벡터가 $a_i - a_j$인 **초평면**이다. $\square$

    열 클래스 전체로 보면 784차원 공간이 볼록한 조각 열 개로 나뉜다. 각 조각은
    초평면들의 교집합이므로 볼록하다.

    1단계와 견주자. 1단계에서는 $a_k = \overline{x}_k$였으므로 경계가
    $(\overline{x}_i - \overline{x}_j)^{\top}\!\left(x - \tfrac{\overline{x}_i + \overline{x}_j}{2}\right) = 0$,
    곧 두 클래스 평균을 잇는 선분의 **수직이등분면**이었다(1단계 연습문제 13).

    | | 1단계 템플릿 학습 | 2단계 선형 모델 |
    |---|---|---|
    | 경계의 꼴 | 초평면 | 초평면 (**같다**) |
    | 법선 방향 | $\overline{x}_i - \overline{x}_j$로 **고정** | 학습한다 |
    | 경계의 위치 | 두 평균의 중점을 지난다 | 학습한다 |

    곧 학습이 바꾼 것은 경계의 **모양**이 아니라 그 **방향과 자리**다. 평평한
    칼이라는 사실은 그대로다. 그래서 두 걸음이 얻을 수 있는 것에 공통의 천장이
    있고, 그 천장이 연습문제 11에서 드러난다.

    | 과적합이다 | 아니다 — 학습 정확도가 시험보다 겨우 1.2%포인트 높다 |
    | 최적화기가 나쁘다 | 아니다 — 손실면이 볼록하다([05](05_gradient_descent.md)) |
    | **모델의 표현력이 모자라다** | **그렇다** |

    학습 정확도가 100%에 한참 못 미치면서 시험 정확도와도 가깝다는 것은 **과소적합**의
    표시다. 처방은 더 오래 돌리거나 정칙화를 더하는 것이 아니라 **모델을 바꾸는
    것**이다.

    시험 정확도가 10 에포크의 92.48%에서 50 에포크의 92.16%로 오히려 조금 내려간
    것도 함께 보라. 더 돌려서 얻는 것이 없다는 뜻이다.

    이것이 [3.3 다층 퍼셉트론](../mnist/03_mlp.md)으로 넘어가는 근거다. 다만 거기서도
    층을 쌓는 것만으로는 이 자리에 그대로 머문다는 사실을 먼저 보게 된다.

## 정리하며

**다룬 것** — 선형 모델 $y = xA + b$

MNIST 이미지를 784차원 벡터로 펼치고 아핀 변환 하나로 로짓 10개를 만든다. 찾아야 할 수는 7,850개이며, 이는 1단계 템플릿 학습과 **정확히 같은 수**다. 두 걸음의 차이는 모델의 크기가 아니라 그 수를 평균으로 못박느냐 데이터에 맞추어 움직이느냐에 있다.

이 모델은 입력을 순서 없는 숫자 꾸러미로 보며, 그릴 수 있는 결정 경계는 초평면뿐이다. 두 한계는 각각 3.4절과 3.3절에서 풀린다.
