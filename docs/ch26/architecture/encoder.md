# 인코더 그물
고르게 나눈 변분 추론: 자료를 어림 사후 분포에 옮기는 법 배우기.

---

## 1. 학습 목표

이 절을 마치면 다음을 할 수 있게 된다.

- 분포 매개변수를 내놓는 인코더 얼개 설계하기
- $\mu$과 $\log\sigma^2$을 위한 두 머리 얼개 짜기
- 고르게 나눈 추론과 그 셈의 이점 이해하기
- 자료 갈래에 따라 여러 층 인식개 인코더와 누비기 인코더 세우기

---

## 2. 인코더의 노릇

### 추론에서 고르게 나누기로

고전 변분 추론에서는 자료 점 $x_i$마다 따로 변분 매개변수를 가장 좋게 한다. 변분 오토인코더의 인코더는 **고르게 나눈 추론**을 한다. 곧 신경망 하나 $q_\phi(z|x) = \mathcal{N}(\mu_\phi(x), \sigma^2_\phi(x))$이 어떤 들임이든 그 어림 사후 분포에 옮긴다. 표본마다의 가장 좋음을 셈의 효율과 맞바꾸는 것이며, 추론에 앞먹임 한 번만 든다.

### 인코더가 내놓는 것

인코더 그물은 들임 $x$을 받아 벡터 둘을 낸다:

- **평균** $\mu_\phi(x) \in \mathbb{R}^d$: 어림 사후 분포의 가운데
- **로그 흩어짐** $\log\sigma^2_\phi(x) \in \mathbb{R}^d$: 퍼진 정도(수치 안정을 위해 로그 공간에서)

```
Input x ──► [Shared Hidden Layers] ──┬──► fc_mu ──► μ ∈ ℝ^d
                                      │
                                      └──► fc_logvar ──► log(σ²) ∈ ℝ^d
```

## 3. 여러 층 인식개 인코더

### 구조

```python
import torch
import torch.nn as nn

class MLPEncoder(nn.Module):
    """
    벡터 들임(예컨대 펼친 MNIST)을 위한 온전히 이어진 인코더.
    
    얼개: input_dim → hidden_dim → hidden_dim → (μ, logvar)
    """
    
    def __init__(self, input_dim=784, hidden_dim=256, latent_dim=32):
        super().__init__()
        
        # 공유 특징 추출
        self.shared = nn.Sequential(
            nn.Linear(input_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, hidden_dim),
            nn.ReLU()
        )
        
        # 분포 매개변수를 위한 따로 둔 머리
        self.fc_mu = nn.Linear(hidden_dim, latent_dim)
        self.fc_logvar = nn.Linear(hidden_dim, latent_dim)
    
    def forward(self, x):
        """
        인수:
            x: 들임 텐서 [배치 크기, 들임 차원]
        반환값:
            mu: 평균 [배치 크기, 숨은 차원]
            logvar: 로그 흩어짐 [배치 크기, 숨은 차원]
        """
        h = self.shared(x)
        mu = self.fc_mu(h)
        logvar = self.fc_logvar(h)
        return mu, logvar
```

### 왜 머리를 나누는가?

평균과 로그 흩어짐은 내놓기의 성질이 다르다. 평균 $\mu$은 갇혀 있지 않고 숨은 특징의 온전한 표현력에서 덕을 본다. 로그 흩어짐 $\log\sigma^2$은 불확실함을 다스리며 흔히 다른 잣수로 모인다. 마지막 쏘기만 빼고 층을 모두 나눠 쓰면 그물이 공통 특징 나타냄을 배우면서 마지막 대응만 특화할 수 있다.

## 4. 누비기 인코더

### 그림 자료에

```python
class ConvEncoder(nn.Module):
    """
    그림 들임을 위한 누비기 인코더.
    
    공간 차원을 차츰 내림 표집하면서
    채널 깊이를 늘린 뒤 숨은 매개변수로 쏜다.
    """
    
    def __init__(self, in_channels=1, hidden_channels=32, latent_dim=32):
        super().__init__()
        
        self.conv_layers = nn.Sequential(
            # 28x28 → 14x14
            nn.Conv2d(in_channels, hidden_channels, 4, stride=2, padding=1),
            nn.ReLU(),
            nn.BatchNorm2d(hidden_channels),
            
            # 14x14 → 7x7
            nn.Conv2d(hidden_channels, hidden_channels * 2, 4, stride=2, padding=1),
            nn.ReLU(),
            nn.BatchNorm2d(hidden_channels * 2),
            
            # 7x7 → 4x4
            nn.Conv2d(hidden_channels * 2, hidden_channels * 4, 3, stride=2, padding=1),
            nn.ReLU(),
            nn.BatchNorm2d(hidden_channels * 4),
        )
        
        # 펼치고 쏜다
        flat_dim = hidden_channels * 4 * 4 * 4  # 들임 크기에 달렸다
        self.fc_mu = nn.Linear(flat_dim, latent_dim)
        self.fc_logvar = nn.Linear(flat_dim, latent_dim)
    
    def forward(self, x):
        """
        인수:
            x: 들임 그림 [배치 크기, 채널, 높이, 너비]
        """
        h = self.conv_layers(x)
        h = h.view(h.size(0), -1)  # 펼친다
        return self.fc_mu(h), self.fc_logvar(h)
```

## 5. 로그 흩어짐 매개변수화

### 왜 시그마를 곧바로 내놓지 않는가?

표준 편차 $\sigma$은 양수여야 한다. $\sigma$을 곧바로 내놓으면 양수임을 강제할 활성화 함수(부드러운 정류 선형 같은)가 필요하다. 대신 $\log\sigma^2$을 내놓고 $\sigma = \exp(0.5 \cdot \log\sigma^2)$을 셈하면 활성화 함수 없이 저절로 양수가 된다.

| 매개변수화 | 양수임 | 기울기의 몸가짐 | 표준 고름 |
|-----------------|------------|-------------------|-----------------|
| $\sigma$ 곧바로 | 부드러운 정류 선형이나 지수가 필요 | 기울기가 사라질 수 있다 | 아니오 |
| $\sigma^2$ | 부드러운 정류 선형이 필요 | 제곱 잣수 문제 | 아니오 |
| $\log\sigma^2$ | 지수로 저절로 | 얌전하다 | **예** |

### 수치적 안정성

로그 흩어짐이 아주 크거나 작으면 값을 가두어 수치 넘침을 막는다:

```python
def safe_reparameterize(mu, logvar, max_logvar=10.0):
    """가둔 로그 흩어짐으로 다시 매개변수화한다."""
    logvar = torch.clamp(logvar, min=-max_logvar, max=max_logvar)
    std = torch.exp(0.5 * logvar)
    eps = torch.randn_like(std)
    return mu + std * eps
```

## 6. 고르게 나누기의 벌어짐

### 무엇인가?

**고르게 나누기의 벌어짐**은 고르게 나눈 인코더가 이룬 증거 하한과 표본마다 가장 좋게 해서 이룰 수 있는 증거 하한의 차이다:

$$\text{고르게 나누기의 벌어짐} = \mathcal{L}^*(\theta; x) - \mathcal{L}(\theta, \phi; x)$$

여기서 $\mathcal{L}^*$은 $x$마다 따로 가장 좋은 $q^*(z|x)$을 쓴다.

### 왜 중요한가

인코더는 모든 자료 점에 두루 통해야 하므로 들임마다 사후 분포를 완벽히 어림할 수 없다. 이것이 고르게 나누기의 값이다. 곧 표본마다의 가장 좋음을 내주고 빠른 추론을 얻는다.

### 벌어짐 줄이기

고르게 나누기의 벌어짐을 줄이는 전략에는 표현력이 더 좋은 인코더 얼개 쓰기, 인코더가 내놓는 것에 고르게 하는 흐름 쓰기($q_\phi(z|x)$이 흐름 바탕 분포가 된다), 시험 때 기울기로 몇 걸음 다듬기(반쯤 고르게 나눈 추론)가 있다.

## 7. 설계 지침

### 숨은 차원 고르기

인코더는 자료에서 사후 매개변수로 가는 대응을 배울 담이를 넉넉히 갖춰야 한다. 어림잡아 숨은 차원은 적어도 숨은 차원의 2~4배여야 하고 숨은 층의 수는 자료의 복잡함에 따라 늘려야 한다.

### 초기화

여느 첫자리매김(자비에/허)이 대개 잘 통한다. 어떤 이는 단위 흩어짐이 아니라 웬만한 흩어짐으로 시작하려 로그 흩어짐 머리의 치우침을 작은 음수(예컨대 -1)로 첫자리매김한다:

```python
# 첫 흩어짐이 웬만하도록 로그 흩어짐 머리의 치우침을 첫자리매김한다
nn.init.constant_(encoder.fc_logvar.bias, -1.0)
```

### 배치 고르게 맞추기

인코더의 배치 고르게 맞추기는 익히기 안정에 도움이 되지만 $\mu$과 $\log\sigma^2$ 머리 뒤에는 쓰면 **안 된다**. 분포 매개변수화를 흔들기 때문이다.

<div class="drillbox" markdown>

**연습문제 1.** <span class="diff easy" title="쉬움"></span>
인코더가 내놓는 것이 오토인코더와 어떻게 다른가? 출력의 개수를 세어 보라.

</div>

??? success "연습문제 1 풀이"
    오토인코더의 인코더는 코드 하나를 내놓는다. 병목이 $k$이면 출력이 $k$개다.

    변분 오토인코더의 인코더는 **분포**를 내놓는다. 가우시안이므로 평균과 분산이
    필요하고, 출력이 $2k$개가 된다.

    ```python
    self.head = nn.Linear(256, 2 * k)     # mu 와 logvar
    mu, logvar = self.head(h).chunk(2, dim=1)
    ```

    바뀐 것이 이 한 줄뿐인데, 이것이 압축기와 만들어 내는 모델을 가른다
    ([23.5절](../../ch25/limits/latent_sampling.md)).

    매개변수로 보면 마지막 층만 두 배가 된다. $256 \times 16$이 $256 \times 32$가
    되므로 4,096개가 늘 뿐, 전체 100만여 개에 견주면 0.4%다. **거의 공짜로 성격이
    달라진다.**

<div class="drillbox" markdown>

**연습문제 2.** <span class="diff hard" title="어려움"></span>
다시 뽑기(reparameterization)가 왜 필요한가? $z \sim \mathcal{N}(\mu, \sigma^2)$을 그냥 뽑으면 무엇이 안 되는가?

</div>

??? success "연습문제 2 풀이"
    기울기가 흐르지 않는다.

    `torch.normal(mu, sigma)`로 뽑으면 그 표집 연산은 미분할 수 있는 함수가 아니다.
    뽑힌 $z$는 $\mu$의 함수가 아니라 난수 생성기의 결과이므로
    $\partial z / \partial \mu$가 정의되지 않고, 역전파가 인코더까지 이어지지 못한다.

    다시 뽑기는 무작위성을 **매개변수에 기대지 않는 자리로 밀어낸다.**

    $$z = \mu + \sigma \odot \varepsilon, \qquad \varepsilon \sim \mathcal{N}(0, I)$$

    이제 $\varepsilon$이 난수이되 $\mu$, $\sigma$와 무관하고, $z$는 그 둘의 **미분
    가능한 함수**다.

    $$\frac{\partial z}{\partial \mu} = 1, \qquad
      \frac{\partial z}{\partial \sigma} = \varepsilon$$

    그래서 기울기가 $z$를 지나 인코더로 흘러간다.

    이 요령이 변분 오토인코더를 실용적으로 만든 핵심이다. 없으면 점수 함수 추정량
    (REINFORCE) 같은 것을 써야 하는데, 그쪽은 기울기의 분산이 훨씬 커서 잘 익지 않는다.

    쓸 수 있는 조건이 있다. 분포를 "매개변수 + 매개변수와 무관한 잡음"으로 다시 쓸
    수 있어야 하며, 가우시안은 되고 베르누이 같은 이산 분포는 안 된다. 이산 숨은
    변수를 다루기 어려운 까닭이 여기 있다.

<div class="drillbox" markdown>

**연습문제 3.** <span class="diff med" title="중간"></span>
익힐 때와 평가할 때 인코더를 다르게 써야 하는가?

</div>

??? success "연습문제 3 풀이"
    쓰임에 따라 다르다.

    | 무엇을 하는가 | $z$를 어떻게 얻는가 |
    |---|---|
    | 익히기 | 반드시 뽑는다. $z = \mu + \sigma\varepsilon$ |
    | 다시 세우기를 보고 싶을 때 | $z = \mu$로 두는 편이 깔끔하다 |
    | 가능도를 어림할 때 | 여러 번 뽑아 평균 |
    | 코드를 특징으로 쓸 때 | $z = \mu$ |

    익힐 때 뽑지 않으면 KL 항이 뜻을 잃는다. $\sigma$가 손실에 영향을 주지 않게 되어
    인코더가 그냥 오토인코더가 된다.

    반대로 평가할 때 뽑으면 같은 입력에 매번 다른 결과가 나와 재현되지 않는다. 그래서
    다시 세우기 그림을 보일 때는 $\mu$를 쓰는 것이 관례다.

    `model.eval()`이 이것을 알아서 해 주지 **않는다**는 점을 조심해야 한다. 드롭아웃과
    달리 이 선택은 모델 코드에 직접 적어 주어야 한다.

**연습문제 4.** <span class="diff med" title="중간"></span>
인코더의 $\sigma$가 모든 입력에 대해 같은 값이면 어떻게 되는가?

</div>

??? success "연습문제 4 풀이"
    입력마다 다른 확신도를 나타낼 수 없게 된다.

    변분 오토인코더가 $\sigma(x)$를 입력의 함수로 두는 까닭은, 어떤 입력은 코드가
    분명하고 어떤 입력은 애매하기 때문이다. 전형적인 1이라면 $\sigma$를 작게 두어
    "이 코드가 확실하다"고 말할 수 있고, 흐릿하고 애매한 글씨라면 $\sigma$를 크게
    두어 여러 코드가 그럴듯하다고 말할 수 있다.

    $\sigma$를 상수로 묶으면 그 표현을 잃는다. 다만 완전히 못 쓰게 되지는 않고,
    실제로 $\sigma$를 학습되는 상수 하나로 두는 간단한 변형도 쓰인다. 그때는
    KL 항이 $\mu$만 벌하는 꼴이 되어 결국 $\mu$에 대한 L2 벌점과 비슷해진다.

    거꾸로 $\sigma$를 지나치게 자유롭게 두면 무너짐이 쉬워진다. 어떤 차원에서
    $\sigma \to 1$, $\mu \to 0$으로 가 버리면 그 차원이 죽는다
    ([자유 비트](../training/free_bits.md)).

**연습문제 5.** <span class="diff easy" title="쉬움"></span>
인코더의 은닉층을 깊게 하면 무엇이 좋아지는가?

</div>

??? success "연습문제 5 풀이"
    $\mu(x)$와 $\sigma(x)$가 더 복잡한 함수가 될 수 있다. 곧 **제안 분포가 참된 사후
    분포에 더 가까워질 여지**가 생긴다.

    [KL 항 연습문제 3](../theory/kl_term.md)에서 보았듯 증거 하한의 느슨함이 곧
    $D_{\mathrm{KL}}(q(z\mid x) \| p(z \mid x))$이므로, $q$를 잘 맞출수록 하한이
    빡빡해지고 실제로 $\log p(x)$를 최대화하는 데 가까워진다.

    다만 한계가 분명하다. $q$를 아무리 깊게 해도 **가우시안**이라는 모양은 그대로다.
    참된 사후 분포가 여러 봉우리를 가지면 가우시안 하나로는 따라갈 수 없고, 깊이는
    그 문제를 풀어 주지 않는다.

    그 한계를 넘으려면 $q$의 모양 자체를 바꾸어야 하며, 흐름 모델을 인코더에 얹는
    방법이 그 길이다.

    깊이로 메울 수 있는 몫이 실제로 얼마나 되는지 재어 볼 수 있다. 익힌 모델을 얼려
    두고, 시험 표본마다 $(\mu, \log\sigma^2)$을 **직접** 기울기로 다듬어 증거 하한을
    더 높일 수 있는지 보면 된다. 인코더가 한 번에 내놓은 값과의 차이를
    **고르게 나누기의 벌어짐**(amortization gap)이라 한다.

    | | $-$ELBO |
    |---|---|
    | 인코더가 낸 값 | 99.191 |
    | 10걸음 다듬은 뒤 | 97.095 |
    | 100걸음 다듬은 뒤 | **95.654** |

    벌어짐이 **3.537**이다. 곧 인코더는 표본마다 따로 최적화한 것보다 3.5만큼 나쁜
    답을 내놓고 있으며, 그만큼이 "모든 입력을 하나의 그물로 처리한다"는 편의의 값이다.

    어디가 어긋났는지도 볼 수 있다. 다듬는 동안 $\mu$는 평균 0.6656만큼 움직였는데
    $\sigma$는 0.4238에서 0.4261로 거의 그대로였다. **틀린 것은 주로 중심의 자리이고
    퍼짐은 꽤 맞게 내놓고 있었다**는 뜻이다.

    이 벌어짐을 줄이는 길이 둘이다. 인코더를 키우거나(고르게 나누기를 잘하게 하거나),
    익힐 때 아예 이 다듬기를 몇 걸음 끼워 넣는 것이다. 뒤쪽을 반복 추론
    (iterative amortized inference)이라 부른다.

**연습문제 6.** <span class="diff hard" title="어려움"></span>
다시 뽑기를 쓸 때 기울기의 분산은 무엇에 달려 있는가? $\sigma$가 크면 익히기가 어려워지는가?

</div>

??? success "연습문제 6 풀이"
    $\partial z/\partial \sigma = \varepsilon$이므로 $\sigma$에 대한 기울기는 뽑힌
    $\varepsilon$에 곧바로 비례한다. 표본 하나로 어림하면 그 기울기의 분산이 그대로
    실린다.

    그런데 $\sigma$ 자체가 크면 $z$가 크게 흔들리므로 **다시 세우기 항의 값도** 표본마다
    크게 달라진다. 곧 $\sigma$가 크면 기울기 잡음이 커진다.

    다행히 이것이 스스로 잦아드는 구조다. 다시 세우기 항은 $\sigma$가 작기를 바라므로,
    익히기가 진행되면 $\sigma$가 줄어 잡음도 준다. 문제는 반대쪽이다. $\sigma$가
    지나치게 줄면 KL이 $\sigma \to 1$로 당기고, 그 균형이 깨지면 무너짐이 온다.

    실무에서 쓰는 요령이 둘이다.

    - **$\log\sigma^2$을 범위로 자른다.** `logvar.clamp(-6, 2)` 같은 식으로 극단을 막는다
    - **KL을 서서히 켠다**(KL annealing). 초기에 $\beta$를 0에서 1로 올리면 인코더가
      먼저 쓸모 있는 코드를 배운 뒤에 KL의 압력을 받는다

**연습문제 7.** <span class="diff med" title="중간"></span>
인코더와 디코더가 서로 다른 깊이여도 되는가? 어느 쪽을 더 크게 두는 것이 나은가?

</div>

??? success "연습문제 7 풀이"
    되고, 실제로 그렇게 두기도 한다.

    **디코더를 더 크게** 두는 편이 보통 낫다. 디코더가 하는 일이 더 어렵기 때문이다.
    인코더는 784차원을 16차원으로 줄이면 되지만, 디코더는 16개의 수에서 784개를
    지어내야 한다. 정보를 버리는 쪽보다 지어내는 쪽이 어렵다.

    특히 만들어 내기가 목적이라면 디코더의 품질이 곧 결과의 품질이다. 인코더는 익히고
    나면 뽑을 때 쓰지 않으므로($z$를 사전 분포에서 바로 뽑는다) 더욱 그렇다.

    거꾸로 나타냄이 목적이면 인코더가 중요해진다. 쓰는 것이 코드이고, 그 코드를
    만드는 것이 인코더이기 때문이다.

    곧 **무엇에 쓸 모델인지가 어디에 예산을 쓸지를 정한다.**

**연습문제 8.** <span class="diff med" title="중간"></span>
인코더 출력을 $\mu$와 $\log\sigma^2$으로 반씩 쪼개는 대신 층을 둘로 나누어도 되는가?

</div>

??? success "연습문제 8 풀이"
    된다. 두 방식이 있다.

    ```python
    # 방식 1: 한 층에서 2k개를 내고 쪼갠다
    h = nn.Linear(256, 2 * k)(x)
    mu, logvar = h.chunk(2, dim=1)

    # 방식 2: 층을 둘 둔다
    mu     = nn.Linear(256, k)(x)
    logvar = nn.Linear(256, k)(x)
    ```

    매개변수 수가 같고 표현력도 같다. 방식 1의 가중치 행렬을 위아래로 자르면 방식 2의
    두 행렬이 되기 때문이다.

    차이는 읽기 편함뿐이다. 방식 2가 뜻이 또렷해서 좋아하는 사람이 많고, 방식 1은
    행렬 곱이 한 번이라 아주 조금 빠르다.

    한 가지 실질적인 차이가 생길 수 있다. 두 갈래를 **다르게** 초기화하거나 다른
    학습률을 주고 싶을 때는 방식 2라야 손대기 쉽다. 예컨대 $\log\sigma^2$의 마지막
    층을 0으로 초기화해 $\sigma = 1$에서 출발하게 하는 요령이 그렇다.

**연습문제 9.** <span class="diff easy" title="쉬움"></span>
인코더의 출력에 활성화 함수를 걸어야 하는가?

</div>

??? success "연습문제 9 풀이"
    걸지 않는다. $\mu$는 실수 전체를 쓸 수 있어야 하고, $\log\sigma^2$도 마찬가지다.

    활성화를 걸면 곤란해진다. ReLU를 걸면 $\mu$가 음수를 못 가져 코드가 첫 사분면에
    갇히고, 시그모이드를 걸면 $(0,1)$에 갇힌다. 어느 쪽이든 $\mathcal{N}(0,I)$과
    맞출 수 없으니 KL 항이 줄지 않는다.

    [오토인코더 쪽](../../ch25/architecture/01_ae_fully_connected.md)에서도 병목에
    활성화를 걸지 않는 것이 낫다고 했는데, 변분 오토인코더에서는 그 정도가 아니라
    **걸면 안 된다.** 사전 분포와 맞추는 일이 모델의 정의에 들어 있기 때문이다.

    은닉층에는 물론 활성화를 건다. 마지막 한 층만 선형으로 둔다.

**연습문제 10.** <span class="diff med" title="중간"></span>
인코더를 익히고 나면 그 코드를 분류에 쓸 수 있는가? $\mu$를 쓸 것인가 뽑은 $z$를 쓸 것인가?

</div>

??? success "연습문제 10 풀이"
    쓸 수 있고, **$\mu$를 쓴다.**

    $z$는 뽑을 때마다 달라지므로 같은 입력이 다른 특징을 갖게 되어 분류기가 혼란스럽다.
    $\mu$는 결정적이며 그 입력에 대한 인코더의 가장 좋은 추정이다.

    다만 변분 오토인코더의 코드가 오토인코더의 코드보다 분류에 낫다는 보장은 없다.
    KL 항이 정보를 버리게 하므로, 분류에 필요한 정보까지 버렸을 수 있다. $\beta$를
    키울수록 그 경향이 심해진다.

    실제로 재어 보면 $\beta$가 커질수록 살아 있는 차원이 16개에서 5개까지 줄어드는데
    ([베타 VAE](../architecture/beta_vae.md)), 그만큼 코드가 담는 정보도 준다.
    분류가 목적이라면 $\beta$를 작게 두거나 애초에 오토인코더를 쓰는 편이 나을 수 있다.

    $\sigma$도 버리지 말 것을 권한다. 그 값이 큰 표본은 인코더가 확신하지 못한
    것이므로, 이상 탐지나 능동 학습에서 쓸모가 있다.

## 정리하며

| 조각 | 몫 | 짜기 |
|-----------|---------|----------------|
| **나눠 쓰는 층** | 들임에서 특징을 뽑는다 | 정류 선형을 곁들인 온전히 이어진 층이나 누비기 층 |
| **평균 머리** | $\mu_\phi(x)$을 내놓는다 | 선형 쏘기, 갇히지 않음 |
| **로그 흩어짐 머리** | $\log\sigma^2_\phi(x)$을 내놓는다 | 선형 쏘기, 옭아매지 않음 |
| **다시 매개변수화** | $z = \mu + \sigma \cdot \epsilon$을 뽑는다 | 뒤먹임 퍼뜨리기를 되게 한다 |
