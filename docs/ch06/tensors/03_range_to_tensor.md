# 범위를 텐서로

고르게 늘어선 수를 만드는 길은 둘이다. **보폭을 정하는** `arange`와 **개수를 정하는** `linspace`다. 끝값을 어떻게 다루는지가 다르고, 보폭이 실수일 때 원소가 몇 개 나오는지도 다르다. 이 쪽은 그 차이와, 실수 보폭이 셈을 어긋내는 자리를 본다.

## 1. 코드

```python
"""범위에서 텐서로."""
import torch

# ========================================================================
# 메인
# ========================================================================

def print_info(t):
    # 텐서를 빠르게 살펴보는 도우미 함수.
    # - t: 값 미리보기(PyTorch가 dtype에 따라 보기 좋게 출력한다)
    # - t.shape: 1차원은 [N], 2차원은 [R,C], 스칼라(0차원)는 []
    # - t.dtype: 지정하지 않으면 추론된다(기본적으로 정수→int64, 실수→float32)
    # - requires_grad: autograd 플래그(실수/복소수 텐서에 True로 설정하지 않으면 False)
    print(f"{t = }", f"{t.shape = }", f"{t.dtype = }", f"{t.requires_grad = }", sep="\n", end="\n\n")

def main():
    # --------------------------------------------
    # 1) 파이썬 range  →  텐서 (COPY)
    # --------------------------------------------
    # torch.tensor(range(...))는 반복 가능 객체에서 원소를 복사한다.
    # dtype이 추론된다. 정수는 기본적으로 모두 torch.int64가 된다.
    r1 = range(5)   # [0, 1, 2, 3, 4]
    t1 = torch.tensor(r1)
    print_info(t1)
    # 기댓값: tensor([0, 1, 2, 3, 4])   torch.Size([5])   torch.int64

    # --------------------------------------------
    # 2) (start, stop, step)을 쓰는 range
    # --------------------------------------------
    # 파이썬의 range는 반개구간이다. start는 포함하고 stop은 제외한다.
    r2 = range(2, 10, 2)  # [2, 4, 6, 8]
    t2 = torch.tensor(r2)
    print_info(t2)
    # 기댓값: tensor([2, 4, 6, 8])   torch.Size([4])   torch.int64

    # --------------------------------------------
    # 3) torch.arange  — range를 감싸는 것보다 낫다
    # --------------------------------------------
    # 텐서를 곧바로 만든다(dtype/device/requires_grad를 지정할 수 있다).
    # 파이썬 range와 같다: 반개구간 [start, stop).
    t3 = torch.arange(0, 10, 2)
    print_info(t3)
    # 기댓값: tensor([0, 2, 4, 6, 8])   torch.Size([5])   torch.int64

    # --------------------------------------------
    # 4) 실수 보폭을 쓰는 torch.arange
    # --------------------------------------------
    # 실수 보폭은 반올림 오차가 누적될 수 있다. 결과는 여전히 반개구간이다.
    # dtype=...으로 지정하지 않으면 기본 실수 dtype은 float32이다
    t4 = torch.arange(0.0, 1.0, 0.2)
    print_info(t4)
    # 예시 출력: tensor([0.0000, 0.2000, 0.4000, 0.6000, 0.8000])

    # --------------------------------------------
    # 5) torch.linspace — 양쪽 끝점을 모두 포함한다
    # --------------------------------------------
    # start부터 end까지(양끝 포함) 균등 간격의 점 `steps`개를 반환한다.
    # 이는 arange의 반개구간 동작과 다르다.
    t5 = torch.linspace(0, 1, steps=5)
    print_info(t5)
    # 기댓값: tensor([0.0000, 0.2500, 0.5000, 0.7500, 1.0000])

    # --------------------------------------------
    # 6) torch.range — 폐기 예정(대신 arange를 쓴다)
    # --------------------------------------------
    # 예전에는 있었지만 모호성 때문에 폐기되었다. torch.arange를 쓰는 것이 낫다.
    # 여기서는 폐기 경고를 피하기 위해 *대체* 호출을 보여준다.
    t6 = torch.arange(1, 5)  # [1, 2, 3, 4]
    print_info(t6)

    # --------------------------------------------
    # 7) 실수 보폭의 함정 — 원소가 하나 더 나온다
    # --------------------------------------------
    # 1부터 1.3 앞까지 0.1씩이면 1.0, 1.1, 1.2 — 셋이어야 한다.
    # 그런데 넷이 나온다.
    t7 = torch.arange(1, 1.3, 0.1)
    print("arange(1, 1.3, 0.1) =", t7)
    print("원소 수:", len(t7), "(셋을 기대했다)")
    print("마지막 값:", repr(t7[-1].item()))
    print("마지막 값 < 1.3 :", t7[-1].item() < 1.3)
    # 반개구간 규칙은 지켜졌다. 마지막 값이 1.3보다 **작기** 때문이다.
    # 어긋난 것은 셈이다. 0.1은 이진 실수로 정확히 적히지 않으므로
    print("(1.3 - 1) / 0.1 =", repr((1.3 - 1) / 0.1), "← 3이 아니다")
    # 3.0000000000000004가 되고, 여기에 올림을 하면 4가 된다.
    # 그래서 원소가 넷이 되고, 넷째 값은 1.3처럼 찍히지만 실제로는 1.3보다 작다.

    # 끝값이 중요하면 linspace로 적는다. 몇 개인지를 내가 정하기 때문이다.
    print("linspace(1, 1.2, 3) =", torch.linspace(1, 1.2, 3))

    # ---------------------- 추가 참고 사항 ----------------------
    # • torch.arange/linspace에서는 dtype/device를 직접 제어할 수 있다:
    #     torch.arange(0, 10, 2, dtype=torch.float32, device='cpu', requires_grad=False)
    # • 균등 간격의 *개수*가 중요하면(양끝 포함) linspace가 낫다.
    #   보폭 기반 수열(끝값 제외)에는 arange가 낫다.

if __name__ == "__main__":
    main()
```


## 2. 논의

**끝값을 넣는가 빼는가.** `arange`는 반개구간 $[\text{start}, \text{stop})$이라 끝값을 **뺀다.** 파이썬 `range`와 같은 규약이다. `linspace`는 양끝을 **넣는다.** 그래서 같은 구간을 적어도 모양이 다르다.

$$
\texttt{arange(0, 1, 0.25)} = [0,\ 0.25,\ 0.5,\ 0.75], \qquad
\texttt{linspace(0, 1, 5)} = [0,\ 0.25,\ 0.5,\ 0.75,\ 1]
$$

**무엇을 내가 정하는가.** 이것이 둘을 가르는 진짜 기준이다. `arange`에는 보폭을 주고 개수는 PyTorch가 센다. `linspace`에는 개수를 주고 보폭을 PyTorch가 센다. 내가 아는 쪽을 주는 함수를 골라야 한다.

| | 내가 정하는 것 | PyTorch가 정하는 것 | 끝값 |
|---|---|---|---|
| `arange(start, stop, step)` | 보폭 | **개수** | 뺀다 |
| `linspace(start, end, steps)` | 개수 | **보폭** | 넣는다 |

**실수 보폭은 개수를 어긋낸다.** 위 7번이 그 자리다. `arange(1, 1.3, 0.1)`은 1.0, 1.1, 1.2 셋이어야 하는데 넷이 나온다. 반개구간 규칙을 어긴 것은 아니다 — 넷째 값은 `1.3000`으로 찍히지만 실제로는 1.2999999523162842이고, 1.3보다 작으므로 규칙상 들어올 자격이 있다. 어긋난 것은 **개수를 세는 셈**이다. 0.1은 이진 실수로 정확히 적히지 않아서

$$
\frac{1.3 - 1}{0.1} = 3.0000000000000004
$$

이 되고, 올림하면 3이 아니라 4가 된다. 원소 하나가 더 붙는 까닭이 여기에 있다.

그래서 규칙은 간단하다. **보폭이 실수이고 개수가 중요하면 `arange`를 쓰지 않는다.** 개수를 내가 적는 `linspace`에는 이 함정이 없다. 정수 보폭이면 `arange`가 안전하다 — 나누어지는 셈이 정확하기 때문이다.

!!! note "`torch.range`는 폐기되었다"
    이름이 비슷한 `torch.range`는 끝값을 **넣는** 함수였다. 한 글자 차이로 규약이 반대인 것이 혼란을 불러 폐기되었고, 지금 쓰면 "파이썬 `range`와 어긋난다"는 경고가 난다. 자료형도 다르다.

    ```python
    torch.range(1, 4)    # tensor([1., 2., 3., 4.])  원소 4개, float32
    torch.arange(1, 4)   # tensor([1, 2, 3])         원소 3개, int64
    ```

    위 6번이 `torch.range(1, 4)` 대신 `torch.arange(1, 5)`를 적은 까닭이다.

??? success "연습문제 1 풀이"
    ```python
    import torch

    a = torch.arange(0, 2, 0.5)
    print(a, len(a))
    print(torch.linspace(0, 2, 5))      # 끝값 2가 끼어든다 — 다른 텐서다
    print(torch.linspace(0, 1.5, 4))    # 이것이 같다
    ```

    ```
    tensor([0.0000, 0.5000, 1.0000, 1.5000]) 4
    tensor([0.0000, 0.5000, 1.0000, 1.5000, 2.0000])
    tensor([0.0000, 0.5000, 1.0000, 1.5000])
    ```

    적어야** 한다. 개수도 4로 직접 센다.

    곧 `arange`의 `stop`과 `linspace`의 `end`는 이름만 비슷하고 뜻이 다르다. 하나는
    "여기까지 가기 전에 멈춘다", 다른 하나는 "여기가 마지막 원소다"이다.

??? success "연습문제 2 풀이"
    ```python
    import torch

    print(len(torch.arange(0, 1, 0.1)))        # 10 — 끝값 1이 빠진다
    print(len(torch.arange(0, 1.05, 0.1)))     # 11 — stop을 밀어 넣어야 한다
    print(len(torch.linspace(0, 1, 11)))       # 11
    print(torch.linspace(0, 1, 11)[-1].item()) # 1.0 — 정확히 1이다
    ```

    ```
    10
    11
    11
    1.0
    ```

    `arange`가 10개를 주는 것은 끝값을 빼기 때문이다. 11개를 받으려면 `stop`을 1보다
    크게, 그러나 1.1보다는 작게 밀어 넣어야 한다 — 1.05처럼 **아무 뜻 없는 수**를
    고르는 셈이다. 그 수가 왜 1.05인지는 코드에 적히지 않으므로 읽는 사람이 다시
    생각해야 한다.

    `linspace(0, 1, 11)`는 원하는 것을 그대로 적는다. 끝값이 1이고 개수가 11이다.
    게다가 마지막 원소가 **정확히** 1.0이다. `arange` 쪽은 0.1을 열 번 누적한 값이라
    1과 미세하게 어긋날 수 있다.

    끝값이 중요하면 `linspace`를 쓴다.

<div class="drillbox" markdown>

**연습문제 3.** <span class="diff hard" title="어려움"></span>
아래 두 줄은 똑같은 셈을 하는 것처럼 보인다. 구간의 길이가 0.3이고 보폭이 0.1이니 둘 다 원소가 셋이어야 한다.

```python
torch.arange(0, 0.3, 0.1)      # 몇 개?
torch.arange(1, 1.3, 0.1)      # 몇 개?
```

실제로 찍어 보면 개수가 다르다. 왜 다른지 밝혀라. (힌트: `(stop - start) / step`을 `repr`로 찍어 보라.)

</div>

??? success "연습문제 3 풀이"
    ```python
    import torch

    for start, stop in [(0, 0.3), (1, 1.3)]:
        t = torch.arange(start, stop, 0.1)
        print(f"arange({start}, {stop}, 0.1) -> {len(t)}개   "
              f"(stop-start)/step = {(stop - start) / 0.1!r}")
    ```

    ```
    arange(0, 0.3, 0.1) -> 3개   (stop-start)/step = 2.9999999999999996
    arange(1, 1.3, 0.1) -> 4개   (stop-start)/step = 3.0000000000000004
    ```

    `arange`는 원소 개수를 $\lceil (\text{stop}-\text{start})/\text{step} \rceil$로 센다.
    참값은 두 경우 모두 정확히 3이지만, 이진 실수로는 3을 **맞출 수 없다.** 오차가
    어느 쪽으로 떨어지는지가 갈린다.

    - $0.3 - 0 = 0.3$을 0.1로 나누면 **3보다 조금 작은** 2.9999999999999996이다. 올림하면 3이다.
    - $1.3 - 1$은 0.30000000000000004가 되어, 0.1로 나누면 **3보다 조금 큰** 3.0000000000000004다. 올림하면 **4**다.

    곧 올림이 오차를 증폭한다. 참값보다 조금이라도 크면 원소가 통째로 하나 더 붙는다.
    시작점을 0에서 1로 옮긴 것만으로 결과가 달라지는 까닭이 이것이다 — 구간의 길이는
    같아도 **뺄셈이 만드는 오차의 방향이 다르다.**

    그래서 실수 보폭으로 개수를 맞추려 하지 않는다. 개수가 중요하면 `linspace`에
    개수를 직접 적는다.

## 정리하며

고르게 늘어선 수를 만드는 두 함수는 **내가 무엇을 아는가**로 갈린다.

- **보폭을 안다** → `arange(start, stop, step)`. 끝값을 빼고, 개수는 PyTorch가 센다.
- **개수를 안다** → `linspace(start, end, steps)`. 끝값을 넣고, 보폭은 PyTorch가 센다.

`arange`의 `stop`과 `linspace`의 `end`는 이름이 비슷하지만 뜻이 반대다. 하나는 "가기 전에 멈출 자리"이고 하나는 "마지막 원소"다.

실수 보폭에는 함정이 하나 있다. `arange`가 개수를 $\lceil (\text{stop}-\text{start})/\text{step} \rceil$로 세는데, 이진 실수에서 이 나눗셈이 참값을 정확히 맞히지 못한다. 오차가 위로 떨어지면 올림이 원소를 하나 더 붙인다. `arange(0, 0.3, 0.1)`은 셋인데 `arange(1, 1.3, 0.1)`은 넷인 까닭이고, 구간의 길이가 같아도 시작점에 따라 결과가 달라지는 까닭이다.

**실수 보폭으로 개수를 맞추려 하지 않는다.** 개수가 중요하면 `linspace`에 개수를 적는다. 정수 보폭이면 `arange`가 안전하다.
