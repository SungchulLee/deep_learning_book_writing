# 나눗셈법

나눗셈법은 해시 함수를 만드는 가장 간단하고 널리 쓰이는 기법이다. 정수 키 $k$과 크기가 $m$인 테이블이 주어지면 해시값은 $k$을 $m$으로 나눈 나머지이다. 구현하기 쉽고 계산이 효율적이지만 그 효과는 $m$을 어떻게 고르느냐에 크게 달려 있다.

## 정의

**나눗셈법**은 키 $k$의 해시를 다음과 같이 계산한다.

$$
h(k) = k \bmod m
$$

여기서 $m$은 해시 테이블의 칸 수이고 $\bmod$은 나머지 연산(정수 나눗셈의 나머지)을 뜻한다. 결과 $h(k)$은 언제나 $\{0, 1, \ldots, m-1\}$ 안에 있어 테이블의 칸을 곧바로 가리킨다.

이 연산에는 정수 나눗셈 한 번만 필요하므로 시간이 $O(1)$이고, 키와 테이블의 크기 말고는 메모리가 더 들지 않는다.

## 테이블 크기 고르기

$m$을 어떻게 고르느냐가 나눗셈법이 키를 얼마나 잘 흩뿌리는지를 정한다. 잘못 고르면 조직적인 뭉침이 생기고, 잘 고르면 거의 균등한 분포를 얻는다.

### 피해야 할 크기

**2의 거듭제곱.** $m = 2^p$이면 $k \bmod 2^p$은 $k$의 하위 $p$비트만 뽑는다.

$$
k \bmod 2^p = k\ \&\ (2^p - 1)
$$

여기서 $\&$은 비트 AND를 뜻한다. 즉 해시가 $k$의 상위 비트를 모두 무시한다. 키의 하위 비트에 구조가 있으면(예: 짝수, 4의 배수, 워드 경계에 맞춘 메모리 주소) 분포가 크게 나빠진다.

**10의 거듭제곱.** 마찬가지로 $m = 10^p$은 마지막 $p$개 십진 자리만 뽑는다. 키가 학번, 전화번호, 우편번호라면 마지막 몇 자리는 키 전체보다 정보량이 적을 때가 많다.

**작은 약수를 갖는 수.** $m$과 키의 분포가 공약수 $d > 1$을 가지면 $m$개의 칸 가운데 $m/d$개에만 키가 들어간다. 예를 들어 모든 키가 짝수이고 $m$도 짝수이면 짝수 인덱스의 칸만 쓰인다.

### 권장하는 크기

$m$으로는 **2의 거듭제곱에서 먼 소수**가 좋다. 까닭은 두 가지이다.

1. $m$이 소수이면 $k \bmod m$이 하위 비트뿐 아니라 $k$의 모든 비트에 달리게 된다.
2. 2의 거듭제곱에서 떨어뜨려 두면 해시가 단순한 비트 양상에 좌우되지 않는다.

??? example "테이블 크기 선택의 영향"

    키 $\{0, 8, 16, 24, 32, 40, 48, 56\}$(모두 8의 배수)을 생각해 보자.

    $m = 8$(2의 거듭제곱)일 때는 다음과 같다.

    $$
    h(k) = k \bmod 8 = 0 \quad \text{for all } k
    $$

    모든 키가 칸 0으로 가서 뭉침이 최대가 된다.

    $m = 7$(소수)일 때는 다음과 같다.

    $$
    \begin{array}{rcl}
    h(0) = 0,\quad h(8) = 1,\quad h(16) = 2,\quad h(24) = 3 \\
    h(32) = 4,\quad h(40) = 5,\quad h(48) = 6,\quad h(56) = 0
    \end{array}
    $$

    키가 7개 칸 전체에 흩어지고 충돌은 하나뿐이다. 짜임새 있는 입력에 소수 크기가 낫다는 것을 보여 준다.

## 단순 균등 해싱 아래의 분석

단순 균등 해싱 가정 아래에서 각 키는 어느 칸으로든 같은 확률로 해시되고, 칸마다의 기대 키 수는 적재율 $\alpha = n/m$이다. 이때 나눗셈법은 다음을 이룬다.

- **기대 사슬 길이:** $\alpha$
- **탐색 실패의 기대 시간:** $\Theta(1 + \alpha)$
- **탐색 성공의 기대 시간:** $\Theta(1 + \alpha/2)$

$m$이 $n$에 비례하면(곧 $\alpha = O(1)$이면) 모든 연산이 기대 $O(1)$ 시간에 돌아간다.

## 실무 지침

나눗셈법에서 $m$을 고를 때 다음 어림 규칙이 도움이 된다.

1. 어떤 정수 $p$에 대해서도 $2^p$에 가깝지 않은 **소수** $m$을 고른다.
2. 흔한 어림법: 바라는 적재율을 $\alpha_{\text{target}} \approx 0.75$이라 할 때 $n / \alpha_{\text{target}}$ 근처의 소수를 $m$으로 고른다.
3. 원소를 1000개쯤 담을 테이블이라면 $m = 1009$, $m = 1013$, $m = 1021$이 좋은 선택이다(모두 소수이고 2의 거듭제곱 근처가 아니다).

## 구현

다음 파이썬 구현은 충돌 해결에 분리 체이닝을 쓰며 정수 키에 나눗셈법을 적용하는 모습을 보인다.

```python
"""
분리 사슬법을 쓰는 나눗셈법 해시 표.

해시값이 고르게 퍼지도록 m을 소수로 고른
h(k) = k mod m을 보인다.
"""


# === 나눗셈법을 쓰는 해시 표 ===

class DivisionHashTable:
    """나눗셈법 h(k) = k mod m을 쓰는 해시 표."""

    def __init__(self, size: int = 11):
        """소수인 표 크기로 초기화한다 (기본값 11)."""
        self.size = size
        self.table: list[list[tuple]] = [[] for _ in range(size)]
        self.count = 0

    def _hash(self, key: int) -> int:
        """나눗셈법으로 해시값을 계산한다."""
        return key % self.size

    def put(self, key: int, value) -> None:
        """열쇠-값 쌍을 넣거나 갱신한다."""
        index = self._hash(key)
        for i, (k, v) in enumerate(self.table[index]):
            if k == key:
                self.table[index][i] = (key, value)
                return
        self.table[index].append((key, value))
        self.count += 1

    def get(self, key: int):
        """열쇠에 딸린 값을 돌려주고, 없으면 None을 돌려준다."""
        index = self._hash(key)
        for k, v in self.table[index]:
            if k == key:
                return v
        return None

    def load_factor(self) -> float:
        """지금 적재율 n/m을 돌려준다."""
        return self.count / self.size


# === 시연 ===

if __name__ == "__main__":
    ht = DivisionHashTable(size=7)

    keys = [10, 20, 30, 40, 50]
    for k in keys:
        ht.put(k, k * 10)

    for k in keys:
        print(f"h({k}) = {k} mod 7 = {k % 7}, value = {ht.get(k)}")

    print(f"Load factor: {ht.load_factor():.2f}")
```

**출력:**
```
h(10) = 10 mod 7 = 3, value = 100
h(20) = 20 mod 7 = 6, value = 200
h(30) = 30 mod 7 = 2, value = 300
h(40) = 40 mod 7 = 5, value = 400
h(50) = 50 mod 7 = 1, value = 500
Load factor: 0.71
```

## 연습문제

**연습문제 1.**
나눗셈법에 대해, 적재율이 $\alpha = 0.75$일 때 삽입과 조회의 기대 시간과 최악의 경우 시간을 계산하라.

??? success "연습문제 1 풀이"
    기대 시간은 충돌 해결 전략에 달렸으며 균등 해싱을 가정한다. 체이닝에서는 기대 시간이 $O(1 + \alpha) = O(1.75)$이다. 개방 주소법에서는 탐색에 실패할 때 기대 탐사 횟수가 $\approx 1/(1-\alpha) = 4$이다. 최악의 경우는 모든 키가 같은 칸으로 해시될 때의 $O(n)$이다.

**연습문제 2.**
나눗셈법을(를) 써서 키 10, 22, 31, 4, 15, 28, 17을 크기가 7인 해시 테이블에 넣어라. 최종 테이블의 상태를 보여라.

??? success "연습문제 2 풀이"
    해시 함수 $h(k) = k \bmod 7$을 적용하고 이 쪽의 방법으로 충돌을 처리한다. 키마다 해시를 계산하고 충돌을 해결한 뒤 키를 놓는다. 최종 테이블의 내용을 보인다.

**연습문제 3.**
나눗셈법은(는) 딥러닝의 임베딩 테이블에서 어떻게 쓰이는가? 토큰 $V = 50{,}000$개의 어휘를 $m = 30{,}000$개의 버킷에 대응시킬 때 충돌의 양상을 분석하라.

??? success "연습문제 3 풀이"
    $V/m \approx 1.67$이므로 비둘기집 원리에 의해 충돌이 반드시 생긴다. 버킷마다 평균 1.67개의 토큰이 같은 임베딩을 나누어 쓴다. 충돌률과 그것이 모델의 품질에 미치는 영향은 해시 함수의 품질과 임베딩의 차원에 달렸다(차원이 높을수록 충돌을 더 잘 견딘다).

---

**연습문제 4.**
$\alpha > 0.75$일 때 해시 테이블의 크기를 다시 잡으면 삽입의 상각 비용이 $O(1)$으로 유지됨을 증명하라.

??? success "연습문제 4 풀이"
    크기를 다시 잡는 사이(용량 $m$에서 $2m$까지)에 삽입이 $m/4$번 일어난다(적재율이 $0.375$에서 $0.75$로 간다). 크기 조정에는 $O(m)$이 든다. 삽입 하나당 상각된 크기 조정 비용은 $O(m)/(m/4) = O(4) = O(1)$이다. 여기에 (균등 해싱 아래) 삽입마다의 기대 비용 $O(1)$을 더하면 전체 상각 비용은 $O(1)$이다. $\square$
