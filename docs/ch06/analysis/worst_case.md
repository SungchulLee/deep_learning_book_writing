# 최악의 경우 분석

해시 테이블 연산의 기대 $O(1)$ 보장은 **평균의 경우**에 대한 결과이며, 키가 칸에 고르게 흩어질 때 성립한다. 최악의 경우 $n$개의 키가 모두 한 칸으로 충돌하여 모든 연산이 $\Theta(n)$으로 떨어진다. 이 최악의 경우가 언제 왜 일어나는지, 그리고 어떻게 막을지 이해하는 것은 튼튼한 시스템을 만드는 데 꼭 필요하다.

## 최악의 경우의 한계

결정적인 해시 함수 $h : U \to \{0, 1, \ldots, m-1\}$과 크기가 $m$인 해시 테이블이 무엇이든, 다음을 만족하는 키 $n$개의 집합 $S$이 존재한다.

$$
h(k) = j \quad \text{for all } k \in S
$$

여기서 $j$은 고정된 어떤 칸이다. 이는 비둘기집 원리에서 따라 나온다. $|U| \gg m$이므로 전체 집합의 키 가운데 적어도 $|U|/m$개가 같은 칸으로 간다. $h$을 아는 공격자는 그중 $n$개를 고를 수 있다.

$n$개의 키가 모두 한 사슬에 들어가면 해시 테이블은 정렬되지 않은 연결 리스트로 퇴화한다.

- **탐색:** $\Theta(n)$ (사슬 전체를 훑는다)
- **삽입 (중복 검사 포함):** $\Theta(n)$
- **삭제:** $\Theta(n)$

이 $\Theta(n)$의 최악의 경우는 체이닝, 선형 탐사, 이차 탐사, 이중 해싱 등 **어떤** 충돌 해결 전략에도 해당한다. $n$개의 원소가 모두 논리적으로 같은 버킷에 있기 때문이다.

## 최악의 경우는 언제 일어나는가

최악의 경우는 이론적인 호기심거리에 그치지 않는다. 실무에서도 여러 상황에서 일어난다.

**적대적인 입력.** 웹 서버에서 공격자는 매개변수의 키가 모두 같은 칸으로 해시되는 HTTP 요청을 만들어, 해시 테이블의 성능을 무너뜨려 서비스 거부를 일으킬 수 있다. 이 공격은 여러 웹 프레임워크(PHP, 자바, 파이썬, 루비)의 해시 함수를 알아내어 실증된 바 있다.

**조직적인 키 양상.** 키가 해시 함수와 맞물리는 구조를 공유하면 뜻하지 않은 충돌이 생긴다. 예를 들면 다음과 같다.

- 테이블 크기의 배수인 키: 모든 $k = cm$에 대해 $h(k) = k \bmod m = 0$이다.
- 해시 함수가 접두사에 민감할 때 접두사가 같은 문자열 키.
- 테이블 크기가 2의 거듭제곱일 때 잇따른 정수 키. 선형 탐사에서 뭉침을 일으킨다.

**나쁜 해시 함수 설계.** 키의 일부만 쓰는(예: 마지막 몇 비트만 보는) 해시 함수는 무시한 비트에서만 다른 키를 구별하지 못한다.

## 최악의 경우 탐색의 하한

다음 정리는 어떤 결정적인 해시 함수로도 $\Theta(n)$의 최악의 경우를 피할 수 없음을 형식화한다.

**정리.** $|U| \geq nm$인 결정적 해시 함수 $h : U \to \{0, 1, \ldots, m-1\}$이 무엇이든, $|h(S)| = 1$(모든 키가 한 칸으로 해시됨)을 만족하는 키 $n$개의 집합 $S \subseteq U$이 존재한다.

*증명.* 비둘기집 원리에 의해 적어도 한 칸 $j$은 다음을 만족한다.

$$
|\{k \in U : h(k) = j\}| \geq \frac{|U|}{m} \geq n
$$

이 원상에서 키 $n$개를 고른다. 모두 칸 $j$으로 가므로 $|h(S)| = 1$이다. $\square$

이 정리는 어떤 해시 함수 하나로도 가능한 모든 입력 집합에 대해 선형보다 나은 최악의 경우 탐색을 보장할 수 없음을 보인다. 방어는 무작위화(보편 해싱)나 구조적 보장(완전 해싱)에서 와야 한다.

## 최악의 경우에 대한 방어

$\Theta(n)$의 최악의 경우를 감당할 만한 한계로 바꾸는 기법이 여럿 있다.

### 보편 해싱

초기화 시점에 보편 족에서 해시 함수를 무작위로 고르면 어떤 고정된 적대적 입력 집합도 한결같이 최악의 거동을 일으킬 수 없다. 키 $n$개의 어떤 집합에 대해서도 다음이 성립한다.

$$
\mathbb{E}[\text{chain length at slot } h(k)] \leq 1 + \frac{n-1}{m}
$$

공격자는 자기가 모르는 해시 함수를 파고들 수 없다. 족 안의 개별 해시 함수의 최악의 경우는 여전히 $\Theta(n)$일 수 있지만 하필 그 함수가 골라질 확률은 무시할 만하다.

### 완전 해싱

미리 알려진 정적 키 집합에 대해 FKS 두 층 방식은 **충돌이 하나도 없는** 해시 함수를 만들어 $O(n)$ 공간으로 최악의 경우에도 $O(1)$ 조회를 이룬다.

### 버킷마다 균형 나무 두기

어떤 구현은 사슬이 문턱값을 넘으면 균형 이진 탐색 나무(예: 레드-블랙 나무)로 바꾼다. 그러면 버킷 $j$의 키 수를 $n_j$이라 할 때 버킷마다 최악의 경우 탐색 시간이 $O(\log n_j)$으로 제한된다.

자바의 `HashMap`은 사슬이 8개 원소를 넘으면 연결 리스트에서 레드-블랙 나무로 바꾸어, 모든 키가 충돌해도 최악의 경우 탐색 시간을 $O(\log n)$으로 제한한다.

### 암호학적 해싱

키를 쓰는 암호학적 해시(예: SipHash)를 쓰면 비밀 키를 모르는 공격자가 충돌하는 키를 찾는 것이 계산적으로 불가능해진다. 파이썬(3.3부터), 러스트를 비롯한 여러 언어가 해시 범람 공격을 막으려고 SipHash 기반 해싱을 쓴다.

## 최악의 경우와 기대의 경우

최악의 경우와 기대의 경우 사이의 성능 차이는 근본적인 설계 절충을 드러낸다.

| 항목 | 기대의 경우 | 최악의 경우 |
|---|---|---|
| 탐색 시간 | $\Theta(1 + \alpha)$ | $\Theta(n)$ |
| 가정 | 단순 균등 해싱 가정 또는 보편 해싱 | 적대적 입력 |
| 확률 | 압도적으로 그럴 법함 | 특정한 입력이 있어야 함 |
| 방어 | 좋은 해시 함수 | 무작위화 또는 완전 해싱 |

실무에서는 기대의 경우가 지배적이다. 실제 해시 테이블 작업 부하를 재어 보면 사슬의 길이가 평균 $\alpha$인 푸아송분포에 가깝게 따르며, 대부분의 실제 키 분포에서 균등 분포 가정이 성립함을 확인해 준다.

## 확률적인 최악의 경우 한계

보편 해싱 아래에서도 아주 긴 사슬이 작은 확률로 생길 수 있다. 보편 해싱 아래 키가 $n$개이고 칸이 $m = n$개인 해시 테이블의 **최대 사슬 길이**는 다음을 만족한다.

$$
\Pr[\max_j L_j > c \cdot \log n] \leq \frac{1}{n^{c-1}}
$$

여기서 $c > 1$은 상수이다. 즉 가장 긴 사슬이 높은 확률로 $O(\log n)$이므로 연산마다 확률적인 최악의 경우 한계가 $O(\log n)$이 된다.

더 강한 해시 족(예: $O(\log n)$-독립 해시 함수)을 쓰면 최대 사슬 길이가 높은 확률로 $O(\log n / \log \log n)$이 되어 균형 이진 탐색 나무의 성능에 이른다.

??? example "병적인 분포와 고른 분포"

    키 $n = 8$개와 칸 $m = 4$개를 생각해 보자.

    **병적인 경우** (모든 키가 칸 0으로 해시된다):

    | 칸 | 키 | 사슬 길이 |
    |---|---|---|
    | 0 | $k_1, k_2, k_3, k_4, k_5, k_6, k_7, k_8$ | 8 |
    | 1 | -- | 0 |
    | 2 | -- | 0 |
    | 3 | -- | 0 |

    탐색 시간: $\Theta(8) = \Theta(n)$.

    **고른 경우** (키가 고르게 흩어진다):

    | 칸 | 키 | 사슬 길이 |
    |---|---|---|
    | 0 | $k_1, k_5$ | 2 |
    | 1 | $k_2, k_6$ | 2 |
    | 2 | $k_3, k_7$ | 2 |
    | 3 | $k_4, k_8$ | 2 |

    $\alpha = n/m = 2$이 상수이므로 탐색 시간은 $\Theta(1 + \alpha) = \Theta(1 + 2) = \Theta(1)$이다.

## 요약

어떤 결정적 해시 함수든 최악의 경우 탐색 시간은 $\Theta(n)$이며, 모든 키가 한 칸으로 충돌할 때 일어난다. 이 최악의 경우는 이론에 그치지 않는다. 적대적인 입력, 조직적인 키 양상, 나쁜 해시 함수 설계가 모두 실무에서 이를 일으킬 수 있다. 보편 해싱은 최악의 경우를 높은 확률로 $O(\log n)$으로 줄이고, 완전 해싱은 정적 키 집합에서 이를 아예 없애며, 버킷마다 균형 나무를 두거나 암호학적 해싱을 쓰는 혼합 방식은 동적인 상황에 실용적인 방어를 준다.

## 연습문제

**연습문제 1.**
최악의 경우 분석에 대해, 적재율이 $\alpha = 0.75$일 때 삽입과 조회의 기대 시간과 최악의 경우 시간을 계산하라.

??? success "연습문제 1 풀이"
    기대 시간은 충돌 해결 전략에 달렸으며 균등 해싱을 가정한다. 체이닝에서는 기대 시간이 $O(1 + \alpha) = O(1.75)$이다. 개방 주소법에서는 탐색에 실패할 때 기대 탐사 횟수가 $\approx 1/(1-\alpha) = 4$이다. 최악의 경우는 모든 키가 같은 칸으로 해시될 때의 $O(n)$이다.

---

**연습문제 2.**
최악의 경우 분석을(를) 써서 키 10, 22, 31, 4, 15, 28, 17을 크기가 7인 해시 테이블에 넣어라. 최종 테이블의 상태를 보여라.

??? success "연습문제 2 풀이"
    해시 함수 $h(k) = k \bmod 7$을 적용하고 이 쪽의 방법으로 충돌을 처리한다. 키마다 해시를 계산하고 충돌을 해결한 뒤 키를 놓는다. 최종 테이블의 내용을 보인다.

---

**연습문제 3.**
최악의 경우 분석은(는) 딥러닝의 임베딩 테이블에서 어떻게 쓰이는가? 토큰 $V = 50{,}000$개의 어휘를 $m = 30{,}000$개의 버킷에 대응시킬 때 충돌의 양상을 분석하라.

??? success "연습문제 3 풀이"
    $V/m \approx 1.67$이므로 비둘기집 원리에 의해 충돌이 반드시 생긴다. 버킷마다 평균 1.67개의 토큰이 같은 임베딩을 나누어 쓴다. 충돌률과 그것이 모델의 품질에 미치는 영향은 해시 함수의 품질과 임베딩의 차원에 달렸다(차원이 높을수록 충돌을 더 잘 견딘다).

---

**연습문제 4.**
$\alpha > 0.75$일 때 해시 테이블의 크기를 다시 잡으면 삽입의 상각 비용이 $O(1)$으로 유지됨을 증명하라.

??? success "연습문제 4 풀이"
    크기를 다시 잡는 사이(용량 $m$에서 $2m$까지)에 삽입이 $m/4$번 일어난다(적재율이 $0.375$에서 $0.75$로 간다). 크기 조정에는 $O(m)$이 든다. 삽입 하나당 상각된 크기 조정 비용은 $O(m)/(m/4) = O(4) = O(1)$이다. 여기에 (균등 해싱 아래) 삽입마다의 기대 비용 $O(1)$을 더하면 전체 상각 비용은 $O(1)$이다. $\square$
