# CPU와 기억 장치

---

---

## 2. CPU는 어떤 일꾼인가

CPU(중앙 처리 장치)는 **적은 수의 아주 똑똑한 일꾼**이다. 요즘 노트북의 CPU는 대개 코어를 4개에서 16개쯤 가진다. 코어 하나하나가 매우 빠르고, 분기 예측이나 비순차 실행 같은 장치를 갖추어 "다음에 무엇을 할지 모르는" 일도 잘 해낸다.

그래서 CPU는 다음에 강하다.

- 조건이 얽힌 논리, `if` 문이 많은 코드
- 순서를 지켜야 하는 계산
- 한 번씩만 일어나는 잡다한 일

반대로 CPU가 못하는 것은 **같은 계산을 수백만 번 되풀이하는 일**이다. 코어가 16개뿐이라면 아무리 빨라도 한 번에 16갈래밖에 못 나눈다. 신경망 학습이 정확히 이런 일이므로, 뒤에서 GPU가 등장한다.

---

## 3. 기억 장치의 층

계산을 하려면 자료가 CPU 가까이 와 있어야 한다. 그런데 빠른 기억 장치는 비싸고 작으며, 싼 기억 장치는 크고 느리다. 그래서 컴퓨터는 기억 장치를 **층**으로 쌓는다.

| 층 | 크기 | 걸리는 값 | 견주면 |
|---|---|---|---|
| 레지스터 | 수백 바이트 | 1 클럭 미만 | 손에 든 것 |
| L1 캐시 | 수십 KB | 약 1 ns | 책상 위 |
| L2/L3 캐시 | 수 MB | 약 10 ns | 서랍 속 |
| RAM(주기억 장치) | 수 GB ~ 수십 GB | 약 100 ns | 책장 |
| SSD | 수백 GB ~ 수 TB | 약 100 µs | 창고 |

층을 하나 내려갈 때마다 대략 **10배에서 1000배씩** 느려진다. RAM은 캐시보다 100배 가까이 느리고, SSD는 RAM보다 1000배 가까이 느리다.

!!! note "ROM은 왜 여기 없는가"
    ROM(읽기 전용 기억 장치)은 컴퓨터가 켜질 때 쓰이는 펌웨어를 담는다. 딥러닝을 하는 동안에는 건드릴 일이 없으므로 이 책에서는 다루지 않는다. 딥러닝에서 중요한 층은 **캐시 → RAM → (GPU의) VRAM → SSD**이다.

이 표가 실무에서 뜻하는 바는 하나다. **자료를 옮기는 값이 계산하는 값보다 클 때가 많다.** 신경망 학습이 느릴 때, 범인이 계산이 아니라 자료를 나르는 일인 경우가 흔하다.

## 4. 파이썬 반복문은 왜 느린가

기억 장치의 층을 알면 딥러닝 코드에서 가장 먼저 배우는 규칙, 곧 "반복문 말고 배열 연산을 써라"를 이해할 수 있다.

```python
import time
import numpy as np

N = 1_000_000
data = np.random.randn(N)

# ========================================================
# 방법 1: 파이썬 반복문
# ========================================================
# 원소마다 파이썬 객체를 만들고, 형을 확인하고, 다음 원소의
# 주소를 따라가야 한다. 곱셈 자체보다 이 뒤치다꺼리가 훨씬 비싸다.
start = time.perf_counter()
total = 0.0
for x in data:
    total += x * x
loop_time = time.perf_counter() - start

# ========================================================
# 방법 2: NumPy 배열 연산
# ========================================================
# 같은 계산이 C로 짜인 반복문 하나로 내려간다. 자료가 메모리에
# 나란히 붙어 있으므로 캐시가 다음에 쓸 값을 미리 실어 온다.
start = time.perf_counter()
total_np = np.sum(data * data)
numpy_time = time.perf_counter() - start

print(f"원소 개수      : {N:,}")
print(f"파이썬 반복문  : {loop_time * 1e3:8.2f} ms")
print(f"NumPy 배열 연산: {numpy_time * 1e3:8.2f} ms")
print(f"차이           : {loop_time / numpy_time:.0f}배")
print(f"두 값이 같은가 : {abs(total - total_np) < 1e-6}")
```

**출력:**

```
원소 개수      : 1,000,000
파이썬 반복문  :   146.13 ms
NumPy 배열 연산:     0.96 ms
차이           : 152배
두 값이 같은가 : True
```

두 코드는 **같은 곱셈과 같은 덧셈**을 한다. 차이는 오로지 그 계산을 어디서, 어떤 차림으로 하느냐에 있다.

- 파이썬 반복문은 원소마다 파이썬 객체를 다루고, 그 객체들은 메모리 여기저기에 흩어져 있다. 캐시가 도움이 되지 못한다.
- NumPy 배열은 값들이 메모리에 **한 줄로 붙어** 있다. 캐시는 한 번에 한 덩이씩 실어 오므로, 다음에 쓸 값이 이미 와 있다.

!!! tip "이 절의 요점"
    딥러닝 코드에서 텐서를 파이썬 반복문으로 훑고 있다면 거의 언제나 잘못 짠 것이다.
    빠른 코드는 계산을 줄인 코드가 아니라 **자료를 잘 늘어놓은 코드**이다.

## 5. 자료가 나란히 붙어 있다는 것

같은 크기의 배열이라도 메모리에 놓인 차림에 따라 걸리는 값이 달라진다.

```python
import time
import numpy as np

# 2차원 배열은 메모리에 '행 우선'으로 한 줄로 펼쳐져 담긴다.
# 즉 [0,0], [0,1], [0,2], ... 순서로 붙어 있다.
A = np.random.randn(4000, 4000)

def timed(fn, reps=3):
    fn()                                  # 캐시를 데운다
    start = time.perf_counter()
    for _ in range(reps): fn()
    return (time.perf_counter() - start) / reps

# 행을 따라 더하기: 메모리를 앞에서 뒤로 곧게 훑는다
row_time = timed(lambda: A.sum(axis=1))

# 열을 따라 더하기: 4000개씩 건너뛰며 훑는다
col_time = timed(lambda: A.sum(axis=0))

print(f"배열 크기            : {A.shape}, {A.nbytes / 1e6:.0f} MB")
print(f"행을 따라 더하기      : {row_time * 1e3:6.2f} ms  (메모리를 곧게 훑음)")
print(f"열을 따라 더하기      : {col_time * 1e3:6.2f} ms  (건너뛰며 훑음)")
print(f"더한 원소 개수는 같다 : {A.sum(axis=1).size * 4000 == A.sum(axis=0).size * 4000}")
```

**출력:**

```
배열 크기            : (4000, 4000), 128 MB
행을 따라 더하기      :   2.23 ms  (메모리를 곧게 훑음)
열을 따라 더하기      :   2.55 ms  (건너뛰며 훑음)
더한 원소 개수는 같다 : True
```

더하는 숫자의 개수는 정확히 같은데도 걸리는 값이 다르다. 건너뛰며 읽으면 캐시가 실어 온 덩이에서 값 하나만 쓰고 버리게 되기 때문이다.

다만 위에서 잰 차이는 10%대로 그리 크지 않다. NumPy가 이런 뻔한 훑기를 미리 알아채고 덩이 단위로 나누어 처리하기 때문이다. 훑는 차례가 더 불규칙해서 미리 알아채기 어려울수록 차이가 벌어진다. 요점은 배수의 크기가 아니라, **같은 개수의 덧셈인데도 값이 달라진다**는 사실 자체이다.

이 성질은 뒤에서 PyTorch의 `view`, `reshape`, `contiguous`를 이해할 때 다시 나온다. 자세한 것은 [4장의 메모리 배치와 스트라이드](../../ch04/tensor_attrs/memory_layout_strides.md)에 있다.

## 연습문제

<div class="drillbox" markdown>

**연습문제 1.**
위의 첫 번째 코드에서 `N`을 100배 줄이면 파이썬 반복문과 NumPy의 값 차이는 어떻게 되겠는가? 실제로 재어 보고 까닭을 말하라.

</div>

??? success "연습문제 1 풀이"
    차이가 줄어든다. NumPy를 부르는 데에도 **고정된 값**(파이썬 함수 호출, 배열 검사)이 들기 때문이다. 원소가 적으면 이 고정 비용이 전체에서 차지하는 몫이 커져서 이득이 묻힌다.

    같은 이치가 GPU에도 그대로 적용된다. 일감이 작으면 GPU가 CPU보다 오히려 느리다. [CPU와 GPU를 재어 보기](../pytorch/02_cpu_vs_gpu.md)에서 이를 직접 확인한다.

<div class="drillbox" markdown>

**연습문제 2.**
RAM이 SSD보다 1000배쯤 빠르다면, 학습 자료를 매 에포크마다 SSD에서 새로 읽는 것과 한 번 읽어 RAM에 올려 두는 것의 차이는 얼마나 되겠는가?

</div>

??? success "연습문제 2 풀이"
    자료가 RAM에 들어갈 만큼 작다면 한 번만 읽고 올려 두는 편이 압도적으로 빠르다. 그래서 작은 데이터셋은 통째로 메모리에 올린다.

    자료가 RAM보다 크면 그럴 수 없으므로, 읽는 일과 계산하는 일을 **겹쳐서** 한다. GPU가 지금 묶음을 계산하는 동안 다음 묶음을 미리 읽어 두는 것이다. PyTorch `DataLoader`의 `num_workers`가 하는 일이 바로 이것이다.

<div class="drillbox" markdown>

**연습문제 3.**
두 번째 코드에서 `A`를 전치한 `A.T`에 대해 같은 실험을 하면 행과 열의 값이 뒤바뀌겠는가?

</div>

??? success "연습문제 3 풀이"
    그렇다. `A.T`는 자료를 새로 복사하지 않고 **읽는 순서만 바꾼** 것이다. 따라서 `A.T`에서 행을 따라 더하는 일은 `A`에서 열을 따라 더하는 일과 똑같이 건너뛰며 읽게 된다.

    NumPy와 PyTorch 모두 이런 "값은 그대로 두고 보는 방식만 바꾸는" 연산을 즐겨 쓴다. 값이 싸기 때문이다. 다만 그 뒤의 연산이 느려질 수 있다는 것이 이 실험의 요점이다.

## 정리하며

**다룬 것** — CPU의 성격과 기억 장치의 층

CPU는 적은 수의 똑똑한 일꾼이라 조건이 얽힌 일에 강하고, 같은 계산을 수백만 번 되풀이하는 일에는 약하다. 기억 장치는 레지스터에서 SSD까지 층으로 쌓여 있으며 한 층 내려갈 때마다 10~1000배씩 느려진다.

여기서 딥러닝 코드의 첫 번째 규칙이 나온다. **계산을 줄이려 애쓰기 전에 자료를 어떻게 늘어놓았는지 보라.** 파이썬 반복문이 느린 것도, 열을 따라 더하는 일이 느린 것도, 계산량이 많아서가 아니라 자료를 잘못 훑기 때문이다.

다음 절에서는 "같은 계산을 수백만 번" 하는 일을 위해 만들어진 장치인 GPU를 본다.
