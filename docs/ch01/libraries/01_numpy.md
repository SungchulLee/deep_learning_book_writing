## 2. ndarray: 한 줄로 붙어 있는 숫자들

NumPy의 중심에는 `ndarray`가 있다. 파이썬 리스트와 겉보기는 비슷하지만 속은 전혀 다르다.

| | 파이썬 리스트 | NumPy 배열 |
|---|---|---|
| 담기는 것 | 객체를 가리키는 주소들 | 숫자 값 자체 |
| 메모리 배치 | 여기저기 흩어짐 | 한 줄로 붙어 있음 |
| 자료형 | 원소마다 다를 수 있음 | 전체가 하나로 통일 |
| 연산 | 반복문으로 하나씩 | 배열 전체를 한 번에 |

앞 절에서 본 기억 장치의 층을 떠올리면, "한 줄로 붙어 있음"이 왜 결정적인지 알 수 있다. 캐시가 한 덩이를 실어 오면 다음에 쓸 값이 이미 와 있기 때문이다.

```python
import numpy as np

# ========================================================
# 만들기
# ========================================================
a = np.array([1, 2, 3, 4])                 # 리스트에서
b = np.zeros((2, 3))                       # 0으로 채운 (2,3)
c = np.arange(0, 10, 2)                    # 0부터 2씩 건너뛰며 10 미만
d = np.linspace(0, 1, 5)                   # 0과 1 사이를 5등분

print(f"a = {a}")
print(f"b =\n{b}")
print(f"c = {c}")
print(f"d = {d}")

# ========================================================
# 모양과 자료형
# ========================================================
# 딥러닝에서 가장 자주 마주치는 오류는 모양이 어긋나는 것이다.
# 그래서 shape을 읽는 버릇이 중요하다.
x = np.random.randn(100, 3)
print(f"\nx.shape  = {x.shape}   <- (표본 수, 특징 수)")
print(f"x.ndim   = {x.ndim}        <- 축이 몇 개인가")
print(f"x.dtype  = {x.dtype}  <- 어떤 숫자로 담기는가")
print(f"x.nbytes = {x.nbytes} 바이트")

# 자료형을 바꾸면 크기도 바뀐다. 딥러닝에서는 float32가 표준이다.
x32 = x.astype(np.float32)
print(f"float32로 바꾸면: {x32.nbytes} 바이트 (절반)")
```

**출력:**

```
a = [1 2 3 4]
b =
[[0. 0. 0.]
 [0. 0. 0.]]
c = [0 2 4 6 8]
d = [0.   0.25 0.5  0.75 1.  ]

x.shape  = (100, 3)   <- (표본 수, 특징 수)
x.ndim   = 2        <- 축이 몇 개인가
x.dtype  = float64  <- 어떤 숫자로 담기는가
x.nbytes = 2400 바이트
float32로 바꾸면: 1200 바이트 (절반)
```

!!! note "왜 float32인가"
    파이썬과 NumPy의 기본값은 `float64`(배정밀도)이지만, 딥러닝은 거의 언제나 `float32`를 쓴다.
    메모리를 절반만 쓰고, GPU가 `float32`에 맞추어 설계되어 있기 때문이다. 학습에 필요한 정밀도로는 32비트면 넉넉하다. 요즘은 16비트까지 내려가기도 한다.

## 3. 반복문을 걷어내기

NumPy를 쓰는 참뜻은 배열을 만드는 데 있지 않고 **반복문을 없애는 데** 있다.

```python
import numpy as np

X = np.random.randn(1000, 3)
w = np.array([2.0, -1.0, 0.5])
b = 0.1

# ========================================================
# 하지 말아야 할 방식
# ========================================================
preds_loop = np.zeros(len(X))
for i in range(len(X)):
    total = 0.0
    for j in range(len(w)):
        total += X[i, j] * w[j]
    preds_loop[i] = total + b

# ========================================================
# 해야 할 방식
# ========================================================
# 위의 이중 반복문 전체가 행렬 곱 한 줄이 된다.
preds_vec = X @ w + b

print(f"두 결과가 같은가: {np.allclose(preds_loop, preds_vec)}")
print(f"모양: X{X.shape} @ w{w.shape} -> {preds_vec.shape}")
print(f"앞의 세 값: {preds_vec[:3]}")
```

**출력:**

```
두 결과가 같은가: True
모양: X(1000, 3) @ w(3,) -> (1000,)
앞의 세 값: [0.69013398 2.54360786 2.80308321]
```

`X @ w + b`는 이 책 전체에서 되풀이해 나오는 식이다. 선형 모델도, 신경망의 층 하나도 모두 이 꼴이다. 지금은 NumPy로 쓰지만, 뒤에서 PyTorch로 옮기면 **같은 식이 GPU에서 돌고 미분까지 저절로 된다.**

## 4. 방송

모양이 다른 배열끼리 연산할 때 NumPy는 작은 쪽을 자동으로 늘려 맞춘다. 이를 **방송**(broadcasting)이라 한다.

규칙은 두 가지다. 뒤쪽 축부터 맞추어 보아 **크기가 같거나, 한쪽이 1이면** 맞출 수 있다.

```python
import numpy as np

X = np.random.randn(4, 3)          # 표본 4개, 특징 3개

# (4,3)과 (3,) -> 뒤쪽 축 3이 같으므로 행마다 더해진다
col_mean = X.mean(axis=0)          # (3,)
centered = X - col_mean

# (4,3)과 (4,1) -> 뒤쪽 축이 3과 1이므로 열마다 더해진다
row_mean = X.mean(axis=1, keepdims=True)   # (4,1)
row_centered = X - row_mean

print(f"X{X.shape} - col_mean{col_mean.shape} -> {centered.shape}")
print(f"X{X.shape} - row_mean{row_mean.shape} -> {row_centered.shape}")
print(f"\n열 평균을 뺐으니 열 평균은 0: {np.allclose(centered.mean(axis=0), 0)}")
print(f"행 평균을 뺐으니 행 평균은 0: {np.allclose(row_centered.mean(axis=1), 0)}")

# keepdims를 빠뜨리면 모양이 어긋나 엉뚱한 방송이 일어난다
wrong = X.mean(axis=1)             # (4,) 이지 (4,1)이 아니다
try:
    X - wrong
except ValueError as e:
    print(f"\nkeepdims 없이 빼면: {e}")
```

**출력:**

```
X(4, 3) - col_mean(3,) -> (4, 3)
X(4, 3) - row_mean(4, 1) -> (4, 3)

열 평균을 뺐으니 열 평균은 0: True
행 평균을 뺐으니 행 평균은 0: True

keepdims 없이 빼면: operands could not be broadcast together with shapes (4,3) (4,) 
```

`keepdims=True`를 빠뜨려 생기는 오류는 딥러닝 코드에서 대단히 흔하다. 게다가 운이 나쁘면 **오류가 나지 않고 조용히 틀린 계산**이 되므로 더 위험하다.

## 5. NumPy는 CPU에서만 돈다

NumPy는 GPU를 쓰지 못한다. 이것이 NumPy의 한계이자, PyTorch가 필요한 까닭이다.

| | NumPy | PyTorch |
|---|---|---|
| 배열/텐서 | `ndarray` | `Tensor` |
| 도는 곳 | CPU만 | CPU와 GPU |
| 자동 미분 | 없음 | 있음 |
| 쓰임새 | 자료 다루기, 전처리 | 신경망 학습 |

문법은 놀랄 만큼 비슷하다. `np.zeros`는 `torch.zeros`이고, `X @ w`는 그대로 `X @ w`이다. 그래서 NumPy를 알면 PyTorch의 절반은 이미 아는 셈이다. 나머지 절반이 **장치**와 **자동 미분**이며, 그것이 다음 절의 주제이다.

## 연습문제

**연습문제 1.**
`np.arange(12).reshape(3, 4)`의 모양과 원소를 예상하고 확인하라. 이어서 `.T`를 취하면 모양이 어떻게 되는가?

??? success "연습문제 1 풀이"
    `arange(12)`는 0부터 11까지이고, `reshape(3,4)`는 이를 행 우선으로 채우므로 첫 행이 `[0,1,2,3]`이 된다. `.T`는 `(4,3)`이 되며 값을 복사하지 않고 읽는 순서만 바꾼다.

---

**연습문제 2.**
`X`가 `(N, D)`일 때 각 특징을 평균 0, 표준편차 1로 만드는 한 줄을 쓰라.

??? success "연습문제 2 풀이"
    ```python
    X_std = (X - X.mean(axis=0)) / X.std(axis=0)
    ```
    `axis=0`은 표본 방향으로 훑어 특징마다 하나씩 값을 낸다. 여기서는 결과가 `(D,)`이고 뒤쪽 축이 맞으므로 `keepdims`가 없어도 방송이 바르게 일어난다.

    표준편차가 0인 특징이 있으면 0으로 나누게 되므로 실제로는 `X.std(axis=0) + 1e-8`처럼 작은 수를 더한다.

---

**연습문제 3.**
`(3, 1)`과 `(1, 4)`를 더하면 결과의 모양은 무엇인가?

??? success "연습문제 3 풀이"
    `(3, 4)`이다. 뒤쪽 축은 1과 4이므로 1이 4로 늘어나고, 앞쪽 축은 3과 1이므로 1이 3으로 늘어난다. 원소 3개와 4개로 12개짜리 표를 만드는 셈이며, 모든 짝의 조합을 구할 때 자주 쓰는 수법이다.

## 정리하며

**다룬 것** — `ndarray`와 배열 연산

NumPy 배열은 같은 자료형의 숫자를 메모리에 한 줄로 붙여 담는다. 그 덕분에 캐시가 잘 듣고, 반복문 없이 배열 전체를 한 번에 계산할 수 있다.

기억할 것은 셋이다. **모양과 자료형을 늘 확인할 것**, **반복문을 배열 연산으로 바꿀 것**, **방송 규칙에서 `keepdims`를 빠뜨리지 말 것.**

NumPy는 CPU에서만 돈다. 같은 문법을 GPU로 가져가고 자동 미분까지 얹은 것이 PyTorch이다.
