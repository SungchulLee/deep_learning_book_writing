## 2. 표에는 표에 맞는 그릇이 있다

NumPy 배열은 **전부 같은 자료형**이어야 한다. 그런데 현실의 자료는 그렇지 않다. 나이는 정수, 키는 실수, 성별은 글자, 가입일은 날짜인 표가 흔하다.

Pandas의 `DataFrame`은 이런 표를 위한 그릇이다. 열마다 자료형이 다를 수 있고, 열에 이름이 있으며, 행에는 색인이 붙는다.

딥러닝에서 Pandas의 자리는 분명하다. **자료를 읽고 다듬어 숫자 배열로 만드는 데까지**가 Pandas의 몫이고, 그 뒤로는 NumPy와 PyTorch가 받는다.

```python
import numpy as np
import pandas as pd

rng = np.random.default_rng(0)
n = 8

df = pd.DataFrame({
    "나이": rng.integers(20, 60, n),
    "키": rng.normal(170, 8, n).round(1),
    "지역": rng.choice(["서울", "부산", "대구"], n),
    "가입점수": rng.normal(50, 15, n).round(1),
})
# 빠진 값을 일부러 만들어 둔다. 현실의 자료에는 거의 언제나 있다.
df.loc[2, "키"] = np.nan
df.loc[5, "가입점수"] = np.nan

print(df)
print(f"\n모양: {df.shape}")
print(f"\n열별 자료형:\n{df.dtypes}")
```

**출력:**

```
   나이      키  지역  가입점수
0  54  165.7  부산  41.8
1  45  172.9  대구  45.3
2  40    NaN  부산  56.2
3  30  177.6  서울  65.6
4  32  164.4  대구  48.1
5  21  159.9  대구   NaN
6  23  165.0  대구  40.0
7  20  170.3  서울  55.3

모양: (8, 4)

열별 자료형:
나이        int64
키       float64
지역       object
가입점수    float64
dtype: object
```

## 3. 먼저 훑어보기

모델을 만들기 전에 자료를 들여다보는 일은 건너뛰어서는 안 된다. 학습이 되지 않는 까닭의 상당수가 자료에 있다.

```python
# 숫자 열의 요약: 개수, 평균, 표준편차, 사분위수
print("숫자 열 요약:")
print(df.describe().round(2))

# 빠진 값이 어디에 몇 개나 있는가
print(f"\n열별 빠진 값 개수:\n{df.isna().sum()}")

# 범주형 열에는 어떤 값이 몇 번씩 나오는가
print(f"\n지역별 개수:\n{df['지역'].value_counts()}")
```

**출력:**

```
숫자 열 요약:
          나이       키   가입점수
count   8.00    7.00   7.00
mean   33.12  167.97  50.33
std    12.29    5.98   9.15
min    20.00  159.90  40.00
25%    22.50  164.70  43.55
50%    31.00  165.70  48.10
75%    41.25  171.60  55.75
max    54.00  177.60  65.60

열별 빠진 값 개수:
나이      0
키       1
지역      0
가입점수    1
dtype: int64

지역별 개수:
지역
대구    4
부산    2
서울    2
Name: count, dtype: int64
```

`describe()`에서 눈여겨볼 것은 **개수(count)가 열마다 다른지**와 **평균과 표준편차의 크기 차이**이다. 개수가 다르면 빠진 값이 있다는 뜻이고, 열마다 크기가 크게 다르면 그대로 학습에 넣었을 때 큰 값을 가진 특징이 손실을 지배한다.

## 4. 빠진 값 다루기

빠진 값은 그대로 두면 학습이 되지 않는다. `NaN`이 하나라도 섞이면 손실 전체가 `NaN`이 된다.

```python
# 방법 1: 빠진 값이 있는 행을 버린다 — 자료가 넉넉할 때
dropped = df.dropna()

# 방법 2: 다른 값으로 메운다 — 자료가 아까울 때
# 평균으로 메우는 것이 가장 흔하나, 그만큼 분산이 줄어든다는 대가가 있다.
filled = df.copy()
filled["키"] = filled["키"].fillna(filled["키"].mean())
filled["가입점수"] = filled["가입점수"].fillna(filled["가입점수"].median())

print(f"원래 행 수      : {len(df)}")
print(f"버렸을 때 행 수 : {len(dropped)}")
print(f"메웠을 때 행 수 : {len(filled)}, 남은 결측: {filled.isna().sum().sum()}")
```

**출력:**

```
원래 행 수      : 8
버렸을 때 행 수 : 6
메웠을 때 행 수 : 8, 남은 결측: 0
```

!!! warning "메우는 값은 학습 자료에서만 구하라"
    평균으로 메울 때 그 평균을 **전체 자료**에서 구하면, 시험 자료의 정보가 학습에 새어 든다.
    이를 자료 새어 나감(data leakage)이라 하며, 시험 성적을 실제보다 좋게 보이게 만든다. 평균은 반드시 학습 자료에서만 구해 시험 자료에도 그 값을 쓴다.

## 5. 범주를 숫자로

`"서울"` 같은 글자는 그대로 계산에 넣을 수 없다. 숫자로 바꾸어야 하는데, 바꾸는 방식이 중요하다.

```python
# 나쁜 방법: 서울=0, 부산=1, 대구=2 로 번호를 매긴다.
# 모델이 "대구 > 부산 > 서울" 이라는 없는 순서를 배우게 된다.
bad = filled["지역"].map({"서울": 0, "부산": 1, "대구": 2})

# 좋은 방법: 원-핫 부호화. 범주마다 열을 하나씩 만든다.
onehot = pd.get_dummies(filled["지역"], prefix="지역").astype(int)

print("원-핫 부호화 결과:")
print(onehot.head())
print(f"\n번호 매기기 -> 모양 {bad.shape}, 없는 순서가 생긴다")
print(f"원-핫      -> 모양 {onehot.shape}, 순서가 생기지 않는다")
```

**출력:**

```
원-핫 부호화 결과:
   지역_대구  지역_부산  지역_서울
0      0      1      0
1      1      0      0
2      0      1      0
3      0      0      1
4      1      0      0

번호 매기기 -> 모양 (8,), 없는 순서가 생긴다
원-핫      -> 모양 (8, 3), 순서가 생기지 않는다
```

범주에 실제로 순서가 있다면(예: 낮음/보통/높음) 번호를 매기는 편이 낫다. 순서가 없다면 원-핫이 옳다.

## 6. 표에서 텐서까지

Pandas의 마지막 일은 숫자 배열을 넘겨주는 것이다.

```python
import torch

# 숫자 열과 원-핫 열을 이어 붙여 최종 특징 표를 만든다
features = pd.concat([filled[["나이", "키"]], onehot], axis=1)
target = filled["가입점수"]

# DataFrame -> NumPy 배열
X_np = features.to_numpy(dtype=np.float32)
y_np = target.to_numpy(dtype=np.float32)

# NumPy 배열 -> PyTorch 텐서
X = torch.from_numpy(X_np)
y = torch.from_numpy(y_np)

print(f"DataFrame {features.shape} -> NumPy {X_np.shape} -> Tensor {tuple(X.shape)}")
print(f"텐서 자료형: {X.dtype}")
print(f"특징 이름: {list(features.columns)}")
print(f"\n첫 두 행:\n{X[:2]}")
```

**출력:**

```
DataFrame (8, 5) -> NumPy (8, 5) -> Tensor (8, 5)
텐서 자료형: torch.float32
특징 이름: ['나이', '키', '지역_대구', '지역_부산', '지역_서울']

첫 두 행:
tensor([[ 54.0000, 165.7000,   0.0000,   1.0000,   0.0000],
        [ 45.0000, 172.9000,   1.0000,   0.0000,   0.0000]])
```

`DataFrame` → `ndarray` → `Tensor`로 이어지는 이 길이 표 자료를 다루는 거의 모든 작업의 첫머리에 놓인다. `dtype=np.float32`를 지정한 까닭은 앞 절에서 본 대로 딥러닝의 표준이 32비트이기 때문이다.

## 연습문제

<div class="drillbox" markdown>

**연습문제 1.**
`df.describe()`의 `count`가 열마다 다르게 나왔다. 무엇을 뜻하는가?

</div>

??? success "연습문제 1 풀이"
    그 열에 빠진 값이 있다는 뜻이다. `describe()`는 `NaN`을 세지 않으므로, `count`가 전체 행 수보다 작으면 그 차이가 곧 빠진 값의 개수이다. `df.isna().sum()`으로 확인할 수 있다.

---

<div class="drillbox" markdown>

**연습문제 2.**
범주가 10,000가지인 열을 원-핫으로 바꾸면 어떤 문제가 생기는가?

</div>

??? success "연습문제 2 풀이"
    열이 10,000개로 늘어나 메모리를 크게 먹고, 그 가운데 하나만 1이고 나머지는 0인 매우 성긴 표가 된다.

    이럴 때 쓰는 것이 **묻힘**(embedding)이다. 범주마다 짧은 실수 벡터를 배정하고 그 벡터 자체를 학습한다. 원-핫이 10,000차원이라면 묻힘은 64차원이면 넉넉하다. 자연어 처리에서 낱말을 다루는 방식이 바로 이것이다.

---

<div class="drillbox" markdown>

**연습문제 3.**
`torch.from_numpy(X_np)`로 만든 텐서의 값을 바꾸면 `X_np`도 바뀌겠는가?

</div>

??? success "연습문제 3 풀이"
    바뀐다. `from_numpy`는 자료를 복사하지 않고 **같은 메모리를 함께 쓴다.** 한쪽을 고치면 다른 쪽도 고쳐진다.

    복사본을 원하면 `torch.tensor(X_np)`를 쓰거나 `.clone()`을 붙인다. 메모리를 아끼려면 함께 쓰는 편이 낫고, 뜻하지 않은 변경을 막으려면 복사가 낫다.

## 정리하며

**다룬 것** — 표 자료를 읽어 텐서까지 잇는 길

Pandas는 열마다 자료형이 다른 표를 다루는 그릇이다. 딥러닝에서 Pandas의 몫은 자료를 읽고, 훑어보고, 빠진 값을 다루고, 범주를 숫자로 바꾸어 **숫자 배열로 넘겨주는 데까지**이다.

빠진 값을 메울 때는 그 값을 반드시 학습 자료에서만 구해야 한다. 범주는 순서가 없다면 원-핫으로 바꾸되, 범주가 너무 많으면 묻힘을 쓴다.

`DataFrame` → `ndarray` → `Tensor`가 표 자료를 다루는 표준 경로이며, 이때 `float32`로 맞춘다.

앞의 연습문제 3개로 직접 확인할 수 있다.
