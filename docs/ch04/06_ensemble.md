# 앙상블 — 여러 모델의 예측 결합

[4.1절](01_two_ladders.md)은 시드를 바꾸면 같은 모델이 72.36%에서 73.25%까지 흔들린다고 재었다. 거기서 그 흔들림은 **재는 것을 방해하는 잡음**이었다. 스텝 사이의 이득이 그 흔들림보다 큰지를 따져야 했으니까.

이 절은 같은 흔들림을 **자원으로 쓴다.**

하는 일은 이것뿐이다. 시드만 다른 모델 다섯 개를 따로 학습시키고, 시험할 때 다섯의 확률을 평균 낸다. 새 구조도, 새 데이터도, 새 생각도 없다.

!!! note "시드 하나가 왜 다른 모델을 만드는가"
    바꾸는 것은 `torch.manual_seed`에 넣는 수 하나뿐인데 나오는 다섯이 서로 다르게 틀린다. 그 수가 정하는 것이 둘이기 때문이다 — **웨이트의 초깃값**과 **배치를 섞는 차례**다.

    둘은 경사 하강법이 어디서 출발해 어느 길로 내려가는지를 정한다. 54만 차원짜리 로스면에는 로스가 비슷하게 낮은 자리가 여럿 있고, 출발점과 걸어온 길이 다르면 대개 **서로 다른 자리**에 멈춘다. 그래서 다섯의 정확도는 70.68~71.79로 비슷한데 고르는 답은 다르다 — 아래 4절이 재는 22.78%가 그 몫이다.

    그러므로 평균 낼 다섯 장을 마련하는 일은 **같은 모델을 다섯 번 만드는 일이 아니라 다섯 군데에 내려앉히는 일**이다. 다섯이 모두 같은 자리에 멈춘다면 평균해도 얻을 것이 없다.

---

## 1. 코드

평균을 내는 곳은 아래 `ensemble()` 하나뿐이다. 나머지는 모두 그 함수에 넣을 **확률 다섯 장을 마련하는 일**이다.

```python
"""4.2절: 같은 모델을 씨앗만 바꾸어 다섯 번 학습하고 확률을 평균한다.

seeds.py가 하던 것과 딱 한 군데가 다르다. 정확도만 적고 모델을 버리는
대신, 시험 집합의 확률을 남겨 둔다.

하는 일은 셋뿐이다.
  (1) 씨앗 0~4로 같은 넷트웍을 다섯 번 학습한다.
  (2) 다섯이 시험 집합에 내놓은 확률 (10000, 10) 을 다섯 장 모아 둔다.
  (3) 그 다섯 장을 겹쳐 모델 축으로 평균한다.
새 구조도 새 자료도 없다. 달라지는 것은 torch.manual_seed 에 넣는 수 하나다.
"""

import torch
import torch.nn as nn
import torch.nn.functional as F
import torch.optim as optim
from torch.utils.data import DataLoader, TensorDataset
import torchvision
import torchvision.transforms as transforms

# === 규약 =====================================================
# 4.1절과 같은 규약이되 에포크만 10이 아니라 5다. 한 모델을 길게 돌리는
# 대신 다섯 모델을 짧게 돌리는 것이 이 절이 하는 거래다.
BATCH, LR, EPOCHS = 100, 1e-3, 5
device = torch.device("mps" if torch.backends.mps.is_available() else "cpu")

# === 자료 =====================================================
# CIFAR-10 채널별 평균과 표준편차로 정규화한다. 이 장이 쓰는 규약이다.
tf = transforms.Compose([
    transforms.ToTensor(),
    transforms.Normalize((0.4914, 0.4822, 0.4465), (0.2470, 0.2435, 0.2616))])
tr_ds = torchvision.datasets.CIFAR10("./data", train=True, download=True, transform=tf)
te_ds = torchvision.datasets.CIFAR10("./data", train=False, download=True, transform=tf)


def materialize(ds):
    """데이터셋 전체를 한 번에 텐서로 펼친다.

    모델을 다섯 번 학습하므로, 그때마다 그림을 디코딩하고 transform 을
    다시 거치면 같은 일을 다섯 번 하는 셈이다. 한 번만 해 두면 다섯 번의
    학습이 그것을 돌려 쓴다. 시험 집합도 마찬가지인데 이쪽은 이유가 하나
    더 있다 — 다섯 모델이 **똑같은 Xte 를 똑같은 순서로** 보아야 확률
    다섯 장을 겹칠 수 있다.
    """
    xs, ys = [], []
    for x, y in DataLoader(ds, batch_size=2000, shuffle=False):
        xs.append(x)
        ys.append(y)
    return torch.cat(xs), torch.cat(ys)


Xtr, ytr = materialize(tr_ds)   # (50000, 3, 32, 32), (50000,)
Xte, yte = materialize(te_ds)   # (10000, 3, 32, 32), (10000,)


# === 넷트웍 =====================================================
class CNN(nn.Module):
    """4.1절 스텝4 그대로. 파라메터 545,098개."""

    def __init__(self):
        super().__init__()
        self.conv1 = nn.Conv2d(3, 32, 3, padding=1)    # 3채널 → 32채널
        self.conv2 = nn.Conv2d(32, 64, 3, padding=1)   # 32채널 → 64채널
        self.pool = nn.MaxPool2d(2, 2)                 # 지날 때마다 변 길이 절반
        self.dropout = nn.Dropout(0.25)
        self.fc1 = nn.Linear(64 * 8 * 8, 128)          # 4096 → 128
        self.fc2 = nn.Linear(128, 10)                  # 128 → 10

    def forward(self, x):                   # 들어올 때      (N, 3, 32, 32)
        # 스텝 1 — 컨볼루션. padding=1 이라 3x3 을 걸어도 변 길이가 줄지 않는다.
        x = self.conv1(x)                   # 채널만 3 → 32  (N, 32, 32, 32)
        x = torch.relu(x)                   # 모양 그대로    (N, 32, 32, 32)
        x = self.pool(x)                    # 변 길이 절반   (N, 32, 16, 16)

        # 스텝 2 — 같은 것을 한 번 더. 채널은 늘고 변 길이는 준다.
        x = self.conv2(x)                   # 채널만 32 → 64 (N, 64, 16, 16)
        x = torch.relu(x)                   # 모양 그대로    (N, 64, 16, 16)
        x = self.pool(x)                    # 변 길이 절반   (N, 64, 8, 8)

        # 스텝 3 — 펴서 빽빽한 레이어로. 64*8*8 = 4096 이 fc1 의 입력 크기다.
        x = x.flatten(1)                    # 축 0(그림)은 둠 (N, 4096)
        x = self.fc1(x)                     #               (N, 128)
        x = torch.relu(x)                   # 모양 그대로    (N, 128)
        x = self.dropout(x)                 # train() 일 때만 (N, 128)
                                            #   끊는다. eval() 이면 그냥 통과

        # 스텝 4 — 클래스 열 개로. 여기서 나오는 것은 **로짓**이다.
        return self.fc2(x)                  # 나갈 때        (N, 10)
                                            #   softmax 는 아직 아니다 —
                                            #   학습은 crit 이, 시험은
                                            #   test_probs 가 각각 씌운다


# === 학습 =====================================================
def train(seed, epochs=EPOCHS):
    """씨앗 하나로 모델 하나를 학습해 **평가 모드로** 돌려준다."""
    torch.manual_seed(seed)        # 달라지는 것은 이것뿐이다 — 웨이트
                                   # 초깃값과 드롭아웃 패턴이 여기서 갈린다
    model = CNN().to(device)
    opt = optim.Adam(model.parameters(), lr=LR)
    crit = nn.CrossEntropyLoss()   # 로짓을 받아 안에서 log_softmax 를 한다.
                                   # 그래서 forward 가 로짓을 내놓는 것이다

    # 섞는 순서도 씨앗을 따라가도록 전용 난수기를 쓴다. 전역 난수기는 바로
    # 위에서 웨이트를 뽑느라 이미 소비되었으므로, 따로 두어야 "씨앗 s의
    # 섞는 순서"가 무엇인지 분명해진다.
    g = torch.Generator().manual_seed(seed)
    loader = DataLoader(TensorDataset(Xtr, ytr), batch_size=BATCH,
                        shuffle=True, generator=g)

    for _ in range(epochs):
        model.train()              # 드롭아웃 켜기
        for x, y in loader:
            x, y = x.to(device), y.to(device)
            opt.zero_grad()
            loss = crit(model(x), y)
            loss.backward()
            opt.step()
    return model.eval()            # 드롭아웃 끄기 — 아래 test_probs 가 이것에
                                   # 기댄다. 켜 둔 채로 재면 모델마다 확률이
                                   # 매번 달라져 겹칠 수가 없다


# === 확률 남기기 ===============================================
@torch.no_grad()
def test_probs(model):
    """시험 집합 1만 장에 대한 클래스 확률 (10000, 10).

    행 하나가 그림 한 장이고 열 열 개가 클래스 열 개다. softmax 를 지났으니
    **한 행의 합은 1**이다. 이 성질 하나가 아래 ensemble() 을 성립시킨다.

    로짓이 아니라 확률을 남기는 까닭은 ensemble() 에 적었다.
    1000장씩 끊는 것은 메모리 때문일 뿐 결과와는 무관하다.
    """
    chunks = []
    for i in range(0, len(Xte), 1000):
        logits = model(Xte[i:i + 1000].to(device))   # (1000, 10) 크기가 제멋대로
        batch_probs = torch.softmax(logits, 1)       # (1000, 10) 행마다 합이 1
        chunks.append(batch_probs.cpu())
    return torch.cat(chunks)                         # (10000, 10)


# === 평균 내기 — 이 절이 하는 일 전부 ==========================
def ensemble(prob_list):
    """확률 여러 장을 겹쳐 **모델 축으로** 평균한 (10000, 10).

    왜 로짓이 아니라 확률인가.
      로짓은 크기가 정해져 있지 않다. 어떤 모델은 [-2, 8] 을, 어떤 모델은
      [-20, 30] 을 내놓으며, 둘이 나타내는 확신이 같아도 그럴 수 있다.
      로짓을 그냥 평균하면 **수가 큰 모델이 평균을 끌고 간다.** 다섯 표를
      걷는 것이 아니라 목소리 큰 하나를 따르는 셈이 된다.
      softmax 를 지나면 다섯이 모두 합 1짜리 확률이 되므로 발언권이 같아진다.
      그래서 평균할 것은 확률이다. (연습문제 1)
    """
    # (1) 다섯 장을 새 축 0에 쌓는다. 축 0이 "몇 번째 모델인가"가 된다.
    stacked = torch.stack(prob_list)        # (5, 10000, 10)

    # (2) 그 축 0으로 평균한다. 같은 그림 같은 클래스에 매긴 다섯 개의 확률이
    #     하나로 합쳐진다. 축 1(그림)이나 축 2(클래스)로 평균하는 것도 문법
    #     으로는 되지만 뜻이 전혀 다르다 — 고를 축은 하나뿐이다.
    #     합이 1인 행 다섯을 평균했으므로 결과도 행의 합이 1이다. 즉 평균은
    #     여전히 확률분포이고, 그래서 argmax 를 할 수 있다.
    return stacked.mean(0)                  # (10000, 10)


def predict(prob_matrix):
    """확률 (N, 10) → 예측 클래스 (N,). 여기서 축 1은 **클래스** 축이다.

    바로 위 mean(0) 의 0과 이 argmax(1) 의 1은 서로 다른 축을 가리킨다.
    (5, 10000, 10) 에서 모델 축을 접고 나면 남는 것은 (10000, 10) 이고,
    그 축 1이 클래스다.
    """
    return prob_matrix.argmax(1)


def acc(pred):
    """예측 (N,) 을 정답 yte 와 견준 정확도(%)."""
    return 100.0 * (pred == yte).float().mean().item()


# === (1) 다섯 번 학습하고 확률을 모은다 ========================
probs = []                                  # 길이 5, 원소마다 (10000, 10)
for seed in range(5):
    m = train(seed)
    p = test_probs(m)                       # 이 모델이 본 1만 장의 확률
    probs.append(p)
    print(f"  씨앗 {seed}  {acc(predict(p)):.2f}%", flush=True)

# === (2) 홑모델들은 어디쯤인가 =================================
singles = [acc(predict(p)) for p in probs]
print(f"\n홑모델 평균 {sum(singles) / 5:.2f}%  가장 좋은 것 {max(singles):.2f}%")

# === (3) 몇 개를 모을 때까지 이득이 이어지는가 =================
# probs[:k] 이므로 "k개"는 언제나 씨앗 0~k-1 이다. 잘한 순서로 고른 k개가
# 아니다 — 고르기 시작하면 시험 집합을 보고 고르는 셈이 된다.
print()
for k in range(1, 6):
    ens = ensemble(probs[:k])               # (10000, 10)
    print(f"앙상블 {k}개  {acc(predict(ens)):.2f}%")

# === (4) 다양성 — 두 모델이 서로 다르게 답한 비율의 평균 =======
# preds 는 확률이 아니라 **답**을 쌓은 것이다. 축 0이 모델, 축 1이 그림.
preds = torch.stack([predict(p) for p in probs])      # (5, 10000)
dis = [100.0 * (preds[i] != preds[j]).float().mean().item()
       for i in range(5) for j in range(i + 1, 5)]    # 쌍 10개
print(f"\n서로 다르게 답한 비율 {sum(dis) / len(dis):.2f}%")

# === (5) 천장 — 다섯 가운데 하나라도 맞힌 비율 =================
# (preds == yte) 는 (5, 10000) 짜리 참거짓표다. any(0) 이 모델 축을 접어
# 그림마다 "다섯 중 하나라도 맞혔는가"만 남긴다. 어떤 결합 방식도 이 값을
# 넘지 못하므로 천장이다.
print(f"신탁 (하나라도 맞힌 비율) {100.0 * (preds == yte).any(0).float().mean():.2f}%")
```

**출력:**

```
  씨앗 0  71.49%
  씨앗 1  71.42%
  씨앗 2  71.29%
  씨앗 3  71.79%
  씨앗 4  70.68%

홑모델 평균 71.33%  가장 좋은 것 71.79%

앙상블 1개  71.49%
앙상블 2개  73.32%
앙상블 3개  74.06%
앙상블 4개  74.41%
앙상블 5개  74.73%

서로 다르게 답한 비율 22.78%
신탁 (하나라도 맞힌 비율) 86.79%
```

## 2. 결과

| | 정확도 |
|---|---|
| 단일 모델 다섯 개 | 71.49, 71.42, 71.29, 71.79, 70.68 |
| 단일 모델 평균 | 71.33% |
| 단일 모델 최고 | 71.79% |
| **다섯 개 앙상블** | **74.73%** |

평균 단일 모델보다 **3.40%포인트**, 가장 좋았던 단일 모델보다 **2.94%포인트** 높다. 위 다섯 단일 모델이 70.68~71.79로 흩어졌으니 **이 자리에서 잰 시드 스프레드는 1.11**이고, 이득이 흔들림의 세 배에 가깝다. 재고 있다고 말해도 된다.

몇 개부터 이득이 붙는지 보면 이렇다.

| 모델 수 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| 정확도 | 71.49 | 73.32 | 74.06 | 74.41 | 74.73 |
| 더해진 몫 | — | **+1.83** | +0.74 | +0.35 | +0.32 |

**이 순서에서는 두 번째 모델이 전체 개선의 절반 이상을 가져왔다.** 이후 추가 개선은 줄었다. 다만 모델을 넣는 순서를 바꾸거나 다른 시드를 쓰면 이 곡선도 달라질 수 있다.

!!! note "이 절의 단일 모델이 4.1절의 바닥보다 낮은 까닭"
    [4.1절](01_two_ladders.md)의 스텝4 CNN은 **72.58%**인데 위 다섯 단일 모델은 70.68~71.79다. 모델도 데이터도 규약도 같고 **예산만 다르다** — 4.1절은 10 에포크를 돌리고 이 절은 5 에포크를 돌린다. 같은 네트워크가 5 에포크에서 71.33%, 10 에포크에서 72.58%다.

    그래서 이 절이 버는 몫은 **제 바닥에서 재야 한다.** 71.33%에서 74.73%로 **+3.40%포인트**다. [장 개요](index.md)의 표에 적힌 +2.15는 10 에포크 바닥과의 **자리 차이**이지 앙상블이 번 몫이 아니다.

## 3. 같은 계산을 어디에 쓸 것인가

이 절이 진짜로 묻는 것은 이것이다. 셈할 여력이 정해져 있을 때, **한 모델을 오래 돌릴 것인가 여러 모델을 짧게 돌릴 것인가.**

[4.5절](04_augmentation.md)이 그 가운데 한쪽을 잰다. 그 값을 미리 가져와 나란히 놓으면 이렇다.

| 쓰는 곳 | 에포크 총합 | 정확도 |
|---|---|---|
| 1개 모델을 30 에포크 | 30 | 71.75% |
| **5개 모델을 5 에포크씩** | **25** | **74.73%** |

**에포크를 더 적게 쓰고 2.98%포인트를 더 얻는다.**

4.5절이 보이듯 한 모델에 25 에포크를 더 주면 그 시간을 전부 **외우는 데** 쓴다. 학습 정확도가 81.40%에서 99.05%로 오르는 동안 시험 정확도는 71.86%에서 71.75%로 제자리였다. 같은 계산을 다섯 클래스로 나누면 각자 덜 외우는 대신 **서로 다른 실수를 하고**, 평균이 그 실수를 지운다.

이것이 앙상블의 요점이다. 이득은 모델이 더 똑똑해져서 나오는 것이 아니라 **실수가 서로 어긋나서** 나온다.

---

## 4. 다양성이 이득을 정한다

실수가 어긋나야 이득이 난다면, **더 많이 어긋나는 모델끼리는 더 많이 얻어야** 한다. 잴 수 있는 주장이다.

다섯 모델이 시험 그림 한 장에 서로 다른 답을 내는 비율을 재고, 같은 실험을 스텝3 MLP로도 해 보았다.

| | 시드 스프레드 (이 절에서 5 에포크로 잰 값) | 서로 다르게 답하는 비율 | 앙상블이 버는 몫 |
|---|---|---|---|
| 스텝4 CNN | 1.11 | 22.78% | +3.40%p |
| 스텝3 MLP | 2.74 | **38.22%** | **+4.29%p** |

MLP의 예측 불일치 비율은 더 높았고 앙상블 개선도 더 컸다. 그러나 두 구조의 단일 모델 성능도 다르므로, 불일치 비율 하나만으로 개선량을 설명할 수는 없다. 다양성과 각 모델의 정확도가 모두 중요하다.

4.1절은 같은 두 네트워크를 10 에포크로 재어 스프레드를 0.89와 1.73으로 적었다. 예산이 짧을수록 더 흩어지므로 이 절의 값이 더 크다. 어느 쪽이든 **MLP가 CNN보다 두 배 넘게 흩어진다**는 관계는 같다.

여기서 [4.1절](01_two_ladders.md)의 표를 다시 읽게 된다. 그 절에서 스프레드가 큰 것은 나쁜 소식이었다. 재기 어렵다는 뜻이었으니까. 같은 수가 이 절에서는 좋은 소식이다. **모델들이 서로 다르다는 뜻이기 때문이다.** 하나의 측정값이 무엇을 재려느냐에 따라 잡음도 되고 자원도 된다.

---

## 5. 천장은 어디인가

평균이 최선인가? 다섯 가운데 **하나라도** 맞힌 비율을 세어 보면 알 수 있다. 매번 맞힌 모델을 골라낼 수 있다면 얻을 정확도이며, 각 모델이 이미 예측한 클래스 중 하나만 선택하는 방식에서는 이 값이 상한이다. 확률을 결합해 새로운 클래스를 선택하는 방식까지 포함한 상한은 아니다.

| | 단일 모델 평균 | 앙상블 (평균) | 오라클 (하나라도 맞힘) |
|---|---|---|---|
| 스텝4 CNN | 71.33% | 74.73% | **86.79%** |
| 스텝3 MLP | 50.35% | 54.64% | 73.47% |

**71%짜리 모델 다섯이 모이면, 그 가운데 정답을 예측한 모델이 있는 경우가 86.79%다.** [4.1절](01_two_ladders.md)의 스텝4 CNN 한 대(72.58%)보다 14.21%포인트 높다. **남의 표현을 빌리지 않고** 이 장이 닿는 가장 높은 값이 [4.5절](04_augmentation.md)의 77.71%이니, 그보다도 9%포인트 넘게 높은 자리다(빌리고 나면 [4.6절](03_vgg16_transfer.md)의 백본 여덟 가운데 여섯이 이 값을 넘는다).

그런데 단순 평균은 그중 74.73%만 건져 낸다. **12%포인트가 "누군가는 알고 있다"와 "평균이 찾아낸다" 사이에 놓여 있다.**

평균이 놓치는 까닭은 간단하다. 한 모델만 정답을 알고 넷이 틀린 쪽으로 몰려 있으면, 평균은 다수를 따른다. 다수결이나 단순 평균보다 나은 결합을 찾는 일이 여기서부터 시작되며, 어느 모델을 언제 믿을지 가리는 것이 그 핵심이다.

---

## 6. 공짜가 아니다

"새 생각 없이" 얻었다고 해서 값이 없는 것은 아니다.

| | 단일 모델 | 5개 앙상블 |
|---|---|---|
| 학습 계산 | 1배 | 5배 |
| 추론 계산 | 1배 | **5배** |
| 저장할 파라메터 | 545,098 | **2,725,490** |
| 정확도 | 71.33% | 74.73% |

학습이 다섯 배 드는 것은 앞의 "같은 계산을 어디에 쓸 것인가"에서 보았듯 오히려 남는 장사였다. 같은 에포크로 더 얻었으니 학습 쪽은 손해가 아니다. 문제는 **추론**이다. 그림 한 장을 판정할 때마다 다섯 번 순전파해야 한다.

그래서 견줄 자리를 옳게 잡아야 한다. [4.1절](01_two_ladders.md)의 스텝4 CNN 한 대는 파라메터 54만 개와 순전파 한 번으로 72.58%를 낸다(10 에포크). 앙상블은 272만 개와 순전파 다섯 번을 들여 74.73%를 낸다(5 에포크씩 다섯). **2.15%포인트에 추론 다섯 배를 치른** 계산이다. 같은 5 에포크끼리 견주면 71.33%와 74.73%로 몫이 3.40%포인트이지만, 내보낼 모델을 고르는 자리에서는 더 잘 학습된 한 대와 비교하는 쪽이 옳다. 정확도만 적고 비용을 적지 않으면 이 거래가 남는 장사처럼 보인다.

그러니 물음은 이렇게 바뀐다. **같은 2%포인트를 더 싸게 살 수 있는가?** [4.3절](07_distillation.md)이 그 물음에 답한다.

**그리고 앙상블이 값진 자리는 따로 있다.** 이미 최선을 다한 모델이 있고, 새 생각은 떨어졌고, 정확도 2~3%포인트가 더 필요하며, 추론 비용은 감당할 수 있을 때다. 대회에서 앙상블이 흔하고 실시간 서비스에서 드문 까닭이 그것이다.

---

## 7. 좋은 점과 아쉬운 점

### 좋은 점

**새 생각이 없어도 된다.** 이 절이 더한 것은 수법 하나가 아니라 **같은 모델을 시드만 바꾸어 다섯 번 학습한 것**뿐이다. 구조도 로스도 최적화기도 그대로이고, 새로 고를 값이 하나도 없다. 이 장의 다른 절은 모두 무엇인가를 새로 들여오는데 이 절만 그렇지 않다.

**이득이 흔들림보다 크다.** 평균 단일 모델보다 3.40%포인트, 가장 좋았던 단일 모델보다도 2.94%포인트 높다. 그 자리의 시드 스프레드가 1.11이니 **이득이 스프레드의 세 배에 가깝다.** 이 장에서 이만큼 또렷한 이득은 흔하지 않다.

**두 대만 써도 대부분을 얻는다.** 더해지는 몫이 +1.83, +0.74, +0.35, +0.32로 빠르게 준다. 다섯 대를 세울 형편이 안 되면 **둘로 절반 넘게** 가져갈 수 있다. 값을 치르는 만큼만 사는 것이 가능하다는 뜻이다.

**거의 언제나 쓸 수 있다.** 얼릴 백본도, 빌려 올 웨이트도, 늘릴 데이터도 필요 없다. 모델 하나를 학습할 수 있으면 앙상블도 할 수 있다.

### 아쉬운 점

**추론이 다섯 배다.** 학습이 다섯 배인 것은 3절에서 보았듯 오히려 남는 장사였지만, 추론은 그림 한 장마다 순전파를 **다섯 번** 해야 한다. 학습은 한 번 치르고 끝나는 값이고 추론은 서비스가 사는 동안 내내 치르는 값이라, 둘을 같은 "다섯 배"로 적으면 안 된다.

**들고 다닐 파라메터가 다섯 배다.** 545,098개가 2,725,490개가 된다. 스텝4 CNN 한 대가 54만 개와 순전파 한 번으로 72.58%를 내는 것과 견주면, **2.15%포인트에 다섯 배를 치른** 계산이다.

**추가 모델의 개선은 작아졌다.** 다섯 번째 모델의 추가 개선은 0.32%포인트였다. 단일 모델의 시드 범위와 이 차이를 직접 비교해 개선이 없다고 판정할 수는 없다. 더 큰 앙상블의 결과도 여기서는 측정하지 않았다.

**다양성에 기댄다.** 4절이 보인 대로 이득의 기초는 모델들이 **서로 다르게 틀리는 것**이다. 시드만 바꾼 다섯은 구조도 데이터도 같아 다양성이 그만큼뿐이고, 그래서 천장도 낮다.

<div class="defn" markdown>

그러므로 앙상블이 값진 자리는 **이미 최선을 다한 모델이 있고, 새 생각은 떨어졌고, 2~3%포인트가 더 필요하며, 추론 비용은 감당할 수 있을 때**다. 대회에서 흔하고 실시간 서비스에서 드문 까닭이 그것이다.

같은 2%포인트를 더 싸게 사는 길은 [4.3절](07_distillation.md)이 잰다.

</div>

## 연습문제

<div class="drillbox" markdown>

**연습문제 1.** <span class="diff easy" title="쉬움"></span>
본문의 코드는 로짓이 아니라 softmax를 평균한다. 로짓을 평균하면 무엇이 달라지는가?

</div>

??? success "연습문제 1 풀이"
    로짓은 크기가 정해져 있지 않다. 어떤 모델은 $[-2, 8]$ 범위를, 어떤 모델은 $[-20, 30]$ 범위를 낼 수 있고, 이때 로짓 차이의 크기가 다르면 소프트맥스의 확신도도 달라진다. 모든 로짓에 같은 상수를 더하는 것은 확률을 바꾸지 않는다.

    로짓을 평균하면 **크기가 큰 모델이 결과를 좌우한다.** 다섯 표를 걷는 것이 아니라 목소리 큰 하나를 따르는 계산이 된다.

    softmax를 지나면 모두 합이 1인 확률이 되므로 발언권이 같아진다. 이 절에서는 각 모델에 같은 웨이트를 주어 확률을 평균한다. 로짓 평균이나 학습된 웨이트도 별도로 검증할 수 있는 선택지다.

    다만 softmax 평균이 유일한 답은 아니다. 기하평균(로그 확률의 평균)을 쓰기도 하며, 이쪽은 **한 모델이라도 강하게 반대하면 그 후보를 죽이는** 성질이 있다. 산술평균은 관대하고 기하평균은 엄격하다.

---

<div class="drillbox" markdown>

**연습문제 2.** <span class="diff med" title="중간"></span>
본문은 시드만 바꾸어 다양성을 얻었다. 시드 말고 무엇을 바꾸면 더 다양해지겠는가? 세 가지를 들고, 각각이 [4.1절](01_two_ladders.md)의 규약을 깨는지 따져라.

</div>

??? success "연습문제 2 풀이"
    **하나, 구조를 섞는다.** CNN 셋과 MLP 둘을 함께 평균한다. 서로 다른 가정 위에 서 있으므로 실수도 크게 어긋난다. 다만 약한 모델(MLP 50%)이 강한 모델(CNN 71%)을 끌어내릴 수 있어, 웨이트를 두어야 할 수 있다.

    **둘, 데이터를 나눠 준다.** 학습 집합에서 매번 다시 뽑아(부트스트랩) 모델마다 조금씩 다른 데이터를 보게 한다. 이것이 배깅이며 무작위 숲이 쓰는 방법이다. 표본 수만큼 복원 추출해도 서로 다른 원본의 수는 줄어든다. 개별 성능과 다양성에 미치는 영향은 데이터와 모델에 따라 달라진다.

    **셋, 어그멘테이션을 다르게 건다.** [4.5절](04_augmentation.md)의 수법을 모델마다 다르게 준다. 자르기만, 뒤집기만, 둘 다.

    세 방법은 각각 구조 또는 학습 데이터를 바꾸므로 시드만 바꾼 이 절의 비교와 조건이 다르다. 특히 구조를 바꾸는 것은 모델 비교의 범위에 들어가지만, 데이터와 예산까지 바꾸면 그 차이도 별도로 기록해야 한다.

---

<div class="drillbox" markdown>

**연습문제 3.** <span class="diff hard" title="어려움"></span>
오라클이 86.79%인데 평균은 74.73%만 건진다. 이 12.06%포인트를 줄이려면 무엇을 알아야 하는가? 그리고 오라클 자체를 실제로 달성할 수 없는 까닭은 무엇인가?

</div>

??? success "연습문제 3 풀이"
    **줄이려면 "어느 모델을 언제 믿을지"를 알아야 한다.** 평균은 다섯을 언제나 똑같이 대접한다. 그림마다 누가 더 미더운지 알 수 있다면 소수의 정답을 살릴 수 있다.

    실마리로 쓸 만한 것들이 있다. 확신도(softmax 최댓값)가 높은 모델에 웨이트를 더 주거나, 검증 집합에서 클래스별로 잘하는 모델을 가려 두거나, 결합하는 방법 자체를 학습시키는 것(스태킹)이다.

    **오라클을 달성할 수 없는 까닭**은 그 값을 계산할 때 **정답을 이미 썼기** 때문이다. "하나라도 맞혔는가"를 세려면 맞았는지 알아야 하고, 그것은 시험 라벨을 본다는 뜻이다. 실제로는 볼 수 없다.

    오라클은 실제 선택 규칙이 아니라 정답을 이용해 계산한 참고값이다. 각 모델의 예측 클래스 중 하나를 선택하는 방식의 상한을 보여 주지만, 모든 확률 결합 방식의 상한은 아니다.

    한 가지 더. 오라클 86.79%는 [4.1절](01_two_ladders.md)의 스텝4 CNN 한 대가 낸 72.58%보다 14.21%포인트 높다. 이 다섯 모델이 **집단으로는** 그만한 정보를 쥐고 있다는 뜻이다. 부족한 것은 정보가 아니라 그것을 꺼내는 방법이다.
