# 데이터 어그멘테이션 — 여섯째 스텝

사다리의 앞선 스텝들은 모두 **모델**을 바꾸었다. 수를 못박다가 학습하고, 레이어를 쌓고, 이웃 관계를 되찾고, 같은 컨볼루션을 더 쌓았다([4.4절](02_depth.md)). 여섯째 스텝은 처음으로 모델을 건드리지 않는다.

바꾸는 것은 **데이터**다. 파라메터는 스텝4의 545,098개 그대로이고 구조도 그대로다. 학습할 때 그림을 조금씩 흔들어 넣을 뿐이다.

견줄 자리는 **같은 모델을 어그멘테이션 없이 같은 예산으로 돌린 값**이다. 5 에포크에서 71.86%, 30 에포크에서 71.75%이며, 아래 표마다 그 짝을 함께 적는다. [4.1절](01_two_ladders.md)의 스텝4 CNN 72.58%는 10 에포크에서 잰 이 장의 바닥이고, 이 절의 두 값은 그 앞뒤 예산이라 조금 낮다. 이 절이 재는 것은 그 바닥까지의 거리가 아니라 **어그멘테이션을 걸었을 때와 걸지 않았을 때의 차이**다. 시드는 42 하나를 쓴다.

!!! note "스텝 번호와 절 번호는 어긋난다"
    이 절은 4.5절이지만 사다리에서는 여섯째 스텝이다. 스텝 번호는 **사다리에서의 자리**를, 절 번호는 **읽는 차례**를 가리키며, 이 장은 낮은 값에서 높은 값으로 올라가도록 절을 놓았기 때문에 둘이 어긋난다. 자세한 것은 [장 구조](index.md)에 적어 두었다.

---

## 1. 무엇을 흔드는가

두 가지만 쓴다.

| 수법 | 하는 일 |
|---|---|
| `RandomCrop(32, padding=4)` | 테두리를 4칸 덧대어 $40 \times 40$으로 만든 뒤 $32 \times 32$를 아무 데나 오려 낸다 |
| `RandomHorizontalFlip()` | 절반의 확률로 좌우를 뒤집는다 |

변환은 표본을 불러올 때 무작위로 적용된다. 같은 원본을 여러 번 봐도 다른 변형을 볼 수 있지만, 같은 변형이 반복될 수도 있다. 원본 5만 장의 종류가 늘어나는 것은 아니며, 허용된 변형을 통해 입력의 변화를 경험하게 한다.

!!! warning "좌우 뒤집기는 데이터셋을 가린다"
    말을 좌우로 뒤집어도 말이다. 배도 배고 개구리도 개구리다. 그래서 CIFAR-10에서는 이 수법이 옳다.

    **MNIST였다면 쓸 수 없다.** 2를 좌우로 뒤집으면 숫자가 아니게 되고, 5를 뒤집으면 더더욱 그렇다. 3장에서 이 수법을 쓰지 않은 까닭이다.

    어그멘테이션이 옳은지 그른지는 모델이 정하지 않는다. **데이터가 무엇을 뜻하는가**가 정한다. 뒤집어도 이름이 그대로인 데이터에서만 뒤집을 수 있다.

시험 데이터에는 어그멘테이션을 걸지 않는다. 어그멘테이션은 학습을 어렵게 만들어 일반화를 돕자는 것이지, 시험 문제를 바꾸자는 것이 아니다.

## 2. 코드

바뀌는 것은 `transform` 하나뿐이다. 모델도 로스도 최적화기도 [4.1절](01_two_ladders.md) 스텝4 그대로다.

```python
"""스텝6: 데이터 어그멘테이션. 4.1절 스텝4의 CNN을 그대로 두고 transform만 바꾼다.

이 절은 **변환 목록 하나만** 바꾼다. 넷트웍도 규약도 손대지 않으므로, 정확도
차이를 어그멘테이션의 몫으로만 읽을 수 있다.

이 쪽의 프로그램이 4.2~4.4절과 다르게 생긴 까닭이 하나 있다. 그쪽은 모두
dataset_to_tensors / materialize 로 자료를 한 번 변환해 큰 텐서로 구워 두고
돌려 썼다. 어그멘테이션은 그 수법을 쓸 수 없다 — 무작위 자르기와 뒤집기는 **에포크
마다 다시 걸려야** 하고, 구워 두면 한 번 뽑은 크롭이 끝까지 고정되어 어그멘테이션이
아니라 자료를 한 번 흔든 것이 된다. 그래서 여기서는 게으른 Dataset 을 그대로
쓰고, 에포크마다 변환 비용을 치른다. 어그멘테이션이 공짜가 아닌 첫째 까닭이다.
"""

import torch
import torch.nn as nn
import torch.optim as optim
from torch.utils.data import DataLoader, Subset
import torchvision
import torchvision.transforms as transforms

# 씨앗은 42 하나다. 이 쪽이 재는 것은 어그멘테이션 있음과 없음의 **차이**이고, 그
# 차이가 믿을 만한지는 4.1절이 같은 넷트웍에서 잰 씨앗 스프레드 0.89로 가늠한다.
SEED, BATCH, LR = 42, 100, 1e-3
device = torch.device("mps" if torch.backends.mps.is_available() else "cpu")
MEAN, STD = (0.4914, 0.4822, 0.4465), (0.2470, 0.2435, 0.2616)

# 시험용 — 언제나 이것을 쓴다
plain = transforms.Compose([
    transforms.ToTensor(),
    transforms.Normalize(MEAN, STD),
])

# 학습용 — 어그멘테이션을 앞에 붙인다.
# 순서가 중요하다. RandomCrop은 PIL 이미지에 걸리므로 ToTensor보다 앞에 온다
aug = transforms.Compose([
    # 32 -> 사방 4픽셀 덧대어 40x40 -> 거기서 32x32 를 무작위로 잘라 낸다.
    # 그림이 최대 네 픽셀씩 흔들리는 셈이고, 나오는 크기는 그대로 32x32 다.
    transforms.RandomCrop(32, padding=4),
    transforms.RandomHorizontalFlip(),      # 기본 p=0.5. 반은 좌우를 뒤집는다
    transforms.ToTensor(),
    transforms.Normalize(MEAN, STD),
])


def datasets(use_aug):
    """세 벌을 돌려준다. 같은 5만 장이 두 가지 변환으로 두 번 등장한다."""
    tr = torchvision.datasets.CIFAR10("./data", train=True, download=True,
                                      transform=aug if use_aug else plain)
    # 학습 정확도를 잴 때에도 plain을 쓴다. 어그멘테이션된 그림으로 재면
    # "얼마나 외웠는가"를 알 수 없다
    # — 잘리고 뒤집힌 그림을 맞히는 정확도는 외운 정도가 아니라 어그멘테이션의
    #   난이도를 재는 값이 된다. tr 과 tr_eval 은 같은 그림 같은 순서다.
    tr_eval = torchvision.datasets.CIFAR10("./data", train=True, download=True,
                                           transform=plain)
    te = torchvision.datasets.CIFAR10("./data", train=False, download=True,
                                      transform=plain)
    return tr, tr_eval, te


class CNN(nn.Module):
    """4.1절 스텝4 그대로. 바뀌는 것은 들어오는 그림뿐이다."""

    def __init__(self):
        super().__init__()
        self.conv1 = nn.Conv2d(3, 32, 3, padding=1)    # 3채널 → 32채널
        self.conv2 = nn.Conv2d(32, 64, 3, padding=1)   # 32채널 → 64채널
        self.pool = nn.MaxPool2d(2, 2)                 # 지날 때마다 변 길이 절반
        self.dropout = nn.Dropout(0.25)
        self.fc1 = nn.Linear(64 * 8 * 8, 128)          # 4096 → 128
        self.fc2 = nn.Linear(128, 10)                  # 128 → 10

    def forward(self, x):                   # 들어올 때      (N, 3, 32, 32)
        x = self.conv1(x)                   # 채널만 3 → 32  (N, 32, 32, 32)
        x = torch.relu(x)                   # 모양 그대로    (N, 32, 32, 32)
        x = self.pool(x)                    # 변 길이 절반   (N, 32, 16, 16)
        x = self.conv2(x)                   # 채널만 32 → 64 (N, 64, 16, 16)
        x = torch.relu(x)                   # 모양 그대로    (N, 64, 16, 16)
        x = self.pool(x)                    # 변 길이 절반   (N, 64, 8, 8)
        x = x.flatten(1)                    # 64*8*8 = 4096  (N, 4096)
        x = self.fc1(x)                     #               (N, 128)
        x = torch.relu(x)                   # 모양 그대로    (N, 128)
        x = self.dropout(x)                 # train() 일 때만 (N, 128)
        return self.fc2(x)                  # 로짓           (N, 10)


@torch.no_grad()
def accuracy(model, ds, idx=None):
    """ds 의 정확도(%). idx 가 주어지면 그 행들만 본다.

    idx 는 **원본 데이터셋의 행 번호**다. 그래서 학습에 쓴 1,000장과 여기서
    재는 1,000장이 정확히 같은 그림이 된다 — 학습은 Subset(tr, idx) 로 돌고
    재기는 Subset(tr_eval, idx) 로 도는데, 둘의 행 순서가 같기 때문이다.
    """
    model.eval()                            # 드롭아웃 끄기
    if idx is not None:
        ds = Subset(ds, idx)
    correct = n = 0
    for x, y in DataLoader(ds, batch_size=1000, shuffle=False):
        correct += (model(x.to(device)).argmax(1).cpu() == y).sum().item()
        n += y.numel()
    return 100.0 * correct / n


def run(use_aug, epochs, n_label=None):
    """n_label이 주어지면 학습 집합에서 그만큼만 쓴다.

    n_label 이 켜지는 쪽이 이 절의 둘째 실험이다. 라벨이 적을 때 어그멘테이션이
    버는 몫은 5만 장일 때와 부호가 다르다.
    """
    tr, tr_eval, te = datasets(use_aug)
    idx = None
    if n_label is not None:
        # 어느 부분집합을 고르는지도 고정해 둔다
        # — 어그멘테이션 있음과 없음이 **같은 1,000장**을 보아야 견줄 수 있다.
        #   전역 난수기를 쓰면 아래 웨이트 초기화와 뽑기 순서가 얽힌다.
        g = torch.Generator().manual_seed(SEED)
        idx = torch.randperm(len(tr), generator=g)[:n_label].tolist()
        tr = Subset(tr, idx)

    torch.manual_seed(SEED)        # 웨이트 초깃값과 드롭아웃 패턴
    model = CNN().to(device)
    opt = optim.Adam(model.parameters(), lr=LR)
    crit = nn.CrossEntropyLoss()   # 로짓을 받아 안에서 소프트맥스를 한다
    g = torch.Generator().manual_seed(SEED)   # 섞는 순서 (위 g 와는 딴 몸이다)
    loader = DataLoader(tr, batch_size=BATCH, shuffle=True, generator=g)

    for _ in range(epochs):
        model.train()              # 드롭아웃 켜기. accuracy() 가 eval 로 두고
                                   # 나가므로 이 줄이 반복문 안에 있어야 한다
        for x, y in loader:        # 어그멘테이션은 여기서 걸린다 — 에포크마다 새 크롭
            x, y = x.to(device), y.to(device)
            opt.zero_grad()
            loss = crit(model(x), y)
            loss.backward()
            opt.step()

    # 학습 쪽은 plain 으로 잰 tr_eval 에서, 시험 쪽은 te 에서.
    # 틈 = 학습 - 시험 이 곧 "얼마나 외웠는가"다
    tr_acc = accuracy(model, tr_eval, idx)
    te_acc = accuracy(model, te)
    tag = "어그멘테이션 있음" if use_aug else "어그멘테이션 없음"
    print(f"  {tag}  {epochs:3d}에포크   학습 {tr_acc:6.2f}  "
          f"시험 {te_acc:5.2f}  틈 {tr_acc - te_acc:5.2f}", flush=True)


# 실험 하나 — 라벨 5만 장. 짧은 예산(5)과 긴 예산(30)에서 부호가 뒤집히는가
print("=== 전체 5만 장 ===")
for epochs in (5, 30):
    for use_aug in (False, True):
        run(use_aug, epochs)

# 실험 둘 — 라벨 1,000장. 자료가 모자랄 때로 옮기면 어떻게 되는가.
# 한 에포크가 50분의 1이라 예산을 30, 100으로 키워도 싸다
print("\n=== 라벨 1,000장 ===")
for epochs in (30, 100):
    for use_aug in (False, True):
        run(use_aug, epochs, n_label=1000)
```

## 3. 5 에포크에서는 정확도가 낮아진다

먼저 스텝4와 똑같이 5 에포크를 돌려 보자.

| 5 에포크 | 학습 정확도 | 시험 정확도 | 틈 |
|---|---|---|---|
| 어그멘테이션 없음 | 81.40% | **71.86%** | 9.54 |
| 어그멘테이션 있음 | 70.16% | **69.34%** | 0.82 |

**2.52%포인트를 잃었다.**

학습·시험 정확도 차이는 9.54에서 0.82%포인트로 줄었지만 시험 정확도도 낮아졌다. 특히 학습 정확도가 무작위 어그멘테이션 입력에서 측정되었다면 시험 정확도와 입력 조건이 다르므로, 작은 차이만으로 과적합이 사라졌다고 판단할 수 없다.

5 에포크에서는 어그멘테이션 모델이 더 어려운 입력에 충분히 적응하지 못했을 가능성이 있다. 다만 어그멘테이션 학습 정확도와 원본 시험 정확도를 직접 비교해 과소적합을 증명할 수는 없다. 다음 절에서는 학습 기간을 늘렸을 때의 결과를 비교한다.

## 4. 예산을 늘리면 뒤집힌다

같은 두 모델을 30 에포크로 돌린다.

| 30 에포크 | 학습 정확도 | 시험 정확도 | 틈 |
|---|---|---|---|
| 어그멘테이션 없음 | **99.05%** | 71.75% | **27.30** |
| 어그멘테이션 있음 | 80.77% | **77.71%** | 3.06 |

어그멘테이션 없는 모델의 학습 정확도는 99.05%까지 올랐지만 시험 정확도는 71.75%로 거의 변하지 않았다. 5 에포크 대비 차이는 −0.11%포인트다. 이 기록은 학습 표본에 대한 적합이 크게 개선되어도 일반화 성능은 함께 좋아지지 않을 수 있음을 보여 준다.

어그멘테이션 있는 쪽은 77.71%다. 5 에포크의 69.34%에서 8.37%포인트가 올랐고, 어그멘테이션 없는 쪽보다 5.96%포인트 높다.

### 둘 중 하나만으로는 안 된다

네 칸을 한데 놓으면 이 절의 요점이 드러난다.

| 시험 정확도 | 5 에포크 | 30 에포크 |
|---|---|---|
| 어그멘테이션 없음 | 71.86% | 71.75% |
| 어그멘테이션 있음 | 69.34% | **77.71%** |

기준점(71.86%)에서 하나씩만 바꾸어 보면 이렇다.

| 무엇을 바꾸었나 | 얻은 것 |
|---|---|
| 에포크만 5 → 30 | **−0.11%p** |
| 어그멘테이션만 켬 | **−2.52%p** |
| **둘 다** | **+5.85%p** |

따로 하면 둘 다 손해이거나 아무것도 아닌데, 함께 하면 5.85%포인트를 얻는다. 따로 한 몫을 더하면 $-0.11 - 2.52 = -2.63$이니, 둘이 함께일 때만 생기는 몫이 $5.85 - (-2.63) = 8.48$%포인트나 된다.

**어그멘테이션의 효과는 이 실험에서 학습 기간과 상호작용했다.** 5 에포크에서는 평균 비교가 불리했고, 30 에포크에서는 유리했다. 어느 한 시점의 결과를 모든 학습 조건으로 일반화해서는 안 된다.

[3장 4절](../ch03/mnist/04_cnn.md)이 드롭아웃을 두고 한 말이 여기서 큰 규모로 되풀이된다. 그 절은 5 에포크에서 드롭아웃을 빼도 0.59%포인트밖에 차이가 없다고 재면서, **정칙화의 값어치는 "얼마나 과적합할 상황인가"에 상대적**이라고 적었다. 30 에포크에서 틈이 27.30까지 벌어지자 같은 종류의 장치가 5.96%포인트를 벌어 준다.

## 5. 라벨이 1,000장뿐이라면

어그멘테이션은 데이터가 모자란 것을 메우는 수법이다. 그렇다면 데이터가 **정말로** 모자랄 때 가장 값을 해야 한다. 5만 장 가운데 1,000장만 쓰고 같은 실험을 다시 돌린다. [4.6절](03_vgg16_transfer.md)이 같은 두 자리(라벨 1,000장과 5만 장)를 다른 수법으로 재므로, 여기서 얻은 값이 그 절의 견줄 자리가 된다.

| 라벨 1,000장 | 학습 정확도 | 시험 정확도 | 틈 |
|---|---|---|---|
| 어그멘테이션 없음, 30 에포크 | 99.90% | 43.79% | 56.11 |
| 어그멘테이션 있음, 30 에포크 | 65.70% | 45.13% | 20.57 |
| 어그멘테이션 없음, 100 에포크 | **100.00%** | 43.04% | **56.96** |
| 어그멘테이션 있음, 100 에포크 | 92.60% | **49.77%** | 42.83 |

셋째 줄을 보라. **학습 정확도가 정확히 100.00%다.** 1,000장을 한 장도 남김없이 외웠고, 시험에서는 43.04%다. 100 에포크를 돌아 30 에포크일 때(43.79%)보다 오히려 조금 나빠졌다.

어그멘테이션은 여기서도 예산이 있어야 값을 한다. 30 에포크에서는 1.34%포인트뿐이지만 100 에포크에서는 6.73%포인트다. 앞 절과 같은 이야기다.

## 6. 어그멘테이션이 메우는 것과 메우지 못하는 것

여섯째 스텝은 원본의 라벨을 유지하는 변형을 통해 일반화를 돕는다. 같은 30 에포크의 기준선 71.75%와 비교하면 어그멘테이션 모델은 77.71%로 5.96%포인트 높았다. 4.1절의 72.58%와의 차이 5.13%포인트에는 학습 기간 차이도 포함되므로 어그멘테이션만의 이득으로 읽지 않는다. 파라메터 수는 같다.

그런데 어그멘테이션이 할 수 있는 일에는 벽이 있다. 오리고 뒤집는 것은 **이미 가진 그림 안에 있는 것을 다시 섞는 일**이다. 바로 위 5절의 표가 그 벽을 보여 준다. 라벨 1,000장에 100 에포크를 쏟아 얻은 49.77%는, 5만 장을 그냥 쓴 처음부터 학습한 CNN(72.58%)보다 여전히 **22.81%포인트** 낮다. 그 1,000장에 없는 생김새는 아무리 흔들어도 나오지 않는다.

그러니 데이터가 모자란 것을 메우는 길이 하나 더 있어야 한다. 있는 데이터를 불리는 대신 **남의 데이터를 가져오는** 것이다.

| | 어떻게 메우는가 |
|---|---|
| 스텝6 어그멘테이션 (이 절) | **있는 데이터를 불린다** (오리고 뒤집어서) |
| 스텝5 전이 ([4.6절](03_vgg16_transfer.md)) | **남의 데이터**를 가져온다 (ImageNet 120만 장) |

같은 물음에 대한 두 답이다. [4.6절](03_vgg16_transfer.md)이 방금 쓴 두 자리에서 전이를 재고, 그 자리에서 두 답을 나란히 놓는다. 라벨이 넉넉해지면 내 데이터 안에 이미 웬만한 변이가 들어 있으므로 남의 데이터를 빌릴 값어치가 줄어들 텐데, 그 줄어드는 폭이 얼마인지도 그 절이 잰다.

### 전이 위에 어그멘테이션을 얹으면

두 답이 서로 쌓이는지는 여기서 재어 둘 수 있다. [4.6절](03_vgg16_transfer.md)이 쓰는 **고정한 VGG16 피처** 위에 같은 어그멘테이션을 걸어 보았다. 이 장의 규약대로 5 에포크다.

정확도의 절대값은 4.6절이 내놓을 값이므로 여기서는 적지 않는다. 여기서 볼 것은 그 값이 아니라 **어그멘테이션이 그 위에서 얼마를 버는가**다.

| 5 에포크 | 처음부터 학습한 CNN | 고정한 VGG16 피처 |
|---|---|---|
| 어그멘테이션이 버는 몫 | **−2.52%p** | **−1.16%p** |

**두 칸 모두 손해다.** 그리고 이 결과를 읽을 때 조심할 것이 있다.

3절에서 보았듯 5 에포크는 어그멘테이션이 손해를 보는 예산이다. 맨바닥 쪽은 30 에포크로 늘리자 −2.52에서 +5.96으로 뒤집혔다. **전이 쪽도 학습 기간에 따라 결과가 달라질 수 있지만, 이 책은 긴 학습 기간을 비교하지 않았다.** 어그멘테이션을 걸면 에포크마다 그림이 달라져 VGG16 피처를 다시 뽑아야 하고, 한 에포크에 15분이 든다. 30 에포크면 일곱 시간 반이다.

그러므로 정직한 결론은 "어그멘테이션은 전이에 도움이 안 된다"가 아니라 이것이다. **5 에포크에서는 두 경우 모두 손해이며, 맨바닥에서 얻은 증거는 이것이 예산 탓임을 가리킨다.**

에포크마다 재어 보면 한 가지가 더 드러난다. 전이 위에서 어그멘테이션이 잃는 몫이 이렇게 움직인다.

| 에포크 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| 어그멘테이션이 잃는 몫 | 2.00%p | 1.62%p | **0.65%p** | 1.59%p | 1.16%p |

어그멘테이션 없는 쪽은 3 에포크에서 이미 평평해진다(그 뒤 세 값이 0.05%포인트 안에 모여 있다). 얼린 피처 위의 선형 분류기라 빨리 수렴한다. 어그멘테이션 있는 쪽은 오르내린다. 에포크마다 **다른 크롭에서 피처를 다시 뽑으므로 학습 분포 자체가 매번 조금씩 달라지기** 때문이며, 이 흔들림은 시드를 바꿀 때 생기는 흔들림과는 종류가 다르다.

그래서 틈이 3 에포크에서 0.65%포인트까지 좁아진다. 세 점만 보고 4~5 에포크를 짐작했다면 "곧 따라잡는다"고 적었을 것이다. 실제로는 4 에포크에서 1.59%포인트로 다시 벌어졌다. [4.1절](01_two_ladders.md) 연습문제 5가 경고한 그대로다.

## 7. 좋은 점과 아쉬운 점

### 좋은 점

**이 장에서 처음부터 학습한 모델이 닿은 가장 높은 값이다.** 77.71%로, 남의 데이터를 빌리지 않고 얻은 것 가운데 가장 높다. 스텝4 CNN의 71.75%에서 **5.96%포인트**를 벌었다.

**라벨 1,000장 설정에서도 개선이 관측되었다.** 100 에포크에서는 43.04%에서 49.77%로 6.73%포인트 높아졌다. 5만 장의 30 에포크 결과와는 예산이 다르므로, 이 두 차이만으로 데이터가 적을수록 어그멘테이션의 효과가 반드시 커진다고 결론 내릴 수는 없다.

**들여올 것이 없다.** 자르기와 뒤집기뿐이고, 새 파라메터도 새 모델도 없다. 전처리 두 줄이면 끝난다. [4.2절](06_ensemble.md)이 모델을 다섯 대 세우고 [4.6절](03_vgg16_transfer.md)이 남의 웨이트를 가져오는 것과 견주면 **가장 싼 수법**이다.

**학습·시험 정확도 차이를 줄인다.** 학습−시험 틈이 27.30에서 3.06으로 **24.24%포인트** 줄어든다. 라벨이 1,000장뿐일 때는 56.11에서 20.57로 35.54%포인트가 줄어 폭이 더 크다 — 메울 것이 많을수록 더 많이 메운다.

### 아쉬운 점

**이 설정의 5 에포크에서는 정확도가 낮았다.** 어그멘테이션 모델은 시험 정확도가 2.52%포인트 낮았고 학습·시험 차이도 작았다. 낮은 차이가 높은 일반화 성능을 보장하지 않으며, 어그멘테이션 입력에서 측정한 학습 정확도를 해석할 때는 평가 조건도 확인해야 한다.

**그래서 예산을 함께 늘려야 한다.** 30 에포크를 돌려야 부호가 뒤집힌다. 곧 "싸다"는 말은 코드에 대해서만 참이고 **계산에 대해서는 참이 아니다.** 여섯 배를 더 돌려야 값을 한다.

**천장이 남의 데이터보다 낮다.** 같은 두 자리를 전이와 견주면 라벨 1,000장에서 49.77% 대 77.46%, 5만 장에서 77.71% 대 84.93%다. **내 데이터를 흔드는 것으로는 남의 데이터 120만 장을 이기지 못한다.**

**무엇을 흔들지는 데이터가 정한다.** 좌우 뒤집기가 CIFAR-10에서 통하는 것은 고양이를 뒤집어도 고양이이기 때문이다. 글자나 숫자였다면 글자의 형태가 달라져 라벨의 의미가 훼손될 수 있다. **공짜로 옮겨 쓸 수 있는 설정이 아니다.**

<div class="defn" markdown>

어그멘테이션은 원본 데이터를 대체하지 않지만, 라벨을 보존하는 입력 변화를 학습하는 데 도움이 될 수 있다. 적용할 변환과 학습 기간은 함께 검증해야 한다. 이 절에서는 30 에포크의 CIFAR-10 비교에서 개선을 관측했다.

그리고 이 절과 [4.6절](03_vgg16_transfer.md)은 같은 물음에 대한 두 답이다. **있는 데이터를 불릴 것인가, 남의 데이터를 빌릴 것인가.** 6절이 그 둘을 나란히 놓는다.

</div>

    어그멘테이션이 도움이 되지 않았다는 결과를 해석할 때도 학습 기간과 변환의 적절성을 함께 확인해야 한다.

**연습문제 3.** <span class="diff med" title="중간"></span>
`RandomHorizontalFlip`은 CIFAR-10에서 쓸 수 있고 MNIST에서는 쓸 수 없다. 그렇다면 **위아래 뒤집기**(`RandomVerticalFlip`)는 CIFAR-10에서 쓸 수 있는가? `RandomRotation(15)`는?

</div>

??? success "풀이"
    **위아래 뒤집기는 이 데이터에서 신중하게 판단해야 한다.** CIFAR-10의 사진은 모두 중력이 있는 세상에서 찍힌 것이라 하늘이 위에 있고 땅이 아래에 있다. 뒤집으면 학습 데이터에 시험 데이터에는 없는 분포가 섞인다. 이름이 바뀌지는 않지만(뒤집힌 말도 말이다) **그런 그림이 시험에 나오지 않는다**는 점이 문제다.

    이것이 좌우 뒤집기와 다른 점이다. 좌우로 뒤집힌 말 사진은 실제로 흔하지만, 위아래로 뒤집힌 말 사진은 흔하지 않다.

    **작은 회전은 검증해 볼 수 있는 후보이다.** $15^\circ$쯤이면 실제 사진에 있을 법한 그래디언트이고 이름도 바뀌지 않는다. 다만 회전은 테두리에 빈 곳을 만들므로 그 처리를 정해야 하고, 각도가 커지면 위아래 뒤집기와 같은 문제에 부딪힌다.

    판단 기준은 하나다. **어그멘테이션해서 만든 그림이 시험에 나올 법한 그림인가.** 이름이 보존되는지만 보아서는 모자란다.

<div class="drillbox" markdown>

**연습문제 4.** <span class="diff hard" title="어려움"></span>
라벨 1,000장에서 어그멘테이션 없이 100 에포크를 돌면 학습 정확도가 정확히 100.00%가 된다. 이를 보고 로스와 그래디언트도 거의 0이므로 **학습을 더 해도 파라메터가 거의 움직이지 않을 것**이라고 추측했다. 그런데도 시험 정확도가 30 에포크일 때(43.79%)보다 100 에포크일 때(43.04%) 더 나빠졌다. 어떻게 된 일인가?

</div>

    학습 정확도 100%는 **모든 그림을 옳게 분류한다**는 뜻이지 로스가 0이라는 뜻이 아니다. 교차 엔트로피는 옳게 맞혀도 확신이 더 커질 여지가 남아 있는 한 계속 줄어든다. 정답 클래스의 확률이 0.6이든 0.99든 둘 다 "맞힘"이지만 로스는 크게 다르다.

    그래서 100% 이후로도 경사는 0이 아니고, 최적화기는 **결정 경계를 학습 표본에서 더 멀리 밀어내는 방향**으로 계속 움직인다. 1,000장뿐인 표본에서 그 방향은 대개 표본의 잡음까지 반영하므로, 경계가 진짜 경계에서 조금씩 멀어진다.

    드롭아웃이 있어 매 단계 다른 부분망이 학습되는 것도 한몫한다. 100% 정확도는 평가 모드에서 잰 값이고, 학습 모드에서는 여전히 틀리는 표본이 있어 갱신이 이어진다.

    두 값의 차이 0.75%포인트가 이 장에서 잰 시드 스프레드보다 크게 잡기 어려운 크기라는 점도 함께 적어 둔다. 방향은 여러 번 관찰되는 현상이지만, 이 한 쌍만으로 "나빠졌다"고 단정하려면 시드를 여러 개 돌려 확인해야 한다.
