# 노드 구조

배열은 연속된 메모리 덩어리를 요구하므로, 원소를 밀어야 해서 중간에서의 삽입과 삭제가 비싸다. 연결 리스트는 원소를 메모리 여기저기에 흩어 놓고 포인터로 이어 이 제약을 없앤다. 연결 리스트의 기본 구성 요소는 **노드**이다. 데이터 원소 하나와 열에서 다음 노드를 가리키는 참조(포인터)를 담는 작은 그릇이다. 삽입, 삭제, 순회, 탐색이 모두 이 노드 객체와 포인터를 다루는 일이므로, 연결 리스트의 연산을 공부하기 전에 노드 구조를 이해해 두는 것이 필수적이다.

---

## 1. 정의

**단일 연결 리스트 노드**는 두 개의 항목으로 이루어진다.

1. **데이터**(키, 값, 원소라고도 한다): 리스트의 이 자리에 저장된 항목.
2. **다음**(링크나 포인터라고도 한다): 리스트에서 다음 노드를 가리키는 참조. 마지막 노드라면 `None`(널)이다.

형식적으로 각 노드 $x$은 다음을 갖는다.

- $x.\text{data}$: 저장된 값
- $x.\text{next}$: 뒤따르는 노드를 가리키는 포인터. $x$이 꼬리라면 $\text{NIL}$이다

리스트 자체는 첫 노드를 가리키는 **머리 포인터** 하나로 나타낸다. 머리가 `None`이면 리스트는 비어 있다.

---

## 2. 메모리 배치

배열과 달리 연결 리스트의 노드는 메모리에 연속해서 저장되지 않는다. 각 노드가 따로 할당되며, 다음 노드에 닿는 유일한 길은 `next` 포인터이다. 여기서 중요한 결과 둘이 따라 나온다.

1. **임의 접근이 안 된다**: $k$번째 원소에 닿으려면 머리에서 시작해 포인터를 $k$번 따라가야 한다. 배열의 $O(1)$에 비해 $O(k)$ 시간이 든다.
2. **삽입과 삭제가 유연하다**: 노드를 넣거나 빼는 데는 포인터 몇 개만 고치면 되며, 위치를 알고 있다면 $O(1)$ 시간이 든다. 원소를 밀 필요가 없다.

??? example "메모리에서의 연결 리스트와 배열"

    배열 `[10, 20, 30]`은 연속된 주소를 차지한다.

    ```
    Address: 1000  1004  1008
    Value:   [10]  [20]  [30]
    ```

    같은 값을 담은 연결 리스트는 노드가 아무 데나 흩어져 있을 수 있다.

    ```
    Address 2048: [data=10 | next→5120]
    Address 5120: [data=20 | next→3072]
    Address 3072: [data=30 | next=None]
    head → 2048
    ```

    값은 같지만 메모리 배치는 완전히 다르다.

## 3. 파이썬 구현

```python
"""단일 연결 리스트의 노드 구조."""

# === 노드 클래스 ===
class Node:
    """단일 연결 리스트의 노드 하나.

    속성:
        data: 이 노드에 담긴 값.
        next: 다음 노드에 대한 참조. 꼬리이면 None.
    """

    def __init__(self, data, next_node=None):
        self.data = data
        self.next = next_node

    def __repr__(self):
        return f"Node({self.data})"

# === 도우미: 파이썬 리스트에서 연결 리스트 만들기 ===
def build_list(values):
    """반복 가능한 객체에서 연결 리스트를 만들고 머리 노드를 돌려준다."""
    head = None
    for val in reversed(values):
        head = Node(val, head)
    return head

# === 도우미: 보여 주기 위해 연결 리스트를 파이썬 리스트로 바꾸기 ===
def to_list(head):
    """연결 리스트를 순회하며 값을 파이썬 리스트로 모은다."""
    result = []
    current = head
    while current is not None:
        result.append(current.data)
        current = current.next
    return result

# === 시연 ===
if __name__ == "__main__":
    # 리스트 만들기: 10 -> 20 -> 30 -> 40
    head = build_list([10, 20, 30, 40])

    # 리스트 보이기
    print(f"List: {to_list(head)}")
    print(f"Head: {head}")
    print(f"Second node: {head.next}")
    print(f"Tail: {head.next.next.next}")
    print(f"After tail: {head.next.next.next.next}")
```

**출력:**
```
List: [10, 20, 30, 40]
Head: Node(10)
Second node: Node(20)
Tail: Node(40)
After tail: None
```

## 4. 공간 부담

각 노드는 데이터와 포인터를 함께 저장한다. 원소가 $n$개인 리스트의 총 메모리는 다음과 같다.

$$
n \cdot (w_{\text{data}} + w_{\text{pointer}})
$$

여기서 $w_{\text{data}}$은 데이터 항목의 크기이고 $w_{\text{pointer}}$은 포인터의 크기이다(64비트 시스템에서 보통 8바이트). 파이썬에서는 각 `Node`가 사전, 자료형 포인터, 참조 계수를 갖춘 온전한 객체라서 부담이 더 크다. NumPy 배열의 원소당 8바이트에 비해 노드당 보통 50~100바이트가 든다.

!!! warning "연결 리스트는 메모리를 많이 먹는다"

    파이썬 같은 고수준 언어에서 노드당 부담은 같은 내용을 담은 배열 저장보다 10~20배 클 수 있다. 연결 리스트는 메모리 효율이 아니라 구조적 이점(효율적인 삽입과 삭제) 때문에 고르는 것이다.

---

## 5. 머리 포인터

연결 리스트의 모든 연산은 **머리 포인터**에서 시작한다. 머리는 노드 자체가 아니라 첫 노드를 가리키는 참조를 담은 변수이다. 이 구분이 중요한 이유는 다음과 같다.

- 리스트의 앞에 삽입하면 머리가 바뀌므로, 리스트를 고치는 함수는 새 머리를 반환해야 한다(또는 감싸는 객체를 써야 한다).
- 빈 리스트는 특별한 감시 노드가 아니라 `head = None`으로 나타낸다(다만 이중 연결 리스트 절에서 다루듯 감시 노드를 쓰는 설계도 있다).

## 연습문제

**연습문제 1.**
노드 구조에 대해 삽입, 삭제, 탐색, 접근 연산의 시간 복잡도를 진술하라.

??? success "연습문제 1 풀이"
    복잡도는 구체적인 구현(배열 기반이냐 연결 기반이냐)에 달려 있다. 배열 기반은 접근이 $O(1)$이고 임의의 위치에서의 삽입·삭제가 $O(n)$이다. 연결 기반은 이미 아는 위치에서의 삽입·삭제가 $O(1)$이고 탐색·접근이 $O(n)$이다. 어떤 연산이 주를 이루느냐에 따라 선택이 갈린다.

---

**연습문제 2.**
원소 6개로 노드 구조을(를) 따라가며 각 연산 후의 자료구조 상태를 보여라.

??? success "연습문제 2 풀이"
    구조에 삽입, 접근, 삭제를 차례로 수행하라. 각 단계마다 (연결 구조라면) 포인터를, (배열 기반이라면) 배열의 내용을 보이며 구조가 불변식을 어떻게 유지하는지 나타내라.

---

**연습문제 3.**
노드 구조이(가) PyTorch의 텐서 저장과 어떻게 관련되는지 설명하라. 자료구조의 선택이 메모리 배치와 캐시 성능에 어떤 영향을 주는가?

??? success "연습문제 3 풀이"
    PyTorch 텐서는 캐시에 효율적으로 접근할 수 있도록 연속된 배열로 저장된다. 연결 구조는 autograd 그래프를 훑는 데 내부적으로 쓰인다. 이 선택은 메모리 사용량(배열에는 포인터 부담이 없다)과 접근 양상(캐시 지역성 덕분에 순차적인 배열 접근이 연결 리스트 순회보다 10~100배 빠르다)에 모두 영향을 준다.

---

**연습문제 4.**
반복문 불변식을 사용하여 노드 구조의 주요 연산의 시간 복잡도를 증명하라.

??? success "연습문제 4 풀이"
    알고리즘의 반복문이 유지하는 불변식을 진술하라. 초기화, 유지, 종료를 증명하라. 이 불변식으로부터 반복문이 명시된 횟수 안에 끝남이 따라 나오며, 이로써 복잡도의 상계가 확립된다. $\square$
