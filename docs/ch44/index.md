# 45장: 모델 배포

이 장은 딥러닝 모델을 프로덕션에 배포하는 전체 수명 주기를 다룬다. 직렬화와 최적화에서 서빙 인프라, 분산 계산, MLOps 관행에 이른다. 지연, 처리량, 신뢰성이 거래 성능과 위험 관리에 직결되는 계량 금융에서는 효율적인 배포가 특히 중요하다. 이 장은 연구용 노트북(Jupyter)의 모델을 프로덕션 시스템으로 옮기는 실용적인 지침을 준다.

---

## 1. 직렬화

트레인된 모델을 여러 환경에 배포하려고 저장하고, 불러오고, 내보내기.

- 모델 저장 -- PyTorch 내장 직렬화 방식과 배포 환경 간 이식성
- 상태 사전(state_dict) -- 모델 저장, 전이 학습, 디버깅에 쓰는 PyTorch의 표준 파라메터 직렬화
- TorchScript -- C++, 모바일, 임베디드 환경에 배포할, 파이썬 없이 직렬화할 수 있는 모델 만들기
- ONNX 내보내기 -- 프레임워크와 하드웨어를 넘나들며 모델을 배포하는 개방형 뉴럴 네트워크 교환 형식
- 체크포인트 만들기 -- 오래 걸리는 작업에서 복원, 분석, 모델 선택에 쓸 완전한 트레인 상태 저장

---

## 2. 최적화

효율적인 추론을 위해 모델을 압축하고 가속하기.

- [양자화](optimization/quantization.md) -- FP32에서 INT8/INT4로 수치 정밀도를 줄여 메모리를 아끼고 추론을 빠르게 하기
- 모델 가지치기 -- 불필요한 파라메터를 없애 메모리와 계산이 적은 희소 모델 만들기
- [지식 증류](optimization/distillation.md) -- 큰 교사 모델의 지식을 작고 배포하기 좋은 학생 모델로 옮기기
- [뉴럴 네트워크 아키텍처 탐색](optimization/nas.md) -- 정확도, 지연, 모델 크기를 최적화하는 자동 구조 설계

---

## 3. 추론 최적화

추론 시 처리량을 최대화하고 지연을 최소화.

- CPU 최적화 -- CPU 전용 환경을 위한 스레드 설정, 연산자 융합, 그 밖의 최적화
- TensorRT로 하는 GPU 최적화 -- 커널 자동 튜닝, 정밀도 보정, 레이어 융합을 하는 NVIDIA TensorRT
- 배치 추론 -- 입력 여럿을 한꺼번에 처리해 하드웨어 활용도를 최대화하기
- 메모리 관리 -- 메모리 부족 오류를 막고 지연을 줄이는 GPU·CPU 메모리 최적화
- 스트리밍 추론 -- 실시간 시장 데이터와 거래 신호를 위한 연속 데이터 스트림의 실시간 처리

---

## 4. 모델 서빙

확장, 버전 관리, 모니터링을 갖춘 프로덕션 모델 배포.

- REST API 서빙 -- 요청 배칭, 버전 관리, 수평 확장을 갖춘 모델 서빙 프레임워크
- gRPC 서빙 -- Protocol Buffers와 HTTP/2로 하는 빠르고 지연이 적은 모델 서빙
- TorchServe -- 동적 배칭과 다중 모델 관리를 갖춘 PyTorch의 공식 서빙 프레임워크
- NVIDIA Triton 추론 서버 -- GPU 스케줄링과 모델 앙상블을 갖춘 엔터프라이즈급 다중 프레임워크 서빙
- BentoML -- 컨테이너 지원을 갖추고 프로덕션 품질의 AI 서비스를 만드는 파이썬 우선 프레임워크

---

## 5. 분산 계산

여러 GPU와 노드에 걸쳐 트레인과 추론을 확장하기.

- 데이터 병렬화 -- PyTorch DataParallel로 하는 단일 프로세스 다중 GPU 트레인
- 분산 데이터 병렬 트레인(DDP) -- AllReduce 통신으로 GPU 수백 개까지 확장하는 다중 프로세스 트레인
- 모델 병렬화 -- 큰 모델이 GPU 하나의 메모리를 넘을 때 장치에 걸쳐 분할하기
- 파이프라인 병렬화 -- 마이크로배치의 계산을 GPU에 걸쳐 겹쳐 다중 장치 트레인을 효율적으로 하기
- 완전 샤딩 데이터 병렬화(FSDP) -- 파라메터, 그래디언트, 옵티마이저 상태를 샤딩해 메모리를 아끼는 분산 트레인
- DeepSpeed -- ZeRO 최적화로 파라메터가 수십억에서 수조인 모델을 트레인하는 마이크로소프트의 라이브러리

---

## 6. MLOps

프로덕션에서 머신러닝 수명 주기를 관리하는 관행.

- 실험 추적 -- 재현할 수 있게 하이퍼파라미터, 지표, 산출물을 체계적으로 기록하기
- 모델 레지스트리(MLflow) -- 모델 버전, 단계 전환, 프로덕션 승격을 관리하기
- 머신러닝을 위한 CI/CD -- 모델 변경을 테스트하고 트레인하고 평가하고 배포하는 자동화 파이프라인
- 프로덕션 모니터링 -- 배포된 모델의 성능, 상태, 데이터 드리프트 추적
- 모델 A/B 테스트 -- 프로덕션에서 모델 버전을 비교하며 지표를 통계적으로 분석하기

---

## 7. 금융 응용

계량 금융 시스템에 특화된 배포 고려 사항.

- 프로덕션 파이프라인 -- 거래일 달력, 기업 행동, 규제 요건을 다루는 엔드투엔드 머신러닝 파이프라인
- 실시간 시스템 -- 트레이딩 시스템에서 지연이 일정한 모델 추론을 위한 아키텍처 패턴
- 지연 요건 -- 금융 응용의 지연 예산, 측정 방법, 최적화 기법
- 백테스팅 인프라 -- 미래 정보 누출(look-ahead)과 생존 편향을 제대로 다루며 과거 데이터로 모델 성능 평가하기

---
